# 干净仓库公开准备

本仓库是从清洗后的源码快照建立的独立迁移准备仓库，当前保持 private，尚未完成同名切换或公开。它不继承旧 Git 提交、PR、Actions 日志或私人运行文件；旧库继续保持私人。

## 已准备的边界

- main 与 develop 的源码状态分别保留，旧开放 PR 和本地修改保存于私人迁移账本；没有为了搬迁批量合并草稿。
- README、来源示例和演示素材不使用个人身份；真实课程／笔记样本定位已泛化。旧 PR 链接转为私人历史记录说明，不误指新库编号。
- 公开项目的 CI 候选使用 GitHub 托管运行器、只读 Token 和离线演示，不关联个人 Mac、真实内容或部署凭据。本机已完成 2,476 项测试与构建，48 份服务端追踪通过隐私检查；平台结果须另行确认。
- 私有配置、Git 备份、项目记忆、运行回执和任务交接留在忽略目录或旧私人运行根。当前文件检查不保证将来的提交自动保持干净，每个开发环境仍须维护自己的私有标识阻止清单。

## 实际公开前

1. 对最终提交与两条分支完成隐私、协议、应用测试、构建和平台检查，核对示例、媒体与日志。
2. 维护者已选择 [MIT 许可证](../LICENSE) 用于项目原创源码；核对第三方许可，个人内容不随源码授权。
3. 完成主分支保护与私密漏洞反馈渠道，核对公开后工作流的信任边界。
4. 核对旧库改名、旧检出远端、新库同名切换和每项任务的接续确认；部署绑定仍单独验收。
5. 取得最终公开确认后再切换可见性。公开后的提交与 PR 同样可见，不能重新合入旧私人历史。

本页说明新仓库的准备范围，不声称已经删除旧私人仓库的数据、完成全部运行链路验收或公开仓库。详细流程见[迁移说明](REPOSITORY_MIGRATION.md)和[隐私约定](PRIVACY.md)。
