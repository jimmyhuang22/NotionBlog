# 同步维护 SQL 的回传预算与复用

`scripts/operator-sql/website.ts` 是独立维护程序的显式接入模块。它减少完整验收快照和缩略图资格结果的重复传输，不改变网站 DTO、数据库权限、发布条件或当前后台任务。提交代码不等于安装运行包。

## 查询如何执行

1. 只接受固定 SQL 允许列表；reader 与 writer 使用不同列表、不同缓存命名空间。登记语句始终执行，不缓存、不重试。
2. 每次调用仍在原角色下执行原查询，包括过期、撤回、拥有关系和当前公开资格检查。没有通过“先读摘要、再读正文”增加第二次查询。
3. 同一条 SQL 内将结果物化一次。结果顶层的 `runId`、`revision` 独立返回；小图读取还独立返回本次 `thumbnail`，保留未登记的 null。来源描述、指纹和其他资格字段全部参加本次 SHA-256；登记状态绝不从上次结果推定。
4. SSD 保存 PostgreSQL 实际序列化的文本及其摘要。数据库本次摘要与本地验证过的摘要相等时，只返回摘要和本次批次信息；否则返回新正文。
5. 客户端重新校验缓存文本的摘要，再恢复原查询的行结构，原 DTO 与图片投影校验继续运行。缓存损坏直接停止，不能退回无预算下载。

网站内容读取只对 `links`、`mediaIds` 两组资格集合按固定 C 顺序排序后参与摘要，保留全部成员、重复项和原始字符串。现有 DTO 投影用 Set 检查成员，不依赖这两组数组的排列；正文、记录、分栏和小图批次的顺序均保持。集合成员不是字符串或集合缺失时拒绝，不删除无效项来制造命中。SQL 聚合的默认顺序不保证稳定，见 [PostgreSQL 聚合说明](https://www.postgresql.org/docs/17/functions-aggregate.html)。

新的独立回传字段与集合处理绑定 `website-maintenance-v2` 命名空间和缓存键。首次接入需要填充新缓存；不会使用旧格式缓存冒充新格式命中。新字段也先纳入响应预算检查，过大时仍阻断正文回传。

SQL 内计算摘要仍需数据库执行资格查询与序列化。收益主要是降低数据库向 Mac 的回传量；不保证降低数据库 CPU，也不减少原来的查询次数。首次缓存为空、内容变化、配置变动或缓存淘汰后需要重新传输对应结果。

## 接线示例

调用方必须先冻结会话计划；下面的目录均为已审核的绝对私有路径，命名空间摘要绑定目标数据库、角色、协议及来源配置。计划 ID 为不可变输入的 SHA-256，不能在重启或失败时换目录领取新预算。

```ts
const session = await createWebsiteMaintenanceSession({
  cacheDirectory, budgetDirectory, namespace, plan,
  cacheLimits: {maxBytes: 128 * 1024 ** 2, maxEntryBytes: 8 * 1024 ** 2, maxEntries: 1024},
});
const reader = session.reader(existingReaderExecutor);
const writer = session.writer(existingWriterExecutor);
const repository = createWebsiteDatabaseRepository(reader, {snapshotPageSize: 50});
const snapshot = await repository.readSnapshot(selectedKinds, true);
```

保留已有连接的严格 TLS、查询超时、总截止时间、写入前预检、写入日志及独立 reader 回读。读取只支持本文件模块明确登记的查询，未登记的新查询会被拒绝。通用模块的 `cache: true` 仅适用于人工审核过的读取函数；`SELECT` 本身不能证明没有写入。

## 预算的含义

`OperatorSqlPlan` 必须包含 `version`、`session`、`stopAt`、`maxQueries`、`maxResponseBytes` 和 `maxQueryResponseBytes`。每次发送前，私有账本锁住并预留次数及字节；同一周期的不同阶段、进程和重启共用原计划、原账本。收到结果后按 SQL 响应信封结算；传输结果不明时扣满该次预留额并停止。截止时间、次数、字节耗尽或未结清请求超时后均不能自动恢复。

大结果的字节上限在数据库发回正文前判断；超限时仅返回小状态，客户端停止。响应预算以 PostgreSQL 文本字段的 UTF-8 字节加保守的固定行开销计算，包含缓存命中时独立返回的批次信息。它不是 JSON.stringify 大小，也不是账号账单计数。

**边界：**此模块只约束明确接入它的 SQL 结果，不计连接认证、TLS、其他连接、其他任务、网站生产请求或托管平台内部回源。它不替代真实云端联调的网络中继预算、HTTP 限流、开发离线入口或 Preview 隔离。原程序的逻辑请求／结果计数仍需保留；包装 SQL 增加上行语句长度，安装前应另外核对物理请求量，不能继续把原语句长度称为实际线上的请求字节。

## 存储、验证与安装

缓存目录 0700、文件 0600，拒绝链接及异常所有权，限制单项、总字节和文件数量；缓存可淘汰，预算账本不可自动删除或重建。首次由模块创建新的预算目录；已存在的目录缺少账本时拒绝初始化。文件和目录同步落盘，重新打开有未结清请求的账本时停止。锁未释放时停止，不能以删除锁的方式重试。

测试使用本地 PostgreSQL 和虚构数据，覆盖完整 DTO、新批次、重新打开程序、图片登记后的独立读取、指纹变化、撤回、过期、共享额度及未知写入结果。真实快照的性能回放只能放忽略目录；按固定分页重组的回放属于离线模型，不能当成生产连接或计费降幅实测。

固定程序接入必须另备候选、逐文件摘要、当前包回退副本及安装清单。确认原任务空闲且无锁后再切换；完整验收快照、正文小图队列、网站资格检查与原调度均保留。安装后观察下一轮自然运行的共享响应信封计数和结果；命中率只在实际保存了逐查询计量时报告。不为验收重采全集，也不据此宣布整个账号 egress 已归零。

具体安装前提、观察上限与回退顺序见[安装及有限验收方案](OPERATOR_SQL_INSTALLATION.md)。

## 本次离线定位的证据边界

已复核既有多轮完整快照与响应账本，确认相同最终 DTO 仍可能发生较大回传。当前缓存仅保存每个键的最后一份原始结果，缺少历史原始 SQL 响应对，不能从整理后的 DTO 相同推导原始响应相同，也不能将历史全部用量归因于数组顺序。

受控本机回放分别改变资格集合排列、小图未登记／已登记状态，验证上述两项处理能复用未变化字节；成员撤回、正文顺序、来源指纹改变、过期和损坏继续阻断旧结果。此为机制验证，不是现网原因占比、物理网络或账单节省的实测。本候选保持独立显式接入，不连接网站默认入口、不替换现有固定程序、不恢复来源或自动启用新窗口。
