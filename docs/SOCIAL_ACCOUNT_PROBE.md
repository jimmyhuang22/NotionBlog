# 社交账号采集与样本链路验证

验证日期：2026-10-12（Australia/Melbourne）。本轮由用户明确要求从博客里的既有 B 站、小红书与 Steam 入口测试可行性；测试资料、账号、凭据和执行脚本仅保存在私有环境。

## 结果

7 条真实样本已经完成「来源读取 → 本地 SQLite → 本机程序 → Supabase 临时表 → 回读校验」。这是样本采集和传输验证，尚未实现永久社交数据库、网站时间线接入或定时无人值守运行。

| 平台 | 真实读取证据 | 当前边界 |
| --- | --- | --- |
| B 站 | 3 个已在本人主页发现的公开视频页面，作者标识匹配；服务端页面数据包含精确播放、点赞、评论、分享、收藏、投币和弹幕计数 | 本轮使用公开页面数据，并非已获官方开放平台应用权限；全量发现、分页与长期稳定性待验 |
| 小红书 | 既有 Chrome 会话读取本人主页及 2 条笔记的标题、源时间、类型、点赞、收藏、评论和分享计数；计数与可见详情对应 | 匿名 HTTP 请求跳到登录；当前加载的 90 条本人笔记均为图文，不能据此声称完整历史或视频分支已验收 |
| Steam | 用户提供的 Key 仅向 Steam 官方 API 请求头发送；拥有记录 200/200、近期记录 5/5，返回数量与实际行数一致；两条公开近期游戏与 API 分钟字段交叉核对 | 全量 API 数据是本轮私有只读诊断，不等于已通过未来同步的私人／客户端隐藏审查，也未导入 Notion 或网站 |

## 本地与云端验证

- SQLite 保存 3 条视频、2 条图文、2 条游戏观察，使用平台与稳定条目标识去重。再次读取同批样本不增加记录；较旧样本不能覆盖新采样；模拟传输失败后 7 条待传任务保留。
- 本机 Node/pg 程序使用既有受限 SQL 登录及严格 TLS，单连接、有限超时，只写本会话临时表。7 个完整 JSON payload 回读及 SHA-256 全部一致；重复及旧采样重放验证通过。
- 临时写入事务已回滚，同连接确认表不存在；连接器辅助临时测试也核对残留临时表为 0。没有调用既有内容同步函数、修改既有应用表、修改角色或共享 writer 的 Auth 续期状态。
- 数据比对按稳定身份进行，不假设 SQLite 与 PostgreSQL 使用同一种排序规则。游戏页面上的显示时长和 API 精确分钟分别保留，未知活动日期继续为空。
- 测试事务回滚后，队列保持待传状态；临时验证成功不是永久上传回执，不能把它标记为网站发布完成。

## 实测发现对方案的影响

1. B 站主页的卡片可能表示合集，详情页则对应其中一条稿件，名称和互动数不一定相同。应分别保存作品、合集及单稿件身份与统计范围，再选择时间线呈现层级。
2. 小红书需要保留媒体类型，不能把图文笔记当作视频。当前登录会话下可读取分享计数，但仍须验证后续会话有效性、字段变化、分页和实际视频样本。
3. 本轮没有确认同一作品的跨平台匹配。样本入库保持独立，不能把不同作品或 Steam 游戏与相关录屏强行合并；合并模型仍待本人实际作品关联验证。
4. 页面正文、原始快照、临时媒体地址及凭据只留私有环境；只导出必要元数据与计数。没有保存评论原文或导出 Chrome Cookie。
