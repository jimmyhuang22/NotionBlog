# 相册与正文 1600 预览（F32）

可选 1600 档用于相册、学习笔记、游戏、影视、书籍和展开动态中的正文图片；现有课程封面继续保留。其他封面、关于等普通页、博客、项目、社交媒体和 v1 不因此扩档。页面与灯箱由 Claude 接入。

## 读取和资格

`imagePreviewSrc(image, 1600)` 仅为规范的 `/media/v2/a1.…` 构造参数。媒体路由沿用现有开关及数据库／live-Notion 资格模式，前后均检查当前来源与批次；字节缓存不保存资格，私有一天缓存及 CDN no-store 不变。

SQL 要求当前公开记录属于上述正文类型、locator 为 block，且对应的散列公共块 ID 和图片 ID 仍在正文中。课程 cover 沿用原规则。移除图片、页面或祖先撤回、来源／父 SHA／fingerprint 变化均不能继续借用旧绑定。1600 缺失或无收益时沿用获准原图回退；损坏字节不伪装成功。

## 安装

先单独安装既有课程封面扩展，再安装 `database/body-image-thumbnails-protocol.json` 指定的新迁移。新 registry `nb_thumbnails.body_extensions` 不改变旧课程安装器要求的精确行集；旧迁移字节保持。

```sh
npm run media:thumbnails -- verify-body-images
npm run media:thumbnails -- migrate-body-images --env /absolute/private/admin.env
```

安装使用显式授权和独立 owner 连接，不批量应用迁移目录，不发布或续期内容。新增表启用 RLS；沿用现有受限 read/register API 与到期写入守卫，无新登录或直接表写权。

## 生成与新批次接续

- `planBodyImageThumbnails(runId, snapshot)` 从保存的快照发现正文图片，涵盖嵌套和动态第九张以后的图，排除封面与宽度不大于 1600 的原件。结果只是候选；未加载／部分正文的数量单列，不能当完整盘点。
- 生成遵守已批准清单和预算，保留转正、sRGB、严格解码、40MP、Q85／无损择小；新文件不严格更小则不登记。默认 400／800 计划不变。
- `continueBodyThumbnails` 接收已独立回读的对象证据和旧 source，对一个明确的新鲜批次重新读取当前 SQL 资格、比对完整 source，再追加 1600 绑定并回读登记。不重复编码、上传、下载原件或整批回读已证明的不可覆盖对象。
- 来源变化或撤回分别报告 changed／excluded；批次在操作中变化立即停止，不跨批次拼成功。重复调用核对已有绑定，不覆盖。调用者负责自有锁、截止时间及失败回执。
- 后置步骤在既有内容和基础小图步骤成功后执行，使用该次实际 runId；定时 tick 空跑时不重复处理旧批次。新图和变化图形成新的待生成计划，不能自动扩大付费范围。

## 备份与前端

发布归档保留课程／正文 1600 扩展的精确摘要，空目标须安装匹配扩展后才能恢复；恢复仍不激活公开。原 400／800 归档保持兼容。

当前批次绑定回执就绪后，Claude 再启用“小图 → 1600 → 继续放大取原图”。对象上传或代码合入不能代替真实页面验收；F28 的冷／暖读取也须按实际部署复验。
