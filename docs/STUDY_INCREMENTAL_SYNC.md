# 学习页级增量引擎

本模块接收已确认范围内的页面变化信号，复用完整的本机学习检查点，读取受影响页面并产出差量。它不安装调度、调用旧整批发布来冒充增量、改变来源或启动云迁移。公开 Course、StudyNote、StudyNode、CourseTree 和 AST 保持。

## 已实现

- `createWebsiteStudyChangeSource` 是 worker 专用 Notion 定点适配器：重新核对页面及物理父链，只读取该页正文和立即拥有的子页／数据库记录；不枚举整个课程总表或其他课程正文。子页发现跳过外部视图、链接和引用同步块。每个差量新建资格会话，祖先／schema／正文／子页发现只在同次操作内重用缓存，下一批重新读取。
- `captureStudyCheckpoint` 从完整、仍获准的私有 `WebsiteRecord`（含 evidence／ordinal）形成排序状态，仅读取学习元数据，复用正文与媒体；公开 `readSnapshot` DTO 不能直接冒充这份私有输入。字段／时间漂移拒绝混合新元数据与旧正文；来源配置变化需要新基线。首次未纳入课程仍须在获准的新流程中建立完整基线，不能把旧单课快照称为全部课程。
- `prepareStudyDelta` 合并重复页面信号。明确的页面信号始终重新读其正文，不以父页或子页时间戳没有变化为由跳过。新子页继续读到所需基线；未变化兄弟正文不读。
- 移动、父级改名和跨课程变化只刷新必要后代元数据，保留它们的已发布正文、cover 和媒体标识。数字／日期／正文位置沿用原排序器，差量带受影响目录、页数和最大层级。已知内部链接在本机 AST 中改写或变为不可用，同时输出 `hrefChanges` 给公共层处理非学习内容的入链。
- 归档、移出已配置根或中央 deny 撤回该页和后代。Notion `object_not_found` 也可能是权限丢失，不能直接当作确认删除：未知可用性、读取／媒体失败和结构不完整会使本次差量失败，提交口不调用。同步新鲜度与既有内容的服务行为由公共持久发布政策决定。

当前 Notion 适配器能确认归档／回收站；永久删除需要公共层的可信事件／完整目录证据及权限处置，不能仅把一个 null 当删除。通用 source 端口可在获得此证明后返回 `deleted`，本项没有实现事件验签或提供该永久删除证明。

## 公共发布层接入要求

`syncStudyChanges` 使用三个内部端口：

1. `loadLocal()` 返回 600／700 私有本机检查点，并由公共执行器取得有界服务器版本证据。禁止每个事件远程导出全部学习正文；本机缓存发生漂移时按公共提交日志补齐变化，而非自动全采。
2. `commit(delta)` 在数据库中原子比较 `baseVersion`／`sourceDigest`、执行当前权限与中央 deny、写入全部 upsert／withdrawal／入链修改并返回新版本。记录 `idempotencyKey` 和有界变更日志；仅有旧 `promote/activate` 全批接口不足以实现此口，不能用新一轮旧发布替代。
3. `saveLocal(next)` 在服务器提交确认后原子替换本机检查点。写文件失败或远程结果未知时不报告完成、不要确认队列事件；按提交键／日志恢复，不自动重试发布。持有现有同步互斥锁才能运行这些端口，不能由两个执行器同时更新同一检查点。

媒体准备沿用现有有预算的端口 `registerImage`。缺少端口或任何图准备失败拒绝该正文更新；它负责源指纹／SHA 校验、未变图复用及暂存对象，不能把临时签名地址当新内容。引擎本身不下载、编码或上传。现有 Dagu 的成功发布后小图接续保持，不覆盖为旧单步配置。

公共层的[原子增量发布接口](INCREMENTAL_PUBLICATION.md)已由另一任务合入 develop。本项用真实 PGlite 安装组合验证学习差量可经该接口提交：旧资格到期后更新深层正文、归档旧祖先并保留跨课移动子页、查提交回执和独立 reader 版本，之后中央 deny 仍撤回后代。没有安装云迁移、事件入口、持久队列或定时任务，不能据此称页级同步已经在线。

接公共执行器时，把 `baseVersion` 对齐服务器 `publicationRevision`（`runId:revision`），`sourceDigest` 对齐 `configDigest`，`upserts.map(e => e.record)` 交给 `preparePublicationDelta`，附本次已准备的新媒体；若撤回旧祖先但重新纳入已搬走的后代，也须带回这些后代仍引用的缓存 StoredMedia 描述（无需重新下载／上传），不能假定撤回子树的旧媒体会自动跟随复活。`withdrawalEvidence` 保留直接确认撤回根的原 sourceKey 和原因，数据库级联移除后代；`withdrawals` 则是本机检查点需要移除的全部 ID。`denied` 是政策证据，必须经中央 deny 与新版本恢复处理，不伪装成 deleted／archived 或直接传给只接受来源撤回的 SQL 参数。

公共队列需持久保存 UUID operationId 与 prepare 返回的 payloadDigest，再执行提交；学习 idempotencyKey 是差量摘要，不是 SQL 的 UUID operationId，也不能替代服务器摘要。`hrefChanges` 不属于 SQL 入参，非学习入链由公共执行器从本机私有缓存生成额外 upserts，不能当作数据库会自行改写。父子依赖、目录顺序与入链改动合起来仍须满足公共接口每数组 100 项／16 MiB 的原子预算，超限拒绝并留给依赖批次设计，不直接拆开跨课移动。完整准备、未知结果 lookup、独立 reader 版本与受影响内容核对、检查点原子保存完成后，才可确认队列事件。

私有持久检查点与公共执行器 prepare／verify／finalize 接法见[学习增量运行适配](STUDY_INCREMENTAL_RUNTIME.md)。

## 边界和验收

检查点沿用 20,000 条／16 MiB 和最大 24 层。每轮最多 200 次定点读取，显式上限最多 2,000；这是适配器读取数，不是 Notion HTTP 次数。子页结构每次最多 10,000 块／20,000 直属节点，SDK 完整分页仍必需；生产端还必须沿用 RuntimeReader 的请求、字节、截止时间和取消预算。超限失败，不能自动增大或发布截断结果。

信号输入是页面键，由公共队列验证事件签名、权限与去重；本引擎不把 webhook 载荷中的删除或公开声明当成事实。定时目录／成员／schema／祖先补查仍由公共同步层调度，否则仅处理收到的事件不能保证发现全部删除、漏事件或未来课程。

本机合成验证覆盖深层编辑、未来课程／子页、父正文顺序、数字覆盖、跨课移动、改名、归档／deny、链接撤回、重复事件、预算／范围／媒体失败、原子版本确认与本机检查点失败。完成工程检查后，真实验收只需一次获准基线与代表变更，不重复整库正文和全图读回。
