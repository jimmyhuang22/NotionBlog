# 混合同步调度候选与故障处理

本文件只准备冻结 v1 的持续同步，候选尚未安装或启用。网站 v2 全量验收、前端预览、云端默认 provider 与公开范围由各自任务维护；v1 的耗时和流量不能作为 v2 调度依据。

## 已测成本与候选周期

严格混合发布一轮包含 297 条内容、246 个媒体绑定，耗时 751,994 毫秒（约 12.53 分钟），发出 572 次 Notion API 请求。245 个去重媒体对象共 387,506,614 字节，其中三个转换对象共 3,036,824 字节。这是下载／转换后去重的对象大小，不是网络字节计量；HEIC 原文件、重复绑定的再次下载、重试与 HTTP 开销不在这个数值里。普通图交付改为动态 Notion 地址，但每轮严格采集仍下载全部图片并检查格式、大小和 SHA；动态交付没有取消来源验证。

`scripts/notion-sync/templates/scheduled-launchd.plist` 提供每 1800 秒一次的 **publish 候选**，明确 `--media-provider notion`、固定 release、原输入根及同一 state。原 `private-launchd.plist` 继续保持 dry-run 且没有周期；候选不能与它或其他 cron／自动重试入口同时加载。生成私有候选和 `plutil -lint` 不会启用任务。

| 半小时候选的估算 | 数值与边界 |
| --- | --- |
| 正常日运行次数 | 48 次；按主机始终在线且每轮成功估算 |
| Notion API | 约 27,456 次／天；不包含网站请求、图片 HTTP 或其他程序 |
| 图片校验规模 | 去重输出对象约 18.60 GB／天；普通图保持原字节，仅普通图下载就至少约 18.45 GB／天，另有 HEIC 原文件、重复下载与重试。均不是 Storage 回读或账单 |
| 转换图对象字节 | 每次完整传输约 3.04 MB，48 次约 145.77 MB；上传尝试及校验回读分别计数，不能合称总流量 |
| 正常资格余量 | TTL 3600 秒从批次开始计；周期 1800 秒加本轮耗时后，约余 1048 秒（17.47 分钟） |

上述是同一内容集的线性估算，不是实际下载计量、平台计费测量或耗时上限。已有转换对象也可能先收到带对象字节的创建请求，返回已存在后再回读校验；对象未改变不等于零上传请求。网页端普通图访问另走动态地址，未包含在这些数值里。增量验证或减少完整校验频率需要另行设计，不能跳过现行发布条件。

CLI 工作预算为 1800 秒，适配器还允许清理时间；最长预算并不能满足半小时周期加 TTL 的持续可用要求。因此 30 分钟只是根据本轮实测准备的候选，启用前须接受成本、明确故障响应，并在运行后持续测量。一个预计触发的轮次失败、下一轮才成功时，旧批次可能已过期约一轮同步所需的时间。本机 `launchd.plist(5)` 明确：`StartInterval` 在睡眠期间或任务仍运行时错过的触发会被跳过；它不是唤醒补跑机制。主机睡眠、断网、限流和内容增长都可能扩大空档。不得用延长资格代替故障处理。

## 启用前检查

1. 核对固定 release 的逐文件清单、Node 和转换器摘要，以及同步入口和递归本地依赖与真实验收版本一致。使用该 release 的 `run-private.mjs --mode publish --media-provider notion --check` 完成本机离线检查；这个检查不联网、不续期、不验证当前云端资格。
2. 核对唯一权威输入根、原 state、三类锁和正在运行的进程。与其他 Notion 采集任务错开首次运行，不能为了调度准备轮换它的 writer 会话或删除它的锁。
3. 在私有目录生成填好绝对路径的候选；目录 700、plist 与预先存在的 stdout／stderr 为 600。确认唯一 Label、1800 秒候选周期、publish、notion、`RunAtLoad=false`、`KeepAlive=false`、`Umask=63`，然后 `plutil -lint`。
4. 周期和实际启用范围确认后，才可安装到用户 LaunchAgents 并 bootstrap。首次运行需要独立安排；不把没有立即启动当成故障，不切换云端站点或启用其他栏目。v2 调度须采用其自己的验收、输入与状态，不能套用这个 v1 候选。

## 日志与状态

launchd 日志仍写同一 state 的 `stdout.log`／`stderr.log`，输入和刷新模块的值不输出。现有 CLI 每次保存报告保留最近十份 `run-*.json`，另有 `latest-run.json` 与 `last-success.json`；保存报告时，超过 1 MiB 的 stdout／stderr 会原地截断以保留 launchd 文件描述符。这不是完整审计历史，也不是每次前置失败都有报告：适配器在启动 CLI 前的错误只写 stderr，连续前置失败期间不会触发 CLI 的日志截断。

离线状态命令使用固定 Node 和 release；无需环境文件，不联网、不续期：

```sh
"$NODE" "$RELEASE/scripts/notion-sync/cli.ts" --state-dir "$SYNC_PRIVATE/state" --status
```

启用后还须核对 `launchctl print "gui/$(id -u)/com.homelab.notionblog-sync"` 的加载状态、最近退出码、stderr 和两份报告。检查日志大小；若长期只有前置失败，先停任务、归档受保护日志再清理，不能移动正在由 launchd 持有的日志文件来假装轮转完成。

`last-success.publishedAt` 是本机写 checkpoint 的时刻，不是批次 begin 或 valid-until。不能简单加一小时作为到期时间。真实健康检查应通过受限 reader／已有云端验收读取当前批次的 begin 与 valid-until，并确认 API 和代表图片可用；本机离线检查不能代替它。尚未配置远程消息告警或收件人。

## 故障处理与恢复

| 现象 | 下一步 |
| --- | --- |
| `RUN_BUSY`（适配器退出 75）／`SESSION_BUSY`／CLI `BUSY` | 检查活跃 owner 和锁；不抢锁、不额外启动另一个重试器。候选仅在后续周期再次触发，不承诺自动立即重试 |
| JWT 剩余预算不足、刷新拒绝或身份校验失败 | 停调度并核对唯一会话／受限凭据；不复制旧 writer 文件、不提权，恢复后先按统一入口手动验收 |
| 来源或图片错误、限流、预算超时 | 保留失败报告，修复上游并复验；旧批次仅在原资格内继续可读，过期后受控拒绝，真实 provider 不回退 mock |
| `published-checkpoint-failed`、异常退出／强制终止 | 先核对云端 run、lease 和当前发布状态；不能只看退出码就认为没有 promote，再决定是否重新发布 |
| 强杀／断电遗留锁或临时 env | 停所有统一入口，确认 PID 和 inode，核对云端租约；只清理明确属于已结束运行的残留。`--unlock-stale` 仅处理 state 的 worker 锁，不替代输入根与刷新锁的核查 |

暂停使用已安装的同一 plist 执行 `launchctl bootout`，保留原 state、私有输入及既有对象。恢复使用同一固定 release 和混合参数；旧纯 Storage 运行入口不能发布缺少完整混合索引的新批次。混合媒体完整恢复与整体回退继续遵循 [媒体方案](HYBRID_MEDIA.md) 和 [固定运行说明](SYNC_RUNTIME.md)，不删除旧对象或把旧 Storage 恢复点算作未来普通图的完整备份。
