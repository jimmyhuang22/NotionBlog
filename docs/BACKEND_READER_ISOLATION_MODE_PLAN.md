# R01：网站读取隔离检查的分阶段采用方案

状态：用户已于 2026-10-25 明确批准本次源码与离线测试及常规 develop 交付，按本方案实施。基线为 develop `a66fa841bc5264fc3a66f508611ce73bfbcc1c8a`；真实配置、数据库安装、线上验收和发布均不包含在本次授权内。

## 问题与目标

`getDatabaseRuntime()` 当前无条件用 `isolatedWebsiteReader` 包住网站 SQL。实际目标若还使用有私有证据权限的旧共享 LOGIN，第一次查询就会失败；离线 mock 构建不能证明目标已经隔离。本轮不查询线上状态。

交接记录的方向是先让其他网站修复可按独立发布规则采用，待真实隔离安装并验收后再强制。这里将其固定为一个服务器配置，配套明确诊断和本机发布声明检查；不以关闭检查冒充已完成最小权限。

## 配置和运行行为

变量为 `DATABASE_READER_ISOLATION`，不使用 `NEXT_PUBLIC_`，不写入 Next 的客户端 env 配置，也不接受请求头／查询参数控制。

| 服务器配置 | 网站数据库 runtime 的行为 |
| --- | --- |
| 未设置 | 解析为 off；正式环境无须新增变量即可沿原数据库读取继续工作 |
| off | 不执行新增的隔离目录检查，不因这道检查拒绝读取；每个 runtime 首次实际 SQL 调用时发出一次固定服务器诊断 |
| enforce | 使用现有目录 SQL 和拒绝规则；失败不发业务 SQL，成功及失败的缓存／并发行为保持原样 |
| 空串、空白、大小写变体或其他值 | 在创建数据库 pool 前返回受控 MISCONFIGURED，不静默当成 off |

所有环境使用同一“未设置即 off”的解析规则，避免本机、CI 与正式环境的隐式分叉。原纯包装器 `isolatedWebsiteReader(db)` 默认仍保持 enforce，显式传入 off 才延后；网站 runtime 负责解析环境并传入。这样现有独立调用方和严格权限测试不会因库函数默认值改变而悄悄失效。

固定诊断拟为 `WEBSITE_READER_ISOLATION_DEFERRED`，表示“网站读取隔离尚未强制验证”。不查询账号就不声称账号实际已经隔离或未隔离；不记录 LOGIN、URL、凭据、角色明细、源错误或正文，不新增公开状态接口。并发调用只记录一次。off 不吞掉后续数据库／内容读取错误，不启用 mock 回退。

模式在 runtime 创建时固定，和现有 pool／reader 实例保持一致。切换到 enforce 必须采用新实例／重新启动或新的已批准部署，不承诺修改进程环境后即时重载，也不增加自动重启或 redeploy。

## 保持严格的独立边界

- B20 的直连 Notion 使用独立中央 deny 能力与实际 reader profile 校验，不读取此开关；off 不能让缺能力／宽权限的直连通过。
- 同步公开验收、`nb_delta_reader`、writer、私有媒体验收等既有身份检查不读取此开关，不允许网站配置变成工作程序绕过条件。
- 公开健康继续只返回存活；私有内容 readiness 协议保持，不增加“已隔离”承诺。内容证明不能替代 B03 的真实角色审计。
- 不更改角色、函数授权、SQL／迁移、来源范围、DTO、缓存／媒体策略、依赖或任务暂停。off 期间已有宽权限仍是待修的已知边界。

## 防误开和防遗忘

新增只做本机校验的发布声明入口 `scripts/check-reader-isolation-release.ts`，以及配套发布清单。它不加载业务 env／凭据、不连接数据库或 Vercel、不部署；显式接收阶段、拟采用模式和必要的证据摘要。

| 声明阶段 | 允许的拟采用配置 | 机械拒绝 |
| --- | --- | --- |
| deferred：真实隔离尚未验收 | 未设置／off | enforce，防止迁移前误开 |
| verified：真实隔离与读取已验收 | enforce，并填写核验回执 SHA-256 | 未设置／off、缺失／非法证据摘要，防止声明验收完成后忘记强制 |

阶段／模式参数缺失或非法、额外字段／参数均拒绝；成功只输出阶段和解析后的模式，不输出证据内容。测试使用虚构摘要，不能拿它当真实验收。

拟采用变量未设置时，声明入口用显式的 `--mode unset` 表示，不能省略参数。接口形状为：

```sh
node scripts/check-reader-isolation-release.ts --phase deferred --mode unset
node scripts/check-reader-isolation-release.ts --phase deferred --mode off
node scripts/check-reader-isolation-release.ts --phase verified --mode enforce --evidence-sha256 <receipt-sha256>
```

该入口只验证**声明一致性**，不能自行证明数据库现状、摘要真实性或云端当前变量。发布者须把目标、最终网站提交、阶段、变量是否设置及实际核验回执引用写进本次发布材料，并在获准的发布验收中核对目标配置。它不自动随每次 npm check 查询真实服务，也不改 CI 触发方式。

首次采用 off 仍须明确记录 B03 未完成和风险保留。真实隔离完成后，原安装拥有方提供新回执、更新阶段，拟采用配置必须是 enforce；不能保留旧 deferred 声明绕过后续验收。每次 main 发布仍须独立批准。

## 拟修改范围

1. `src/server/database/website-reader-isolation.ts`：严格模式解析／显式模式包装／固定诊断，保留原 SQL 和默认严格的库调用。
2. `src/server/database/runtime.ts`：pool 创建前解析服务器配置，只为网站 rawDb 传入模式；不改变 publication/scoped/预算包装顺序。
3. 新增本机发布声明检查和相关纯函数；新建局部虚构测试，必要时让既有 runtime 夹具显式选 enforce，不以减少权限断言来通过测试。
4. 更新独立接入／发布说明、需求、决定、状态表和本项进度。冻结 `.env.example`、旧兼容 JSON 及迁移摘要保持；当前源字节的历史拒绝测试若受影响，只更新当前 pin 并保留旧许可拒绝。

## 离线验收

- off／未设置下，模拟旧共享权限的网站仍能读取原公共投影，不执行隔离检查；固定警告并发也只一次，驱动错误继续按原边界失败。
- enforce 下真实 PGlite 角色测试继续拒绝共享成员、writer、owner 与额外私有函数权限，允许隔离 reader；并发合并检查、失败可再检和错误脱敏不变。
- 无效模式在 pool／SQL 调用前拒绝。至少一个实际 runtime／HTTP 子进程验证正式环境未设置可读、enforce 拒绝、缺内容仍失败，不仅测试解析函数。
- 本机发布声明四种阶段／模式组合、未设置、缺证据、非法值和额外输入全部覆盖；明确无外部请求、业务凭据读取或状态写入。
- B20 直连、同步公开 reader 和增量证据 reader 的严格拒绝仍通过；既有缓存／媒体／私有 readiness 回归按影响执行。
- 使用既有 Node 24、依赖和离线出站保护，在最终工作分支集中运行 `npm run check` 与离线 build；隐私、差异和实际合入核对单独完成。没有新依赖、原生引擎安装或真实服务验收。
