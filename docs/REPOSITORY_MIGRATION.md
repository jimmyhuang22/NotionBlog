# 干净仓库迁移

本仓库从经过清洗的源码快照建立新 Git 历史，不携带旧分支、PR 内部引用、Actions 日志、个人配置或旧 `.git`。旧历史及尚未集成的工程保留在私人归档。

线上 main 与开发 develop 分别按冻结的原源码树准备；尚未发布的开发改动不会因为迁移自动成为正式发布。未合入的 PR 与本地修改分别登记和审核，只搬移批准的源码差异，不把旧父链直接合入新仓库。

新仓库已完成同名切换，名称为 NotionBlog；旧库已使用独立的私人归档名称。旧检出的共享远端与新独立检出的远端分别核对，两个仓库均保持私人。改名不等于部署重绑或会话迁移，新旧仓库即使先后使用同名，也有不同的仓库 ID 和提交历史。

2026-10-23 用户已明确授权现有生产项目接续新仓库及本次首次发布，并选择 Vercel 云端完整检查与构建作为本次平台验收。接线、暂存、发布合并和正式域名晋升分别核对；既有域名、环境配置和业务运行根保留，详见[本次决定](decisions/2026-10-23-production-repository-rebind.md)与[执行记录](progress/2026-10-23-production-repository-rebind.md)。

旧工作目录及私人运行根保持，既有来源暂停状态和独立缓存消费者不随代码复制改变。运行包、锁、调度、清理、私有环境文件和生产部署不从公共源码自动重建或恢复。

当前应用项目及已有聊天仍记录旧工作目录，独立的新开发入口需要逐项接续。Codex／Claude 对话不会自动知道 Git 仓库已更换。每项接续工作在开始编辑前核对当前目录、独立 Git 根、远端、分支、HEAD、任务待办及私人配置边界；不能原地更换环境时，通过私有交接摘要接续，原对话和旧检出保留。

文档中的旧库 PR 编号仅用于解释历史技术选择，其原始记录保留私人，不是本仓库的新 PR。逐项迁移映射、未提交内容备份和真实运行回执也保持私有。

同名切换的源码、引用、CI 及会话入口核对见[执行记录](progress/2026-10-22-private-repository-name-cutover.md)。
