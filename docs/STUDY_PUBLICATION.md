# 学习区自动公开与目录顺序

用户于 2026-10-12 确认：已配置课程来源的全部课程及它们拥有的全部页面／子页面公开，未来新增自动纳入；第一层日期为主、可用数字覆盖，子页面按父正文先后。本说明取代当前网站“只选一门试读课程、逐页补名单”的操作方式。冻结 v1 与网站旧名单配置保留兼容；真实站点启用自动规则仍需完成独立扩展安装、配置切换和一次获准的完整发布。

## 纳入边界

- 课程必须是已配置课程 data source 的直属活动页面。
- 学习后代必须沿活动页面、实际块父级或实际拥有的数据库／data source 父级，最终回到上述课程；递归收录拥有的子页面和数据库直属记录，包括以后新增的同类节点。
- 外部网页链接、页面提及、关系属性、`link_to_page`、外部数据库视图及引用其他来源的同步块不授予公开。数据库容器在课程正文中出现，也必须核对数据库与 data source 的实际所有者；视图指向其他位置的数据不能借此纳入。
- 自动范围只适用于该学习根，不改变 About 或其他普通页面的后代规则。归档、删除、移出根范围和中央 deny 均排除；被撤回的祖先会阻断整个后代树。
- 未知父链、权限／查询失败、循环、分页截断或超限必须失败，不能以“空列表”或缺少几页完成发布。页面父链最多 24 层、自动发现最多 20,000 页／100,000 块，完整同步原有 20,000 记录／16 MiB、20,000 媒体／2 GiB 硬上限保留；范围变大不自动提升额度。

单个详情／媒体的 live 资格检查只走该页面的父链，不枚举全部课程。单门目录只发现该门课；完整同步先发现自动学习归属，再处理图片，同一次操作重用已读取的正文块，避免发现子页后又读取相同正文。资格缓存不跨操作。

重构中的页级变更适配与发布接口要求见 [学习增量引擎](STUDY_INCREMENTAL_SYNC.md)。它复用上述范围和排序，独立于旧全批 worker；公共持久发布层的原子差量提交口与队列接好之前，不代表已启用自动增量。

## 配置与可选数字属性

网站 v2 私有配置仍使用 `schemaVersion: 2`。课程来源设为 `publication.mode=all`、空 allowlist；增加一个 `study-note` 来源使用 `publication.mode=course-descendants`、空 allowlist，`dataSourceId` 指向同一个课程根，`coursePageId=null`。每门课的数据库由物理所有权发现，不逐门写固定来源编号。旧逐页学习来源应禁用，避免重复收录；其他已获准来源保持原配置。

课程字段沿用已有映射。自动笔记字段是模板映射；实际数据库的标题属性自动匹配，未拥有的可选日期／类型／网址保持 null／unknown。数字覆盖通过私有 `fields.order` 映射到笔记数据库的 number 属性；属性不存在或值为空即没有覆盖值，不要求每个库立即补属性，已经存在但类型错误仍报告配置错误。

数字属性应加在每门课内部存放直属笔记的数据库，课程总表不需要这个属性。普通子页面没有数字属性也能按正文位置排序。具体数据库名称、链接和属性名由后端的私有配置说明给出，不写入公共文档。

## 排序与上一篇／下一篇

第一层先放有数字的页面，数字从小到大；相同数字按日期从早到晚、再按自然标题。未填数字的随后按日期从早到晚；无日期最后。标题中的数字按数值比较，例如 Week 2 在 Week 10 前；最后以页面 ID 保持稳定。

子页面按它们在父正文中的出现位置。只有数据库行而没有独立正文块位置时，在该数据库的正文位置内按自然标题；没有可用位置的旧名单子页也按自然标题。第一层数字与日期不覆盖子页正文顺序。

例如 Week 1、Week 2、Week 3 都没数字，只给 Week 3 填 30，它排到最前面；需要 Week 3 排在它们后面，就分别填 10、20、30。这是用户选择的“填了优先”规则，没有另做插入位置算法。

Notion 的数据源查询未指定 sorts 时不保证顺序。[官方数据源查询说明](https://developers.notion.com/reference/query-a-data-source)明确了这一点。现在已有 Views API，能执行视图的过滤与排序，但[官方视图说明](https://developers.notion.com/guides/data-apis/working-with-views)和[视图查询说明](https://developers.notion.com/reference/create-view-query)没有给出手工拖动行序的可靠契约；其中 `manual` 配置用于分组等布局。本实现采用已确认的日期／数字规则，不能据此宣称官方 API 永远不支持手动行序，也不把未排序的查询结果当作它。

直接 Notion 目录和采集使用同一排序器。排序写入已有私有 `evidence.ordinal`，数据库用冻结的 reader `read_content` 按课程／ordinal 有界读取，所有分页绑定同一 run／revision；不读取所有课程正文来排一门课。公开 `StudyNode` 与页面组件不增加字段，上一篇／下一篇继续沿用树数组顺序。

## 收回页面

要立即撤回，给后端该 Notion 页面链接并要求加入中央 deny：该页和所有后代会从数据库正文、目录、搜索、内部链接与媒体资格中排除，后续自动收录也不会重新公开它。恢复时明确要求移出 deny。中央撤回会使正在暂存的租约失效，执行前应协调正在运行的发布任务。

把页面归档、放入回收站或移出学习根也会使新采集和 live 媒体拒绝它；已发布的数据库正文并非实时 Notion 查询，要立即收回仍应使用中央 deny，不能只依赖下次同步。直接 Notion 私有预览需要传入相同 deny 集合或用 Notion 的归档／移出动作；网站实际读库继续以中央规则为准。

## 工程和实际发布

`database/website-study-migrations/001_automatic_study.sql` 是独立扩展，原 v1／v2 SQL 文件和摘要不修改。扩展只放宽明确的学习模式，并包装原策略／stage；旧策略走原实现。新笔记必须属于已暂存的同一课程与父链，不能跨课程、覆盖课程身份或形成循环。迁移 owner 从已检查 manifest 登记扩展摘要，受限 writer 在 begin 前验证它；worker 无权编辑策略、公开范围或 deny。

准备迁移不等于已安装或扩大了网站范围。本项不在正在进行的旧范围发布中改策略。实际启用前先确定空闲窗口、最终私有配置、失败／回退方案及一次完整采集的耗时和字节额度，再取得用户另行批准。预检和排序测试不运行全量 dry-run；真实发布成功后再交付新鲜 reader 的课程／学期数量、每课页数和最大层级、代表正文、partial 类型统计与一门课程的目录顺序给 Claude。

小图采用既有发布回执／reader 交接流程；工程导出文件、旧 Preview 和暂存租约都不是新成功发布。既有 189 小图流程继续独立推进，不为本项重编码或重复上传，也不顺带发布已暂停的自动加载。
