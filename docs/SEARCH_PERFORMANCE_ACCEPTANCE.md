# 搜索耗时与 S13 验收接续

S13 已作为现有搜索优化的补充证据接收。它是历史观测，不是当前部署复测；接收反馈没有授权安装、启用、合并、部署或新的真实请求窗口。页脚布局偏移继续由 UI/UX 处理。

## 历史证据及适用范围

S13 测量的是旧 main `6134ae6`／发布 608：公开缓存开启、内容来源暂停、搜索预筛关闭。原始命令与输出已在私人证据中定位，三个 API 请求各一次、间隔一秒，均为 200：

| 原词类别 | 原始 API TTFB |
| --- | ---: |
| 随机词，历史无结果 | 2.808051 秒 |
| 中文词 | 2.831022 秒 |
| 英文词 | 2.774442 秒 |

交接摘要第一项写成 2.77 秒，与原始输出不符，以原始输出为准；保留原文及更正回执。三个词的实际字面值、编码和来源行摘要只保存在私人验收清单，没有换成新词。浏览器三次无结果页使用的是另外三个随机词变体，不能拿它们代替 API 验收词。

同轮浏览器结果出现耗时为 2.7–5.4 秒；这不是 API TTFB，也不与三个 curl 样本逐请求对应。报告中 3 次 API 请求、9 次搜索页加载不等于 12 个数据库连接，页面自动子请求／字节没有完整计量；不并入本任务六个已关闭诊断窗口的账本。

[较早本机对照](progress/2026-10-22-search-pair-results.md)的 5.7–7.1 秒包含路由编译；后续独立两请求结果使用另一版本与同一英文词，亦不能补作 S13 三词的重复样本。不同时间、批次、环境、缓存和路径的耗时不相减、不拼成三次验收。

## 耗时构成与候选覆盖

以下依据当前候选源码解释路径，不替代旧部署的阶段观测：

| 阶段 | 当前可见证据 | 本候选的作用／待测内容 |
| --- | --- | --- |
| DNS、TCP、TLS、网络与平台分发／启动 | S13 仅保留 `time_starttransfer`，未保存分段 | 不直接优化；后续记录客户端各阶段，单列实例首次请求 |
| 服务初始化、池创建及借连接 | `service`、`database-runtime`、`database-pool`、`database-acquire` 与池状态 | 沿用已有进程内连接池，不把借还次数当新连接数；需记录实际冷暖及等待队列 |
| 能力检查、资格遍历、片段及引用投影、SQL 往返与反序列化 | `search-read`、`database-roundtrip` | 必要条件预筛减少返回候选；`filtered-scope` 在候选含学习笔记时复用同语句已成功资格。仍遍历合格记录，未知引用和当前媒体仍检查；不是全文索引或跨请求资格缓存 |
| DTO 整理、可见正文构造、匹配、排序、分页及指纹 | `search-text`、`search-match` | 保留原逻辑，不提前只读首屏；需要单独量耗时 |
| 末尾版本复核 | `search-version` 及相关数据库往返 | 保留；不能为降低耗时删除 |
| JSON 序列化、响应提交与下行；浏览器启动搜索、渲染和布局 | 部分在 repository trace 之外；浏览器有自己的时间轴 | API 与页面分别测，不把页脚晚到或布局偏移归因给 SQL |

源码入口见[搜索 API](../src/app/api/search/route.ts)、[HTTP 包装](../src/lib/content/website-http.ts)、[公开缓存](../src/server/public-cache/runtime.ts)、[搜索读取](../src/server/database/website-repository.ts)和[阶段计时](../src/server/content-read-timing.ts)。搜索明确绕过公开 DTO 缓存，API 返回 private／no-store；其他列表缓存命中低于一秒不意味着搜索拥有同样成本。当前 middleware matcher 也不覆盖搜索 API。

阶段计时有嵌套，不能把 `search-read` 与其内部数据库往返再相加。数据库往返包括驱动、网络和传输，不是纯数据库 CPU。单次 HTTP 与服务端 trace 未绑定时，不拆分精确占比；S13 的 2.8 秒目前不能全部归因给数据库，也不能用较早约 1.1 秒的借连接时间直接扣除。

## 后续有限验收方案

必须保留 S13 的三个原词，各三次，记录每次状态码、TTFB、总时间和结果指纹；不能只留最快一次。历史“无结果”不是当前结果数的预设，同一已发布批次的新旧 DTO、完整顺序、游标和可见引用必须一致。

建议比较方案是同条件的 on-demand 与 filtered-scope 各九次，共十八次 API GET，按词和轮次顺序交错；这是待定窗口方案，不是已获十八次请求许可。不夹带预热、HTML、浏览器导航、第三种模式或重试。只做单版本复验时是九次，但不能据此声称对照改善。若要隔离资格复用的增量收益，再加入 filtered 路径必须另列请求与预算。

拟定首轮效能目标为：候选每词三次的 TTFB 中位数不高于同窗基线，总体九次中位数降低至少 20%；全部单次值和最坏值仍报告。此为方案目标，不是已达到的收益或稳定性 SLA；三个样本不能证明 p95。任何错误、语义或撤回差异均先判失败，不能用较快但不完整的结果通过。

执行前须另外固定目标环境／部署与源码摘要、真实选项及栏目、已发布批次、读角色、当前同步后置和负责人空闲窗口。连接数、接收字节、请求数、时长、截止与首错停止分别限定；身份／版本／前后置探针另记，不隐藏在 API 次数内。客户端记录 DNS／连接／TLS／首字节／总时长；服务端保留阶段及池状态，绑定同一次请求但不记录搜索正文或凭据。

仅本机候选对照不能关闭 S13 的线上体验项。实际托管环境不可用、来源状态不符、未知 SQL 结果或输入变化时停止，不以恢复业务、放宽守卫或重新部署来临时取得样本。当前不生成执行许可、nonce、可运行采样器或启停任务；旧窗口余额继续为零。

安装与回退仍按[候选接入说明](FILTERED_SEARCH_SCOPE.md)：先固定实际受检迁移及角色／结构前像，安装与应用启用分开；配置回退须创建原选项的新实例并退出旧实例，卸载只处理本次新增对象。本轮只固定了源码侧输入，实际云端 owner、角色继承和结构前后像尚未核查。
