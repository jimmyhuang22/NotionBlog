# 2026-10-23：源码公开并使用 GitHub 托管 CI

用户明确要求“帮我把仓库公开吧，然后把 CI 转到 GitHub 上”，授权干净新仓库的可见性切换及相应检查配置；旧归档、个人配置和内容保持私人。

main／develop 的 PR 与手动检查使用标准 GitHub 托管 `ubuntu-latest`，Node 24、双锁文件安装、完整 `npm run check`／`npm run build`、45 分钟上限及只读 Token 保持。只运行离线 fixtures，不接入真实来源或部署凭据；不恢复已退役的个人原生运行器，不迁移树缓存／历史通过回执，不新增 schedule。

公开后启用两条长期分支的 PR 保护，管理员同样遵守，禁止强推和删除，要求解决讨论。main 额外要求 `Check and build (Node 24)` 通过且分支为最新；develop 保留按影响本机验证后普通合并的现行规则，不强制等待平台。单人维护不要求无法自批的额外批准。外部贡献者工作流均需维护者审批，并启用私密漏洞反馈。

本决定取代此前 README 整理阶段暂不公开的限制，以及原生运行器退役后等待另行约定平台检查的状态；不修改历史私人 CI 的失败／取消／SKIPPED。正式发布仍须对最终集成版本验收，由用户逐次授权合入 main；发布请求打开期间继续暂停 develop 合并。源码公开不恢复业务任务、不扩大内容资格、不触发手动部署。
