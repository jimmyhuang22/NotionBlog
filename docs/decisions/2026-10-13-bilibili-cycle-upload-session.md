# 2026-10-13：B 站周期复用受限上传会话

用户同意继续上一轮上传连接复用及分阶段耗时方案。旧程序已在单批内复用，但每批最多分别打开视频、合集两条连接，跨批次关闭重建；既有运行的上传阶段只占总工作进程时间约 18%，不预先承诺显著提速。

B 站周期仅在实际发送合格 pending 时惰性建立一条 `nb_social_worker` 连接，使用原 TLS 验证、超时及 max=1 的配置。首次发送视频与合集时各自验证原角色、登录身份、权限和 schema 版本，此后复用该周期同一连接及各自发送器。独立单批 CLI 和小红书仍用旧连接生命周期，不把共享会话扩大到其他运行任务。

周期记录连接尝试／成功、两套协议握手、发送尝试／有效回执及分阶段耗时。退出前等待当前 statement 的既有有界超时，释放客户端并关闭 pool；清理失败标记人工处理。node-postgres 的 [连接池文档](https://node-postgres.com/features/pooling)和 [Pool API](https://node-postgres.com/apis/pool)说明客户端归还、销毁与结束 pool 的要求，实现仍保留现有客户端超时。

连接出错、丢回执、身份／协议拒绝、输入凭据或范围摘要变化后不在本周期悄悄重连。每次发送仍重新核对范围，子批次和整周期取消均在发送前及响应后检查；已提交但未确认的 payload 留在 pending，后续显式恢复继续使用原幂等 ingest。共享会话仅串行发送，不增加并行 RPC、批量事务、云权限或自动云错误重试。

代码交付与固定运行包安装分别记录。真实验收使用原到期目标，空闲轮确认零来源／零云连接，不重采整批制造结果或接管其他对话的 Runner。日常合并遵守用户随后确认的 [集中 CI 规则](2026-10-13-batched-development-ci.md)，真实平台通过与本机结果分别记录；main 发布继续验收最终集成版本。
