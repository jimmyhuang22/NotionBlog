# 2026-10-15：小红书笔记就绪判断与字段诊断

用户同意接续处理已定位的两处暂停。原 HTTP 失败目标当前匿名读取与完整校验成功，旧失败响应未留存，具体字段仍未知；浏览器超时诊断显示标签持续 loading，原代码未读取笔记状态。修正不把这些证据写成已还原平台根因。

- 仅 HTTP 来源的投影校验增加固定错误类别：页面结构、标题、封面、发布时间／更新时间及四种计数；沿用原本地尝试记录、周期回执与健康记录。错误不带原字段值、正文、分享地址或 Cookie，不增加数据库对象，也不降低身份、日期及计数校验。
- 少量浏览器补采沿用现有诊断选项，在标签实际地址属于该目标且未冻结／丢弃时，即使状态仍 loading 也允许立即读取固定 MAIN 函数；缺少笔记状态继续有界等待。作者、目标身份及可分享资格仍须通过。默认旧浏览器批次不启用该行为。
- 注入等待受原二十秒和任务租约共同限制，超时关闭自己的标签，迟到结果不能变成成功。已发起读取后未取得数据时记录笔记状态阶段，不再一律归为页面未加载。
- 不增加自动网络重试，不修改人工暂停、恢复 ticket、公开范围、账号／域权限、B 站线路或检查频率。实际安装仍先固定受检源码和回退文件，然后只验原失败单篇，精确 ACK 与受限回读后再显式恢复；无整批重采或整套 CI。

Chrome 的 `executeScript` 默认等待 `document_idle`；提前读取使用已有 `scripting` 权限下的 `injectImmediately`，并不保证脚本在页面加载前执行。依据：[官方 API](https://developer.chrome.com/docs/extensions/reference/api/scripting#method-executeScript)。
