# 2026-10-13：自动加载先关着发布，封面小图上线后再打开

用户确认，Claude 落实。补充并部分取代 [列表边滚动边加载](2026-10-12-scroll-loading.md) 的第 3 条。

## 定了什么

“边滚动边加载”的代码已经随整合请求进了 develop。作品库的列表封面还没有小图：影视、书籍、游戏一页 24 张，抽查到的原图最大 4.3 MB，自动加载会让访客一页接一页地下载它们。用户从三个做法里选定：**把自动加载关掉再发布**，其余已经做好的前端修正照常上线；另两个做法是暂不发布、照现在的 develop 直接发布。

- 关着的时候，八个列表页的末尾是原来的“加载更多”按钮，点一下加载一页。
- 返回时恢复已加载的列表和位置、悬浮的“回到顶部”，不受这个开关影响，随这次发布上线。
- 打开的条件：作品库列表封面的 400 像素小图上线，并在正式站点上确认过。届时由用户发话，改开关的那个合并请求照常走 develop 与发布。

## 取代的旧决定

原先定的是“合并请求做完后先不合并，等预览图全量上线再合进 develop”。合并这一步已经由整合请求完成，所以等待的对象从“合并”改成“打开开关”，条件也从“预览图上线”明确为“作品库列表封面的小图上线”：动态图片的小图已经上线，但那不够。
