# 2026-11-03：按意图预取、只读事务流水与图片一天回访（Codex）

## 决定

用户要求继续解决首次加载慢和图片缓存到期后校验慢，正式发布前再次确认。

- 顶部栏目入口只在悬停、键盘聚焦或触摸后恢复 Next 默认预取；首次挂载不自动预取全部栏目，当前栏目不额外预取。点击反馈和栏目加载边界保留。
- 内容与社交只读连接使用现有 `pg` 的流水能力。先一起发送 `BEGIN READ ONLY`、`SET LOCAL statement_timeout` 并确认成功，再一起发送参数化业务查询和 `COMMIT`。必须收齐所有结果，确认事务关闭后才复用连接；预算或取消阻止清理时销毁连接。
- 仍执行相同业务查询、公开资格和撤回检查，SQL 指令与结果字节使用原预算；不改变连接池容量、角色、TLS、数据库迁移或写入路径。
- 用户明确选择将版本图片的私有浏览器缓存延长到一天，同时加速到期校验。`tagged-v1` 下，已经通过资格检查且原本获准缓存字节的 v2／s1／s3 图片采用 `private, max-age=86400, must-revalidate`，200／304 一致。此条取代[同日五分钟图片回访决定](2026-11-03-static-media-revisit-cache.md)的时长；页面五分钟回访缓存、静态资源、可变地址、实时来源和错误响应规则保持。
- 下架或同一 v2 地址重新生成缩略图后，已看过的浏览器副本最多仍可显示一天；不能远程擦除这些副本。新源站请求仍执行撤回检查，版本换图使用新地址。到期后必须重验证，不允许 `immutable`、过期错误复用或共享缓存。流水只缩短源站校验的等待，不缓存图片公开资格。

## 理由与边界

四次依次等待让简单读取也受网络往返支配。现有驱动支持按顺序处理多个已发送命令，可缩为两组等待，并保持独立结果和错误处理。不能用把用户参数拼入多条 SQL 的方式替代参数化查询。

默认导航预取可能只获取加载边界，请求数量不等于完整内容查询数量；本决定只减少首次挂载的主动请求，不声称消除所有预取或后端工作。整体提速仍受数据库执行、冷连接、页面查询数量与图片存储读取影响。
