# 2026-10-17：社交封面跟随统计确认独立排队

用户要求接续作品页缺失封面，补充原封面工程的运行接线。统计采样与封面处理继续分开：只有精确云回执及本地 ACK 成功后，才从同份 Observation 生成媒体待办；合集封面从同次已验证 HTML 提取，并绑定完整统计快照摘要，不额外请求页面、不改变冻结统计载荷。

待办使用独立私有 SQLite，按显示模式、类型与作品键记录最新完整引用，较旧输入不能覆盖较新输入；媒体完成仅能清除受检 generation，不清除处理中到达的新引用。普通发布相同 URL 不因点赞变化重做，合集相同 URL 的新采样仍需更新来源时间资格；已有绑定相同则无需取图、编码、PUT 或对象回读。

独立消费者每轮最多二十项、单并发，整轮共用三分钟／八十 MiB 原件／一百二十次逻辑对象操作上限，不逐件重置预算；首错停止，保留错误和剩余项。同引用失败不会随下一轮静默重试，显式 retry 只重置最多二十项本地待办，本身不联网。缺图、当前切片、失败、来源旁记录缺口分别统计，失败不回滚或重采统计。

默认没有 `social-cover-policy.json` 即关闭。已有精确本地 ACK 可通过显式 seed 补建待办，源库只读，不补造采样时间或合集来源。代码、真实图片处理、权限／运行安装和全覆盖验收分别记录；旧一次性 writer 会话及关闭的请求窗口不能作为常态安装凭据。网站内容同步暂停和其他媒体任务保持各自边界。

用户已明确批准本轮具体安装方案：现有专用媒体角色启用常态登录，原权限不扩；复用两个独立Storage身份，每个非空批次新建仅内存会话并局部退出。两张固定样本通过后启用每五分钟的独立队列检查，以支持小时统计产生的变化量；这不改变B站／小红书原采样周期，空队列不请求云端。所有合集仍从自然采样补来源，不为补图重新采集全集。

自然执行发现接近硬时限才派发最后一项会产生取消失败，补充正常切批规则：剩余少于三十秒时停止派发，保留pending供下一次原调度处理；硬期限不变，不增加重试或请求预算。来源已被新generation替换时保留新版并计superseded，不能把旧版拒绝报成当前失败。
