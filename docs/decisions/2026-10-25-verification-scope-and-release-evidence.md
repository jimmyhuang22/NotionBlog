# 2026-10-25：收敛验证范围并复用发布证据

用户要求固化本轮经验，避免以后把开发与发布验证做得过慢。本决定补充按影响验证与发布规则，不改变授权、必需检查或主分支保护。

1. **先写完成条件。** 用一句话明确交付物及最少验收项。网站发布、本机程序安装、数据库扩展、数据恢复与持续任务分别管理；可选采用项列后续，不持续扩成当前阻塞。
2. **先做便宜预检。** 写文件前确认工作目录和目标存在；命令先核对解释器、绝对入口／preload、双锁依赖、参数类型、计划路由和解析器。认证先查本机到期信息，不能先发真实请求才发现过期。
3. **定向验证用小夹具。** 正常与拒绝路径复用小型虚构仓库；真实兼容仅做一次固定实际 base/head 重放，不让每个负例重复复制、扫描全历史。先测夹具成本，超时／中断不算通过。
4. **稳定后集中完整验收。** 按现有规则完成一次 check／冷 build；失败后只重做必要范围。受检树、依赖和相关环境未变时复用结果，纯文档、无关更新或零文件差异的历史同步不触发应用全套。
5. **验证实际发布基线。** CI 先核对真实 main 的脚本摘要、能力和辅助文件，不能只测方便的 develop 样本。未知版本仍拒绝；改变信任来源先审阅批准。
6. **先识别冷构建外部资源。** 字体等资源优先复用本机原字节、版本、字符覆盖、回退度量与许可证；不用旧构建缓存或假资源掩盖离线失败。
7. **先查最新已有回执。** 新阶段先读最新 develop 和本机记录，引用其他会话已完成的验收及限制。只补缺口，不重复消耗线上流量；必要的一轮访问统一列范围、预算、有效期及停止条件。
8. **区分工具中断与授权关闭。** 未发请求且授权有效时可修正本机工具，继续未发请求；不得重发已完成请求或重开关闭窗口。记录器须分开保存本机工具状态与授权状态，不改写原回执制造余额。
9. **区分证明层次。** 源码、本机、平台、部署身份、网站效果和业务采用分别报告。失败、跳过、中断如实保留；旧 PR 结果不替代发布 PR 必需检查，CI 等待期间不额外手动派发重复验证。
10. **收尾核对最新状态。** 用户或其他会话可能在等待期间合并；最终重新核对 PR／提交／树，不能仅凭同一账号归因。遇变化先确认，不擅自回滚、部署或恢复任务。汇报聚焦结果、剩余阻塞和下一步，避免把记录完善当作新工作阶段。

本决定由需求文档链接；后续按 AGENTS.md 读取需求与决策时执行。它不新增测试、CI 任务、依赖、云端操作或发布授权。
