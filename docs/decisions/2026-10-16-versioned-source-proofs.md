# 2026-10-16：来源验证摘要只排除响应层编号

读取接口返回的顶层 request_id 是传输响应编号，每次读取可能变化，不应使同一内容的缓存失效。新增 digestVersion=2，仅在单项响应或列表实体的最外层移除该字段，再执行既有文件签名地址规范化；嵌套属性同名字段、正文、父链、归档/删除标记和完整列表次序仍纳入摘要。

没有版本号的已存摘要保持旧算法，不能把不可逆的旧哈希当作新版证明；匹配失败照常补采。未知版本拒绝。仅允许固定前序运行包到固定修复字节的兼容迁移，其他映射、契约、依赖和运行修改仍拒绝。旧工件、公开资格及日期不改。

修复避免响应编号误报变化，但完整来源验证仍需当前嵌套读取和媒体核对，不保证省略网络请求或在固定时长内完成。日常调度依据实测整轮耗时、下一轮内容完成时间和服务器资格期限一起核定；具体新的周期、额度与未来批次期限仅在私有执行方案得到授权后启用。
