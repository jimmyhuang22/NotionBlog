# 决策记录

每项决策一个文件，随落实它的合并请求一起提交。2026-10-12 及之前的决策在存档 [DECISIONS.md](../DECISIONS.md) 里，那个文件不再追加，也不往里加“见某个新文件”的链接。

## 怎么写

- 文件名 `YYYY-MM-DD-简短英文名.md`：日期取用户确认当天，名字用小写字母、数字和连字符，说的是决策本身，例如 `2026-10-12-deploy-only-from-main.md`。
- 第一行 `# YYYY-MM-DD：标题`，日期与文件名一致。
- 正文照旧：谁确认的、定了什么、范围和边界、取代或补充了哪一条旧决策。个人身份与真实来源的细节只写本地记忆，不写在这里。
- 只新建自己这项决策的文件。旧决策被改变时不回头改旧文件或存档，在新文件里写明取代的是哪一条。

## 怎么读

文件名按日期排序，新的在后。同一件事有多条时以日期最新的为准；这里没有的，再看存档。

## 为什么不再写同一个文件

原因与进度记录相同，见 [进度记录说明](../progress/README.md)：各方都在同一个文件顶部加一节，同时打开的合并请求就会在 GitHub 上互相冲突。

`tests/record-entries.test.ts` 随 `npm run check` 运行：检查这里的文件名与首行格式，拒绝存档里晚于 2026-10-12 的小节，也拒绝存档里指向单独记录的链接。
