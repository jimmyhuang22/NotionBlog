# 2026-10-13：合并按影响验证，不反复追无关主线更新

用户在纯进度记录请求等待期间多次因其他请求进入 develop 而重新同步、检查后，明确要求直接合并该请求，并分析、修改不必要的规则。本决策取代日常合并“必须包含最新 develop，所有分支本机都跑完整 check／build”的无差别要求；不改变开发从最新 develop 起步、普通合并、平台检查、权限与正式发布授权。

强制同步每一次目标分支更新不能单独证明逻辑兼容，在多个会话同时工作时会使已完成请求反复变更提交、重跑已有检查。纯说明和进度记录不会改变产品执行路径。保留冲突检查、当前提交的自动检查及按影响选择的本机验证，更符合实际风险。

合并前检查 develop 的新变化。有冲突、同一逻辑或本项依赖／契约／fixtures／配置／数据库协议及迁移／检查环境变化时先整合，再检查受影响行为；无法判断影响时先整合验证。无关页面或说明记录更新不要求重同步与推送。核对最终合入的本项改动与受检改动一致，不夹带未审修改。

应用代码或构建输入改变，在工作分支集中完成一次 `npm run check` 和 `npm run build`；仅因无关提交出现不重复。纯说明、进度或开发约定文档做记录格式、相关链接、差异和隐私检查。可执行代码、依赖、构建／测试／部署配置、SQL、契约、fixtures、运行输入不能按纯文档处理。

GitHub 当前完整自动检查保持，失败或未完成均不能自行合并。main 发布仍针对完整集成版本 check／build／平台验收，并沿用每次明确发布授权。共享范围、视觉确认、公开范围、凭据与云配置仍按原规则取得批准。
