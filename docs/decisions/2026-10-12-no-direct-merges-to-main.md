# 2026-10-12：除发布外不向 main 开合并请求

用户确认（合并了提出这条规则的合并请求 #121）。

- **定了什么**：除 develop → main 的发布请求外，不向 main 开合并请求，只改文档的也一样；统一进 develop，随下一次发布上线。确实必须直接进 main 时先经用户同意，合入后由开请求的一方把 main 同步回 develop。规则原文在 `AGENTS.md`。
- **为什么**：每次合并到 main 都会创建一次正式部署。免费套餐滚动 24 小时内最多 100 次部署，当天用完后一次发布被平台拒绝；当天零点（UTC）之后的 10 次正式部署里有 8 次来自直接指向 main 的请求。
- **没有采用的办法**：用平台的“忽略构建步骤”让只改文档的提交跳过构建。平台文档写明被它取消的构建仍计入部署额度，省不下次数。
- **范围**：只约束合并请求指向哪条分支，不改变“发布只由用户合并”“合并到 develop 由开请求的一方自己完成”等既有规则。
- **与旧决策的关系**：补充存档里的“已确认十五”（develop／main 两条分支的分工）；取代当天早些时候“直接进 main 之后把 main 同步回 develop”那一条的前半句，同步的做法保留为例外情形的善后。
