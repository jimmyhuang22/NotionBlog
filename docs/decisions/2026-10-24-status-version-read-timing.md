# 2026-10-24：补齐动态首屏与版本接口的安全计时（Codex）

用户先批准两个固定计时操作的私人候选，再明确批准一次 GitHub 基线同步及独立分支的本地正式集成和离线验证。本地集成阶段没有提交、推送、开请求、合并、部署、读取项目真实服务或恢复任务；后续提交与草稿请求按用户另外确认的范围执行，不由本次计时决定授予合并、发布或任务恢复许可。

沿用 CONTENT_READ_TIMING=enabled。Status 服务端页面使用 status-page/status 包住原工作函数，保留首屏和年份并行、列表限制、focus/year、JSX、错误和 notFound。版本接口使用 content-version/unknown，禁用时仍在作用域前返回 404；原 try 内的查询、校验、摘要和成功响应构造受计时包裹，原 catch 留在外侧，失败先记 error 再返回同一 503。不能把成功构造的 503 Response 记录为成功读取。

共用类型和解析白名单仅增加这两个固定 operation，阶段、开关、日志字段与原操作保持。没有额外 SQL、DTO、缓存规则、公开资格、角色、依赖或云配置变更；不输出路径、查询词、参数、正文、来源或原始错误。

函数内部时长不包括此前框架排队、模块导入和完整流式响应结束；数据库往返也不是纯 SQL 执行。并行和嵌套阶段不可相加为端到端总时间。离线验证不等于线上改善，真实采样和发布另按授权边界执行。具体语义见[计时说明](../CONTENT_WAIT_TIMING.md)。
