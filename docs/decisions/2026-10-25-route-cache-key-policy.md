# 2026-10-25：路由资格目标规范化与正结果缓存

用户明确批准 [N04 方案](../BACKEND_ROUTE_CACHE_KEY_PLAN.md)的源码、离线验证及常规 develop 交付，包含正常 PR／push 自动 CI。

资格缓存入口逐段单次解码并稳定编码，合并当前资格语义中的重复／尾分隔符；规范化后再次确认受管形状。无效目标／focus 直接 missing，不读 provider、不写持久缓存；未受管地址的全局路由行为不改。调用方规范后签名，内部入口仍先验证原始 target 的现有 HMAC，再做同一规范化，保留新旧调用兼容及固定目的地／部署／时间边界。

持久投影仅对 route-verdict 的 found、contentRepository 元数据的非 null／undefined、原子笔记资格 true 采用正结果准入。先完成既有 generation、日期和预算守卫，再跳过负值写入；错误仍拒绝，不变成 missing。三个操作使用固定策略标记隔离旧缓存键，其他投影、全站版本、一天边界及发布刷新协议保持。

移除负缓存会增加重复缺失请求的实时读取；不宣称限流、全站容量硬上限或既有负项已删除。本决定补充[公开缓存决定](2026-10-21-public-content-cache.md)，不授权真实项目／缓存回读、purge、凭据／变量变更、运行包安装、任务恢复、main 发布、部署或手动派发 CI。

按用户同轮反馈，整组修复稳定后集中一次完整 check／build，开发中使用直接相关的定向回归，后续仅因新改动、失败或集成疑点补验受影响范围。
