# 2026-10-23：成功批次后的有界清理与滚动总账

用户确认先准备长期清理的离线代码候选。旧候选每日最多处理两批，不能作为覆盖来源增长的长期吞吐保证；本决定新增显式 v3 准入，保留旧 v2 行为与所有现有保护规则。

独立轮询在完整来源／图片／快照／课程目录／访客／正文后置成功、共享锁空闲时，对新的成功来源批次最多准入一次。不将清理塞入内容同步的时限，也不调整来源频率。每次仍最多两批、三十分钟、三十二 MiB逻辑 SQL 返回；所有尝试共享滚动二十四小时最多八次尝试、十六批、六十四 MiB逻辑 SQL 返回、七百五十次删除调用及二十五万删除行。上限不保证实际吞吐：归档、依赖、锁和预算都可能更早阻断。

总账固定在同一归档目录，绑定同一状态目录，记录永久来源去重及滚动用量。没有总账或原状态为 STOPPED 时拒绝，不自动初始化、迁移或复位。成功只按完整用量回执结算；未知结果、进程异常、回执缺失或锁释放不确定均保留整笔预留并停止，跨日和重启不解除。预算在准入前耗尽时不启动业务连接；已开始的失败不得自动重试。
