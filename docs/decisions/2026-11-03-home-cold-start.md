# 2026-11-03：首页在自托管启动时有限预热

在用户授权优化服务器重启后首次首页等待的范围内，采用以下实现；正式发布仍须另行确认，不继承上一轮发布授权。

- 仅自托管公开网站且启用 tagged-v1 时，准备 Next 后、正式端口监听前，从临时回环端口顺序读取内容版本及完整首页。普通开发、Preview 与未开启缓存的配置不预热。
- 总等待上限十秒，累计响应正文上限 1 MiB。只读首页首屏，不读取图片、脚本、其他栏目或翻页，不设置持续定时预热。
- 首页成功取得首屏数据后输出无显示作用的 template 标记；HTTP 200 的错误占位页不能当作预热成功。失败记录脱敏结果后继续启动，不重试、不扩大原有请求或数据库预算。
- 复用现有读取及缓存路径；访客仍要查询当前内容版本，跨版本、撤回、有效日窗口和失败缓存边界不变，不增加资格缓存或连接池容量。
- 预热会延长启动阶段，目的是降低服务就绪后的首次等待；不把工作提前表述为数据库冷查询本身变快，也不将本机跨区域测试当作 AWS 性能结果。
