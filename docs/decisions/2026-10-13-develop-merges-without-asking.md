# 2026-10-13：合并到 develop 不必等用户逐个放行
状态：部分取代。合并条件以 [2026-10-22-develop-merge-local-verification](2026-10-22-develop-merge-local-verification.md) 为准；“不必等用户逐个放行”仍有效。

用户确认（2026-10-13 在负责 UI/UX 的 Claude 对话里提出“把这个规定改掉”，并在随后的选项里选定“只放开 develop”）。

- **定了什么**：指向 develop 的合并请求，Claude 与 Codex 在条件满足后直接合并，不需要等用户，也不必等用户逐个说“合并某个请求”；另一方开的请求在同样条件满足时也可以代为合并。条件不变：分支已合入最新的 develop 且没有冲突，本机 `npm run check` 与 `npm run build` 通过，合并请求上的平台检查通过，正文写明验证方式与限制；使用普通合并。
- **为什么**：书面规则本来就写着由开请求的一方自己合并，但实际做法变成了每个请求都等用户说一句才合并，用户一天里要逐个放行十几次。
- **没有改的**：发布到 main 仍然只由用户合并。用户选项里另有“发布到 main 也放开”和“放开但合并前先告诉用户”两项，没有选。用户可以就某一次发布明确指定由某一方代为合并（2026-10-13 的两次发布都是这样做的），这种指定只对那一次有效。
- **边界**：自行合并不等于可以跳过用户的决定。需要用户先看方案的视觉与排版改动、共享范围、公开范围、凭据与云端配置、对外可见的发布动作，仍然先得到用户确认再实现与合并。除发布请求外不向 main 开合并请求的规则不变。
- **与旧决策的关系**：补充存档里的“已确认十五”（develop／main 两条分支的分工）和 [除发布外不向 main 开合并请求](2026-10-12-no-direct-merges-to-main.md)；不取代其中任何一条。规则原文在 `AGENTS.md` 的“分支与合并”。
