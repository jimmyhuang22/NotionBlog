# 2026-10-22：develop 按影响完成本机验证后合并

用户在前端交接中确认：“按 CLAUDE.md：本机验证通过就合并到 develop，不等平台检查。”Codex 于 2026-10-23 按用户转交的说明同步仓库约定。

日常 develop PR 在无冲突、按影响完成本机验证、正文写明受检提交／验证方式／限制，并核对实际合入差异后自行普通合并。已知代码、协议或构建失败仍须先解决；本机通过、平台排队或 `SKIPPED` 都不能写成平台通过，历史失败／中断证据保留。不为无关 develop 更新重复同步或检查。

专用 Mac mini 原生运行器已于 2026-10-22 退役，新旧仓库注册均已移除，系统服务已卸载并持久停用，见[退役记录](../progress/2026-10-22-private-ci-retirement.md)。当前私人 PR 的平台应用检查跳过，没有两小时集中检查，不再手动派发私人 CI；恢复平台检查及其节奏须另行约定。工作流本身不在本项修改范围，公开后的标准托管路径仍须实际验收。

本项重申[集中 CI 决策](2026-10-13-batched-development-ci.md)中 develop 不等待平台检查的原则，取代其两小时集中检查安排；补充[私人准备 CI](2026-10-22-private-preparation-ci.md)及[按影响验证](2026-10-13-merge-validation-by-impact.md)，明确当前退役状态和 develop 的合并条件。旧决策与记录作为历史保留。

main 发布仍按既有规则验收最终集成版本、通过平台检查并由用户合并，或由用户就某一次发布明确指定代为合并。本次仅决定 develop，CI 停用期间如何满足 main 平台验收仍待用户另行决定，不能据此放宽发布要求。发布 PR 打开期间[暂停 develop 合并](2026-10-13-develop-hold-during-release.md)的约定继续有效；共享范围、公开范围、云端配置与部署授权不变。
