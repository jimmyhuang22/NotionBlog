# 2026-10-12：进度与决策记录改为每项一个文件

用户在查看三个互相冲突的合并请求后确认：进度记录不再写进同一个文件，随后要求决策记录照同样办法处理。

- 进度写在 `docs/progress/`，决策写在 `docs/decisions/`，每项一个文件，命名 `YYYY-MM-DD-简短英文名.md`，首行 `# YYYY-MM-DD：标题`。各自只新建或修改自己的文件。
- `docs/PROGRESS.md` 与 `docs/DECISIONS.md` 成为 2026-10-12 及之前的存档，不再追加，原有各节不改写、不迁移。决策以日期最新的为准，新文件写明取代哪一条。
- `npm run check` 检查两个目录的文件名与首行，并拒绝两份存档里晚于 2026-10-12 的小节。

原因：所有合并请求都在同一个文件顶部加一节，任意两个同时打开的请求只要一个先合并，另一个就在 GitHub 上冲突；`.gitattributes` 的“两边都保留”只在本机生效，而且在本机也会吞掉空行、交错标题。当天因此冲突的请求有十多个，没有一个是代码冲突。

范围：只改变记录的存放方式与相关说明。`docs/REQUIREMENTS.md` 仍是各方就地维护的单一文件；分支、合并与发布规则不变。
