# 2026-10-13：发布请求打开期间暂缓向 develop 合并

用户在发布完成后明确允许继续，并确认日常合入 develop 不需要等待平台检查；同时指出，发布请求打开时继续更新 develop 会使发布检查重新排队，要求下次先等发布合并完再合开发改动。

从 develop 向 main 的发布请求打开起，默认暂缓向 develop 合并，直至该发布完成合并。每次日常合并前核对未完成的发布请求；存在发布时，工作分支仍可继续开发、按影响验证和准备 PR，已验证改动保留在分支。用户另行明确解除暂停时按新指令执行，不自行取消发布检查或修改发布来源来避开等待。

发布完成后恢复原日常规则：本机验证、冲突及实际差异核对通过即可普通合并 develop，不等待平台检查。main 发布授权及当前集成版本的正式验收继续按原约定；本项不修改 CI workflow、运行器、部署配置或业务同步任务。

此决策补充 [日常开发与集中 CI](2026-10-13-batched-development-ci.md) 和 [develop 自行合并](2026-10-13-develop-merges-without-asking.md)，不恢复逐个开发请求等待平台检查的旧要求。
