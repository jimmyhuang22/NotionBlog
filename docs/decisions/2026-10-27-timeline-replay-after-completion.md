# 2026-10-27：通关／白金后又玩的游戏另加一条“在玩”动态

用户转交反馈 F47 并选定改法“甲”，Claude 实施。这是对 [2026-10-21 时间线完成日期](2026-10-21-timeline-completion-dates.md) 的补充，不取代它；同时让 [2026-10-18 首页游戏横条](2026-10-18-home-game-line.md)“落在最近玩的那天”对通关后又玩的游戏也成立。

- 通关／白金的游戏最多两条事件。完成事件 `game-cleared`／`game-platinumed` 维持 2026-10-21 的规则：取手填 `playedDate` 结束端，单日取该日；没有手填日期就没有完成事件，平台、发行、编辑或采集日期都不能替代它。
- 平台最近游玩日（`lastPlayedDate`，按站点时区取到日）晚于完成事件所在的那一天，或者根本没有完成事件时，在最近游玩那天另生成一条 `game-playing`。`occurredAt` 是单点日期，`end=null`，精度 `date`，不带出几点几分；事件 ID 为 `game:{id}:{day}`，与完成事件不会相撞。比较按站点时区的日子，同一天或更早时不加。
- 只保存每款游戏最近一次的平台游玩日，没有逐日历史：连续几天都玩，只在最后一天出现一条。逐日记录需要后端另存游玩历史，不在本决定内。
- 在玩状态的游戏照旧取手填与平台中较晚的一天；影视、书籍和作品库列表与年份（`archiveDate`）不变。
- 原时间线、首页两版混排、翻页、演示数据与已保存快照共用这一投影。投影版本升为 `completion-replay-v3`，旧规则的游标即使原批次未变也会被拒绝，要求重新读取首批。
- 不新增字段、数据库迁移、Notion 查询或重采；前端卡片不改（`game-playing` 已画成“在玩”横条）。
