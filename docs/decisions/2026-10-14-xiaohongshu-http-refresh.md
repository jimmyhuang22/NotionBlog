# 2026-10-14：已有小红书笔记采用独立 HTTP 刷新候选

用户在 GitHub 调研、有界匿名 HTTP 试验后要求继续实现。范围为原有已审核笔记的统计刷新，优先暂停原因和恢复，再减少开页与进程启动；自动发现新笔记仍是后续独立阶段。

- 新来源为 `public-note-page-ssr`，浏览器仍为 `browser-note-state`；不将 HTTP 数据包装成浏览器数据。采样时间表示完成读取的时间，不证明上游缓存已即时更新。
- 一个周期复用一个 Python `curl-cffi` 会话和一个 PostgreSQL 连接。脚本是本项目的窄适配，不安装多平台爬虫工作台、不运行签名器、不给 Cookie／调试器权限。
- 保留 24 小时到期、十五分钟本地检查、五篇一批、最多三十二批／三十分钟；最多一百六十请求、六十四 MiB 解码响应、单页二 MiB／十五秒，不跟随重定向、不自动重试。只取笔记 HTML，不取图片、视频或评论正文。
- 旧 B 站固定程序会解码共享库中的小红书行，因此新来源写入独立 SQLite。候选准备按固定键复制原历史、pending／acked 和尝试记录，原库与共享配置保持可供旧程序读取。
- 云端只扩展原 `valid_observation` 和私有 meta 的 `http_note_version`，原协议版本保持 1。HTTP 客户端采集前核对能力，旧客户端继续使用旧握手；不增加角色权限或发布批准。
- 源／身份／配置／上传／退出错误保持人工恢复。健康回执记录阶段、代码、实际成功采样／上传时间、剩余数量及成本；普通周期检查不解除暂停，旧未记原因的暂停也不得假定已恢复。`resume` 优先补传近期 pending；过期采样按原到期规则重新读取。仅本地锁竞争延期。
- 启用时 Native Messaging 路由关闭旧小红书浏览器任务，B 站分派保持独立；默认关闭的 sidecar、候选 App 和独立 Dagu YAML 不会自行注册或启用。

补充原[周期设计](../SOCIAL_REFRESH_CYCLE.md)，不替代未启用环境的浏览器路径。代码合并不会安装 SQL、切换运行包、启用调度或创建网站部署。实际安装须绑定确定提交和固定原清单，先做一篇到期样本的来源／上传／读取验收，再开放原周期。回滚保留新库与 outbox，恢复旧浏览器真实采集；禁止把 HTTP 行改名后复制回旧共享库。
