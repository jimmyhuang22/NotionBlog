# 2026-10-13：平台检查不重复已有答案的内容
状态：已失效。公开仓库的检查不沿用私人阶段的树缓存或历史通过回执，见 [AGENTS.md](../../AGENTS.md)。

用户在 Claude“分支合并检查”对话的选项里确认，由该对话修改共享的 `.github/workflows/check.yml`：同样的内容已经通过过完整检查的不再整套重跑；只改文档的只跑记录格式测试和隐私检查。

范围与边界：

- “同样的内容”按 git 的树编号判断，文件完全相同才算；记录两周内有效，Node 主版本变化后失效。
- “只改文档”指相对所接续的提交只有 `docs/` 下的文件和根目录的 `.md` 文件变化。代码、测试、依赖、SQL、契约、fixtures 和配置都不算。
- 判断不了时一律跑整套并且不留记录。检查的内容本身（类型、三项协议、测试、隐私、构建与服务端追踪）没有减少。
- 触发方式、运行器、谁可以合并、发布只由用户合并，都不在这条决策里，保持 [集中 CI 决策](2026-10-13-batched-development-ci.md) 的现状。发布版本仍须通过平台检查；它的内容与刚通过整套的内容完全相同时，这次检查会显示“已验证”，这是同一份内容的同一个结论，不是用别的版本顶替。

同一轮选项里用户还选过“运行器用本机期间，合并只要求平台检查、不另在本机跑完整检查与构建”。大约二十五分钟后，用户在后端对话里提出“不过 CI，直接合并，然后继续开发”，由 [集中 CI 决策](2026-10-13-batched-development-ci.md) 落实并先合入了 develop：日常合并以按影响的本机验证为准，平台检查改为集中运行。两者在“日常合并以什么为准”上相反，以后一个为准，前一个没有写进规则，也不生效。

做法与读法见 [运行说明](../GITHUB_ACTIONS_RUNNER.md)。
