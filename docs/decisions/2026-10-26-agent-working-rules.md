# 2026-10-26：代理工作规则：读法、云端流量与重试

用户在 Claude 对话里确认：整理本地开发文档，云端流量规则按推荐写法重写，并先审阅改动再合并。

## 为什么

2026-10-24 至 10-26 的几项恢复工作反复停在申请授权上：每一步都要一个带字节预算、有效期和停止条件的新“窗口”，任何小错误都结束整轮且不得重试，还要先做封存包、清单和签收，甚至要求一项拿不到的证明。审阅发现：

- 用户明确提出的只有一条：访问项目云端（包括只读）要先说明原因、征得同意。预算窗口、零重试、“窗口关闭就作废”“继续不算续期”是在执行中逐步加上的细则；封存、签收和 provider 证明完全是执行方自己加的前提，用户 10-26 已明确取消。
- 这条 egress 条款和 10-24 起的几份决定只写在一份落后 develop 的本机检出里，没有提交，不同对话按不同规则工作。
- 开局必读的需求、全部决策、进度、存档和私有记忆合计约 4.3 MB，无法通读，代理只能挑最近的记录读，而最近的记录几乎全是停止与授权流水，于是这种做法被一再沿用。

## 定了什么

规则正文写在 [AGENTS.md](../../AGENTS.md) 的“云端流量、授权与重试”一节，要点：

- 小量只读直接做：打开单页、单条 COUNT／EXPLAIN、健康与身份检查、发布后抽查，每天合计不超过 50 MB，在进度记录里写一句。
- 写入、安装／配置／凭据变更、恢复或调整定时任务、正式发布、批量下载与备份、超出每日小额度的读取，先用一两句话征得同意。
- 一次批准覆盖整个任务，直到完成、用户叫停或用量明显超出说好的量级；“继续”就是继续同一个任务；批准方案即批准执行，除非用户说“只准备”。
- 没写入、没发布的临时错误在同一任务内自行修正或重试，最多 3 次；写入结果不明、数据或身份对不上、可能越过公开范围时立即停下再问。
- 不把封存包、manifest、SHA 清单、签收或交接回执作为开工前提；拿不到的证明不作为前提，需要豁免时只问一次；同一件事不开多条执行线，互斥用程序已有的锁。
- 开局只读 [入口说明](../START_HERE.md) 和 AGENTS.md，其余按任务检索；决策只记长期选择，一次性的批准写进进度记录；被取代的旧决策在第二行加状态说明。

## 范围与边界

- 取代 2026-10-24 用户提出、只存在于本机未提交改动里的 egress 授权条款（`2026-10-24-project-egress-authorization`），以及各次恢复方案里“业务零重试”“窗口关闭即作废”的执行约定。用户“访问云端要说明原因”的本意保留，改为按任务和量级判断。
- 不改变定时程序自身的重试与停止设计；修改程序行为照常走代码改动与验证。
- 不改变合并、发布、公开范围、凭据与正式部署的既有规则。
