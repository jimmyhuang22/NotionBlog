# 小红书账号增量同步

本项依赖[HTTP 刷新基础](SOCIAL_REFRESH_CYCLE.md)，由现有 Chrome 扩展及 Mac mini 调度器配合，不增加常驻采集服务。账号模式默认关闭，实际安装与代码完成分别记录。

## 发现与统计

| 工作 | 周期 | 实际操作 |
| --- | --- | --- |
| 发现新笔记 | 每小时 | 一个自有目录标签页，读取整页新一段；稳定 ID 与本地清单去重 |
| HTTP 统计 | 每篇最后真实采样后一小时到期 | 每十五分钟检查本地队列，只处理到期或近期 pending；每轮最多四十个待处理作品，复用解释器及受限连接 |
| 登录渲染补采 | 每十五分钟本地检查，统计仍一小时到期 | 只为新作品首次确认和需要登录的作品创建自有标签页，每批最多三篇 |

匿名请求的起点至少间隔五秒，间隔跨小批次保留，等待可取消；已有新鲜浏览器证据或 pending 补传不增加匿名请求。按最久未成功采样排序，未选到的到期作品保留下一轮，不将四十项批次伪装成全范围完成。验证码目的地记录 `SOURCE_VERIFICATION_REQUIRED` 并暂停，不能转成逐篇例外或自动反复重试。

两条 Dagu 本地检查错开五分钟：B 站保留每小时 00／15／30／45 分，小红书 HTTP 改为 05／20／35／50 分（`CRON_TZ=Australia/Melbourne 5,20,35,50 * * * *`）。两者仍各自十五分钟一次，跨小时也相隔十五分钟；HTTP 准备程序生成相同配置。Chrome 目录与少量渲染补采的原 alarm 保留。本项减少同时起跑的共享锁竞争，长周期仍可能重叠，BUSY 延期规则继续有效；不启动第二个调度服务或重启既有服务。

频率是到期策略，不是一小时内必达保证：Mac 睡眠、Chrome 未运行、验证码、锁竞争和网络错误会延迟。源端没有可用的完整批量计数或变更通知，所以已有统计都每小时更新仍需周期性读取；增量减少的是重复接入、目录翻页和无意义的详情重采，不凭点赞没变推断评论没变。

目录最多十次滚动尝试、三百个唯一卡片、九十秒及原租约期限；先检查一整页，至少渲染三十张且末尾五张 ID 都已知才可成功停止。避免单个置顶卡过早终止，大于边界的突发新内容明确报缺口。仅有正向发现证据，未出现在这一段的旧卡片不自动下架。每次使用自建标签页并在结束时关闭，不操作其他标签页。

B24 修复（2026-10-24）：未找到上述边界时，每隔至少三秒重试自有标签页滚动，仍计入原十次上限。按有序卡片 ID 而非卡片数量识别进展，支持数量不变但身份推进的渲染。连续可读取的卡片 ID 十秒不变，明确返回 `XHS_DIRECTORY_STALLED` 并沿用暂停／人工恢复；无页面就绪或租约／总期限耗尽仍为 `BROWSER_TIMEOUT`，超过滚动／数量预算为 `XHS_DIRECTORY_GAP`。页面失去就绪会重置停滞观察，不把中间缺失的观察当作十秒稳定。

少于三十张或最后五张仍含新作品时，页面即使看起来到底也不能靠停滞判成功；本轮没有可信的自然末尾证据，因此明确停止，不上报完整历史或自动删除旧作品。后续若要让这些目录自动成功，需独立验证自然末尾／加载状态的真实页面证据并审阅协议。当前修复的是有界推进和准确错误归因，不声称已支持自然末尾自动成功；源码合并也不安装扩展、恢复目录任务或执行真实采集。

## 配置与证据

原 `refresh-config.json`、`browser-links.json`、B 站工作流和共享 SQLite 保留。新私有 `xiaohongshu-account.json` 绑定原配置摘要及唯一账号，包含 `enabled`、`discoveryHours:1`、`statisticsHours:1`；派生 HTTP 范围使用原独立 XHS 状态库及小时到期规则，不将新来源写回旧共享库。

目录证据和待接入 ID 保存在 `discovery-xiaohongshu/state.json`。新作品 ID 使用平台／账号／笔记键派生稳定作品键，实际确认图文或视频后再加入 `xiaohongshu-discovered.json`，不会用标题自动关联其他平台作品。浏览器租约及窄投影在 `xiaohongshu-browser-notes/`，发布身份、作者、类型、租约、时间、完整批次及摘要在写入前验证；浏览器显式要求平台 `shareInfo.unShare=false`，未知或不可分享时停止，不猜测公开状态。

目录的公开访问令牌仅用于构造同一笔记的候选地址。候选地址没有展示资格；实际 HTTP 读取或自有浏览器标签页访问确认同一身份之后，才用原始采样时间登记链接证据。旧分享地址与核对时间不会因目录检查被覆盖；保留现有网站可识别的分享地址结构。来源分别为 `public-note-page-ssr` 与 `browser-note-state`，不执行 SSR 脚本，也不把 HTTP 内容伪装成浏览器采样。

匿名响应的同笔记“暂时无法查看”或空详情图只进入这一篇的渲染补采，不解释为删除，不写假零。其他重定向、身份不符、限流、登录验证、损坏状态和上传错误保持明确暂停。`xiaohongshu-link-holds.json` 只保存键、地址摘要、时间和原因；已接受的浏览器投影可以在一小时内补传，保留实际 `observedAt`，不会将处理时间替换为采样时间。

## 受限云端与恢复

浏览器补采新增本机白名单诊断：`BROWSER_PAGE_LOAD_TIMEOUT`、`BROWSER_NOTE_STATE_TIMEOUT`、`BROWSER_LEASE_EXPIRED` 分别记录页面等待、笔记数据等待、租约耗尽。保留二十秒单页等待与两分钟租约；诊断只包含 job、匿名目标 SHA、等待毫秒／轮数、最后标签页状态、可选冻结／丢弃标记和 `NOTE_STATE_MISSING`，不写正文、Cookie 或完整地址。旧 `BROWSER_TIMEOUT` 保留未知阶段，不反推历史原因。[Chrome Tabs 文档](https://developer.chrome.com/docs/extensions/reference/api/tabs)说明了冻结／丢弃字段；缺少字段保留 null，不推断机器睡眠或平台验证。

单篇恢复使用独立 SSD ticket，先保存旧暂停，只接受现有失败目标；三十分钟内由现有扩展领取一次、一次仅一篇。领取即消耗许可，重启／第二次事件不重开标签页；过期或失败保持暂停。接受新鲜快照后可补传同一数据，但不重新采样，也不在这个补采流程里接入新作品。相同目标／快照的本地 ACK 核对后停在 `BROWSER_RECOVERY_ACCEPTED`；操作者用原 reader 回读相同 SHA，再显式完成恢复，才解除少量补采暂停。新登录／验证码不自动恢复。

固定运行包的 `browser-notes-cli.ts` 提供 `status <runtime>`（只读）、`arm <runtime> <existing-note-id>`（不采集）、`finish <runtime> <recovery-id> <reader-sha256>`（核对 ACK 后解除）、`cancel <runtime> <recovery-id>`（归档未接受 ticket，保留暂停）。`retry-upload <runtime> <recovery-id>` 仅在有同一任务的新鲜完整快照时显式补传；源超时没有快照时拒绝，不打开页面，也不清除 HTTP 人工恢复状态。已捕获／接受的 ticket 不能直接 cancel 丢掉样本。实际运行切换、扩展重载和样本回读分别记录；不更改原 Dagu HTTP 程序、B 站或云端权限。

完成命令的摘要参数表示“回读确认后的源摘要”：用同键的真实 worker ACK／受限 worker SELECT 核对源 SHA，再用 reader 核对完整公开投影的身份、采样、计数、类型与链接。reader 视图不暴露原始源 SHA；不得为验收新增其源列权限，或宣称该列由 reader 直接读出。

新 SQL 默认不授权任何账号；新增两张私有 RLS 表、账号能力标记和两个仅供原 worker 使用的固定函数。worker 无账号表、审批表或新增表写入权限，reader 权限不扩展。新记录必须属于显式启用账号、符合稳定作品键、实际类型和时间、已验证跳转地址及总体容量限制；禁用绑定及旧展示撤回不被重发现恢复。新旧账号接入共用已有容量锁，不能并发越过五百张上限。

正常上传确认按键和 SHA；未知结果保留 pending，普通检查不清除错误。人工处理登录／验证或配置问题后使用固定运行包的 `http-cycle-cli.ts resume`，恢复前保存目录／渲染暂停回执；近期 pending 优先补传，超过一小时的浏览器证据需重新采样。共享 HTTP 周期锁避免新作品登记在一次固定统计周期中改变范围。

启用顺序：核对冻结包和原配置 → 安装已审阅 SQL 并限定账号 → 切换原专用启动器与扩展文件 → 用户重载扩展 → 一篇已有到期作品的采样／受限上传／reader 回读 → 显式解除本项旧暂停并启用小时策略 → 观察下一自然周期。所有安装前的测试保持本地或限定只读，不因检查失败重采全部作品或触发网站部署。
