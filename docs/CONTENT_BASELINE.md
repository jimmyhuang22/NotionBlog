# 完整内容缓存的独立回读初始化

`scripts/website-incremental-sync/content-baseline.ts` 把同一次已接受完整发布的 records、全部媒体描述及发布状态，验证后保存到后台私有内容缓存。它不是新的采集器、全量发布器或图片处理器；不读取 Notion、对象字节，不写云数据库，不改调度和网站模式。

主运行器在首个完整发布后，使用已验证独立 reader binding 的原始 reader 构造 `createDatabaseContentBaselineReader(binding.reader)`，把同一采集工件的 records／media、实际独立读回的 state 和已接受完整发布 UUID 传给 `initializeContentBaseline`。学习排序 companion 仍由学习基线初始化器处理；不得再运行一次旧完整采集来补普通缓存。

初始化先读当前发布状态，再通过现有 published snapshot 读取全部十种支持内容类型的资格名单及全部合格媒体 ID。使用固定原始投影，避免网站 compact projection 隐藏未引用媒体，从而错误证明完整。页面或媒体集合不一致时，在逐页读取之前停止；学习子集、少一条普通页、少一个未引用描述均不能算完整基线。

随后固定同一发布版本，逐页独立读回私有正文、来源归属、顺序和拥有的全部媒体描述，与冻结的输入逐项相等比较。最后再读全局状态，确认发布版本、配置、schema 和 policy epoch 全部未变，才生成完整内容 digest 并调用缓存自身的事务初始化。默认最多 2,000 次逐页读取，可显式调整至 20,000；输入上限 32 MiB，媒体描述最多 20,000。取消、权限或数据库错误、版本变动和不完整证明均不得初始化。缓存已存在时不覆写；正常增量运行直接加载，不能每天重复初始化。

此证明只针对数据库中当前合格内容和媒体描述，不证明对象字节已完整迁移，也不代替初始来源采集的完整性。完整发布 UUID 必须来自主运行器的接受记录，reader 必须来自独立受限登录绑定；writer 回执、自填布尔值、公开 DTO 和学习单独证明不能替代本步骤。运行器仍需持有与旧发布共用的 canonical mutex，在同一安装／源策略下完成两份本地基线和后续恢复，再执行增量发现。
