# 内容发布后的自托管交付入口

用 `python3 -B` 运行下述Python命令。此入口在原内容发布流程安全结束后，把同一份已采集内容交给既有自托管交付器。它不采集来源、不执行持久发布指针采纳、不安装服务、不恢复定时，也不修改原轮次脚本。

## 两个独立的退出结果

`scripts/self-hosted-delivery/sync-entry.py --request /absolute/private/invocation.json` 是前台外层入口。请求文件0600，保存原Python路径、轮次脚本路径、原批准参数数组、原工作目录和批准时间。批准文字包括Unicode、换行及字面符号均按argv原样传递，不经shell拼接；可选原截止参数也不改写。外层不重试来源命令，不修改来源计次或其内部十分钟启动检查；另行拒绝在原批准十分钟之后启动子进程，等待交付不会延长该时限。

外层自身命令行只包含中性入口与请求文件路径，不包含轮次脚本名或当前轮次编号。原脚本在自己的子进程组中运行，保留环境和标准输入输出；外层向该组转发取消信号。来源的非零退出码或终止信号原样返回，**不以交付成功覆盖来源失败，也不以交付失败覆盖来源退出码**。交付结果单独输出并写入请求指定的结果文件，不能只用外层退出码判断上海是否已更新。

`delivery.py --config /absolute/private/config.json --run-id UUID` 是独立的单版本交付命令。其退出码为：成功／已交付／被更新版本取代0；明确未发布或输入失败1；写入不明／需核对3；已发布但读回或HTTP检查未通过4；等待安全收尾、锁或采纳75。它不会重新执行来源。

## 执行顺序和共享锁

1. 原来源子进程退出。按指定轮次读取维护状态，等待已发布或已发布但收尾未完成；原程序仍处于正文／清理阶段时，不根据锁短暂消失推断完成。
2. 等待原四个协调锁释放。外层此时不持有这些锁，只前台有界等待；等待结束留下明确待办，不创建后台轮询或定时任务。已有待办仅用单版本 `delivery.py` 继续；不要为续交付重跑外层入口或来源。遇到未发布失败直接结束。
3. 由原操作方执行既有持久指针采纳。入口只读该工具的当前结果，要求目标版本一致、成功退出、独立reader验证与锁清理完成；有pending或提交未决结果就停止。入口不启动、重试或代替采纳。
4. 交付子阶段取得四个原共享锁，重新核对状态与采纳，才运行既有交付器。队列版本去重、取得锁后再次读取状态；旧版本不能覆盖较新的已完成交付。锁竞争只清自己已取得的部分，不删他方锁。
5. 展示文件完整后才发布同批数据库内容。未知写入保留交付子阶段的原锁并报告；已发布但后验失败不重做写入。成功释放自持锁。

这里区分“外层不持锁”与“交付子进程沿用原互斥锁”。不新增第五把业务锁或协调服务。

## 请求与接入边界

请求含 `enabled`、`attempt`、`approvedAt`、`startNotAfter`、`source`、`deliveryConfig`、`waitSeconds` 和 `resultFile`。其中 `startNotAfter` 必须严格等于 `approvedAt + 600`，原批准放在 `source.arguments`；路径/轮次编号留请求文件，不放外层命令行。实际例子与个人配置留忽略目录。配置及请求均须明确启用，否则不执行；本轮准备的真实接线样例保持禁用。

交付配置引用既有维护状态、来源capture、四锁、采纳结果目录及预期revision／epoch／配置，另指定交付命令、队列和最后已交付版本文件。采纳身份/版本不匹配时不能自动采用新值放行。来源正文或原件缺失时明确失败，不回云端重新采集。

本入口适用于后继轮次试运行，既有待执行轮次继续原调用方式，实际切换范围见本项私有记录。旧入口被直接调用时不会自动经过本外层。定时、告警渠道、COS临时前缀自动清理、服务器安装和真实来源运行均不随本轮离线代码启用。

## 离线验证

Python行为检查由 `tests/self-hosted-delivery.test.ts` 运行，全部使用临时虚构来源脚本、私有状态和采纳结果。覆盖原批准/截止/退出状态、父进程命令行、四锁、人工清理后再采纳、非整轮成功的已发布内容、重复/并发去重、版本顺序、失败和未知结果。生成小图片通过现有生成器，验证只传展示副本、缺文件拒绝及400/800/1600读取；没有修改生成器，不把本机接收验证写成新的服务器现场验收。
