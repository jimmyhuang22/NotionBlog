# 社交采集器

`scripts/social-sync/` 是当前仓库内独立运行的 TypeScript 程序。首个交付为指定 B 站公开视频页面 → 作者／作品核验 → 本地 SQLite → 私有待上传导出；第二步加入指定小红书笔记的浏览器投影导入；不需要额外数据库服务，不包含网页入口。平台接入范围见 [探索方案](SOCIAL_VIDEO_EXPLORATION.md)，本阶段采集实现为本项目独立代码，没有引入第三方采集框架。现在另有独立的受限 Supabase 上传链路，见 [云端接入](SOCIAL_CLOUD.md)。

后续新增 [合集与详情批次](SOCIAL_COLLECTIONS.md)：`collect-collections` 使用独立本地数据库与候选 DTO，`plan-details` 只生成有界离线计划；合集尚不能通过旧 `upload` 发送，现有单发布协议保持。

## 输入与运行

使用 Node 24–26，SQLite 来自 Node 自带模块。运行输入、数据库和状态必须放在同一个独立私有目录，使用规范绝对路径（不经符号链接）、当前用户所有、权限 700；配置与文件为 600。开发和验收使用外置 SSD，固定运行版本与内置运行状态仍需后续安装验收；不要指向其他 worker 的目录。

复制 `scripts/social-sync/templates/config.example.json` 为私有目录的 `config.json`，替换其中**虚构**的作者与作品。结构如下：

```json
{
  "version": 1,
  "publications": [
    {
      "platform": "bilibili",
      "workId": "example-work",
      "accountId": "10001",
      "url": "https://www.bilibili.com/video/BV0000000001/"
    }
  ]
}
```

`workId` 是人工指定的作品关联键，同一作品的发布可使用相同键；它不是平台视频 ID。配置现接受 B 站和小红书，合计最多二十条明确指定发布，不发现账号全量历史。作者 ID 必须是字符串。只接受 `https://www.bilibili.com/video/BV…/`，查询参数移除，统计范围仍是稿件级，不因为 `p` 参数变为分 P 统计；短链不自动解析。重复平台／作者／作品标识拒绝。已存储发布的作品关联键变化会在采集前拒绝，重新关联流程尚未提供。

从本次功能检出根运行：

```sh
node scripts/social-sync/cli.ts --help
node scripts/social-sync/cli.ts collect /ABSOLUTE/PRIVATE/social-sync
node scripts/social-sync/cli.ts status /ABSOLUTE/PRIVATE/social-sync
node scripts/social-sync/cli.ts export /ABSOLUTE/PRIVATE/social-sync
```

没有新增根 package 脚本、生产依赖、站点栏目开关或共享 DTO。采集模块不由网页请求触发，网站构建不需要本人的输入或平台会话。

## 数据与失败规则

- 仅从视频页面的 `window.__INITIAL_STATE__` 提取惰性 JSON，不执行网页脚本。返回稿件与作者必须和输入一致；稿件统计与稿件身份核对，合集仅保存标识、标题、集数，不以合集统计覆盖单稿件。
- 保存标题、简介、封面引用、实际发布时间、观测时间、响应摘要及播放／点赞／评论／分享／收藏／投币／弹幕计数。未知计数和日期为空，零保留零；近似显示值或异常数值不伪造为精确数字。封面只登记获准格式的引用，本阶段不下载图片或视频。
- 观测时间是本次读取成功的时间，不代替平台更新时间，也不证明上游缓存的数据瞬时最新。没有 Cookie、签名算法或登录绕过；重定向、限制、非 HTML、异常状态、过大响应与网络失败均明确记录，保留上次成功数据。
- 每条成功观测在一个 SQLite 事务内保存历史采样、最新投影与队列。重复的同时间／同内容采样不新增；同时间但不同内容拒绝；旧采样不覆盖最新值。再次真实采集产生新的历史采样，但发布记录和该发布的待上传项仍各只有一条。
- 独立目录使用既有原子进程锁。每次页面请求最多十五秒，解压后的正文最多 2MiB；串行请求间隔一秒，CLI 整轮两分钟后取消。单视频与合集的 HTTP 5xx 均记录 SOURCE_TEMPORARY_ERROR；分类本身不增加重试或恢复暂停。一个作品失败不会清除其他作品；退出非零和报告中的失败／取消状态表示本轮未全部成功。
- SQLite 使用私有文件、参数化语句及版本检查，拒绝链接、其他用户文件、宽松权限和未知 schema。初始本地 schema 版本为 1，不是网站冻结 SQL 协议；未来版本需显式迁移。

`social.sqlite` 保存记录，`latest-run.json` 保存匿名计数，`status` 返回作品／发布／采样／队列计数和匿名失败状态。异常日志不包含链接、标题、作者 ID、原响应或底层错误正文。详细数据仍留私有数据库及导出文件。

## 待上传接口

`export` 把当前最多一百条待上传观测保存到同目录的 `pending.json`。每条包含稳定发布键、完整观测和 SHA-256；导出不会确认上传，也不会改变队列状态。最初没有云端发送器；当前新增 `upload`，只有独立云端配置与受限回执通过后才确认，网站读取仍未接入。未配置云端时不能把 export 当上传成功。

库函数 `flushOutbox` 接受有界传输回调，正式 `upload` 使用专用 SQL 登录和私有 ingest 入口；回执须同时匹配发布键和该负载摘要才能确认。失败或错误回执保持待传并记录匿名错误码；旧的在途回执不能确认较新的排队采样。已用模拟传输验证这些边界，不能把模拟成功当成真实 Supabase 写入。

所有观测均标记 `websitePublicationApproved=false`。本地采集不授予整账号或作品公开资格。评论仅保存数量，不保存原文；小红书的指定笔记投影已接入，抖音、平台历史发现、作品管理界面、网站读取与定时任务仍未接入，永久云端已按独立私有域接入。Steam 继续使用既有游戏程序。

## 本轮验证

- 合入最新 develop 后，Node 24 的仓库完整检查 **748 项测试**、类型及三类协议／摘要通过，生产构建的 **35 份追踪**排除私人运行文件。新增二十项覆盖字段／身份、HTTP 拒绝与大小、SQLite 重开、重复／旧样本／冲突、队列回执、失败恢复、文件与锁，以及真实子进程 CLI；这二十项也在 Node 26 通过。
- 正式 CLI 对三个此前获准的本人 B 站样本实际重新采集。第一轮新增三个发布，第二轮更新三个发布，均无失败；三个作品／三个发布、六个历史采样、三个待上传项，重复执行没有新增发布记录。
- 实际导出的三条负载与 SQLite 读回和 SHA 一致，全部作者／稿件及统计范围通过；文件权限核对通过。独立故障副本的三个重复采样不新增、三个旧采样拒绝、三个模拟上传失败仍待传，真实主数据库没有假确认。
- 真实账号、URL、SQLite、导出、故障副本和回执留忽略目录。本轮实际云端写入、上传确认、原媒体下载及周期任务安装均为零。

当前独立社交写入端已实现；下一步验证平台有效分享链接和网站只读入口，不调用旧内容同步函数或轮换旧凭据代替。

## 小红书指定笔记输入

小红书输入使用 `platform: "xiaohongshu"`、24 位小写十六进制的作者 ID 和笔记 ID，以及 `https://www.xiaohongshu.com/explore/…`。不解析短链或发现全账号；配置链接中的查询参数被移除，存储的 `originalUrl` 是用于身份校验的规范链接。实测在现有登录浏览器直接打开无访问参数的笔记链接会返回“页面不见了”（300031），而从作者主页进入详情可读；当前不能把该规范链接当作已经可用的评论跳转。网站接入前还须验证平台真实分享链接及其有效期，不把会话 Cookie 或私人访问参数写入公开 DTO。两个平台的发布可用相同 `workId`，人工确认作品关联后才使用同一个键；相似标题不自动合并。

```sh
node scripts/social-sync/cli.ts capture-script /ABSOLUTE/PRIVATE/social-sync
node scripts/social-sync/cli.ts import-xhs /ABSOLUTE/PRIVATE/social-sync
```

`capture-script` 从私有 `config.json` 生成同目录 600 权限的 `browser-capture.json`，其中 `script` 为本项目独立编写的浏览器读取片段。它不启动浏览器，也不创建数据库。在获准的浏览器会话打开指定笔记、重新加载详情后，在开发者控制台执行该片段；返回 `SOCIAL_SYNC_SNAPSHOT ` 加 UTF-8 base64 投影。编码仅为避免控制台自动缩短 URL，不是加密或签名；把标记后的完整编码存入私有 `xiaohongshu-snapshot.json`：

```json
{"version":1,"snapshots":["ENCODED_CAPTURE_FROM_BROWSER"]}
```

同一文件也接受解码后的投影对象；最多二十条、总文件不超过 256KiB。片段仅读取当前路径对应的 `noteDetailMap` 条目，并核对当前笔记 ID（兼容 Vue ref）及预期作者；目标缺失时拒绝，不挑另一条。小红书的 `shareCount` 与其他程序的字段不可直接混用。读取片段不触碰 Cookie、评论列表、正文、私信、收藏列表或视频地址。

`import-xhs` 在创建数据库前校验整个输入和配置，拒绝额外字段、未知类型、身份不一致、过期五分钟以上或未来超过三十秒的采样；全部观测在一个 SQLite 事务入库，后一个冲突会回滚前一个。再次导入保持原捕获时间和响应摘要，不刷新时间，重复不增记录；不会确认云端上传。浏览器片段会返回页面缓存中的值，捕获时间不证明上游瞬时新鲜，导入校验也不证明来自可信远端；私有输入提供方须可信。

小红书内部观测为 v2（本地数据库 schema 仍为 1）：`normal` 为 `image-note`，`video` 为 `video`；`metricsScope` 为 `individual-note`，增加 `updatedAt` 和四项 `metricDisplay`。发布时间与平台更新时间独立保存；播放、投币与弹幕为 null。不将 `1.2万`、`999+` 等显示转成精确数字，也不将缺失转成零；非法数字拒绝。封面仅登记 xhscdn 子域引用并升级 HTTPS，不下载或保证链接长期有效。正文和合集均为 null。小红书的 `responseSha256` 是狭窄浏览器投影的摘要，不是完整 HTTP 响应摘要。B 站既有 v1 负载和摘要原样保留。

本阶段 `collect` 仍只自动读取 B 站；小红书目标明确报 `BROWSER_SNAPSHOT_REQUIRED`。混合配置中各目标分别成功或失败，不把老本地数据视为本轮采集成功。浏览器桥接已通过两篇真实图文及十六项新增测试；真实视频、无人值守会话续期与账号全历史另行验证。

## 正式云端上传

```sh
node scripts/social-sync/cli.ts upload /ABSOLUTE/PRIVATE/social-sync
```

同目录 `cloud.env` 必须为独立私有文件（600），使用专用 `SOCIAL_DATABASE_URL`，格式见模块内 `templates/cloud.env.example`。TLS 默认验证证书，远端不能禁用；启动后核对当前角色／会话登录均为 `nb_social_worker`、无特权且社交 schema 为 1。不要指向 Notion worker、网站 reader 或高权限数据库账号；不复用其会话。

`upload` 仅发送当前私有配置中仍存在的待上传目标，移出配置的记录留本地并报告 skipped，退出非零；云端还须有操作者登记的启用绑定。先按当前配置筛选待办，再最多读取一百条获准队列；已移出配置的所有待办只计入 skipped，不占批次名额、不加载正文、不自动删除。单连接逐条传输，单次 SQL 十秒／客户端十二秒超时，整轮两分钟取消。原始负载上限 192KiB，在发送端和服务器都校验身份／字段及 SHA；只有实际保存键和摘要匹配才确认，旧在途回执不能确认新数据。错误或中断保留 pending，数据库提交后丢回执可幂等重试。

永久云端只保留最新投影，本地完整采样历史不变，观察时间不被上传时间替代。所有 `websitePublicationApproved` 仍为 false；新 Data API／网站 reader 没有读取权限，没有调度或页面开关。独立 schema、RLS／列权限、注册和回执规则见 [社交云端说明](SOCIAL_CLOUD.md)。

本轮验收：Node24 完整 764 项测试、类型／三协议／344 候选隐私检查和生产构建 35 份私人追踪通过；Node26 的 36 项社交回归通过。两篇真实小红书图文与三个重新读取的 B 站视频共同保存五发布／五采样／五待传，SQLite 读回、导出 SHA 和私有权限一致，实际云端写入为零。

云端阶段实际验收：正式 CLI 首次确认五条，重新实际采集三个 B 站样本后确认三个更新，再次 upload 确认零条；本地五发布／八采样／pending 零，云端五份最新投影和本地内容／摘要完全一致。专用角色通过两并行重复回执与八项真实拒绝检查，原内容状态与计数未变，网站公开资格仍为零。
