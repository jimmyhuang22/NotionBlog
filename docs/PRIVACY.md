# 隐私与提交约定

最后更新：2026-10-25。

NotionBlog 已按用户明确授权公开源码，旧归档保持私人，见[公开决定](decisions/2026-10-23-public-github-hosted-ci.md)。源码公开不扩大内容范围；个人原始资料或凭据不进入源码仓库，开发流程不自行改变可见性或发布。

源码规则、推送历史边界与可信 CI 的接口见[扫描说明](PRIVACY_SCANNING.md)。固定 legacy 边界、旧规则自举或一次 PASS 均不等于全部历史无秘密，也不授权真实凭据处置或历史改写。

## 本地文件与仓库文件

以下内容只保留在本地，并通过 `.gitignore` 排除：

- 原始开发包目录与压缩包，包括真实 Notion 盘点、来源配置、页面索引和个人开发材料。
- `.local/` 内的完整项目记忆、个人站点配置、真实来源编号、来源公开配置与手动允许列表。
- `.env`、`.env.local` 及其他实际环境文件中的凭据、来源配置和部署信息。
- 真实 Notion 响应、原始正文、媒体注册信息、临时文件地址、导出、缓存、调试日志和本地构建产物。
- 私人图片、截图和其他尚未明确允许提交的资产。

可提交文件包括通用需求与协作规则、内容契约、运行代码、虚构模拟内容、通用演示媒体及经过清洗的配置示例。`.env.example` 等示例也要检查：文件名含“示例”不代表其中的来源编号和个人信息可以提交。

个人站点名称、域名、账号、具体课程记录和完整来源结构写入本地配置或项目记忆，公共文档使用通用项目身份。

## 提交与推送检查

在首次提交前和后续提交前运行：

```sh
npm run privacy:check
```

该命令检查已跟踪文件和 Git 未忽略的候选文件。`npm run privacy:check -- --staged` 直接读取暂存区内容，避免工作文件已经清洗但暂存版本仍含敏感内容的情况。发现问题时只报告路径和类别，不打印匹配的敏感值。

通用规则检查私有目录、凭据、私有页面链接、临时签名地址、个人路径和学生邮箱。本地 `.local/privacy-blocklist.json` 可补充实际个人标识与真实来源编号；该文件本身不提交。因此，其他人的克隆需要配置自己的本地标识清单，检查脚本也不能保证发现所有个人信息。

本地已启用 `.githooks/`：提交前检查暂存区，推送前检查仓库候选文件。新的克隆可执行 `git config --local core.hooksPath .githooks` 启用相同检查。实际验证结果记录到[进度记录](PROGRESS.md)。

同时检查暂存文件清单与变更内容，确认只有预期的公共文件。不要使用强制添加把忽略的原始开发包、环境文件或私有记忆加入提交。

`.gitignore` 只影响未跟踪文件的选择，不会自动保护已经被 Git 跟踪的内容，也不会清除已有提交。首次提交前应确认历史与暂存内容均满足隐私约定；若文件已被跟踪，需要从索引中移除并核对历史，不能仅补一条忽略规则。

## 开源前复核

任何未来公开都需要用户明确授权。准备公开时复核所有拟公开的分支、标签和提交历史，不仅检查当前文件；同步检查说明文档、发布附件和其他拟公开材料。

若历史中出现个人信息或凭据，先完成清理和验证。凭据即使从文件中移除也应按实际暴露情况处理。当前检查脚本不能替代对全部历史和公开材料的复核。

## 运行时边界

Notion 凭据、真实来源配置和原始响应只在服务端读取，不能放进公开目录、浏览器组件或客户端构建结果。公开错误与日志避免输出原始请求、凭据和私有页面信息。

网站公开资格与 Git 是否提交互相独立。用户已明确允许指定 Status 来源使用 `publication.mode=all`，包括该 data source 中现有及未来新增的活动记录；这项授权只适用于指定 status 来源，不自动扩大到其他来源、普通子页或整个工作区。冻结 v1 只有 status 接受整来源模式；网站 v2 的其他来源须有各自授权，学习规则如下。

课程与学习笔记按 2026-10-12 新决定改为全部当前与未来自动公开，但仅限已配置课程来源的直属课程及它们实际拥有的多层子页面、笔记数据库记录。每页仍须验证完整、活动的物理父链；中央 deny 排除该页及后代，名单兼容只用于旧配置／冻结 v1。普通链接、提及、关系、外部数据库视图和引用的同步块不会纳入。其他普通页面仍不因父级公开而获得资格。详情、内部链接、媒体和缓存继续检查同一边界；Notion 连接可读范围不能扩大网站范围。规则与撤回见 [学习自动公开](STUDY_PUBLICATION.md)。

生产构建也不能打包忽略的私人文件。`next.config.ts` 排除本地来源、环境文件、原开发包及私有导出，运行时本地读取不参与自动文件追踪。`npm run build` 在编译后核对所有服务端文件清单；出现私人文件会使构建失败。托管使用私有环境配置，不能为了通过构建而把 `.local/` 复制进仓库或上传包。

元数据与正文采用同一链接清洗规则，私有 Notion 页面地址及临时签名地址不进入普通文本或公开超链接。媒体定位只包含允许页、块身份及不可逆的签名属性标记，真实属性映射和原始 URL 留在服务器。媒体每次重新检查资格和归属；已下载内容及已经签发的上游 URL 不能即时追回。

Notion 的结构化用户提及统一转换为不可点击的 `User`，不从提及对象公开显示名、用户 ID、邮件、头像或附带链接。此规则同时用于正文、目录标题、图片说明与替代文本，以及标题／摘要等富文本元数据；不额外查询用户资料，也不按名字猜测或清洗作者手工输入的普通文本。旧数据库快照已经丢失原始提及类型时，不能安全地靠字符串替换清洗，须在后续获准更新运行包和重新采集后生成新投影；源码合入不代表历史副本已删除。
