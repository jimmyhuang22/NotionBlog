日常 develop PR 仍按影响本机验证、核对实际差异后普通合并，不等待平台检查；已知代码、协议或构建失败须先解决。main 发布须对最终集成版本完成 check／build 和平台检查，并由用户逐次授权；发布请求打开期间暂停 develop 合并。前次生产接续的 Vercel 专项验收安排只适用于[那次发布](progress/2026-10-23-production-repository-rebind.md)。

## 工作流与保护

| 项目 | 配置 |
| --- | --- |
| 触发 | 应用检查仍为 main／develop 目标 PR 与手动；独立隐私扫描另覆盖分支 push，无 schedule |
| 环境 | 标准 GitHub 托管 `ubuntu-latest`、Node 24 |
| 检查 | 应用先可信历史扫描，再两份锁文件安装、完整 `npm run check` 和 `npm run build`，45 分钟上限；独立隐私只用 Git／Node，不安装依赖 |
| 输入与权限 | 离线 fixtures、隔离 PGlite 和本地媒体，Token 只读，checkout 不保留凭据 |
| main | PR 保护、管理员受约束、解决讨论、禁止强推／删除，完整检查通过且分支为最新 |
| develop | 同样 PR 保护，保留本机验证后合并规则，不强制等待平台 |
| 外部 PR | 所有外部贡献者工作流需维护者审批；不配置真实来源或部署凭据 |

N03／N07 增加独立 `Repository privacy`，不设置共享 concurrency；原 `Repository checks` 保留应用取消机制与 `Check and build (Node 24)` 名称。分支 push 不产生同名构建跳过实例，不新增 required check 或仓库设置。可信来源、固定事件 OID、旧规则自举与手动输入见[源码扫描说明](PRIVACY_SCANNING.md)。本机 YAML／引导验证不是实际 Actions 证明；新手动工作流与默认分支表单的采用仍按独立发布顺序，不为此自动合 main 或派发检查。

托管工具缓存中的 Node 可能允许组／其他用户写入，冻结发布校验会拒绝这种运行时。CI 复制同一 Node 字节到临时专用目录，验证复制一致并设置非组／其他用户可写权限，后续 npm 和子进程使用该副本；生产权限校验保持。

既有主线工作流按公开状态选择 Ubuntu，本项候选进一步固定 `runs-on: ubuntu-latest` 并移除私人自托管路径。候选尚待集成不影响当前公开路由生效。平台验收须核对仓库、SHA、运行器及全部步骤，不能把跳过、排队或本机通过视为 Actions 已通过；Linux 专属跳过如实记录，Mac 专用断言由本机覆盖。

## 复用既有运行器（历史接线背景）

以下保留退役前的接线边界，不是当前可执行的复用步骤。新的私人运行环境须另行审查和配置。

既有运行器是仓库级注册，只能接收其绑定仓库的任务。新仓库即使最终与旧库同名，仓库 ID 也不同，修改 YAML 标签不会自动搬迁注册。

接线前保存当前注册及受管服务配置，核对运行器 idle 并防止新旧任务同时争用。注册、移除与服务配置通过官方短期注册方式和既有运维管理入口处理；不提取 Git 凭据，不改磁盘权限、系统隐私权限、账户权限或守卫。单个运行器只承接一个任务，失败保留记录。源码、旧工作区和业务同步不随 CI 重新绑定移动或恢复。

旧库的两小时调度、树缓存和历史通过回执不复制到新库。`scripts/ci/check-plan.ts` 保留原实现和测试，新工作流暂不使用其历史缓存，首次实际验收执行完整检查与构建。CI 接线候选与实际注册／成功验收分别记录。

## 公开交接与历史清理

本次退役已停止服务并移除原生自托管注册；本次公开前已复核无在途原生任务和无残留注册。只改 `runs-on` 或依赖 PR 条件不能阻止他人提交修改工作流。保留旧私人运行根及可恢复的受管配置。需要继续私人 CI 时，在保持私人的仓库单独管理，不将外部 PR 分派到个人机器。

本次已配置主分支保护并验收标准托管路径，私人阶段 CI 日志及平台材料已复查。工作流通过不自动授权公开仓库、部署或恢复业务同步；正式发布仍按 [AGENTS.md](../AGENTS.md) 执行。

本轮已按具体授权删除该次自托管验收的云端日志和单个可重建 npm 缓存；删除后日志不可读取，仓库 Actions 缓存与产物均为零。验收成功状态、步骤结果和受检提交元数据仍保留，原始日志与复核材料仅存私人目录。这项历史清理没有删除成功验收元数据或旧归档历史；本次实际公开结果单独记录。

GitHub 当前将自托管运行器和公开仓库标准托管运行器列为免费使用；私人仓库的托管分钟额度与之不同。官方说明：[计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)、[仓库级运行器范围](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners)、[原生运行器安全边界](https://docs.github.com/en/actions/reference/security/secure-use)。
