## 第一项：一次目录元数据核查

私人材料中已固定原完整单条 SELECT 草稿及 SHA，拟读取以下白名单，不调用应用函数。该完整草稿没有执行；实际两次目录 SELECT 均使用更窄的受限身份版本，不读取下表的迁移登记行：

| 范围 | 返回内容 | 边界 |
| --- | --- | --- |
| 会话 | 数据库名、session/current user、服务端版本、只读状态 | 会话身份不自动等于待安装者或实际 reader |
| 七个相关 schema | owner 与 ACL | 不读取其他业务 schema |
| 相关函数 | 签名、owner、ACL、definer、volatility、search_path、定义 SHA256 | 最多 128 项；不导出函数正文或任意配置值 |
| 关联角色与成员关系 | 从应用角色、函数／schema owner 和会话身份开始的关联分量；继承、SET ROLE 与管理选项 | 最多 128 角色、256 条边；不读密码目录 |
| 相关默认权限 | 角色的全局与七个 schema 默认 ACL | 最多 128 项 |
| 读取扩展登记 | nb_read.migrations 的版本 1 至 5 和摘要 | 不读取发布批次、来源、正文、媒体、租约或其他状态行 |

拟议上限为一次 SELECT、一个受计量的数据库连接、64 KiB 结果 JSON、256 KiB 数据库接收字节、10 秒语句／60 秒全程、首错停止、零重试。数量或输出超限返回不完整状态，不能把截断当通过。连接与传输限制必须在实际执行通道中强制；不能把一个 MCP 调用或一次池借还声称为一个物理连接。该草稿未绑定真实目标、身份、截止或执行入口。

执行前先由原运行负责人核实目标项目及实际连接身份。版本一至三对照锁定协议；版本五或三个同签名函数存在时先辨认归属，不覆盖、不重跑。目录定义 SHA256 用于目录前后比较，不替代迁移文件字节 SHA。本次查询也不提供完整表结构或业务数据前像，不足以单独批准安装、证明 owner 底层权限或验收实际 reader。

## 首次核查的实际限制与后续修正

用户已确认并用完一次目录读取许可。原完整草稿没有执行：现有受限身份的已审协议不开放登记表，实际较窄查询只返回可见目录与权限布尔，登记表保持未读，不额外探测真实授权。一次 SELECT 返回后未通过事务只读状态守卫，连接关闭且零重试；未验收或留存目录结果，不能以本次尝试认定安装前置已通过。见[执行记录](progress/2026-10-23-search-catalog-preflight-read.md)。

启动参数不能代替实际事务状态验证。后续方案明确计入五条客户端 SQL 提交：BEGIN READ ONLY、SET LOCAL statement_timeout='10s'、SET LOCAL lock_timeout='1s'、一条目录 SELECT、ROLLBACK。查询验证会话只读与两个限时值；SET LOCAL 仅限当前事务，语义见 [PostgreSQL 17 事务说明](https://www.postgresql.org/docs/17/sql-start-transaction.html)与[参数说明](https://www.postgresql.org/docs/17/sql-set.html)。仍只使用原受限身份，登记行不读，不改长期配置。

新方案限定一次客户端连接、64 KiB 结果／256 KiB TCP 接收、十秒语句／六十秒全程、零重试；客户端连接计量不推断连接池内部后端数。失败停止后续 SQL，关闭连接回滚，不追加未列明探针或清理语句。原四组事务测试与新增六组通道测试均通过，包含受限 PGlite 角色、首错不续发和回滚后超限仍丢弃结果；这十组本机验证不代替实际环境结果。

用户随后针对上述五提交范围明确继续，新的单次窗口已实际成功：五次客户端 SQL 提交、一次目录 SELECT、一个客户端到既有数据库入口的连接；TCP 接收 32,193 字节、序列化结果 25,643 字节、2,415 毫秒。返回的事务只读状态为 on，statement_timeout 为 10s、lock_timeout 为 1s；ROLLBACK 成功，客户端与转发器均关闭。元数据结果仅保存在私人材料，许可消费完毕、零重试。旧失败及其未接受结果状态保留，不追溯判定旧启动参数的确切失效原因。

该次可见目录未见候选的三个新函数，但当时迁移登记表未读取，不能据此断言版本五未占用、基础摘要匹配或实际安装者具备底层权限。会话身份、目录函数定义 SHA 与迁移文件字节 SHA 也不能互相替代。该窗口原记录保持，见[决定](decisions/2026-10-23-search-catalog-readonly-transaction.md)和[执行记录](progress/2026-10-23-search-catalog-readonly-transaction.md)。

## 独立完成：原连接器身份与登记核查

实际仅提交一次连接器调用和一条固定 SELECT；返回一个完整结果，四条登记、两项 owner，紧凑 JSON 为 693 字节。会话身份与 owner 符合预期，基础版本 1–3 的登记摘要与锁定迁移字节 SHA 一致，版本五在此快照不存在。原始结果和逐项比对仅在私人材料保存。连接器会话报告只读状态为 off；本次批准和验收依据固定无写入 SQL，不能声称经过 BEGIN READ ONLY，或获得之前的十秒语句／六十秒全程保证。连接器内部连接、重试和传输量未知。

## 第三项：S13 对照的明确草案

两个实例使用同一受检源码／构建、区域、运行参数、栏目和已发布批次，仅搜索模式分别为 on-demand 与 filtered-scope。现有模式在 repository 构造时确定，不能在同一缓存实例中切环境变量模拟两种模式；公共 API 不接受模式参数。本轮不创建实例或部署。

原三个词字面值继续只存私人清单；每词每模式三次，共 18 次首屏 GET。按三轮、每轮原词顺序：第一轮基线／候选，第二轮候选／基线，第三轮基线／候选。并发为一，前次完成后至少一秒间隔；不夹带预热、重试、重定向、HTML、浏览器、第三模式或游标翻页。保留原首屏参数；不为凑齐结果提高 page size。

拟议限额如下，尚未授予或分配：

| 项目 | 上限／条件 |
| --- | --- |
| 首屏样本 | 18 API GET；每次最长 30 秒，整窗最长 600 秒 |
| 客户端 HTTP 连接／接收字节 | 最多 18 次／16 MiB 总计、每响应 1 MiB |
| 数据库新连接／接收字节 | 最多 36 次／256 MiB 总计；必须按实际驱动传输计量 |
| 同时请求 | 1；两个实例各自冷暖、重启及池状态单独记录 |
| 额外身份／批次／权限与前后置探针 | 不包含在 18 次内，当前为零；须先明确 SQL、次数与字节 |
| 首错停止 | 非 200、版本／身份漂移、语义差异、超限、超时、账目或关联丢失即结束，不补样本 |

18 个样本比较首屏 DTO、total、完整首屏顺序、hasMore、nextCursor 及版本／结果指纹。若 hasMore 为真，只能报告首屏和游标承诺的一致，不能声称真实环境全页遍历通过；完整分页与真实撤回验收须另列次数和有限数据操作范围，不能偷偷追加 GET 或修改业务内容。

现有 CONTENT_READ_TIMING 没有单次 HTTP 关联键，池 checkouts 也不是新连接数。客户端必须保存逐次 DNS／TCP／TLS／TTFB／总时间、HTTP 状态与响应字节；服务端阶段、实例、连接与字节须有同一次请求的可靠对应方法。共享托管日志不能仅按时间接近配对，也不能用平台响应标识冒充应用日志里已有同一键。源码未新增关联字段；固定托管身份、关联方法和强制计量前，这份草案不可执行。

性能目标仍为各词中位数不退、九次总体中位数至少降低 20%，完整单次与最坏值都保留。小样本不作 p95 或稳定性承诺；没有对应阶段证据时只报告 API 结果，不推算 SQL 占比。原六个诊断窗口全部关闭、余量为零，不借用其他任务的许可或预算。
