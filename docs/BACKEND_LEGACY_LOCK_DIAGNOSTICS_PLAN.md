# B06 遗留锁诊断与完整基线取消方案

状态：基于 develop `12a2a9ee6288a7e24039c66d205a5e76c5cd06e0` 的源码复核；用户于 2026-10-25 明确批准“同意源码与离线验证”，包含新增只读诊断入口及常规 develop 交付，见[决定](decisions/2026-10-25-legacy-lock-diagnostics.md)。本项仅交付源码、离线验证和人工处理规程。

## 已核实的问题与最小修复

- 完整基线 CLI 仍使用一次性信号监听。外层 HTTP 预算取消会同步重发 SIGTERM，消耗内层监听；资源清理期间的后续信号可能直接终止进程。改为持续监听，在原 finally 完成后移除，不改变命令、退出码、预算或锁协议。
- 共享 worker 锁读取直接 JSON.parse；空文件、损坏 JSON 或非法 owner 会抛出原始解析错误。改用既有固定 MISCONFIGURED 错误并保留文件，避免原文进入错误。合法旧 `{pid}` 锁仍兼容，PID 存在或身份无法确定时仍不删除。
- manual-run.lock 至少存在 v1 `{pid,startedAt}`、v2 `{pid,runId,adapter}` 等格式，其他受控任务也可占用相同文件名。当前没有统一恢复凭据，不能凭文件名、年龄或 PID 猜测可删除性。

## 新增一个显式、只读的本机诊断入口

拟新增 `scripts/notion-sync/lock-diagnostics.ts`，仅接受 `--directory ABSOLUTE_PATH` 或 `--help`，不接入 package scripts、同步入口、调度、health 或自动重试。

只查看操作者明确指定目录中的固定 `worker.lock` 与 `manual-run.lock`；不递归、不搜索其他目录、不读取环境文件、不创建缺失目录或报告文件。读取前核验目录／文件所有者、私有权限与符号链接，目录必须是无符号链接的规范路径。使用 O_NOFOLLOW／O_NONBLOCK，打开后再次确认普通文件，避免被替换成 FIFO 后挂起；实际最多读取 8 KiB 加一个超限探测字节，不先无界 readFile 再判长。复核前后目录／文件身份及元数据；变化或无法证明安全时固定报告，不继续推断。

输出采用固定版本的匿名 JSON，仅含锁名、文件／格式状态、PID 存在性和人工审阅标记；不输出路径、PID、runId、正文、原异常或私有字段。区分缺失、空、损坏 JSON、非法 owner、已知旧格式、未知格式、不安全、读取期间变化和无法读取。已知格式也不视为当前业务 owner 已证实；未知格式不猜测解析。

仅对已识别且合法的 PID 使用 `kill(pid, 0)` 查询存在性，不发送终止信号。存在只能说明该 PID 当前存在，无法证明它是原进程；ESRCH 也不能证明子进程、数据库租约、提交或预算已收尾。权限拒绝或其他不确定结果保持 unknown。任何锁存在或状态不确定均要求人工审阅，没有可自动恢复／删除的结果。

命令没有解锁、抢锁、force、改权限、清理、恢复任务、探测数据库或刷新业务状态的能力。它是一个有竞态边界的文件快照：同 UID 写入者的 ABA 替换、最后检查后的变化仍无法排除，不是操作系统级身份凭据或原子业务状态证明。

## 人工处理规程

先由原运行拥有方核对任务来源、运行包、调度、子进程、数据库租约／未知提交及原授权账本，再决定是否需要一份具体处置方案。空／坏／未知锁和 PID 复用均保留；诊断输出不构成删除许可。现有 unlock-stale 仍仅处理原 worker 锁，并保留原显式调用边界；本项不为 manual-run.lock 增加删除工具。

真实遗留锁检查或处置须独立授权；本轮不读取、清理或恢复实际运行目录，也不复用其他工作线已关闭的窗口。

## 验收与交付

开发期只做必要定向验证，源码稳定并独立审阅后集中一次完整 `npm run check` 与离线 `npm run build`；之后仅对真实新改动、失败或集成疑点补验。

- 使用本项临时目录验证缺失目录不创建、空／坏 JSON 与非法 owner 保留、旧格式兼容、存活 PID 保守拒绝、权限／符号链接／超限与替换／改写拒绝、匿名输出及目录内容不变。
- 使用本项创建的虚构子进程验证 PID 存在／退出及未知身份，不扫描系统或真实任务进程。
- 子进程运行真实完整基线 CLI 的监听与 finally，测试边界替代远端 host；在异步清理期间重复 SIGTERM／SIGINT，确认清理、锁释放、取消退出码和监听移除。该测试不宣称验证了实际数据库取消。
- 核对历史 capture 的拒绝守卫与冻结输入，不因源码变化放宽运行包字节许可。
- 提交前做隐私、暂存、记录和链接核验；英文 PR、base develop，核对发布暂停、目标更新及实际合入差异。正常 PR／push 自动 CI 包含，不手动派发，不将跳过或本机通过写成平台通过。

不包含依赖安装、真实 Notion／Supabase／Storage／网站请求、凭据／云配置、实际运行包采用、业务暂停／恢复、main 合并或部署。
