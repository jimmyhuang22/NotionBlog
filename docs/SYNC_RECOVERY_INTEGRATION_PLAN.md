# 映射恢复与课程重投影的后续整合方案

本文件保留旧私人仓库 #435／#466 的原共享范围方案。用户确认后，源码已在 PR22 准备并组合诊断与收尾候选；当前实现与默认拒绝边界见[能力说明](SYNC_RECOVERY_CAPABILITIES.md)。本方案不是安装步骤或旧运行窗口的续期；所有历史兼容表和旧版本校验器保持。

## 拟实现的最小范围

| 部分 | 拟保留的行为 | 拒绝与边界 |
| --- | --- | --- |
| 配置转换 | 仅允许已启用课程来源删除 recommendation／difficulty 及其既有别名映射；绑定前后源文件摘要和规范配置摘要 | 不接受来源、公开名单、时区、其他字段映射或任意配置覆盖；至少实际删除一项 |
| owner 策略操作 | 独立显式事务锁定当前状态，核对旧摘要、预期 revision／epoch／当前批次、无在途 lease，核对来源和 permits 未变；只更新配置摘要并推进 revision | 不自动调用原 configure_policy，不重建来源；保持 epoch、当前成功指针和历史 run 行，不向普通 writer／reader 授予此操作 |
| 新 lease 核验 | 独立 SQL 能力核对新 lease、旧批次真实状态／fence／revision／配置及新批次尚未暂存；返回服务器时间与新 lease 截止 | 仅既有受限 writer 可执行，撤销 PUBLIC／reader；不修改任一历史期限、不把旧批次直接标成完整 |
| 重新采集 | 从候选复用集合排除课程 DTO，课程按当前转换器重采；其他页面仍逐项验证完整来源证明、父链和媒体 | 课程重投影能力只能由精确版本核验结果开启，不新增用户可随意传入的跳过校验开关；强制 fresh qualification |
| 主机接线 | 显式绑定旧来源文件、生产者／消费者程序、源摘要、完整工件、剩余预算及回退输入 | 新格式或能力未被明确识别时拒绝；不读取任意旧捕获，不把目录或图片缓存当作正文公开资格 |

## 兼容协议与测试资料

历史 JSON、历史生产者和既有允许字节保持不变。新转换使用独立能力和追加的精确 before／after 表；接受条件由固定生产者、全部实际变化文件与 Node 身份共同约束，不使用通用“忽略版本”开关，也不以“只有诊断改动”推导工件永久兼容。

新运行程序的全部变化必须重新列入新表，包括诊断／收尾和此后实际进入 develop 的相关 mapper、正文转换、依赖及运行边界。不能把旧分支的整份 after 清单原样当作新库允许值。当前正在使用的运行输入与最新完整成功工件需由原拥有方按同一时点交回，才能固定真实迁移目标；源码阶段不选择或操作在途批次。

新库的主机回归继续从固定公开源码资料建立测试程序，不导入旧 Git 对象。既有历史输入仍应获得原结果；把新字节塞入旧转换必须拒绝。追加转换要覆盖完整成功路径和逐文件篡改、丢文件、组合两项旧转换、错误来源／Node／生产者及同版本伪造等失败路径。

## 验收与交付顺序

1. 审阅上述新增数据库能力、配置／主机参数和独立兼容格式后，在最新 develop 的另一短期分支实现核心、默认拒绝的接线与离线回归。SQL 只作为独立增量源码交付，不执行数据库安装。
2. 离线验证仅删除映射、策略回滚、旧成功内容保持可读、错误身份／权限／在途 lease 拒绝、课程强制重采、其他内容变化及撤回／移动／坏图阻断；保留当前发布前有界修复、预算和旧捕获字节。
3. 对最终实现执行完整 check／build、协议与隐私核对；平台结果单独记录。贡献实际进入新 develop 后，再核对哪些旧请求已被完整替代。
4. 主机安装、真实来源／媒体、数据库能力安装、固定转换启用、调度及正式发布均按具体后续窗口分别验收。源码审阅不授予运行授权，也不要求其他任务中断正在进行的自然同步。

清理实现已有独立编辑登记，本项不重建或覆盖该候选。映射与课程转换也不携带 retention 安装、目录摘要重绑或真实删除。
