# 搜索结果的课程与父级上下文方案

本项接续 UI/UX 审查 U04，保留初次评审的两个方案供追溯。用户随后选定“来源行”，并批准最小共享字段；实施见[决定](../decisions/2026-10-23-search-result-context.md)、[实现边界](../SEARCH_RESULT_CONTEXT.md)及[实施进度](../progress/2026-10-23-search-context-implementation.md)。原位恢复 PR #19、关键词切换保护 PR #12 仍未合并，本项普通整合其受检实现并保留两项修复，不代为合并这些请求。

## 初次评审证据（实施前）

- [搜索 DTO](../../contracts/website.ts)的 `SearchHit` 只有类型、标题、地址、摘要与更新时间，两个搜索入口均无法直接判断同名笔记的课程及父级。
- [完整内容 DTO](../../contracts/content.ts)的笔记有 `courseId`、`parentId`、`breadcrumbs`，课程有 `code`。这不表示这些字段已经存在于搜索结果，也不表示可从浏览器额外读取私人来源补齐。
- [共享搜索投影](../../src/lib/content/website.ts)只生成既有字段；当前 scoped 的[文字搜索迁移](../../supabase/migrations/20261017131837_scoped_search_parts.sql)进一步只返回基础元数据与文字片段，没有课程／面包屑字段。filtered 与 precomputed 也必须纳入兼容核对，不能只在 mock 或完整快照下接通。
- [数据库投影](../../src/server/database/website-repository.ts)按当前资格清理引用。已存面包屑不是永久公开证明；上下文不能绕过课程归属、祖先撤回、来源或栏目限制。

## 两种展示

两种方案使用相同信息、结果次序和阅读目标。原型只用虚构数据，展示快捷搜索与完整搜索页，以及跨课程同名、同课不同父级、长路径、缺失值和其他栏目。

| 方案 | 结构与取舍 |
| --- | --- |
| 来源行（推荐） | 标题下显示“课程 › 父级 › 父级”，摘要随后。层级连续，视觉较轻，适合现有搜索的条目结构。 |
| 课程标签 | 类型旁加课程标签，标题后单独显示父级路径。课程较醒目，但重复同课结果时标签更多、条目略高。 |

课程优先显示实际课程编号，缺编号时显示实际课程名；不补造缩写。路径不重复当前标题或“学习”总入口，按课程到直属父级的顺序显示。直属笔记仅显示课程，不留悬空分隔符；缺失上下文及非学习内容沿用现有行。长标签自然换行，不将判断所需的信息仅藏在 hover 或标题提示中。

整个结果仍是原来的一个阅读入口，上下文为纯文字，不新增父级跳转、筛选或分组，不改搜索匹配／排序。可访问名称需要包含用于区分的课程及父级，避免同名链接只靠视觉才可判断。正式组件继续保留换词保护、输入法、键盘选择、取消与已确认的恢复操作。

## 已批准的最小共享范围

用户已批准向 `SearchHit` 添加可选、可空的显示字段：

```ts
context?: {
  courseLabel: string;
  parentLabels: string[]; // 从课程之后到直属父级，不含当前结果。
} | null;
```

这里只传当前可公开的显示文字，不暴露来源 ID、物理父链 ID、私人配置或新的 URL。旧响应缺字段时继续显示现有结果；没有可证明的课程身份时为 null，不能从 slug、摘要或地址推断。实施上限为 32 层父级、每标签 256 字符、总计 4,096 字符，未知或超限省略整条上下文，不静默丢弃层级；元数据页另有条数和字节上限。

本次授权的范围限于该 DTO 的兼容扩展、统一服务／provider 的对应投影、两个搜索组件及其局部样式、虚构回归样本和必要离线测试。不会因本方案自动启用栏目、其他来源、可选搜索优化或更大的公开范围。

## 实施与验收边界

1. 先冻结用户选定的展示和共享范围。实施时重新核对最新 develop、PR #12／#19 状态及其他搜索 owner 的编辑登记，不提前重做后端优化或覆盖旧修复。
2. 上下文只能来自同一受检内容版本和当前资格的元数据。复用完整笔记中已经清理的路径需要验证其祖先对应；精简读取需要独立补足，不能在浏览器逐篇请求正文。优先对实际返回的一页做有界批量投影，不能为六条／十二条结果逐条读整门课程。
3. 如果精简数据库路径确需新增 reader 能力，用独立扩展／新迁移，保留既有冻结 SQL、摘要、旧运行包和默认开关。不预先声称“不需要迁移”或“零新增 SQL”；精确实现及成本须另行验证。真实安装、填充、开关启用和正式部署不包含在这次方案确认中。
4. 未启用的新能力允许旧响应保持缺字段；一旦显式配置启用，其读取、权限或版本失败必须保留真实失败，不能用“缺上下文”掩盖。合法未知与服务失败分别处理。mock、Notion、legacy／scoped、on-demand／filtered／precomputed 的对应支持范围须明确，不以其中一条通过代替全部。
5. 保留关键词、种类、匹配、排序和总数，独立验证首屏／分页及投影版本与当前资格绑定。课程改名、父级移动、祖先／课程撤回、混合版本、缺课程、缺编号、深链／长标签和禁用栏目都要覆盖；资格变化时旧上下文不得留在新返回中。不能承诺新增投影后旧游标逐字节不变。
6. 应用实现按项目要求集中运行完整检查、构建和两个入口的浏览器验证；初次原型没有执行 provider 搜索或工程全套。后续实施的离线验证另列在实施进度，不能据此声称真实 provider、正式性能、真机或完整读屏体验通过。

初次评审未改契约和应用；用户后续批准来源行及上述最小共享范围，现按该决定实现。真实安装和开关启用仍待单独授权，没有向 develop／main 合并、部署或调整业务任务。
