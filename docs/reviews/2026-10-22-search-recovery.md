# 搜索恢复操作评审

本项接续 UI/UX 审查中的搜索失败和空结果恢复问题，仅审查并提供原型，不修改应用。关键词切换保护已经由独立 PR #12 提交，实施本方案前需重新核对其实际集成状态，保留该保护及其他会话的搜索读取工作。

## 当前实现

- [搜索页](../../src/app/search/page.tsx)能保留已提交的关键词及栏目，原表单仍可再次提交；首次读取失败或繁忙时只给文字提示，没有提示旁的恢复操作。
- [快捷搜索](../../src/components/search-palette.tsx)失败或繁忙后没有原词重试入口；修改关键词会重新请求，但不应要求用户为重试而改词。
- [搜索结果](../../src/components/search-results.tsx)在空结果时统一建议选“全部”，即使当前已经没有栏目筛选。后续分页已有独立恢复能力，本项不重建它。
- [搜索契约](../../contracts/website.ts)的 `SearchHit` 只有类型、标题、地址、摘要及更新时间，没有课程代码或父级路径。因此同名结果的课程上下文仍是独立契约需求，不能从不透明地址猜课程或在浏览器读取私人来源补齐。

## 两种候选

“原位操作”在现有提示行旁增加短操作，窄屏自然换行；“集中提示”把提示和按钮放到独立的居中区域。两者仅比较布局和视觉重量，恢复规则相同。推荐原位操作，延续现有搜索较轻的反馈层级；这只是建议，不是用户已经选定的设计。

| 状态 | 提供的操作 | 保留内容 |
| --- | --- | --- |
| 首次搜索失败 | 重新搜索 | 当前关键词与栏目 |
| 服务繁忙 | 由用户稍后重新搜索 | 当前关键词与栏目，不编造冷却倒计时 |
| 正在重试 | 等待状态，阻止重复提交 | 关键词与栏目 |
| 已选栏目但无匹配 | 搜索全部栏目 | 关键词，仅移除栏目筛选 |
| 已经搜索全部栏目仍无匹配 | 修改关键词 | 聚焦当前输入框，不为聚焦发请求 |

每次明确点击最多发起一次请求，不自动循环重试或绕过后端冷却／公开资格检查。换词、关闭及取消后不能由旧请求重新填回结果；保留已有输入法与键盘保护。快捷搜索和完整搜索页共用相同语义，但不为了共享外观而增加全局状态或新组件库。

## 实施边界

本轮不修改 DTO、provider、搜索协议、排序、来源、数据库、fixtures、依赖或栏目。课程上下文另行形成共享契约方案并取得批准，不作为恢复操作的前置条件。

视觉方案须先由用户选择；确认后从当时最新 develop 接入对应组件、搜索页首次失败与空结果操作，再按应用影响集中运行完整检查、构建及针对性浏览器验证。原型只用虚构演示内容和本地状态；主题色和可用字体供比较布局，不复刻完整主题装饰，不证明真实接口可用性、平台通过、生产性能或真机体验。

本次原型及私人验证记录保留本机与本对话，未写入公共 fixtures。没有合并、发布、恢复来源或安装任何运行包。
