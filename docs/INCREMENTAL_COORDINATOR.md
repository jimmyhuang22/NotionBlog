# 增量同步协调层

`scripts/website-incremental-sync/coordinator.ts` 提供 `createIncrementalCoordinator`，把普通页准备、学习领域、公共队列的持久终态和数据库提交组合为 `runIncrementalCycle` 所需的七个端口。它只接收显式适配器，不读取环境变量、创建连接、采集来源、设置计时任务或启用新模式。

全站发布版本会在动态和其他普通内容更新时变化。普通变化也必须先用学习检查点的 `stageOtherPublication` 保存待提交状态，独立 reader 验证本次提交后，由学习领域的 `finalize` 安装新的检查点，再由执行器确认队列。学习事件交给学习领域自己的 `prepare`，协调层不覆盖其已准备的目录。内容、发布范围、媒体描述和全站版本沿用既有协议。

## 显式接线

- `publication`：数据库发布端口的 `state / submit / lookup`；连接通过独立受限 reader、writer 的绑定预检。`study.verify` 必须使用同一独立 reader，不直接把写入回执当成证明。
- `regular`：普通单页准备端口；`study`：学习领域 `prepare / verify / finalize / retire`；`checkpoint`：同一个私有学习检查点实例。
- `queue`：本轮实际队列的 `assertPreparing / attemptClosure`，通过闭包保持方法的实例上下文。
- `sourceKeys / studySourceKeys / scopeDigest`：与实际配置和队列一致。此协调器针对已启用学习区的混合网站；不接受空学习来源，也不为无学习栏目创建假基线。

返回值可直接传给公共执行器；其结构类型不导入尚由其他分支维护的队列或学习模块，也不复制它们的存储。来源发现、单页读取、媒体准备和完整学习基线仍由各自提供者完成。

## 中断与拒绝

准备返回后再次检查队列租约和事件 generation。只有完整、摘要匹配且来自已配置来源的差量才能保存检查点和进入提交。所有提交与恢复必须匹配检查点内的操作 ID 和 payload 摘要。

丢失 SQL 回复、独立验证失败或本机安装后丢失确认时，执行器保留未知提交。重启后只查询原操作、取得独立证明、幂等安装本机状态；不重新采集和发送。缺失回执或后来出现另一个发布版本时，不能据此清理或重发。

明确 SQL 拒绝、准备阶段取消的清理，需要队列已经持久保存的完整终态。协调层重新查询 `attemptClosure` 并核对操作、来源、页面、generation、原因、摘要和处置；证据匹配才调用学习领域退役，之后执行器确认退役。超时、租约到期和调用方提供的布尔值不替代持久证明。

## 验证边界

提交的十一项端口测试覆盖普通／学习路由、提交顺序、失败证明、只查回执恢复、未保存操作、范围与版本变化、准备时取消或 generation 变化、正文被改写、未知来源和终态伪造。
