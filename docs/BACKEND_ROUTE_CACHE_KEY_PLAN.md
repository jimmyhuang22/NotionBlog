## 已复现的问题

当前 `canonicalRouteTarget` 只清查询噪声，保留编码、重复分隔符和尾斜线；`qualifyRoute` 却逐段解码并忽略空段。路由判定相同，持久键仍可不同。外层 route-verdict 会保存 missing，内部 `publicRepository` 的元数据 null 和笔记资格 false 也会保存；只修外层仍会留下增长点。

使用当前真实规范化、资格判定及 `readPublicProjection` 函数，配合虚构仓库和只存成功 Promise 的内存缓存端口，得到：

| 输入 | 当前结果 | 内存端口保存的项 |
| --- | --- | --- |
| 同一课程的 64 种百分号编码 | 全部 found，64 个不同 target | 64 个外层键＋1 个元数据键 |
| 32 个不存在的课程 | 全部 missing | 32 个外层键＋32 个 null 元数据键 |
| 32 个不存在的合法 Status focus | 全部 missing | 32 个外层键＋32 个 null 元数据键 |
| 32 个不存在的课程笔记 | 全部 missing | 32 个外层键＋32 个 false 资格键 |
| 正确旧签名的 `/study/../../not-a-route` | URL 归一化后落到未受管路径，当前仍 found | 1 个外层键 |
| provider 抛错 | unknown，不能当作 missing | 0 项 |

这些是本机真实函数与虚构端口的结果，不是线上 Next／Vercel 缓存实测，没有项目请求。旧签名样本只在本机 Request／Response 调用，没有 HTTP 出站。

## 已批准的完整范围

1. **统一目标解析。** 在共享纯函数中对每段只解码一次、检查解码结果、再稳定编码；按当前资格语义合并重复／尾斜线。保留 Unicode、大小写、合法标点和双重编码的区别，禁止把 `%252F` 继续解成分隔符。不跳转、不改访客地址栏。
2. **明确受管路由形状。** 覆盖 about、blog／photos／projects、library 固定类别、study 课程／笔记／学习项目和 Status。URL 归一化后再次核对范围；非法编码、解码后的斜线／反斜线／控制字符、无效形状和无效 focus 明确 missing，零 provider／零持久写入。只在缓存资格入口使用，不把全局 `qualifyRoute` 的未受管地址默认行为改成 false。
3. **两端共用、保持验签顺序。** 新调用方先规范化再签名；内部入口先验证原始 target 的现有 HMAC，再按同一解析规则分类。合法旧签名不能绕过规范化；身份、部署、时间窗、长度、固定 origin 和响应大小限制保持。非授权请求仍 401；无法确认的读取失败仍 unknown／503，不改成 404。
4. **阻止两层负缓存。** 公共投影增加可选的结果准入，仅对路由 found、内容元数据非 null／undefined、原子笔记资格 true 允许持久写入。missing／null／false 采用与现有超大结果跳过存储相同的受控返回机制；先完成原 generation／日期守卫，再在持久写入前跳过存储。其他操作的结果缓存不扩大修改。
5. **隔离旧策略。** 只给上述受影响操作加入固定策略标记，避免新代码继续读取旧策略的负缓存；全站缓存版本、一天边界、namespace、发布 generation、标签与清理协议保持。既有负项不自动物理删除，不触发真实 purge。

主要源码范围：`src/server/public-cache/route-lookup.ts`、`read.ts`、`runtime.ts`、`src/app/api/internal/cache/route/route.ts`；必要时 middleware 只接入目标分类。前端 DTO、provider 权限、数据库协议／SQL、依赖、栏目开关和真实配置不改。

## 定向验收与收尾

开发期间只运行与本项直接相关的规则／投影／签名回归，复用既有测试组织并使用虚构内容：

- 同一语义的编码、重复／尾斜线统一为一个外层键；不同课程、note／focus、大小写和双重编码保留区别，规范化幂等。
- 覆盖受管路由表、URL dot 路径、坏百分号／UTF-8／分隔符；无效 focus（重复、空、超长、非法字符）零 provider、零写入。
- 多个不存在的课程、focus、笔记，外层及嵌套投影均零新增持久键；已有真实 found 继续命中，策略标记隔离旧项。
- 新旧签名调用、错误签名／部署／时间窗及固定目的地保护保持；provider 错误继续 503。
- 既有 feature 开关、课程归属、祖先资格和撤回不放宽；generation／日期变化、取消及读取预算先于返回生效。
- 采用项目锁定的 Next 实现做一个隔离缓存端口验证，确认受控异常在写入前退出；不迁移到 use cache，不新增依赖。

本机锁定 Next 指南已读取：`unstable_cache` 已建议迁移，但本项保持既有 API，避免混入框架迁移；已核对安装实现只在 loader 成功后写结果。此静态依据不代替实施后的定向验收。

整组源码稳定后，集中运行一次 `npm run check` 和离线 `npm run build`；此后仅因新改动、实际失败或集成疑点补验受影响范围。使用既有 Node 24、依赖、字体和外部出站守卫，无安装／下载；不为每个小改重复全仓库检查。合并前按常规核对发布暂停、受检提交与实际差异，向 develop 开 PR，普通合并并删除短支。正常 PR／push 自动 CI 的结果与本机分开，不手动派发。

## 代价与授权边界

不保存缺失资格，会增加重复访问不存在 ID 时的读取次数；原期限、取消和 SQL 预算保持。此项降低可由任意缺失 ID 制造的持久缓存项数量，不承诺限制全部请求／计算成本，不顺带实现全局限流。成功项随实际获准内容、现有 generation 和日期窗口增长，不是全站缓存容量的硬上限。
