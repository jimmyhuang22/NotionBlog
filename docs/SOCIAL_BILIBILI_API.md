# B 站 JSON 来源候选

这是默认关闭的离线候选。测试数据是虚构的结构样本，**没有证明当前真实接口可用**。接口或账号受限时停止，不自动登录、处理验证码或改请求其他接口。

## 来源与校验

单视频 `public-video-api-json` 与原 `public-video-page-ssr` 并存；合集 `bilibili-collection-api-json` 与原 `bilibili-collection-ssr` 并存。原记录版本和前端 DTO 保留。解析原始 JSON，摘要使用响应原文，不构造假的 SSR 脚本。

候选传输仅对既有目标的 BV 构造固定主机请求，一次 GET，严格 TLS、无 Cookie、无跳转或回退。HTTP 状态、JSON 成功状态、BV、作者、公开与付费限制必须通过；完成读取的时间是采样时间，不承诺上游缓存即时更新。单条响应上限 8 MiB，仍受整个批次和周期的共享字节预算约束。

合集共用现有完整成员／分 P／日期验证；缺字段、作者混入、成员不完整或总计身份不符都失败。分类、封面旁记录和播放关联直接消费同一次真实 JSON，不额外请求页面来补齐未知值，不用代表视频的数字替代合集总计。

`20261024070000_social_bilibili_api_source.sql` 为单视频和合集私有 meta 增加可选的 `bilibili_api_version=1`。迁移在事务内核对两个原校验函数的精确前像，仅扩展来源值，保留函数 OID、ACL、角色、RLS 与读取投影。新客户端在任何来源 GET 前核对两项能力和当前凭据／范围；旧握手忽略新增能力列。能力列表示协议兼容，不授予发布资格。

## 状态隔离

配置示例见 [bilibili-api.example.json](../config/bilibili-api.example.json)。示例的摘要和路径都是占位值，不能直接作为实际配置。

启用前需准备两份独立私有 SQLite，并绑定现有 `refresh-config.json` 的规范化摘要：

- `stateDirectories.publications` 与 `stateDirectories.collections` 互不包含，也不得与原出版物、合集或小红书 HTTP 状态目录重叠。
- 状态文件须通过原私有文件、权限、非符号链接及单链接检查。不能用硬链接充当隔离副本，也不在采集时创建或迁移旧业务库。
- API 出版物目录同时容纳新的分类、周期、发现、待审和执行回执。原目录里的旧格式和旧业务暂停保留；周期／发现状态存在但尚未接续到新位置时拒绝执行。
- 已有周期健康、发现状态及未完成作业须逐项审阅后接续，保留历史暂停；不能只建空目录绕过旧失败，也不能重写旧 scope 摘要把过期或不同范围的捕获包变成新证明。
- 旧待审候选在新位置尚无替代时仍以只读方式参与审阅。新 JSON 候选只写新位置，避免旧程序读取无法解码的来源。

`cycle-cli`、发现桥接和播放验证读取同一默认关闭选项。实际安装应让状态消费方使用当前 CLI／状态路径，不能把原位置的旧回执标为新来源的当前结果。新来源发生异常时保留人工恢复锁，不沿用 SSR 的自动退避再采策略。

## 安装与回退

本次代码不复制真实状态、不写配置、不装 SQL、不改变调度。真实安装前准备完整来源、原生客户端、SQL、正常缓存后置、字节预约、时限和停止条件，再取得具体许可。现有媒体队列和当前公开规则继续生效，统计 ACK 不等于媒体处理或网站整体更新完成。

停用或回退时先暂停调用并关闭新来源选项，保留新数据库、pending、原始摘要和已确认 ACK；不得将新来源改名后复制回旧库。若已写新来源，保留能读取这些记录的兼容校验，不删除历史或恢复旧凭据。回到 SSR 配置也不代表原页面故障已消失。
