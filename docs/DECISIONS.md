# 决策记录（存档）

本文件是 2026-10-12 及之前的存档，不再追加。之后的决策每项一个文件，写在 [docs/decisions/](decisions/README.md)；同一件事有新决策时以新文件为准。

## 2026-10-12：社交全量接入先盘点可见目录

用户在盘点中补充合集更新偏好：稳定合集对应首页一张卡，新增成员更新该卡与摘要；统计采样不当作内容更新，独立视频仍独立。合集／单集统计、成员身份、原始日期／内容更新时间／观察时间分开，不能按标题或集数差值直接合并。当前 DTO 尚无合集更新语义，下一后端阶段新增明确契约，不重解释原日期字段。

用户同意先完成目录与覆盖清单。逐平台发布身份核对分页、去重和末尾，目录与详情／上传／公开分开；分页失败或保留旧列表不推进成功进度。真实标题和身份仅保存在外置忽略目录，原采样时间、队列、绑定和网站资格保持。目录规模已超过现有网站读取边界，后续先准备有界批次与容量／分页变更，再验收历史采集，见 [盘点说明](SOCIAL_CATALOG.md)。

## 2026-10-12：社交上传采用独立私有 SQL 域

用户确认继续受限 Supabase 上传阶段。在现有试验项目新建 `social_sync`，与冻结内容／网站协议分离；专用 `nb_social_worker` 登录只访问已登记且启用的指定发布。选择 SECURITY INVOKER 写入函数，必要列授权、RLS、完整字段校验、不可变绑定和单调时间触发器一起约束直接 SQL，不授予旧库权限，也不刷新旧 worker 或 reader 会话。

云端只保留最新投影，不上传全部本地历史，后续有趋势图需求再单独讨论保留周期。数据库按原始输入字节重新验证 SHA，返回实际保存记录的键和摘要；相同观测重试返回同一回执，旧值／时间冲突拒绝，断网和取消不假确认。新 schema 初始零公开资格；操作者的绑定授权不等于网站发布授权。凭据只在私有文件与服务器密码散列中，不进入源码、migration 明文或 Git，常规 worker 日志不输出凭据。

## 2026-10-12：小红书先接浏览器狭窄投影

用户要求继续开发。现有会话可读指定小红书笔记，匿名 HTTP 会跳登录；先实现自有读取片段与独立 `import-xhs`，不增加采集框架、Cookie 导出或签名逆向依赖。采集入口显式区分 HTTP 与浏览器输入，小红书没有输入时不返回旧数据当成功。当前页 ID 的普通字符串和 Vue ref 均检查，详情条目、作者和页面路径同时匹配；输入五分钟过期，批次身份／字段预检与数据库事务保证失败不留下部分记录。

B 站 v1 观测不改，小红书用内部 v2 观测区分图文／视频、平台更新时间和显示计数；SQLite schema 不变，网站契约不扩展。近似数仅保留显示文字，精确数为 null；不保存评论、正文、访问令牌或原媒体。浏览器输入桥接不等于无人值守、全历史、真实视频或永久云端上传通过。 原平台无参数规范链接实测不可读，先仅用于身份；网站跳转链路须验证真实分享链接，不能把去参数后的 URL 当作已通过。

## 2026-10-12：补齐作品页后执行账户同步

用户同意补齐平台清单中缺少的作品页并继续版本核查，之后实际执行账户同步。新建 Game 页仅包含可靠的作品资料，个人体验字段留空；已有不同版本的个人页保留。Nintendo 先核对软件标识与官方产品的 `applicationId`，当前展示名称或硬件标签不单独作为升级权益证据。地区发行日期写明来源口径，不推定个人地区；合辑软件保留自身统计范围。

人工维护与账户 worker 的写入范围仍分别约束：前者按授权补建作品和维护核查备注，后者只写平台账户字段。真实 collect／dry-run／apply 之后回读两端关系、时长、人工字段及排除配置；封面文件身份核对忽略临时签名 URL 的刷新。失效隐私政策必须得到新的实际核验，不因本轮写入而长期续用。

一般网络作品资料可采用可核对的公开发行或公测日期，核查备注明确公告地区及阶段；这不填写个人服务器地区。已确认包含本体的组合页，可接收该本体的精确软件统计；购买商品 SKU 与账户软件标识分开，合集商品页面不能独自证明账户统计为合集总时长。

## 2026-10-12：自动部署收紧到 main

用户要求尽量减少部署次数。自动 Git 部署仅允许 main，取代之前 main／develop 都部署的安排；develop 仍为日常集成分支，工作分支与 develop 的验证由本机和 GitHub Actions 执行。集中积累改动后，由用户合并 develop → main 的发布请求。

`vercel.json` 使用 `**: false` 与精确的 `main: true`，同时覆盖含斜线的工作分支。配置从各分支提交读取，旧分支须先整合最新 develop；已存在的 Preview 不随新提交更新。手动部署、重新部署与部署钩子需用户明确要求，不用于替代日常检查或内容同步；Git 配置不自动禁止这些入口。依据见 [Vercel Git 配置](https://vercel.com/docs/project-configuration/git-configuration)。

## 2026-10-12：核查状态与历史说明分开

用户同意把已登记问题的处理状态从历史备注中分离：作品库采用“待核查／已确认”，平台采用“已关联／缺作品页／版本待核／无需关联”。空值为未分类，已确认只针对已登记问题，不说明所有资料完整。保留原备注、来源证据、个人字段和全部账号数值；试玩及服务不因分类而删除、归档或并入正式游戏。

待核视图按新状态筛选，并接收有说明但尚未分类的新条目。自动管理的 `Sync Status` 保持原协议，人工字段独立保存；运行配置合并须保留各目录已有排除，不以较新绑定覆盖较旧文件中的独有规则。实际账户重新采集和只读 dry-run 与 Notion 维护分开记录；失效隐私证据不能续写时间戳，用户当前实际核对完整名单后的新确认单独记录。

## 2026-10-12：作品版本与首映口径确认

用户明确了若干作品版本、观看形式及一组重复导入，并同意优先使用可靠网站处理一般资料。确认的版本写回原页；个人体验、平台填写、正文与历史说明保留。实际平台账户产品与原页版本不一致时保持独立，支持平台资料不代填个人拥有状态；组合命名的作品页可关联其范围内已核实的单个版本，统计只来自实际产品，不推断另一个版本的所有权。

影视发行日采用可核实的原始首映、首次公开放映或原始开播时间，包括更早的节展放映。公共评分按具体作品／季别记录来源，书籍页数按 ISBN 匹配可靠书目；页数与阅读状态分别维护，不能为了完成率改写个人记录。原值及校正依据追加保存，尚未核实的日期、版本或绑定继续标记复核。

维护中已确认软件执行标识不必等同于商店购买 SKU；正式版、好友通行证和合辑可能共用标识。公开商店资料用来核对软件及版本，不能单凭它反推个人购买、DLC 或升级包权利。缺少对应个人作品页、试玩、服务和范围未明的合辑继续独立保存，在核查备注写明具体原因。
