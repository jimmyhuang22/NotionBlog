## 主机接线

`runHostedCommitRollout` 为核心提供实际文件锁、不可变日志、专用 pg Client 和既有共享账本。模块加载不发起项目请求，也没有 CLI 或 env 自动加载；只有受审控制程序提供完整 manifest、精确摘要对应的用户批准记录、预定操作及凭据读取函数后，才执行所选动作。调用方和材料生产者须处于审阅的可信运行边界内。

manifest 固定同一目标、运行图／软件包摘要、原锁顺序、来源收尾证据、共享预算引用，以及最多四个单次操作槽。每槽绑定核心计划和一次性 nonce；总驱动连接额度预先按全部槽的上限累计，不能靠增加未使用或负额度槽抵消。操作之间使用同一账本，并串行取得本轮私有控制锁。nonce／operation 已认领或前次记录未结清时不重新执行。

运行图至少覆盖来源、社交、媒体、独立缓存消费者、下架和维护；每个执行入口都要有软件包中的代码 pin，每把原锁都须在明确顺序中出现。源端的六锁不是全部活动的替代证明。既有消费者内层锁与旧启动程序的外层 fence、等待进程，以及独立社交写入者都必须由实际拥有方确认纳入。代码验证清单自洽和文件身份，**不能自己发现清单外的程序，也不能仅凭 actor 名称证明程序遵守该锁**。

连接前检查代码／状态／收尾材料的摘要、规范绝对路径、拥有者、文件类型、链接和权限。凭据文件不进入预检 pins；它们只由通过批准、认领、实际 hold 后的读取函数取得。私有原锁目录必须已经存在；没有替换原运行配置、改名 worker.lock、创建新原锁目录、发信号或偷取已有锁的行为。持有与释放均核对原 inode／设备和字节，并 fsync 文件及目录；外来替换保留，其他确定属于本轮的锁按逆序收尾。

来源收尾材料须来自可信拥有方，绑定同一父许可 nonce、运行图、全部 actor 和不超过 30 分钟的有效时间，并明确服务器 lease 已关闭；其文件摘要包含在软件包 pin 中。该声明仍须由审阅者核实来源，不能将 fixture 生成器或本机暂停标记当作服务器证据。数据库事务中的实际 sourceIdle、writer 和围栏检查继续保留。

## TLS 与连接结束

每次使用专用 Client，不复用网站池。目标摘要绑定数据库主机／端口／库名／LOGIN 及 CA 摘要，密码保持在内存中且不进入摘要或回执。连接串拒绝 query／fragment 和缺失身份，不允许 sslmode 等参数覆盖。CA 验证、实际加密／authorized 属性及证书主机名检查均须成立；同一操作只读取一次凭据，不刷新或重新认证重试。

凭据返回后及每次连接／SQL 前重新检查子操作期限，不能借父窗口更长而在子窗口结束后联网。实际 CommandComplete 及 UPDATE 行数直接交给事务核心；没有把 ROLLBACK 包装成 COMMIT。socket 必须观察到 close；关闭等待上限到达时破坏本轮连接并观察结束，返回关闭错误并保留不确定状态。没有用 Promise.race 丢下后台写入，也不据客户端关闭断言托管后端或来源 lease 已释放。相关行为参照 [Node TLS](https://nodejs.org/api/tls.html#tlscheckserveridentityhostname-cert)及 [Supabase SSL](https://supabase.com/docs/guides/platform/ssl-enforcement)。

## 同一账本与停止条件

复用 `qualified-shared-budget-v1` 的原计划、原状态、原计数和原停止规则，不修改其协议。各操作的 SQL 调用／请求字节在 driver 前记账，结果字节即使越限也不退账；多语句迁移算一次 driver 调用，内部 DDL／函数执行另行列示。跨槽依据不可变前次回执及当前调用的单调下界拒绝账本 revision／计数回退；不能为新动作初始化另一份零计数状态。

该旧账本未定义连接计数，因此用已批准 manifest 中不可增补的单次槽保守预约驱动连接总额；每槽又由实际专用 Client 工厂限制尝试数。这里的驱动次数、SQL JSON 逻辑字节、client stream 的接收观测以及平台计费分开记录，不能相加或宣称精确账单硬限。

原账本的清理窗口最多 20 秒，新适配器据此收紧子许可，不把它改成安装方案中预留的 15 分钟。正常窗口内核账 ROLLBACK 记普通 SQL；业务期限／账本停止后，只允许在原清理额度和时限内发送 ROLLBACK。已开始的语句及 socket 收尾继续等候有界结果与真实事件，不能承诺整个进程在某一毫秒硬终止。最终项目提案必须按完整入口重编预算，原 32 MiB 仅是未批准的保守项目预留。

任一动作失败后写入本轮 business-stop，后续写槽停止。核账槽必须提前列在同一批准清单，且预算与窗口仍有效；配额／期限耗尽或连接关闭未证明时不核账、不重试。最终主机回执写盘或私有控制锁释放失败，也返回显式错误并保留已观察到的提交／核验结论，不能将其降为回滚或删除外来文件。

## 提交不明后的核账

核账只接纳同一父清单中前次失败操作的不可变最终记录、明确关闭的客户端及仍属该操作的完整原锁。取得私有串行锁后按原 metadata 围栏排序执行有界 NOWAIT 表锁，再读固定目录、来源／角色／缓存指纹和配置／空意图；不执行 DDL、开关更新、来源恢复或清理。

该核账事务为取得表锁使用 BEGIN，**不是 READ ONLY 事务**，但不写业务或控制数据，最后以 ROLLBACK 结束。原事务尚持有围栏或实际前像漂移时立即停止；没有自动轮询等待锁。匹配结果仅报告 matches-before／matches-after／mismatch，表示当前状态与已审前后像的关系，不能从状态相符重建丢失的提交 ACK 或断言是谁提交。

只有明确匹配、目录及连接核验完成并保存核账记录后，才能释放原操作的本项锁。旧 unknown 原件保持，business-stop 也不解除；不会因此继续下一写槽。超出原窗口或缺乏可信的持续持锁／客户端收尾证据，须重新准备完整受审恢复方案，不能沿用旧剩余额度。
