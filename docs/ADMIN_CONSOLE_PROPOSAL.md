# 后台控制台方案

记录日期：2026-10-25。状态：方案，冻结语义待 Codex 确认。本文件提出功能、运行位置、后端需求、分工和顺序。

进展（2026-10-25）：用户请 Claude 开发控制台的界面与适配层，后端能力仍等新模式上线后接入。第一版六项功能已在 `console/` 用演示数据完成，代码说明见 [console/README.md](../console/README.md)；与后端的对接改为一个由后端提供的桥接命令，协议见[对接协议](CONSOLE_BRIDGE.md)。数据库协议、同步程序、调度和公开范围没有改变。

## 为什么要做

现行同步每两小时把全部已公开页面连同正文完整重读一遍，因为已发布内容四小时后失去资格，程序需要不断证明每个页面在 Notion 中仍可公开。基本不再更新的页面（例如已结课的课程）每天也要被重读 12 次；同步或 Mac mini 停止超过资格时间，网站内容就不可用。

Codex 已完成、尚未切换的新模式（[持久发布](CONTENT_PUBLICATION.md)与[增量发布](INCREMENTAL_PUBLICATION.md)）会解决其中两点：已发布内容长期有效，之后只读取变化页面；执行端停止只影响更新，网站继续服务。

新模式解决不了的是：

- **不再更新的内容仍在同步范围内。** 程序仍要对它们做目录核对，Notion 里的误删、移动或权限变化仍会影响网站。按现行规则，把页面移出同步范围会被当作撤回（见[学习公开与排序](STUDY_PUBLICATION.md)），来源配置摘要变化还会要求重新完整发布，所以不能靠改配置“冻结”。
- **日常操作要敲命令。** 立即同步、看同步结果、紧急下架都需要在 Mac mini 上手动执行带私有路径的命令。

控制台就是补这两块：一个只在内网可用的小网站，给这些操作配上按钮，并引入“冻结”状态。

## 不做什么

- 不替代 Notion 编辑学习笔记；不自研完整的富文本编辑器。
- 不做 Notion 与网站的双向同步。同一个字段只在一个地方写，见下文“每类内容在哪里写”。
- 不放到公网，不进入网站的构建与部署。
- 第一版不改动态、影视、书籍、游戏的编辑方式。

## 功能清单

### 第一版

| 功能 | 用户看到什么 | 依赖的后端能力 |
| --- | --- | --- |
| 同步状态 | 上次成功时间、当前是否在运行、最近失败及原因、待处理队列数量 | 运行器的状态查询（只读，JSON 输出） |
| 立即同步 | “立即同步全部”按钮；可选“只同步这个页面”。点击后显示进度，结束显示结果 | 经 Dagu 或运行器触发一轮，沿用同一把锁；已有运行时提示“正在同步”，不另起第二个 writer |
| 冻结 | 输入站内页面地址或 Notion 链接，或在公开内容一览里勾选；显示将冻结的页面数和图片数，确认后执行 | 冻结状态，见下文 |
| 解冻 | 两种：永久解冻（放回日常同步）；同步一次（拉取最新内容后自动重新冻结） | 同上 |
| 紧急下架 | 输入地址，显示计划（页面、后代、图片数量），二次确认后执行；失败可续办 | 现有 `scripts/public-cache/withdraw-cli.ts` 的计划、执行、续办三步，见[公开缓存与本机下架](PUBLIC_CONTENT_CACHE.md#立即下架) |
| 公开内容一览 | 按栏目和课程列出已公开内容，标出“同步中”“已冻结”“已下架”，可搜索 | 只读查询已发布内容及冻结、deny 名单 |

每个操作都显示明确的加载、成功、失败与“结果未知”状态，结果未知时只提供核对和续办，不提供盲目重试。

### 第二版

| 功能 | 说明 |
| --- | --- |
| 修改冻结页面 | 改标题、日期、段落里的文字，替换或删除图片。只开放已冻结的页面，因为冻结后数据库是它们唯一的维护来源。需要修改历史和撤销 |
| 刷新缓存 | 对指定页面强制刷新公开缓存，复用现有刷新队列 |
| 图片覆盖情况 | 哪些页面的图片已有独立原图和小图，哪些还依赖 Notion 动态地址 |
| 其他任务状态 | 游戏平台和社交采集的最近运行结果，只读 |

## 每类内容在哪里写

| 内容 | 编辑位置 | 说明 |
| --- | --- | --- |
| 正在更新的学习笔记 | Notion | 正文结构最复杂、层级最深，继续走增量同步 |
| 已冻结的页面 | 数据库，经控制台修改 | 不再读取 Notion；解冻时以 Notion 为准，会覆盖控制台的修改（解冻前提示） |
| 动态 | Notion（暂定） | 新模式上线后配合“立即同步”使用；是否改到控制台以后再议 |
| 影视、书籍、游戏的人工字段 | Notion | 如果改到控制台，Notion 只接收单向回写用于查看，不再在那里编辑 |
| 游戏平台时长、奖杯等自动数据 | 采集程序 | 可另议直接写入数据库，不经过 Notion；不能覆盖人工字段 |
| 社交作品 | 采集程序 | 已经直接进数据库，不变 |

## 运行位置

**建议：运行在 Mac mini 上，只通过家庭局域网或 Tailscale 访问。**

- 同步程序、锁、私有配置和受限凭据都在 Mac mini 上，控制台可以直接调用，不需要让云端反向连入。
- 不对公网开放。仓库已经公开，一个能下架、冻结和改数据库的入口放在公网上风险过大。
- Mac mini 已有 Dagu 调度和 Dashboard，控制台可以与它们并列，“立即同步”通过 Dagu 触发，保留同一份运行历史。
- 手机安装 Tailscale 后在外面也能使用。

访问控制：只监听本机或 Tailscale 接口，不绑定公网地址；在 Tailscale 访问控制之外再加一道控制台登录。控制台进程使用专门的受限账号，只能读状态、改冻结名单、触发运行和执行既有下架流程，不持有数据库管理员、网站部署或 Notion 写入凭据；Notion 读取仍只由同步程序进行。

不建议放在 Vercel：Vercel 连不进 Mac mini，立即同步只能改成写待办、等 Mac mini 来取；还需要一套面向公网的可靠登录，与网站构建混在一起也会扩大公开代码的攻击面。

代码位置待定。建议放在同一仓库的独立目录，复用 `contracts/` 和现有组件，但不进入网站构建、不部署到 Vercel。是否新增依赖属于共享范围，开工前确认。

## 冻结状态：后端需要做什么

以下是对 Codex 的需求，具体实现与协议由 Codex 设计。

1. **独立的冻结名单。** 与中央 deny 类似，单独保存、单独计版本，不写进来源配置，冻结和解冻不改变来源配置摘要，因此不触发重新完整发布。
2. **冻结范围。** 冻结一个页面即冻结它在冻结时刻的全部已发布后代。冻结后在 Notion 里新增的子页不会被收录，控制台需明确提示。
3. **同步跳过。** 增量发现、目录核对、正文读取、媒体核验都跳过冻结范围。Notion 中的删除、移动、权限变化不再影响已冻结内容。
4. **图片先独立。** 冻结前检查范围内的所有图片都已有独立原图（必要时含小图），仍依赖 Notion 动态地址的先补齐，否则拒绝冻结并列出缺口。冻结后的页面不能再依赖 Notion 交付图片。
5. **下架优先于冻结。** 中央 deny 与现有下架流程对冻结内容照常生效。
6. **站内链接。** 正在同步的页面与已冻结页面之间的链接保持可用；任一方被撤回时沿用现有的链接修订与“不可用”标记。
7. **解冻。** 永久解冻：移出冻结名单，下一轮把整个范围当作已变化，重新读取并比较，只发布差异；若 Notion 中已删除或不再公开，按正常规则撤回。同步一次：在同一把锁内完成“解冻、读取发布、重新冻结”，中途失败保持冻结并保留上一已发布版本。两者执行前都要能列出将被覆盖或撤回的内容，供控制台确认。
8. **操作入口。** 提供带 JSON 输出的命令或本机接口：冻结、解冻（永久／一次）、列出冻结范围、预览影响；输入接受站内地址或 Notion 链接，沿用下架工具的身份解析。所有操作写入审计记录（时间、对象、结果）。
9. **立即同步入口。** 可从外部触发一轮增量同步，可选限定到指定页面；与定时任务共用锁；返回运行编号，可查询进度和结果。
10. **备份。** 冻结内容在数据库和对象存储中是唯一维护副本（Notion 中的版本可能已不同），须纳入备份与恢复演练。
11. **修改冻结页面（第二版）。** 已冻结记录的受限写入：对现有正文结构做字段级修改、替换图片，保存修改历史并可撤销，成功后刷新对应缓存。

## 先后顺序

1. **确认方案。** 用户与 Codex 确认冻结语义、运行位置、代码位置和第一版范围。
2. **新模式上线。** Codex 完成持久发布、增量运行与独立媒体的切换及验收（含当前发布前的其他阻塞项）。这一步完成前，不在旧模式上做冻结。
3. **冻结与立即同步入口。** Codex 实现第 1–9 项，用命令行在一门已结课课程（例如 FIT9131）上验收：冻结后同步不再读取它，网站正常显示，图片不走 Notion，下架仍有效，“同步一次”能拉取变化并重新冻结。
4. **控制台第一版界面。** Claude 用演示数据完成六项功能的界面，与第 3 步并行。
5. **联调。** 在 Mac mini 上接入真实入口，经 Tailscale 从电脑和手机各完成一次立即同步、冻结、同步一次和状态查看；下架只用获准的测试页。
6. **第二版。** 冻结页面修改、缓存刷新、图片覆盖和其他任务状态。
7. **再议。** 用一段时间后，决定动态或作品库是否改在控制台写。
