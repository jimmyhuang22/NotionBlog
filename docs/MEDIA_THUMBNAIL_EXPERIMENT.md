# 本机缩略图试验

最后更新：2026-10-11。

本轮仅验证小尺寸图片的文件大小与显示效果。现有媒体策略仍为正文读 Supabase 数据库、普通图片使用当前 Notion 托管地址或原外链、HEIC／HEIF 转换版本读 Storage，详见 [混合媒体说明](HYBRID_MEDIA.md)。缩略图的托管平台尚未选择，本轮没有云端下载或上传，也没有接入网站。

## 目的与使用场景

列表封面与动态九宫格通常不需要在首次浏览时下载完整原图。候选方案是列表先加载小尺寸副本，点击灯箱时再读取原图；文字截图、图表与学习正文需要按实际显示宽度和文字清晰度单独判断。

本轮的缩略图是缩小后的预览，不能称为原图的近乎无损压缩。文件大小减少同时来自分辨率降低与编码变化，不能把结果归因于换格式，也不能推算所有图片或全站流量会按相同比例下降。

## 样本与生成方法

- 从既有获准本机图片副本中选择 18 个非随机样本：8 个 JPEG、10 个 PNG，其中 2 个 PNG 含实际透明像素。
- 生成宽度上限为 400 和 800 像素的两档图片，保持比例，不放大小原件；处理流程执行方向规范化，并统一到 8 位 sRGBA。
- 每档比较 WebP 质量参数 85 与同尺寸 lossless WebP；16 个不透明样本另比较 JPEG 质量参数 85、4:4:4 色度采样。
- 按实际编码字节选择较小的候选；候选均保存供本机对照，不覆盖原件。

质量参数是编码器设置，不表示“保留 85% 的原图质量”。像素差异与 lossless 对照均以已经缩小的 sRGBA 参考为基准，不能据此证明与原始分辨率、原始色深或原始色彩空间完全一致。

缩放与编码选项的方法参考见 Sharp 官方 [resize 说明](https://sharp.pixelplumbing.com/api-resize/)与 [output 说明](https://sharp.pixelplumbing.com/api-output/)。这些文档说明 API 行为，不替代本轮实际字节与浏览器验证。

本组包含照片与截图，但不覆盖高宽比至少 2.5 的长图、动画、16 位原件、需实际旋转的原件或 HEIC／HEIF 原件；处理流程支持的步骤不等于这些场景已经验收。

## 文件大小结果

以下为这 18 个样本的实际生成文件大小。MB 使用十进制，1 MB = 1,000,000 字节。

| 文件集合 | 字节数 | 大约大小 | 相对这组原件减少 |
| --- | ---: | ---: | ---: |
| 原件 | 62,768,091 | 62.77 MB | — |
| 400 像素档，18 个引用 | 285,868 | 0.286 MB | 99.54% |
| 800 像素档，18 个引用 | 846,090 | 0.846 MB | 98.65% |
| 两档合计，36 个引用 | 1,131,958 | 1.132 MB | 不代表单次页面下载量 |
| 两档按输出 SHA 去重，35 个对象 | 1,129,012 | 1.129 MB | 不代表单次页面下载量 |

400 像素档选择了 18 个质量参数 85 的 WebP；800 像素档选择了 17 个质量参数 85 的 WebP 和 1 个 lossless WebP。一个小原件没有被放大，两档产生相同字节，因此去重后对象数为 35。

这组数据表明缩小预览可以明显减少首次展示所需字节，但不能证明 400 像素对所有视口、屏幕像素密度、图片比例或文字内容都足够。实际页面应按显示尺寸选择图片档位；灯箱仍需保留原图入口。

## 验证状态

独立字节复核与本机 Chrome 对照页检查已通过，范围如下：

- 原件及两组副本共 54 次 SHA 核对通过，18 个原件未变；104 个候选的格式、实际字节、尺寸、SHA 与像素统计复核通过。
- 36 个缩小参考独立重建通过；36 个同尺寸 lossless WebP 候选与参考的全部 RGBA 像素相等，104 个候选的 alpha 与对应参考一致。
- Chrome 逐项检查全部 18 个样本的 400／800 档，共 36 组原图与择小缩略图加载：均完成解码，实际宽度正确，失败数为零。浏览器检查的是这 36 个择小输出，不是全部 104 个编码候选。
- 对代表照片／游戏截图、中文文字截图与透明图进行实际显示和 100% 像素模式的视觉对照。390／320 像素宽视口下，对照页没有横向溢出；800 档九宫格的 9 张缩略图均加载，链接均指向原图。
- 实际点击对照页中的代表缩略图，在新窗口成功打开并解码 1764 × 1916 像素的完整原图；对照页检查期间控制台警告和错误均为零。
- 对照页 HTML 不含私有源路径或远程 URL；私有目录权限为 700、文件为 600。

这是实验对照页的验收，不是实际网站接入、手机真机或国内网络验收。视觉对照不代表用户已经批准最终尺寸和质量；本组也未覆盖上述长图及其他特殊格式。

本机对照页、样本图片、原件路径、个人正文、来源编号和逐图片哈希映射都保存在忽略的私有目录，不能作为公开 fixtures、文档附件或平台预览提交。

本轮没有修改 Notion、云端对象、媒体 DTO、worker、前端、数据库发布批次或调度；生成器与图片输出不进入提交。已有图片的实际来源选择保持原方案。

文档分支的 `npm run check` 与 `npm run build` 已通过：557 项测试、类型检查、两组协议检查及 292 个候选文件的隐私检查；33 份服务端构建追踪清单均排除私有运行文件。独立 HTML 相对路径与私有目录／文件权限复核也通过。工程检查不替代上述图片字节和浏览器验收。

## 后续接入条件

1. 由用户查看本机对照页，判断照片、透明图与文字截图的清晰度，选择尺寸和质量；另补本组没有覆盖的格式和长图场景。
2. 根据真实列表尺寸、设备像素密度与目标网络，确定需要哪些档位，再选择 Supabase Storage、腾讯云对象存储或其他托管方式。当前文件大小试验不验证任何托管平台的访问速度、费用或可用性。
3. 若决定接入，缩略图采用独立对象与输出 SHA 映射，不能覆盖原对象；图片变化需要重新生成，并保留回退到原图的路径。
4. 缩略图读取仍须服从所属内容的当前公开资格、撤回与来源变化检查，不能用永久缩略地址绕过现有媒体资格入口。
5. 后端与前端另行确认缩略图和原图在 DTO 中的区分及各自用途。Codex 负责生成、映射与媒体资格，Claude 负责列表、九宫格、灯箱的展示与交互；本试验没有改动共享契约。

托管接入、持续增量生成、故障回退、真实浏览器页面与目标网络验收应作为后续独立任务。离线文件结果不代表网站已使用缩略图。
