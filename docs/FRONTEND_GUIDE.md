最后更新：2026-10-12。给在新设备上继续前端工作的 Claude。通用的环境、分支和私有配置迁移见 [开发接手说明](DEVELOPMENT_HANDOFF.md)；本文件只讲前端：已经定下的设计、代码怎么组织、怎么验证、还剩什么。

[前端开发交接包](FRONTEND_HANDOFF.md) 是后端最初交给前端的任务说明，其中“页面与缺项”一节已全部完成，现在只作历史与接口参考。

## 已经定下的设计

这些是用户逐轮看过设计稿后确认的，不要重新发散方向；要改先问用户。

- **风格**：“墨水”。暖纸色底带一点纸纹、纸色圆角卡片、蓝黑墨水色作唯一强调色；标题、导航、动态文字等短文字用霞鹜文楷，长正文仍用系统字体。浅色与深色两套变量，默认跟随系统，页头按钮可切换并记住。这是用户主动提出调整后从多轮原型里选定的，取代最初的柔和苹果风。
- **文楷的用法**：标题、月份、导航和短句用文楷；会写到很多行的正文（笔记、文章、动态卡片里的正文）用系统字体。阅读页没有本页目录时把正文收在约 40 个汉字一行。
- **动态都是卡片，卡片随内容宽窄**：每条动态是一张卡片，宽度贴合里面的文字，最宽到整栏；一句话的动态就是一张只有标题的小卡片，有正文的最窄 280，展开全文后占满整栏（里面可能有图和表格）。图片跟在卡片下面。用户从四种宽度、两种短动态的做法里选定（2026-10-13）。作品卡与栏目小卡片的宽度没有动。
- **发在其他平台的作品按各平台自己的样子画**：B 站是横封面，播放和点赞压在封面底部；小红书是竖封面，标题下面一个点赞数。只留播放和点赞，不写数字是什么时候读的（2026-10-14 起连超期也不写）；作品的日期和动态一样写成“今天、昨天、N 天前 · 日期”。连着的几件排成一排可以横向滑动的小卡片。没有封面时是不带画框的同一张卡，连着的几件仍是清单；作品页有封面后也用同一种卡片，按行等高排开。用户 2026-10-14 从三个样子里选定（另两个：封面在左的横卡片、带小封面的紧凑清单），见 [决策记录](decisions/2026-10-14-work-cover-cards.md)。**2026-10-17 起（反馈 F22）B 站不再显示点赞，只留播放；首页上有封面的 B 站作品改成 B 站主页式小卡片**（见下面“首页上连着的几件作品”与 [决策记录](decisions/2026-10-17-bilibili-home-cards.md)）。
- **七天内的动态，时间写成“昨天 · 10 月 13 日 22:52”**：相对说法在前（今天、昨天、前天、3 到 7 天前），日期紧跟在后；今天的只写“今天 09:12”；八天及更早的照旧只写日期，将来的日期也只写日期。只记了日期的不补钟点。相对说法用墨色，日期保持原来的灰色。动态页和首页时间线的每一条都这样写；博客、作品库、学习笔记不动。用户 2026-10-14 从四个写法里选定，见 [决策记录](decisions/2026-10-14-relative-status-time.md)。
- **最新一条动态**：首页时间线上最新的那条，圆点带一圈淡墨，卡片左侧一道墨线（和课程卡片的书脊同一个做法），时间旁标“最新”。用户从三个做法里选定。
- **没有封面的作品**：格子里用文楷竖排片名，左侧一道墨线，像立在书架上的书脊；横向的格子（游戏、相册）片名横排。封面读取失败时也是这个样子。用户从三个做法里选定。
- **封面还在路上时**：格子先显示同一种书脊，标题晚约 0.3 秒才出现，封面到了淡入盖上去、书脊随即撤掉；封面来得快就看不到标题闪一下。用户从三个样子里选定（另两个是空白格、只画墨线不写字）。只用于作品库的列表和详情，相册卡片没有做。
- **动态页的年份切换只占一行**：放不下时横向滑动，哪一侧还有内容，哪一侧的边缘渐隐；选中的年份会被带进可见范围。用户从三个样子里选定（另两个是折成两行、近三年加“更早”菜单）。作品库的状态切换项目少，仍按原样换行。
- **作品库的年份切换与排序**：影视、书籍、游戏在状态切换之下多一排年份（全部、各年、无日期），和动态页的年份切换同一个样子，放不下时横向滑动；年份按看过、阅读、游玩的日期算，条数跟着当前状态走。桌面上年份在左、排序在右，共一排；640 以下排序收成年份右边的一个小按钮，写着当前的排序，点开选另外两种，这样手机上封面之上只有两排控件。用户从三个排法里选定（另两个是年份单独一排胶囊加一排排序、年份画成和排序一样的小字）。选了某一年后列表里不再重复那一年的分组标题；只有一个年份可选时不出现年份切换。
- **点筛选后立刻有回应**：点年份、状态或排序后，新列表到达之前，被点的那一项立刻变深，旧列表整体变淡；动态页的年份切换也一样。用户从两个做法里选定（另一个是筛选下方一条走动的细线）。切换快于 0.1 秒时看不到变淡。
- **动效的取舍**：原来瞬间切换的地方都有过渡（图片加载、“加载更多”、展开动态、看大图开合），另有首页介绍区的依次入场和页面之间的淡入淡出（页头不动）。用户明确不要“内容随滚动才浮现”这一类。所有动效在访客偏好减少动态效果时都不播放，样式集中在 `motion.css`；页面切换靠 `src/components/page-transition.tsx`（布局里包住页面内容）。
- **作品详情的信息区**：状态、我的评分、进度排在最上面一行——状态是墨色小签，评分在能画的时候画成墨点（旁边始终有原始数值），进度是一条墨线；其余信息是下面两行安静的“标签＋值”。缺失的评分和日期仍然写明“未评分”“日期未记录”。
- **学习首页**：宽屏上学期名在左栏、课程卡片在右栏，学期之间一道细线；900 以下回到上下排列。学期从早到晚排（样本学期在最上面，用户 2026-10-17 指定，[决策记录](decisions/2026-10-17-semesters-oldest-first.md)），没有学期的课程排最后；同一学期里的课程照接口给的顺序。
- **课程代码只出现一次**：课程名在来源里通常写成“代码 课程名”。学习首页的卡片、课程页的标题、课程目录的抬头这三处，代码已经单独写在上面的小字里，标题就只写课程名（`src/lib/format.ts` 的 `courseName`）；课程名不是以自己的代码开头时原样显示。浏览器标签页的标题、面包屑和搜索结果仍用完整的名字。用户从两个做法里选定（另一个是去掉小字那一行、标题保持完整）。
- **正文里的提示**：“部分内容无法显示”这类提示在正文里是带一道警示色细线的一行小字，不是整块色底；页面自己有本页目录时，正文里来自内容源的目录块不再重复显示。
- **笔记阅读页三栏（2026-10-21）**：1100 宽起课程目录是正文左边的一栏，粘在页头下、自己滚动，右边是本页目录；更窄时“课程目录”按钮在左上，目录从左边滑出、打开时整页其余部分不可操作。墨水与苹果的正文直接写在纸上、不套卡片，上一篇／下一篇是一条细线下的两行字，宽度停在正文右边；手帐的胶带纸和千禧的窗口保留各自的卡片。正文里的链接是一行细框（小圆标、名称、去掉 https 的地址，视频写“YouTube 视频”），折叠块没有底色、展开后挂在一条细线上。取代 10-19 的“专注阅读、目录按需打开”，见 [决策](decisions/2026-10-21-note-reading-layout.md)。
- **页头吸顶**：墨水主题在 761 宽及以上页头留在顶部，纸色实底、不用毛玻璃，滚动后才出现一道细线；手机上页头是两行，不吸顶。吸顶的页头把自己的高度写进 `--header-h`，锚点跳转和阅读页两侧的粘性栏用它让位；别的主题要吸顶时设同一个变量即可。用户看过对比稿后决定不在站名前加印章。
- **列表边滚动边加载（2026-10-17 打开）**：首页、动态、影视、书籍、游戏、博客、项目、搜索结果共用一个列表末尾。打开时，滚到接近末尾自动加载下一页，一次一页，末尾平时是一行安静的小字，出了问题才变回按钮（用户从三个做法里选定，另两个是自动加载三页后停下要点一下、只自动加载不加别的）。开关是 `list-tail.tsx` 顶部的 `LOADS_BY_ITSELF`：2026-10-13 起关着（作品库封面还是原图），2026-10-17 正式站点上确认作品库与相册列表封面都已是 400 小图后打开（[决策记录](decisions/2026-10-17-scroll-loading-on.md)）。关掉它，所有列表末尾就回到“加载更多”按钮。不受开关影响、一直在的两样：返回时恢复已加载的列表和位置；往下滚过一屏半后右下角出现的“回到顶部”，全站每一页都有，滚到页脚时让开。
- **落款与小处**：页脚是站名（文楷）加首页那一笔，右边是“回到顶部”，订阅源可用时才出现“订阅”；演示数据下的提示保留在页脚。找不到页面是一张歪着的空白纸页加一滴墨。首页时间线加载时先画出墨线和墨点，内容位置是淡墨色短条。
- **主题切换**：页头有两个外观按钮（用户 2026-10-17 从三个做法里选定，见 [决策](decisions/2026-10-17-scheme-button-and-theme-menu.md)）：调色盘按钮打开主题菜单，里面是四套主题（墨水、苹果、手帐、千禧）和一个“明暗跟随系统”开关；月亮／太阳按钮点一下就在浅色与深色之间切换，不开菜单，切换动效从这个按钮出发。第一次来跟随系统，点过一次月亮就记住选择，想回到跟随系统时在主题菜单里打开开关。墨水、苹果与手帐有浅深两套，千禧只有浅色：千禧下月亮按钮留在原位，点一下在它下面冒出“千禧只有浅色”，不切换，主题菜单里也不显示开关、改写“这套主题只有浅色”。每套主题有自己的切换动效：墨水是墨晕，苹果是淡入，手帐是翻页（新样子带一道斜的软边从左边盖过来），千禧是气泡放大。主题与明暗各自记住，加载时先于绘制套上，减少动态效果时直接切换。这是用户看过 11 种方向的原型后选定的三种加入，取代此前“只做浅色／深色”的决定。清单与规则在 `src/lib/skins.ts`，两个按钮与菜单在 `theme-toggle.tsx`（`ThemeControls`），各主题的变量与细节在 `skins.css`。
- **首页**：居中头像、“你好，我是…”、简介、社交图标，下面是一条时间线。文字动态是主角；其他栏目的更新作为小卡片穿插。
- **头像是“关于”的入口**：关于页可读时，首页的头像右下角有一枚小圆标，点头像在当前页弹出关于页的内容（标题、正文、更新日期，不重复首页已有的头像、名字和社交图标）；鼠标指上去或键盘聚焦时外圈上墨、头像轻轻歪一下。导航里没有“关于”，页脚留了一个“关于”链接兜底，进的是 `/about` 页面。小圆标、页脚链接和弹层版式都是用户各从三个做法里选定的。
- **学习不上首页**：学习内容是给别人参考的，只通过导航进入。
- **爱好类内容克制展示**：首页只以时间线小卡片出现，完整列表在各自栏目。
- **导航里不要重复的筛选**：用户明确否决过首页上的栏目筛选按钮，因为和导航重复。
- **缺失值如实显示**：日期、评分、张数、学期为空时写“未记录”一类文字，不补值、不显示 0。

用户还提过想要“项目”栏目，页面未做，等内容类型与来源确定。设计稿画布的地址属于用户的私人账户，记在私有接手记录里。

导航由 `config/features.ts` 生成：栏目打开后入口自动出现，关闭时对应地址显示“找不到”。首页时间线同理，只合并已启用的栏目。“作品”是例外：它不是内容栏目，而是跟着社交来源的开关（`isSocialEnabled()`）出现，在 `src/app/layout.tsx` 里插在影视等栏目之前。正式站点因此是七项，影视、书籍、游戏、相册收在“更多”里（用户知情并选定，见 [决策](decisions/2026-10-13-works-page.md)）。

页头的排法：栏目不超过六个时全部平铺；超过六个时，影视、书籍、游戏、相册这几个爱好类收进“更多”（其中只开了一个时不收）。**这只在 1024 以下执行**：1024 及以上的宽屏不管几个栏目都全部平铺、没有“更多”（用户 2026-10-13 同意，见 [决策](decisions/2026-10-13-nav-flat-on-wide.md)）。做法是把会被收起的栏目在这一行里再写一遍（`site-nav__wide`），由样式按宽度显示其中一套，服务端不需要知道宽度；按栏目个数切换页头排法的那几条样式只数不带这个类名的条目，改它们时别漏了这个条件。`src/app/layout.tsx` 用 `more` 标记这几个栏目，分组规则与上限在 `src/lib/nav.ts`。六个是实测出来的：四套主题下 320 宽的手机一行正好放得下六个两字栏目，七个就会被裁掉。这是用户 2026-10-12 提出平铺后从三个做法里选定的（另两个是栏目行横向滑动、折成两行），取代此前“爱好类两个及以上就收进更多”的排法；“关于”不在导航里，见上面“头像是‘关于’的入口”。窄屏下页头固定为两行：第一行站名与工具按钮（搜索、主题、明暗；540 以下三个按钮收窄到 40、彼此贴紧，380 以下站名小一档，这样 320 宽也放得下 18 个字符的线上站名），第二行栏目；栏目不超过三个时在 540 以下才换成两行，更多时在 760 以下，页头多了明暗按钮之后，千禧的字更宽，五个栏目时到 780 为止都是两行。当前栏目用墨点标示，当前栏目在“更多”里时“更多”本身也带墨点。

## 代码怎么组织

```text
src/app/            页面与样式（api/ 与 media/ 是后端的路由，不要改）
  globals.css       设计变量、页面骨架、通用小部件
  timeline.css      时间线与首页事件卡片
  prose.css         正文块、看大图、代码高亮配色
  study.css         学习首页、课程与笔记的阅读布局
  library.css       作品库、相册、博客
  motion.css        动效：图片淡入、列表追加、展开、看大图开合、首屏入场、页面切换
```

样式是带前缀的全局类名，没有用 CSS Modules 或工具类框架。新样式放进对应的文件，颜色与圆角一律用 `globals.css` 里的变量，这样浅色、深色和各套主题自动生效。

主题是在根元素上加 `data-skin` 后只改变量和少数组件细节（`skins.css`），不改结构：墨水是默认，不带属性；苹果只换变量和字重；手帐是一本手账（用户 2026-10-19 从五个候选里选定，取代像素主题，见 [决策](decisions/2026-10-19-notebook-skin.md)）：点阵纸底，动态卡片和阅读正文顶上贴一截和纸胶带、动态卡片左右轻轻歪一点，头像像贴上去的照片，当前栏目、“最新”和正文二级标题用荧光笔划一道，图片和封面带一圈白边，时间线是虚线；有浅深两套；胶带颜色故意压得很淡，用户不喜欢糖果色；千禧是 2010 年前后桌面软件的样子：天蓝底带淡淡的方格和玻璃气泡、白色卡片、带高光的蓝色按钮，阅读正文是一扇带三色灯标题栏的窗口（用户给了参考图并从三个方向里选定，原来的粉蓝糖果色已弃用）。新加组件先在墨水下做好，再到另外三套下各看一遍；直接写死的圆角和颜色在千禧下会露出来，写死的背景会盖住手帐的点阵纸。手帐沿用墨水的文楷，千禧用系统黑体，都不另加字体；原来像素主题的两个点阵字体依赖已随像素一起删掉。

字号与圆角各有一套档位，定义在 `globals.css` 顶部：字号九档（`--text-xs` 12 到 `--text-3xl` 28），圆角四档（`--radius-xs` 6、`--radius-sm` 10、`--radius-md` 16、`--radius-lg` 22），另有 999px 的胶囊和 50% 的圆。新样式只用这些变量，随窗口变化的大标题用 `clamp()`；`tests/style-scale.test.ts` 会拦下写死的像素值。主题样式同样只用这些档位，没有例外（像素主题删掉后，它那几个点阵字档位也一起去掉了）。列表里的年份分组标题统一用 `.section-title`，时间线上的月份是线上的小字。

字体有三个变量：`--font-sans`（正文）、`--font-hand`（霞鹜文楷，标题与短文字）、`--font-mono`。文楷来自依赖 `lxgw-wenkai-screen-webfont`，在 `globals.css` 顶部引入，构建时字体文件随站点一起发布，不请求第三方地址；它按字符范围切成约一百个小文件，浏览器只取页面用到的几片。这个字体只有一种字重，用它的地方字重都写 400，不要加粗。纸纹是 `--grain`，只铺在页面底色上，卡片和图片上没有。

几条容易踩的边界：

- **`blocks.tsx` 两边通用**。它没有 `"use client"`，服务端页面和浏览器端组件（展开的动态）都会用到，所以不能在里面引入只能在服务端运行的东西。代码高亮与公式通过可选的 `extensions` 注入：页面里用仅服务端的 `RichDocumentBody`；浏览器端用 `BrowserDocumentBody`，它把代码与公式片段交给 `src/lib/render/actions.ts` 的服务端函数排版，失败时保留普通文本。高亮与公式库不要引入浏览器端。
- **课程目录在布局里**。`study/[course]/layout.tsx` 同时包住课程页和它下面的笔记页，读者在同一门课里切换笔记时目录不会重读。当前页高亮和上一篇／下一篇因此在浏览器端按路径计算（`course-tree.tsx`、`note-pager.tsx`）。目录读取很慢时这一点很重要，不要把目录挪回页面里。
- **课程目录会把当前页带进可见范围**。宽屏上目录粘在侧边、自己滚动；进入页面或在同一门课里换页后，当前页不在目录的可见部分时把它滚到中间，已经看得见就不动（`course-tree.tsx`）。目录的滚动条是一条细线，颜色跟主题走，系统设置为始终显示滚动条时不再是灰色的轨道。有子页面和没有子页面的条目文字起点对齐；子页面数量不显示在行尾（用户选定），读屏仍从展开按钮读到。目录到第四层为止逐层缩进，再深的层级不再继续往里缩，侧栏只有 260 像素宽，标题更需要这点宽度。
- **正文末尾不多留空**。正文、分栏的一栏、提示块、折叠块的末尾：来源里留在最后的空段落不占位置，最后一个非空的块不带下边距，卡片底部和顶部留得一样多；块与块之间的空段落是作者有意留的，照常保留。规则在 `prose.css` 开头，选择器写的是“后面再没有非空兄弟的块”。分栏在窄屏上叠起来时每栏占满整行：各栏的伸展系数由 `src/lib/columns.ts` 从来源的宽度比例换算成不小于 1 的数，小于 1 的系数会让独占一行的栏只占一部分宽度。
- **只装子页面链接的分栏当作一组链接来排**。栏与栏叠起来时相距 10，和相邻两条子页面链接的间距一样；这种分栏的下边距也是 10，所以后面紧跟一条子页面链接、另一组这样的分栏或一段文字时，间距和一条子页面链接后面的一样。分栏里只要有别的内容（文字、图片等），仍按普通分栏的 18。下边距那条规则写在 `:where()` 里，是为了让“正文末尾不多留空”那条规则继续优先，别去掉。
- **封面读不出来时不露出浏览器的破图标**。课程、博客与项目详情、动态、文章列表、相册的封面都用 `cover-image.tsx`。封面还没到时原位是一块浅色（来源给了宽高、调用处也愿意时，按比例先占好位置），到了之后浅色撤掉。读不出来时分三种：详情页和动态里换成和正文图片同一种“封面暂时无法显示”的浅色块；文章列表的卡片直接不放图，和没有封面的卡片一样；相册显示带标题的格子，和没有封面的相册一样。封面常常在页面可交互之前就已经有了结果，所以组件挂载时会看一眼图片当时的状态，不只等事件。作品库的格子用自己的 `Cover`（书脊那一种），首页小卡片与社交卡片的封面是装饰图，没有替代文字，读不出来时只是一块浅色。
- **动态的封面按自己的比例显示**（`.entry__cover` 的 `height: auto`）。来源声明了宽高时，没有这一条的话声明的高度会原样生效，手机上一张横图会被裁成竖的方块。超过 360 高的仍按 360 裁切。
- **面包屑按一行文字排**，不是一排弹性项：长标题在标题内部换行，分隔符不会孤零零挂在行尾。
- **“学习”这一级面包屑由页面自己渲染**，并忽略数据里指向 `/study` 的项。数据库来源不带这一项，直接读来源时带，两边要显示一致。
- **标题层级跟着上下文走**。正文标题的标签由 `src/lib/headings.ts` 换算：正文里最浅的一级紧接它上方的标题，字号仍按来源层级的类名。在别的标题之下渲染正文时，给 `DocumentBody` 传 `topHeading`；时间线的月份与动态标题层级由 `StatusTimeline` 的 `level` 决定。
- **作品列表里标题下面那一行按“一件事一段”来排**。状态、平台、时长、评分各是一段（`src/lib/library.ts` 的 `summaryParts`），段与段之间的小圆点挂在后一段前面的空隙里；窄屏上放不下时在段与段之间换行，换行后圆点落在裁切范围之外，所以不会有以圆点开头或结尾的一行。做法和社交卡片的平台那一行相同（`library.css` 的 `.library__meta`，别改回把圆点写进文字里）。
- **悬浮的“回到顶部”不压住正在读的内容**（`back-to-top.tsx`）。页面的内容栏伸到按钮底下时（手机、较窄的窗口），按钮只在读者往回滚的时候出现，继续往下读就收起；内容栏碰不到按钮的宽屏上，滚深了就一直在。判断用的是内容栏右缘和按钮左缘的实际位置，不是固定的断点；几像素的抖动不算换方向。到页脚时照旧收起。
- **列表里的行内公式和正文里的一样排版**（`typeset-inline.tsx`）。动态条目未展开时显示的那段文字里如果有行内公式，先显示公式原文，随后向服务器要一次排好的标记，做法与展开后的正文相同，排版库不进浏览器；同一个公式只要一次，没有公式的条目不发请求，排不出来的保留原文。
- **封面形状按栏目定**。影视和书籍是 2:3 的竖版，游戏是 16:9 的横版（真实游戏封面都是横图）；读不出来的封面和没有封面一样显示带标题的格子。新栏目接入真实数据后先量一下封面比例再定格子。
- **开发缓存是关着的，不要打开**。`next.config.ts` 里设了 `experimental.turbopackFileSystemCacheForDev: false`。开着的时候，`next dev`（包括 `npm run dev:real` 的真实数据预览）在保留的 `.next/dev` 缓存上重启后，可能对每次页面加载都回“版本不一致”，页面每秒整页重载十几次、每次都重读一遍内容来源，不会自己停下；这与页面内容无关，生产构建也没有这个问题。代价是每次启动后第一次打开页面要重新编译。升级 Next.js 后如果想重新打开，先按进度记录“开发模式无限重载的真正原因”一节的步骤确认不再复现；用脚本打开真实预览时照旧数整页请求数，超过一次就立刻离开。
- **作品的日期也按动态的规则写**（2026-10-14，排查 09）：首页作品清单、首页一排小卡片、作品页左边的日期，七天内写“今天”“昨天 · 10 月 13 日”“N 天前 · 日期”，只到日、不带钟点。规则在 `src/lib/works.ts` 的 `workDayMoment`，输出用 `entry-moment.tsx`，“今天”来自 `use-today.ts`，和动态共用一套，不要另写。作品行里各部分之间的“·”挂在间隙里（`.home-works__part`、`.work-card__part`），折行后落在裁切范围外，所以“昨天 · …”换到下一行时不会以圆点开头。
- **搜索的栏目筛选按下立即有反应**：和动态、作品库的筛选一样用 `link-pending.tsx`，被按的那一项马上变成选中的样子，结果区变淡，新结果到了恢复。
- **正文图片先用 800 宽的小图**（用户 2026-10-14 定的）：影视、书籍、游戏详情，课程页，学习笔记，关于（页面与弹层），博客文章，项目详情，以及动态展开后的正文，都给正文传 `imagePreviewWidth={800}`；点开看大图时再取原图。相册仍是 400。没有小图的图片由媒体路由退回原图，页面不需要特别处理。小图请求本身失败时（2026-10-16 线上出现过读取小图约 12 秒后返回 503），正文图片、各种封面和动态卡片的小封面都改取一次原图，原图也失败才显示失败状态（`content-image.tsx`、`cover-image.tsx`、`library-grid.tsx` 的 `Cover`）；改取原图后看大图不再先垫小图。
- **苹果主题的蓝与灰比苹果官方深一档，按钮另有一个底色**（2026-10-14，反馈交接包 11）。浅色的强调色是 `#0066cc`、次要灰是 `#636366`，在页面底色、`--soft` 和菜单选中的浅蓝底上都过 4.5:1；深色的强调色仍是 `#2997ff`（作文字在深底上很好），但白字放在它上面只有 3.0:1，所以主按钮取单独的 `--button`（深色 `#0071e3`，浅色等于强调色），悬停时往黑色混而不是往白色混。新加白字放在强调色上的地方，用 `--button`，别用 `--accent`。
- **“加载更多”被拒时先找回读者的位置**（2026-10-15）。列表的翻页标记会因为数据变了而被接口拒绝（社交数据每 15 分钟刷新，首页最常见）。共用的 `use-paged-list.ts` 这时不再直接从第一条重来，而是用 `src/lib/paging-resume.ts` 从头一页页读，直到遇到屏幕上最后一条，把它后面还没显示的接上；上面新出现的条目和已显示条目的变化留到下次打开，所以屏幕上的东西不动、也不提示。最多读“已显示条数 ÷ 页大小 + 2”次、不超过 10 次；找不到（那一条被撤回、途中又变了、或超出次数）就再试一次，仍不行才按原来的做法从第一条重新加载并提示“内容有更新”。
- **游戏详情的日期行**（`src/lib/game-dates.ts` 的 `gameDateRows`）：平台给了日期时，先列“最近游玩”“首次游玩”（各自有才列，只到日），手填的日期有才跟一行“体验日期”；没有手填日期就不列这一行，不显示“日期未记录”（用户 2026-10-16 定的，见 [决策记录](decisions/2026-10-16-hide-empty-experience-date.md)）。平台什么都没给的游戏仍是一行“游玩日期”，没有就写“日期未记录”。
- **填色的当前项获得焦点时，焦点框用它自己的文字色**（2026-10-15）。筛选条在横向滚动时把焦点框画在项目内侧（`.segmented--scroll a:focus-visible` 的负偏移）；千禧主题的当前项是用强调色填满的，原来的强调色焦点框画在里面就看不见了，所以千禧里只对滚动的筛选条（`.segmented--scroll`）改成 `currentColor`。不滚动的筛选条（作品库的状态切换）焦点框画在外侧，仍用强调色；2026-10-16 之前这条规则写宽了，外侧的焦点框也变成了文字色，在千禧下几乎看不见。新加用强调色填满的可聚焦元素，也要看一眼焦点框落在哪种底色上。
- **看大图在舞台上什么都还没有时，中间有一个转圈和“正在加载”**（`lightbox.tsx` 的 `painted`）。线上作品库与相册的照片多数还没有小图，页面上的“小图”地址其实返回原图，看大图要等几兆的原图到了才有画面；以前这段时间舞台全黑，只有顶部一行小字。任何一个版本的图片画出来，转圈就撤掉。
- **页面过渡要等访客第一次操作才打开，不要改成一直开**。`PageTransition` 起初把过渡设为“无”，访客第一次按键或点按（总在换页之前）之后才打开，此后不再关。一直开着的话，页面加载过程中自己发生的每一次内容替换（整页内容换掉“正在加载”、首页时间线稍后流出来、封面占位出现）都会被做成一次视图过渡，本机测得页头变得可交互的时间因此晚约 0.4 秒。改这里之后要验三件事：各页面首次加载期间 `document.startViewTransition` 一次都不被调用；第一次操作就是点栏目链接时，淡出淡入已经在；动态页年份与作品库状态切换时选中块仍然滑动。（这一条当初是为偶发的水合错误加的，后来查明那个错误另有原因，见下一条；这里的做法因为上面的好处保留了下来。）
- **换页是一次交叉淡化（2026-10-21，反馈 F43，取代 10-17 的“换页只淡一次”）**：站内换页不再用视图过渡，由 `page-switch.tsx` 负责。点下站内链接（Next 已接管的点击，且地址的路径变了）或前进／后退时，把旧页的页面区和页脚复制成一层静止、不透明的画面（铺同样的纸底，固定在页头下面），下面真实的页面照常换成加载状态再换成新页，读者看不到；新页到了（路径对上且页面区里没有 `.page-loading` 或 `[data-page-loading]`）再让这层在 180 毫秒内淡掉。60 毫秒内没到就算“在等”：旧页降到 55%，页头下出现 2 像素的强调色进度条，1.6 秒长到 85% 后停住，到达时补满并淡出。等待中再点别的页面只重新开始进度条，最后只淡到最后点的那页。同一门课里换笔记只复制笔记那一栏，左边目录不动。复制时去掉 id、把 iframe 换成同尺寸的空块、粘住的栏（目录、本页目录）按屏幕上的位置画，祖先的类名用 `display: contents` 的空壳带上，所以按祖先写的样式照样生效。新加的加载状态要么带 `page-loading` 类，要么像首页那样放一个 `<span data-page-loading hidden />`，否则换页会在加载状态上就淡出。筛选、排序（同一路径）不经过这里：筛选链接带 `transitionTypes={FILTER_TRANSITION}`（`src/lib/transitions.ts`，故意放在普通模块里：服务端页面要用），只让选中块滑动、列表原地换；新加的筛选链接照样带上。页头不参与：导航的当前栏目和墨线在按下时就移过去。直接打开、刷新、新标签页没有旧页可留，仍显示各栏目自己的加载状态。
- **每个栏目都有自己的加载占位**：根目录的 `loading.tsx` 现在只给首页用，画的就是首页本身的开头（`home-hero.tsx`，内容全来自站点设置）加时间线的浅色条，首页到达时不移动；其他栏目各有一个 `loading.tsx`，用通用的 `page-loading.tsx`（够高，页脚不会先露出来再被推下去）。新加栏目时也要加一个，否则会借用首页的样子。
- **服务端文件只能从 `"use client"` 的文件里拿组件，不能拿普通的值**。布局曾经从 `theme-toggle.tsx`（客户端文件）拿首屏主题脚本的文字，放进 `<head>` 里的 `<script>`。从客户端文件拿来的值，到了浏览器那边不是文字本身，而是“去那个文件的代码里取”的一个引用；页面变成可交互时，`<head>` 里这个元素要等布局的脚本文件到齐才能继续，脚本到得晚的那些次，React 就报水合错误（#418）并把整页丢掉重画——线上约十次冷启动一次。现在脚本文字直接从 `src/lib/skins.ts` 拿。`tests/client-boundary.test.ts` 拦这类写法：`src/app/` 下的服务端文件从客户端文件引入的名字必须是大写开头的组件。
- **关于弹层的内容是点开才读的**。`about-dialog.tsx` 第一次打开时请求 `/api/pages/about`，用 `BrowserDocumentBody` 渲染，之后再开不重复请求；不要改成随首页一起渲染正文，首页不该为它多读一页。头像上的链接是等“关于页可读”的检查（`request-cache.ts` 的 `isAboutAvailable`，开关开着并且这一页已发布；检查慢或失败都算不可读）有了结果才盖到头像上的，放在自己的 Suspense 里，首页的个人介绍不等它；页脚的“关于”链接用同一个检查。链接本身指向 `/about`，脚本没到或被修饰键点击时照常跳转。
- **弹层里还能再开弹层**。正文图片的看大图也是一个对话框，它的关闭事件会经 React 传到外层对话框的 `onClose`；外层要先比对 `event.target`，否则关掉大图会把关于弹层的内容一起清掉。
- **看大图先用页面上的小图垫着**。列表里显示的是 400 像素的预览，看大图要的是原图，原图要几秒才到。`lightbox.tsx` 打开时先显示页面上已经有的那张预览（同一个地址的第二个图片元素会直接复用页面里的那张，不再请求），同时在后台取原图，解码好了再原地换上；顶栏这段时间写“正在加载原图…”，原图取不到时保留预览并说明。照片的宽高已知时，一打开就按最终的位置和大小摆好（`prose.css` 里用舞台的容器查询单位算），所以换上原图时不会跳。页面上的版本本身已经是原图（没有生成预览时预览地址会跳到原图）就不再取第二遍。`ContentImage` 登记图片时把预览地址和宽高一并交给看大图。
- **等图的格子不是空白**。图片淡入靠 `is-loading` 把图片本身设为透明，图片自己的底色也跟着看不见；占位的浅色块画在外面那层按钮上（`.figure__zoom:has(> img.is-loading)`），图片到了就撤掉。
- **图片一律用普通 `<img>`**，不要换成图片优化组件。站内媒体地址每次访问都会重新检查资格，经过优化缓存会绕过这层检查。
- **目录、笔记和学习首页的课程卡片都是 `prefetch={false}`**。一门课可能有几十篇笔记，每篇预取都要读上游；课程地址在送出页面之前也要先向内容服务核对一次，十几张卡片就是十几次。
- **公开页面可缓存（2026-10-21，用户的决定；后端缓存开关默认关）**。接口与后端机制见 [公开内容缓存](PUBLIC_CONTENT_CACHE.md)，页面这一侧的规矩：
  - 失败时直接报错的页面（关于、相册、作品库详情、笔记、学习首页、学习项目、博客与项目）写字面量 `export const revalidate = 86399`，页面函数第一行 `await freshWhenUncached()`（`src/lib/page-freshness.ts`）：缓存开关关着时它让页面照旧按请求生成，否则这一天的页面没人刷新。
  - 自己显示失败提示的页面（首页的动态、课程页与笔记布局的目录）第一行 `await alwaysFresh()`，始终按请求生成，免得“没加载成功”被当成页面缓存一天；它们的数据仍走共享缓存。
  - 带地址查询的页面（作品库列表、动态、作品页、博客列表）读查询本身就按请求生成，不写这两行。搜索与预览保持 `force-dynamic`。
  - 页面不再传服务器时刻 `now`，“今天”和是否省略年份都在浏览器端判断（见下面 `use-today.ts` 一条）。
  - 版本监听 `public-cache-watch.tsx` 挂在 `PageTransition` 里，根布局不动：根元素有 `data-public-cache="tagged-v1"` 时，页面可见期间每 30 秒问一次 `/api/content/version`，页面重新显示时也问一次；版本变了先清 `use-paged-list` 的记忆再 `router.refresh()`；404 即停。不要给列表或图片再各加轮询。
- **影视、书籍、游戏的卡片按意图预取**（`library-grid.tsx` 的 `WorkLink`）：平时不预取；指针在卡片上停约 120 毫秒、键盘聚焦或手指按下后，才让 Next 预取这一页。这一页是按请求生成的，预取只拿到 `[slug]/loading.tsx` 的骨架和页面标题；服务器为此读一次这部作品，不读正文。点下去时卡片立即变淡（`LinkPending`），有预取的直接换到骨架。详情页的标题和正文共用一次读取（`page.tsx` 里的 `cache`）。扫过一排卡片不会触发预取，不要把停留时间去掉。
- **分页共用 `use-paged-list.ts`，列表末尾共用 `list-tail.tsx`**：钩子一次只发一个请求、按 ID 去重、游标失效时从第一页重来并提示；`ListTail` 在读者接近末尾（提前 240 像素，故意留得短，一页可能带很重的图片）时调用钩子的 `loadMore`。新列表直接用这两样，筛选条件变化时给列表组件换 `key` 来清空游标。三条不能破的规矩：加载失败或服务繁忙后不再自动请求，等读者按“重试加载”；游标失效重来之后、或者某一页没有带来新条目之后，同样停下等读者按（钩子的 `held`），真实数据不允许循环请求；末尾那个控件始终是一个真正的按钮，只是自动加载时画成一行小字，键盘和没有滚动观察的浏览器靠它，加载中用 `aria-disabled` 而不是 `disabled`，否则键盘焦点会掉。
- **返回时列表回到原来的样子**。读者翻了几页、点进一条再按浏览器的返回（或前进），列表恢复已加载的条目和滚动位置，不重新请求；通过链接再进同一页则从第一页开始。做法在 `use-paged-list.ts` 顶部：按“接口加查询条件”把已加载的内容记在内存里（只留最近六个列表，刷新页面就没有了，不写进浏览器存储），只有浏览器的返回或前进落在同一个地址时才取用。年份、状态、排序、标签、搜索词都在查询条件里，所以各自分开记。
- **作品库年份已经接入**：页面用 `contentRepository.getLibraryYears(kind, { status? })` 取年份统计，列表的 `year` 与状态、排序一起进地址、列表组件的 `key` 和翻页请求（接口见 [接口说明](LIBRARY_YEARS_API.md)）。读年份参数、拼年份选项、算条数的函数在 `src/lib/year-filter.ts`，动态页与作品库共用。两条规矩：换状态时年份跟着带过去，新状态下没有这一年就显示这个状态的全部，不给一页空列表；年份统计读不出来时只是不显示年份切换，列表照常。
- **筛选链接里放一个 `LinkPending`**（`link-pending.tsx`）：它用 `useLinkStatus` 在这条链接的页面还没到时给自己加上 `data-pending`，本身不占位置也不显示；“被点的变深、旧列表变淡”全靠样式里的 `:has(.link-pending[data-pending])`（`library.css` 末尾），不用另外传状态。新加的筛选链接照样放一个即可。选中项的滑动仍然是到达时的视图过渡，没有改。
- **首页时间线来自后端的混排入口（v2）**。首页用 `homeFeedV2Repository.getPage` 与 `/api/home/feed-v2`（契约在 `contracts/social-timeline.ts`，说明见 [合集云端与时间线 v2](SOCIAL_COLLECTIONS_CLOUD.md) 与 [首页混排接口](HOME_FEED.md)）：每一项要么是站内内容（`source: "content"`，里面的 `event` 就是原来的时间线事件，照旧渲染），要么是发在其他平台的作品（`source: "social"`）；作品的 `work.collection` 非空时是合集或多 P 视频；两种都由 `social-work-card.tsx` 画成一张卡。**首批和翻页必须用同一个版本**：v1 与 v2 的游标互不相认，混用会被拒绝。跨来源的排序、同日合并、合集与单个视频的去重、分页都在后端；`src/lib/timeline.ts` 管站内事件的显示文字，`src/lib/home-feed.ts` 管社交作品的平台名与数字。社交来源默认关闭，关闭时首页和原来一样。v1 的 `homeFeedRepository`／`/api/home/feed` 以及更早的 `getTimeline`／`/api/timeline` 仍在，首页不再使用。
- **社交作品的数字不相加、不补值，卡片上只留播放和点赞**。一个作品一张卡片，只显示所在平台自己的数字，而且只有播放与点赞两项（用户定的：其余的投币、收藏、评论、弹幕、转发不再显示；小红书没有播放量，只显示点赞）。**B 站只留播放（2026-10-17，反馈 F22），播放未知时不拿点赞或别的数字顶上。**其他平台两项都没有而有别的数字时，用它有的第一项顶上，免得有数字的作品被写成“数据未记录”；规则在 `src/lib/works.ts` 的 `leadingFigures`，首页卡片、首页清单和作品页共用。有精确值就用精确值（0 是真的 0），没有精确值但平台给了约数（如“1.2万”）就原样显示，都没有就不显示这一项；一项都没有时写“数据未记录”。只有核对过的原帖地址才是链接，“原平台可能要求登录”只念给读屏，不再占一行。没有日期的作品归在“日期未记录”下。
- **页面上不写数字是什么时候读的**（用户 2026-10-14 定的：先是改成只在超期时写，同一天又定为连超期也不写，因为“未按期更新”说的是后台采集的状态，不是读者关心的事）。鼠标停在数字上仍能看到读取时间（合集另注明是整个合集的合计）。时间取那一处自己的 `observedAt`（合集取 `collection.observedAt`），按站点时区显示，与当年同年时省略年份。各平台按各自的周期采样（B 站 6 小时、小红书 24 小时），**不能拿一个平台的时间代表另一个**，也不能用页面加载或上传的时间。悬停提示的时间来自 `src/lib/home-feed.ts` 的 `sampleTime`；它仍按后端的 `socialSampleStatus` 算出是否超期（`overdue`），但页面已经不用这一项。“现在”取服务器生成页面的时刻，由页面作为 `now` 传下去，用来决定是否省略年份。没有数字的不给提示；时间不合规时也不给，不猜。
- **作品卡片按所在平台的样子画**（`social-work-card.tsx`，用户 2026-10-14 从三个样子里选定，取代原来的作品卡与合集卡）。B 站是 16:9 的封面，左上角一枚小签写类型与集数（“合集 · 12 个视频”“多 P 视频 · 26 个分 P”“视频”），播放和点赞压在封面底部，下面是标题和平台名；小红书是 3:4 的竖封面，标题最多两行，下面一行平台、类型和点赞。形状由平台决定（`src/lib/works.ts` 的 `coverShapes`），封面图按框裁切。几条规矩：
  - **没有封面就是没有画框的同一张卡**：标题、一行平台与类型与集数、带文字标签的播放和点赞、右上角一个去原帖的箭头。不画假封面。现在数据里封面全是空的，所以线上看到的都是这个样子；后端给出封面后自动换成带封面的样子（见后端交接包第十二节）。
  - **封面读不出来**时退回占位（一块浅色加平台标志），用的是 `cover-image.tsx`，不露出浏览器的破图标。
  - **小图档位跟画框形状走，不跟卡片大小走**（`coverPreviewWidths`）：横封面要 800，竖封面要 400。横封面在手机上占满整行，400 在高分屏上会发虚。`imagePreviewSrc` 不认得的地址会原样返回（取到原图），后端给作品封面定了新的站内路径之后，要在同一次发布里让它认得。
  - **整块是一个链接**，只在地址核验过（`originalUrl` 非空）时才是；地址原样使用，不改写、不去参数。没有地址时同样的卡片不可点。卡片在页面里先写标题再写封面上的字（封面用 `order` 挪到上面），所以读屏先念标题。
  - **合集的变化只写真的变化**：第一次采到只是基线（`latestAddition` 为空），不写任何一行（原来写的“最近一集发布于某日”和条目自己的时间重复，已去掉）；成员有明确发布时间的写“新增 N 个视频”；只是被发现的写“发现新增…”并注明“发布时间未知”，条目时间旁另标“发现更新”。取舍在 `src/lib/home-feed.ts` 的 `collectionAddition`。
  - **数字**是平台给的合集合计，不把各集相加。
  - **同一作品还发在别的平台**时，卡片下面每个平台加一行：平台、类型、它自己的播放与点赞、它自己的地址。数字各算各的，不相加。
  - **封面上的字固定是深色底上的白字**，不跟主题变，因为底下是图片。
- **作品页（`/works`）**。服务端用 `socialTimelineRepository.listWorks`，翻页用 `/api/social/works/v2`（一页最多 20 件）；显示规则在 `src/lib/works.ts`，一行是 `work-row.tsx`，列表是 `works-list.tsx`。三件事别改坏：
  - **类名前缀是 `work-row`，不是 `work`**。`.work` 已经是作品库详情页的类名，撞上之后整行会被排成详情页的样子。
  - **各栏是整张表共用的**（`subgrid`），日期、标题、平台、数字才能上下对齐。除标题外各栏都按内容定宽：一行自己的内边距会算进两边的栏，写成固定宽度的栏不会，箭头就会被挤出去。
  - **`src/app/works/loading.tsx` 别删**。它既是读清单时的占位，也让导航对这一页的预取停在占位上；没有它，预取可能把清单也读一遍，而读社交数据的连接很少（见后端交接包第十一节）。
  - **数字只有播放和点赞，不写读取时间**，和首页卡片一致。左边的日期按动态的规则写（“昨天 · 10 月 13 日”），这一栏随最长的一项变宽，日期不换行。页头只有“作品”两个字，没有说明；总数在列表末尾。一件作品发在几个平台就有几行，各带各的数字与地址，不合并、不相加。
  - **有封面之后改成卡片，等高排列**（用户 2026-10-14 从三个样子里选定，另两个：封面都裁成正方形的网格、清单每行加一张小封面）。只要已加载的作品里有一件带封面，整页就用 `social-work-card.tsx` 的小号卡片（和首页那一排同一个）：B 站横封面一行三张，小红书竖封面取能和它等高的宽度（横封面宽度的 27/64），所以各平台保持原形、一行齐平，右边缘不齐是有意的。小号卡片的数字都压在封面底部，标题下面是平台标志和日期。没有封面的作品在行里用占位补齐，所以只有一个平台先有封面时也能看。手机上（640 及以下）是两列，横封面占整行、竖封面占一列，空位由后面的竖封面补上，因此相邻两件的先后可能和时间差一位。尺寸用容器宽度算（`.works__grid` 是容器，`timeline.css`），不要改成固定像素。**全都没有封面时仍是下面这张清单**，现在线上就是。
- **首页时间线里作品上方的“作品”标签是进作品页的链接**（`prefetch={false}`）。这类条目只在社交来源打开时出现，作品页也是，所以不用另外判断。
- **首页上连着的几件作品合成一个条目**。时间线里前后相连、中间没有别的条目的作品（发在其他平台的作品与合集），两件及以上时合成一个条目：上方写它们覆盖的日期（最早到最晚）、“作品”标签和件数。下面怎么排看有没有封面：**其中有封面时是一排小卡片**（`work-strip.tsx`，和单张卡同一个组件的小号，各带自己的日期），放不下就横向滑动——手指直接滑，键盘靠卡片链接或方向键，鼠标另有左右两个小按钮（按钮只是滚动的重复，不进 Tab 顺序、不念给读屏）；一排里没有封面的卡片用占位补齐，免得高矮不一。**全都没有封面时仍是原来的清单卡**，一行一件——标题、平台与类型、日期、播放与点赞、去原帖的箭头；同一作品在几个平台各占一行、共用一个标题。单独出现的一件是一张完整卡片。**B 站作品有封面时（2026-10-17，反馈 F22，用户选“丙”）一律画成 B 站主页式小卡片（`bili-card.tsx`）**：16:9 封面带阴影，左上角 B 站标志加类型，封面底部左边播放、右边集数（只有合集与多 P 有），没有白色卡片底板；封面下标题最多两行（手写体），再下面日期与“新增 N 个视频”（强调色，放不下整段换到下一行）。桌面一排四张（每张约 160 宽起），手机每张 200 宽、露出下一张。单独一件有封面的 B 站作品也用同一种卡（一排里只有一张）。小红书和同时发在几个平台的作品仍用原来的卡片；读屏先念标题和日期，再念平台、类型、播放与集数。一组不跨月，因为月份标题排在条目之间。规矩和卡片相同：各平台的数字各算各的，未知不显示，只有核对过的地址才是链接，超期时才写“数据截至……，未按期更新”。分组在 `src/lib/timeline.ts` 的 `feedRuns`，两种排法都在 `home-works.tsx`；翻页带来的作品如果接着上一页末尾的作品，会并进同一组。
- **“今天、昨天”按日历日算，“今天”是哪一天由 `use-today.ts` 给**。规则在 `src/lib/format.ts`（`relativeDay`、`momentLabel`）：比较的是站点时区下的两个日历日期，不是相差的小时数——站点时区有夏令时，换时那天不是 24 小时，按小时除会差一天。页面会被缓存最长一天，服务器生成页面的时刻不代表今天，所以页面不再传 `now`：缓存的页面和接管它的首次渲染都不知道“今天”（`null`），日期写全；接管后立即改用访客设备的时钟，页面重新显示时和每过一分钟查一次，只有日期变了才重新渲染，页面开一夜不会还写着“今天”。这是用 `useSyncExternalStore` 做的，设备时钟和服务器差一天也不会报水合错误；别改成在渲染时直接 `new Date()`。时间那一行的文字统一由 `entry-moment.tsx` 输出，相对说法与间隔号之间是不换行空格、日期整体不换行，窄屏只会在间隔号之后折行。首页一组连着的作品只覆盖一天时同样加相对说法，跨多天的仍是“…至…”。作品卡片上“数据截至”的时间不用这套写法。
- **真实作品和演示内容混排时逐条标“演示”**。社交来源打开而站内内容还是演示数据时，每条演示内容自己带“演示”标记，页脚的说明也相应改口；全是演示内容时仍只靠页脚那一句。
- **请求入口先判断页面在不在**（`src/proxy.ts`，共享范围，改之前先问用户）。关于页、各详情页和带定位的动态链接，在页面开始输出之前先用元数据查一次，结论有三种（`src/lib/route-verdict.ts`）：在，放行；不在，地址不变、改由 `/content-not-found` 这一页应答，状态码 404；**不知道**（查询本身失败），地址不变、改由 `/content-unavailable` 这一页应答，状态码 503，显示“页面暂时打不开”和重试，重试就是重新载入这个地址。两种情况都不能让错误直接抛出去，否则访客看到的是一页空白的“Internal Server Error”，连页头都没有。**“不知道”时不要改回“放行并把状态码设成 503”**：那样在本机没问题，但在正式环境里只对没有参数的地址（如关于页）有效，课程、笔记、作品详情、相册这些带参数的地址会被部署平台换成它自己的一行英文报错（2026-10-13 内容停摆时在线上看到）；改由固定地址应答则对所有地址都有效，404 一直是这样做的，503 这一种也已在当晚的又一次停摆里在线上确认。代价是入口的查询偶尔失败而内容其实读得到时，访客先看到提示，重试即可。列表页不经过这次查询，读不到时是 200 加同一个提示（`error.tsx` 与那一页共用 `page-unavailable.tsx`）。没有被入口覆盖的地址，带加载占位的动态页面内容是“找不到”时状态码仍是 200 并带禁止收录标记，做站点地图或收录时要考虑。
- **网站图标是按配置生成的**。样子是“方印”：墨色圆角方块上纸色的姓名首字母，浅色、深色各一版（用户从六个样子里选定）。字母取自私有站点配置里的姓名，仓库里没有任何缩写；没有配置姓名、或首字母不是 A–Z 时改画首页那一笔墨线。地址是 `/site-icon/light`、`/site-icon/dark`、`/site-icon/apple` 和 `/favicon.ico`，由 `src/lib/site/icon.tsx` 输出 PNG；字母轮廓来自文楷，存在 `src/lib/site/monogram-glyphs.ts`（由 `scripts/extract-monogram-glyphs.py` 生成，字体包升级时才需要重跑）。标签页图标默认跟随系统深浅色；访客手动切换主题后，`theme-toggle.tsx` 会把图标链接改指向所选主题。
- **个人信息不进仓库**。名字、简介、头像、社交链接来自忽略的 `config/site.json` 或环境变量 `SITE_CONFIG_JSON`，仓库里只有空示例。没配置时显示通用站名、没有问候语。

## 怎么验证

改完至少跑这三样，和云平台的构建方式保持一致：

```sh
npm run check
npm run build
npx next build --webpack && node scripts/check-build-privacy.mjs
```

云平台用的是第三条里的打包方式，和本地默认的不同，新增依赖后尤其要跑。

浏览器验证有三种预览，同一个工程目录里一次只能开一个开发服务器：

```sh
# 演示数据，不需要任何凭据
CONTENT_PROVIDER=mock npx next dev --port 3101

# 演示数据的生产构建，用来查水合错误和主题闪烁
npm run build && CONTENT_PROVIDER=mock npx next start --port 3103

# 真实数据：用设备上已有的私有环境文件启动，读取很慢属正常
npm run dev -- --port 3102
```

验证时的几个办法：

- **看关闭的栏目**：启动预览时用环境变量打开，不用改文件，例如 `CONTENT_FEATURES_JSON='{"post":true,"game":true,"page":true}' CONTENT_PROVIDER=mock npx next dev --port 3101`。
- **看分页**：演示数据的首页有八页、动态三页、搜索“演示”十几页，影视、书籍、游戏、博客各两页，直接滚就能看；要模拟失败、繁忙或游标失效，在浏览器里拦截对应的列表接口。
- **看带图动态与年份切换**：演示数据里没有，只能在真实数据下看。
- **宽度**：手机 375、平板 768、桌面各看一遍，并确认页面本身没有横向滚动；表格和代码块在自己的区域里滚动。
- **四套主题都要看**（页头菜单切换，或在控制台写 `localStorage.skin`），深色下留意自己新加的颜色有没有走变量，千禧下留意写死的圆角，手帐下留意写死的背景色。

真实数据只读、每次打开页面都会访问上游，验证时点到为止，不要循环刷新。

## 做事方式

- 每项工作从最新的 develop 开短期分支，向 develop 开合并请求；按影响范围完成本机验证后自行合并，不等平台检查（develop 约每两小时集中检查一次，发布版本仍须通过平台检查，见 AGENTS.md）。发布到 main 只由用户合并，不要自行合并到 main。Git 上的文字（分支名、提交信息、合并请求）用英文。详见 [共同约定](../AGENTS.md)。
- 自行合并不包括替用户做决定：要先看方案的改动，仍然等用户挑完再实现和合并。
- 和用户对话、项目文档、界面文案都用中文。
- 用户希望先看到方案再定：涉及视觉或排版的改动，先给出可以对比的选项。
- 依赖、契约、fixtures、栏目开关属于共享范围，改之前先和用户确认，并在进度里登记。
- 每次完成后在 [docs/progress/](progress/README.md) 下新建一个文件（不再编辑 PROGRESS.md），写清改了什么、怎么验证的、还有什么限制。只在演示数据下验证过的要明说。
