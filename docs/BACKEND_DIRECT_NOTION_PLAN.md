# B20：直连 Notion 的中央拒绝检查与媒体代理方案

状态：用户已于 2026-10-25 明确批准源码与隔离测试，按本方案实施；真实数据库安装、凭据、联网验收、业务恢复和发布均未获本项授权。实施与验证见本项进度记录。

## 已核实的问题

`getNotionRuntime` 目前只读取 Notion 来源、Token 与图片签名配置，没有接入数据库中央 deny。v2 repository 虽然支持注入 `deniedPageIds`，直连 runtime 没有提供；v1 尚无该输入。图片的旧 `m1` 入口仍调用通用资格解析并向浏览器返回上游 302，现有单页媒体资格方法没有接上。

中央拒绝的权威在数据库；本地空数组、旧导出或 Notion 本身的活动状态不能证明当前未被下架。服务器代取图片也不能直接把任意上游 URL 交给普通 fetch，否则会把原浏览器请求变成服务器出站风险。

## 建议的源码实施范围

| 部分 | 实施内容 |
| --- | --- |
| 单页资格 | 精确详情／链接／媒体按新鲜 page 身份、活动状态、物理 data source 父级和当前 schema 判断 `mode: all` 资格；列表和统计仍完整查询来源。媒体优先用已有 `resolveMediaOwner`，返回 null 后不退回通用解析 |
| 中央 deny 能力 | 新增独立只读 SQL 扩展，按 v1／v2 查询调用方提交的有限页面 ID，只返回对应拒绝标记和政策版本，不返回完整拒绝名单、私有正文或来源信息。冻结迁移不改，不使用同步 writer／owner 连接读取 |
| 权限与版本 | 只给既有网站 reader 组授予该固定函数的 EXECUTE；无直表权限、DML 或新 LOGIN。增加精确能力／目录指纹与角色校验，现有数据库网站默认路径不增加该检查或 SQL 请求；新能力的实际安装仍单独授权 |
| 直连 runtime | `CONTENT_PROVIDER=notion` 必须具备受限只读数据库连接与已安装的中央 deny 能力。缺失时明确 MISCONFIGURED／503，不将“无法检查”当作空名单。此变化意味着直连核对模式不再完全独立于数据库，安装顺序必须先具备扩展与 reader，再采用新直连入口 |
| repository 接线 | 每次操作建立独立的异步 deny 检查端口，按请求页面及学习祖先检查；已发现的候选批量查询，在操作内合并重复 ID，操作之间不缓存正资格。正文内链、列表、目录与媒体共用。政策版本在操作中变化则停止输出，不自动重跑业务读取 |
| 请求限制 | 每次 deny 批次最多 256 个 ID，只回同序布尔结果和固定版本；每个公开操作最多 64 次策略查询、累计 256 KiB 逻辑响应，沿原内容／媒体期限停止，不悄悄增大。超限返回受控不可用，不返回部分结果 |
| `m1` 图片代理 | 仅更改 `CONTENT_PROVIDER=notion` 的现有 `/media/[assetId]` 路径：保留签名格式与当前 owner／block／property 资格，成功返回经校验的图片字节，取消 302；数据库／hybrid 媒体分支的既有交付方式保持其独立范围 |

上述只读策略函数仅核对中央 deny，不要求页面已经同步进已发布批次；来源公开范围仍由当前 Notion 配置及物理父链确定，因此可核对尚未同步的新页面。不能把数据库里尚无该页的内容记录误当成拒绝或许可。

策略版本须同时约束页面和祖先的检查结果，最终输出前再核对。显式被拒绝返回不存在；能力缺失、数据库失败、版本变化或预算耗尽返回不可用。同步程序已有 lease deny 输入保持原规则，不在本项自动安装或替换其运行图。

## 服务器图片读取边界

- 复用既有图片下载校验逻辑和本机 Node 库，不增加项目依赖。仅允许 HTTPS／443，禁止凭据、片段、控制字符、私网／保留／回环／链路本地地址及 DNS 混入这些地址；校验全部 DNS 结果后固定一个公有 IP，TLS 主机名和证书仍按原域名验证。
- 每次图片读取最多两次重定向，每跳重新验证目标和 DNS，每跳只尝试一个已核验地址；无地址切换或业务重试。最多三次图片 HTTP 请求／连接；不得携带访客 Cookie、Authorization、Referer 或转发上游 Set-Cookie。
- 沿用现有媒体 8 秒总期限，正文大小上限 20 MiB；声明大小、实际流量、MIME、魔数及现有图像解码像素边界均核验。JPEG／PNG／GIF／WebP／AVIF 为本项支持范围；SVG／HTML／未知类型、未配置转换器的 HEIC 明确失败，不回退暴露上游地址。
- 采用有界完整缓冲，下载后、发出首字节前重新核对中央政策、Notion owner／祖先、定位与源指纹；期间撤回或换图则拒绝交付。返回 `private, no-store`、`nosniff` 与中性响应头，不转发上游 Location、原始错误或签名地址；客户端取消和期限须终止本轮连接并观察清理。

这里的 20 MiB 是单次图片正文界限，不是云平台计费或整站并发流量硬上限；代理将该直连模式的图片传输移至网站服务器。真实联调、部署与流量窗口不包含在源码批准中。

## 离线验收与安装顺序

先用局部虚构来源、只读策略端口和隔离数据库验证 v1／v2 deny、学习祖先撤回、页面／链接／目录／媒体、策略版本竞态、缺配置／权限／能力失败，以及每批及累计限制。实际 reader／writer／匿名／宽权限角色均做允许与拒绝测试，旧冻结协议保持不变。

图片端用虚构 transport 及仅本机 TLS 夹具核对有效字节、私网／混合 DNS、重定向、错误证书、超量／错 MIME／损坏图片、取消／超时／真实 socket 关闭，以及下载期间撤回／换图。错误不得返回上游 URL，不发真实项目请求。

完成源码后运行完整 check／离线 build、隐私和差异核验，再按日常规则向 develop 开 PR 并普通合并。实际安装必须先验证受限 reader 和独立扩展，再采用新 runtime；不把网站 Git 合并当作真实扩展安装或源任务切换。
