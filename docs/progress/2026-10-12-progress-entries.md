## 起因

用户问三个打开的合并请求（#71、#102、#104）为什么冲突。三个都只冲突在 `docs/PROGRESS.md` 顶部，没有代码冲突：每个请求都在同一位置加一节，其中一个合并后其余的就全部冲突。`.gitattributes` 的“两边都保留”只在本机生效，本机模拟这三个合并都干净，GitHub 上全部报冲突。当天约四个半小时合并了 40 个请求，#102 合入最新 main 四分钟后又因 #101 合并而再次冲突。

## 改动

- 新增 `docs/progress/`：每项工作一个文件，命名 `YYYY-MM-DD-简短英文名.md`，首行 `# YYYY-MM-DD：标题`。写法、读法和原因见该目录的 README。
- `docs/PROGRESS.md` 改为存档，只把第三行换成说明，原有各节一字未动；`.gitattributes` 的规则保留，供切换前开出的分支在本机合并时使用，只更新了注释。
- 新增 `tests/progress-entries.test.ts`，随 `npm run check` 运行：检查新目录的文件名与首行；存档里出现晚于 2026-10-12 的小节即失败，并提示改写到新目录。
- 同步写法说明：`AGENTS.md`、`CLAUDE.md`、`README.md`、`docs/REQUIREMENTS.md`、`docs/DEVELOPMENT_HANDOFF.md`、`docs/FRONTEND_GUIDE.md` 以及 `docs/BACKEND_HANDOFF.md` 的启动指令。其他文档里指向存档的“结果见进度记录”链接仍然有效，未改。
