## 改动与接口

- 新增显式 `build:self-hosted -- --public-website` 与 `deployment: public-website`；普通构建、Preview、CI 和原独立入口的隔离保持。公开与原独立构建标记不可混用，真实配置仍只能在运行时从当前用户的0600文件读取。
- 支持既有轮换网站 reader 和 Supabase pooler 后缀，启动按实际 LOGIN 检查角色、只读权限和私表隔离；社交沿用独立 reader。拒绝管理员、同步、Storage writer 和迁移变量。
- 公开模式保留正式媒体响应头与已有读取接口，不附加开发 CSP 或全站 noindex 头；收录仍由受保护开关控制。社交默认开关使用现有业务接口接受的 `disabled` 值。
- Node 堆上限768MiB，systemd 给出整组1400MiB内存及150% CPU上限；Nginx示例使用8443转回环3100，保留已有443服务。Cloudflare应使用Full (strict)及目标端口覆盖，不把Node端口公开。

## 实际部署与验证

现有主机已扩为2vCPU／2GiB，根盘30GiB，CPU积分模式保持Standard；已有服务和只读监控接续已核对。安装官方Node24.22.2及发行版Nginx，免费源站证书只包含本站两个主机名，私钥留服务器。候选仅通过SSH隧道私下验收，正式域名仍保持既有Notion302，未切DNS或恢复收录。

网站使用既有 Supabase 受限连接、COS 缩略图／社交封面及旧原图兼容读取。没有迁图片、写数据库或安装后台任务。有限真实验收：首页与动态流正常，相册列表及三张400档图片加载成功；仅小型权限／版本元数据查询和页面抽查，预计读取为数MB量级，数据库／对象存储出口未单独计量，未批量抓取。

最终官方Mac Node24.21.0完整 `npm run check` 通过：3252项、零失败、零跳过。Linux/amd64 Node24.22.2普通构建、公开构建、49条服务端追踪隐私扫描及11项自托管针对检查通过。

早期失败保留：Linux验证容器缺少`ps`导致交付测试失败，补装procps后该项3个测试通过；随后完整模拟架构检查遭遇Rosetta分支范围错误中断一个文件，该文件11项单独复验通过，模拟环境完整运行不记为通过。Mac Homebrew Node26运行有33项失败，原因是测试复制Node后找不到其动态库，后改用本机既有官方Node24完成上述完整验证，未修改业务测试或跳过失败。

私下验收还发现并修正了部署默认值及更新包排除规则问题；最终包逐项核对全部服务端文件。严格CA与主机名校验的8443健康接口返回204，未绕过TLS。沿用已安装公共缓存配置，以现有事件验证签名清理接口返回200且回执匹配；只读观察24条待办，没有确认事件或写库。原消费者继续使用原公开Origin、原签名和调度。网站内部资格固定回环Origin，Next原生标签清理保留；不启用Cloudflare页面共享缓存。有限验收后网站进程组约81MiB、峰值约101MiB，整机仍约1.3GiB可用，既有服务active；这不代表长期并发压测通过。
