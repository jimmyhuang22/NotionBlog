## 方法与结果

使用已有 PostgreSQL 17.11 与 Node 24.21 镜像，无下载。每种顺序使用独立临时数据库，网络设为 none、不发布宿主机端口，客户端仅共享其网络命名空间。所有账号、口令、证书和内容均为新建虚构输入；直接使用 PostgreSQL 的严格 TLS 与 SCRAM 密码认证，没有 SET ROLE、SET SESSION AUTHORIZATION 或伪造角色查询结果。

从受检 develop 源码调用原 publication、增量、reader、隔离、已发布缩略图及撤回恢复安装器；冻结运行包不含隔离安装器，因此安装源码和运行源码分别固定。实际读取及证据连接使用选定冻结包，包括其独立 evidence 适配器；未把新安装文件写入旧包或扩大旧许可。

“先隔离、后缩略图／撤回扩展”和“先扩展、后隔离”两种顺序各完成十一项检查，最终零失败、零跳过：

- 原安装器及幂等复验通过；隔离组保持 NOLOGIN，安装器不自动创建或加入 LOGIN；可选只读能力在两种顺序下均保留。
- 网站、同步公开验收、同步证据和 writer 四个独立 LOGIN 实际密码登录，current_user 与 session_user 均为各自身份。错误密码、不受信任证书和非 TLS 连接被拒绝。
- 受限 writer 实际发布虚构记录；网站严格隔离读取器与同步公开读取器仍能读取公共 DTO，未带出 evidence。网站／公开同步／writer 直接调用私有 reader 或读取被测私表均被拒绝；证据账号也不能读该私表或调用增量写入函数。
- 原生证据连接适配器实际准备增量、由 writer 发布，再独立读回完整证据并核验操作；网站随后能读到新公开结果。没有注入连接工厂或用管理身份代读。
- 混组和 NOINHERIT 隐藏成员仍被拒绝；故意失败的成员调整事务回滚后恢复原授权。此回滚只覆盖成员事务，不代表整套 DDL 与凭据切换已原子验收。
- 原生连接池关闭后数据库中无其残留会话；每组八个直接客户端的关闭承诺全部完成，自有数据库和客户端容器均已删除，无匿名数据卷。
