# 2026-11-01：手机上导航放得下就平铺（F53，Claude）

编辑登记：Claude 本轮修改 `src/app/globals.css`、`src/app/skins.css`、`src/lib/nav.ts`（只改注释），更新 `docs/FRONTEND_GUIDE.md` 页头一节，新增 [决策记录](../decisions/2026-11-01-nav-flat-on-phones.md)。组件、契约、接口与媒体路由、fixtures、依赖、栏目开关与后端代码未改。导航属于全局入口，用户这次的反馈就是确认要改（F53 交接包）。

## 问题

用户在手机上看到导航一行只有“动态　学习　作品　更多”，右边空着一半。原因是 321–819 宽一律把影视、书籍、游戏、相册收进“更多”，不管实际放不放得下。

## 改了什么

- 760 宽以下（栏目单独占第二行），七个栏目放得下就全部平铺、不显示“更多”：苹果 320 起，墨水和岛屿 330 起，千禧 376 起。更窄的照旧收起。
- 千禧 361–403 宽时栏目内边距从 11 收到 9，否则 375–403 的常见手机放不下。
- 761–819（千禧到 899）不变：栏目与站名同一行，放不下，照旧收起。
- 页面结构不变：两套都写在页面里，由样式按宽度显示一套。

## 怎么验证的

- 量分界：在正式站点上强制显示七个栏目，四套主题浅色和深色，当前栏目放在第一个（动态页）和最后一个（相册页），从 320 逐像素量到 520。标准是一行排下、不溢出，最后一个栏目右边离屏幕边至少 9 像素，与左边相同。结果：苹果 320、墨水 326、岛屿 328 起放得下；千禧原内边距下 361–403 放不下，收到 9 后 376 起放得下。
- 量结果：把本次构建出的样式表换到正式页面上，不强制显示，同样的外观、页面和宽度从 320 量到 820：
  - 墨水、岛屿：329 收起、330 平铺；苹果 320 起平铺；千禧 375 收起、376 平铺。
  - 541–760 平铺，768、819 收起，820 起平铺（千禧 820 仍收起，900 起平铺，与原来相同）。
  - 每个宽度都没有溢出；顶栏高度与发布前相同（320–389 为 96、390 起 106，苹果 85／91），F50 的第一行不受影响。
- 截图看了当前栏目的标记：墨水的墨线、岛屿的黄色胶囊、千禧的蓝色胶囊都在“相册”上；收起时“更多”带标记，与原来相同。墨水的墨线由脚本定位，换样式表后要触发一次窗口缩放才会移到新位置，正常加载时样式表先到，不受影响。
- Node 24.21.0：`npm run check` 3249 项里 3248 项通过。失败的一项是后端的 `tests/self-hosted-delivery.test.ts`，与样式无关：单独重跑 3 次都通过，不带本改动也通过，是满负载下的计时偶发。`npm run build` 通过，49 份服务端追踪隐私检查通过。

- 分界按七个栏目量；博客、项目打开后要重量。
- 没有在 Safari 和真机上看；用户截图来自 iPhone 上的 Chrome，宽度在 375–440 之间，都落在平铺范围里。
- 随下一次发布上线后，由审查对话在线上复验，通过后关闭 F53。
