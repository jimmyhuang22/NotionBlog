# 2026-10-14：B 站效率有限试验（Codex）

编辑登记：用户批准尝试前轮提出的效率方向。本项在独立工作区完成轻量数据入口、Chrome 开销与历史快照压缩的有限预检；真实样本、响应、进程观察和数据库副本仅留 SSD 忽略目录，不修改前端、原固定包、频率、权限或云端数据。

轻量入口：预定三个已有样本（独立视频、多 P、小合集），最多六次无 Cookie HTTPS 请求／二十四 MiB／两分钟，对比公开 JSON 与原网页结构。第一个请求即 HTTP 412、平台 code -412，实际只发一次、返回五十二字节后停止；没有重试、继续碰其他样本、抓 Cookie、签名规避或降级发布。因此当前机器上不能采用这一路替换 SSR，后两个样本及结构等价性未实测，不声称接口整体可用。

本地基线：只读核对原两份 SQLite；单稿库约 0.86 MiB（包含另一平台），B 站单稿历史九十一条约七十三 KiB。合集库 2.5 MiB，四百六十七条历史正文约 1.62 MiB，目前没有明显存储压力。最大快照的 gzip 样本约缩小百分之八十二，解压摘要与原文一致；单样本比例不外推为整库比例。

压缩原型：仅在独立数据库副本中，将全部四百六十七条历史以 gzip 保存并逐项核对 key、采样时间、原 SHA 与原始 UTF-8 正文。全部字节相同；当前状态、待上传队列和来源尝试表摘要保持，完整性检查通过。副本物理大小降至 1.23 MiB，约减少百分之五十一，原型处理约四十八毫秒、CPU 约三十六毫秒。保留全部历史，没有清理原库。这份副本改变了历史表格式，尚不兼容现有采集器，不能直接替换运行库。

浏览器观察：一次临时目录标签正常读取三页，数量四十二／四十二／二十五，随后关闭，不导入统计或提交目录。操作窗口约一百一十六秒包含电脑工具等待，不能拿它对照原扩展约七秒的自然采样。只读 OS 进程观察包含多个 Chrome 主进程、其他 profile 活动及共享 RSS，出现多组新 renderer，不能绑定到唯一标签；结果仅作为观察证据，不宣称整机变化就是任务开销，也不凭此调整频率或浏览器权限。标签和临时观察进程已结束。

结论：原上传单连接、六小时刷新／十五分钟本地检查及账号自动接入继续运行。轻量 JSON 路线本轮不可用；历史压缩已有完整副本证明，但当前库很小，暂不承担共享 SQLite 格式迁移和旧程序兼容成本。下一项若推进压缩，应先实现兼容读取、迁移失败回滚和原／新启动包联合验收；浏览器单任务测量应先解决 PID／标签绑定，不能根据本轮混合观察宣称优化收益。未运行新的工程全套／构建或 CI，只对本记录做格式、链接、差异及隐私检查。
