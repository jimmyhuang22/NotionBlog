# 2026-11-12：按压反馈（Claude，第五轮设计审查第一批）

编辑登记：Claude 修改 `src/app/globals.css`、`src/app/skins.css`、`src/app/study.css`，新增决策 `docs/decisions/2026-11-12-press-language.md`，在 `docs/FRONTEND_GUIDE.md` 的“已经定下的设计”加一条。组件、契约、接口与媒体路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

## 来由

第五轮设计审查 X-13（手机轻触时出现浏览器自带的青蓝色方块）与 X-14（墨水主题没有自己的按压语言）。用户看过对比原型后选“全部按推荐”：行与文字用墨晕，有投影的卡片和圆钮压进纸里。随后补充交接（`ADDENDUM-skins.md` 甲）把苹果、岛屿、千禧的按压也定成各自的样子，用户同意，并进本批。

## 改了什么

- 根元素 `-webkit-tap-highlight-color: transparent`，和下面的按压态同一次合并。
- 新的主题变量：`--bloom`（墨水强调色 10%，深色 18%）、`--shadow-press`、`--press-depth`（默认 1.5px，岛屿 3px），在墨水浅深、苹果浅深、岛屿浅深、千禧各自定义。
- 墨晕：页头导航项（当前项除外）、“更多”与其菜单项、分段切换（选中项在自己的底色上加深）、首页游戏与单件作品的轻记录、课程目录 `.tree__link`、正文与顶部目录 `.toc a`、底部目录条目、搜索结果、快速搜索结果、学习区的行（`.study-entry`、`.child-page`、课程快捷链接、课程卡）、面包屑。没有内边距的几类外扩 6px。墨水与苹果写成文字的上一篇／下一篇也用墨晕。
- 压进纸里：可点卡片、卡片样式的上一篇／下一篇（岛屿、千禧）、胶囊按钮、页头图标钮、社交圆钮、“本页目录”胶囊、回到顶部。社交圆钮和上一篇／下一篇的按压写在它们自己的悬停规则之后，悬停时按下也能生效。
- 去掉按下变成 82% 的写法（含回到顶部单独那一条），四套都去掉，岛屿圆钮原来的变淡也去掉。
- 各主题：苹果 `--bloom` 与 `--press-fill` 是中性灰（浅 7%、深 12% 白），卡片与圆钮缩到 0.97 并叠一层灰，不下沉；岛屿薄荷晕（浅 14%、深 20%），卡片下沉 3px 踩到台阶，社交圆钮、页头黄胶囊（2px）和分段选中块同样下沉；千禧浅蓝晕，胶囊、页头蓝胶囊、选中分段和白色圆钮按下时高光换到下沿、光晕收掉、不下移。规则集中在 `skins.css` 末尾“Pressing in each skin”。
- 过渡只在 `prefers-reduced-motion: no-preference` 下：墨晕 0.06s 进、0.22s 退；纸面 0.05s 进、约 0.2s 回。

## 怎么验证的

- Node 24.21.0：`npm run check` 通过，3392 个测试全部通过，0 失败、0 跳过（含构建与隐私检查）。
- 本机正式构建，演示数据，无头 Chrome，390 宽，1x。本机构建只开动态与学习两个栏目，影视、书籍、游戏、相册、作品页的分段切换与封面按压没在页面上看到；同一套选择器在动态与学习的分段切换上验证。演示首页没有作品和游戏，首页的两种轻记录是用真实类名临时插进页面看的（不提交）。
- 鼠标按住每类目标（与触摸共用 `:active`），读按住 80ms 时和松开 450ms 后的计算样式：墨水、岛屿、苹果的浅深两色与千禧浅色共七组，各 13 类目标，全部在 80ms 内有变化，松开后与按下前完全一致（无残留），没有一处变淡。苹果卡片与图标钮读到 0.97 的缩小，岛屿卡片、圆钮与选中分段读到 3px 下沉与变薄的底边，千禧选中分段与圆钮读到换到下沿的高光。截图看过墨水浅深两套的前、中、后。
- 轻触色块：触摸模拟下真实点按导航项、学习行与子页面行，连拍按下与松开后的帧，按 Chrome 默认青蓝色数像素。对照组（把默认色块强行加回）在松开后那一帧有 1999、25325、19071 个青蓝像素；改后所有帧都只有背景里原有的淡蓝（0–57 个），没有色块。
- 页头当前项的岛屿黄胶囊与千禧蓝胶囊没进脚本（脚本只按非当前项），规则只读过、没按过。
- 补充交接要的“四套各录一条 390 轻触”：模拟触摸不触发按压态，只能证明没有默认色块（上一条），按压的样子用上面的鼠标结果代替。
- 无头 Chrome 的模拟触摸不会触发 `:active`，所以“手指按住时的墨晕”只用鼠标验证了。

## 限制与下一项

- 只在演示数据与无头 Chrome 下验证；真机（iPhone Safari、Android Chrome）的触摸按压没测。iOS Safari 只在页面有触摸监听时才给 `:active`，React 在根节点上有这类监听，理论上成立，要等发布后真机确认。
- 影视、书籍、游戏、相册、作品页上的分段切换与“压进纸里”的卡片，要在打开这些栏目的环境里再看一眼。
