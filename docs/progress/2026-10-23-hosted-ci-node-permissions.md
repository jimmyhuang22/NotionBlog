## 问题与修复

首次 GitHub 托管 main 检查在 `verifyRelease` 的 Node 可执行文件摘要读取处失败，五项冻结恢复测试报告 `RELEASE_INVALID`，构建跳过。生产校验拒绝组或其他用户可写的文件；不能为通过 CI 放宽这一规则。

使用同字节 Node 24 临时副本验证：模式为 `0775` 时，既有两份测试中的五项失败与托管记录一致；模式为 `0755` 时八项全部通过。该复现说明权限差异能造成观察到的失败；托管机器原始模式仍以候选实际日志为准。

CI 在 setup-node 后，将其可执行文件复制进本次任务的独占临时目录，设置目录 `0700`、副本 `0755`，比较源和副本字节，再通过 `GITHUB_PATH` 供后续 npm 与子进程使用。源工具缓存文件不改动，副本随托管虚拟机销毁；实际模式与字节数记录在日志中。安装双锁、完整 check／build、离线 fixtures 与只读 Token 保持。
