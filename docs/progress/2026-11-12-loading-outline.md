## 来由

第五轮设计审查 M-15（进入栏目先闪通用横线、再换栏目占位，工具条和数据一起晚到）与 M-16（首页时间线在占位撤走后约 400ms 是空的）。用户选“全部按推荐”。

## 改了什么

- **`SectionWaiting`**：按地址画栏目自己的占位。影视、书籍、游戏：标题、状态切换（默认状态选中，不能按）、年份条的高度、排序钮“最近”的壳、年份标题、12 张封面呼吸块加标题与小字。作品：标题、平台切换（带平台图标）、排序钮的壳、`WorksWaiting`。动态：标题、年份条高度、真时间线类名画的月份和两张卡。相册：6 张相册卡。搜索：搜索框（不可用）。其他地址返回空，仍是原来的横线。
- **同一张画三处用**：`PageLoading` 先查 `SectionWaiting`，所以根加载画面（首次访问）和各栏目的 `loading.tsx` 都画栏目轮廓；`page-switch.tsx` 为每个有轮廓的栏目预备一份隐藏副本（标题位置是空槽，点击时写入 `h1`，仍不在页面里留隐藏的 `h1`），点击时用对应那份。
- **`WorksWaiting`**：加年份标题，卡片改成和真卡片相同的顺序与类名（标题、日期、图），切换平台时的等待也用它。
- **文字型占位**：新增 `.skeleton--text`，放在真元素里（标题、月份、日期），高度跟着那一行自己的行高。
- **首页时间线（M-16）**：`RecentFallback` 改用真时间线的月份与行类名，三行灰条的位置与首屏行在画出前垫的灰条相同（`--bar-*` 变量）。画出改为：行本身不再被裁切，竖线一直在；`::after` 一条强调色墨线从第 0 行起逐行往下跑（每行 150ms），之后 0.6s 淡回主题自己的线；圆点从 0.55 弹到原大（不再从无到有）；每行的灰条在墨线到达后 90ms 换成内容。`HomeTimeline` 记住本次浏览画过，回到首页不再带 `--i`。根加载画面的时间线也加了 `timeline--home`，让灰条变量在那里同样可用。

## 怎么验证的

- Node 24.21.0：`npm run check` 通过，3392 个测试全部通过，0 失败、0 跳过（含构建与隐私检查）。
- 本机正式构建，演示数据，无头 Chrome，1x。
- **位置对齐**：把每张轮廓放到真页面的位置上，量标题、工具条、年份条和第一项的位置。动态、作品、搜索对本机真页面，390 与 1440：标题、状态或平台切换、排序钮、年份条、月份、日期行和第一张卡的左上角全部逐像素一致，只有卡片高度随内容不同。影视、书籍、游戏、相册在本机不开放，对正式站点的真页面（只读，挡掉图片）比，390 与 1440：标题、状态切换、排序钮、年份条、第一张封面和标题的位置全部一致；相册卡连高度也一致；作品库卡片只有小字行数不同。
- **慢网络录屏**（每个请求加 700ms，390）：从搜索点“动态”，243ms 起出现动态的轮廓，一直到 1376ms 都是同一种形状，1762ms 内容在原位出现，标题和年份条不动；从动态点搜索同样。首次直接打开作品与动态，录屏里没有出现首页加载画面；岛屿下刷新动态，每一帧背景都是岛屿的颜色（F54 两条复测通过）。整页载入时浏览器在新页面绘制前一直显示旧页面，所以首次访问时的根加载画面录不到，只核对了它和栏目画面用的是同一个组件。
- **首页画出**（390 与 1440，整页载入加 700ms）：第一次绘制起，“最近”下面就有竖线、圆点、月份和灰条，没有空帧；随后逐行换成内容。点“动态”再点站名回到首页：没有一行带画出标记，也没有画出动画在跑。

## 限制与下一项

- 影视、书籍、游戏、相册的占位只在正式站点真页面上比过位置，没有在本机看到真实的进入过程；要在开放这些栏目的环境或发布后复验。
- 首页的录屏用的是演示数据；正式站点首屏有作品、游戏等轻记录，行高与灰条的贴合要发布后看。演示数据下第一屏在主线程忙于水合时，墨线要等水合完才开始走，期间显示的是灰条，不是空白。
- 学习首页仍是横线；状态切换在非默认状态的地址上进入时，占位里选中的仍是默认状态（加载画面拿不到地址参数）。
