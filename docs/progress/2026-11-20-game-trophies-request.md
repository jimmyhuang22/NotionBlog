# 2026-11-20：游戏奖杯的版式与后端需求（Claude）

编辑登记：Claude 修改 `docs/BACKEND_HANDOFF.md`（新增十六与一览一行），新增决策 [游戏详情加奖杯（乙）](../decisions/2026-11-20-game-trophies.md)。代码、契约、fixtures 未改。

## 做了什么

- 用户问游戏页能不能多放资料（例如成就）。核对后：PSN 的奖杯完成度、已获得总数、总数和白金数已由平台同步写进 Notion 的平台记录，没进网站；四种等级的分别计数、多个奖杯组、逐个奖杯和 Steam 成就都还没采集；任天堂没有奖杯系统。
- 原型：在线上《艾尔登法环》详情页注入三个方向，墨水主题 1280 与 390，乙和丙另拍深色 1280。奖杯名称、日期、比例和数量全是虚构的，图标是占位。对比页在前端忽略目录 `.local/previews/game-trophies-20261120/`，生成脚本未提交。
- 用户选乙；确认多平台各套分开显示、有奖杯时不显示“还没有写下记录”；Notion 正文的去留以后再定。
- 交接包十六写明两步的数据、存放方向（直接进网站数据库）、隐私与空值规则和演示数据要求。

## 怎么验证的

- 只改文档：核对了记录格式、链接和差异，没有个人信息与真实账户数据。没有运行 check / build。
- 原型只在线上页面上注入后截图，没有改站点代码，也没有用真实奖杯数据验证。

## 限制与下一项

- 等 Codex 交付第一步统计后，前端做左栏那一组；逐个奖杯到位后做“奖杯”一节并去掉有奖杯时的空正文提示。
- Steam 读本人成就是否要求“游戏详情”公开没有核实。
