## 剩余瓶颈：实际资格查询仍跨区

**地域锁定验收未通过。** 部署元数据已接受单函数 `sin1` 配置，运行时为 Node 24；真实请求的分段计时仍出现 `syd1` 资格目录读取。页面函数的跨区 span 指向 `sin1`，与较快的页面目录计时对应；不能用部署顶层区域或本机打包结果代替实际执行证据。

- 浏览器首次项目请求：悉尼目录作用域 1,392ms，其中取得连接 1,027ms、两次 SQL 往返共 342ms（含首次能力检查），首次观察池 total／idle／waiting 均零；同请求新加坡页面目录约 11ms。
- 固定部署较早请求：悉尼目录作用域 1,421ms，取得连接 1,045ms、两次往返 347ms；新加坡页面目录约 32ms，其中取得连接 22ms、往返 7ms。与该请求资格前台 1,577ms／页面前台 46ms 相符。
- 紧接请求：悉尼目录约 175ms，取得空闲连接约 0.1ms、一次往返约 172ms；新加坡页面目录约 11ms，一次往返约 8ms。取得连接不等于数据库执行时间，往返也包含网络；现有证据不支持升级数据库规格或删除资格检查。
- CLI 每个请求聚合多个日志；分析只读取一次子日志数组，排除顶层摘要的重复消息，不把它算成额外 SQL 或额外请求。

[平台路由中间层说明](https://vercel.com/docs/routing-middleware)将其描述为缓存之前的全局执行层；[平台架构说明](https://vercel.com/blog/update-regarding-vercel-service-disruption-on-october-20-2025)亦说明该层部署于各 CDN 区域。真实测量与此相符。本次配置被接受，没有达到将实际资格查询固定到数据区的目标，不能继续把改入口文件名或产物中的区域字段当成解决办法。

## 功能验收、建议与边界

正常 DNS／TLS 下八项只读检查全部通过：database v2 健康、项目／课程／笔记 200，以及不存在项目、课程、笔记和错误课程所属关系的 HTML 404／no-store。该部署近 15 分钟有界扫描未检出 5xx；没有实施线上撤回或故障注入，其回归依据既有测试与此前本机 503 验证。

建议保留当前功能正常、已能定位阶段的发布，但将性能结论标记为部分改善、地域目标未完成。下一项由后端准备固定数据区域的资格查询入口，中间层只取得资格结果，继续逐请求核验资格、撤回与 404／503；先验证这种边界和调用开销，再单独安排下一次发布。该方案尚未实现，不新增跨请求正缓存、放宽权限或修改 Claude 的页面交互。页面过渡仍有约 400ms 的既有动画，不把它混入 SQL 耗时。
