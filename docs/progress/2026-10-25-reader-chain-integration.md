## 修改与目的

上一项只验证 host／preload，本轮将双读取身份继续接入配置编译、profile 读取、原生目标检查、fresh-reader 准入、完整准备程序及四个有 SQL 的后置读取入口。同步公开账号与证据账号各自限定身份和用途；网站账号、混合成员、互换 profile、文件摘要漂移及旧入口不能进入对应路径。准备程序同时核对 packet、recipe 与准入回执的读取身份及文件引用。

保留来源候选的连接复用、停止守卫、owner 回执检查、混合缓存协调和精确 AFTER 事件绑定。替换会重新生成旧身份的历史计划生成器，改为无副作用的双身份审阅编译器；丢弃旧 recipe 文件引用，要求后续重新保存、取摘要并绑定。其输出始终未批准，不包含可执行 nonce 或期限，不自动安装。

新增身份检查计入预算提案：fresh-reader 从 6 次变为 7 次 SQL；source-child 与四个后置入口分别增加 2 次，整链共增加 11 次。拟议原生 SQL 总额为 20,970、连接总额仍为 75；后置逻辑 SQL 上限为 5,514。这些是未来来源执行链的保守预约，不是已获授权的隔离切换额度或账单硬上限，也不重新打开任何已关闭窗口。

公共 DTO、provider、依赖及数据库迁移未变。1,750 个应用文件与原隔离候选逐字节一致；本轮变更集中在私人协调与运行准备模块。

## 验证

最终 89 项 Node 与 36 项 Python 回归全部通过，共 125 项，无跳过；针对性重跑不累加。覆盖读取角色拒绝、配置与预算绑定、实际 host 检查、池生命周期、STOP、owner 回执、缓存协调及失败收尾。

新增整条准备路径用虚构配置运行审阅编译器、scope materializer、prepareOperation 和实际 host 检查，确认新 preload、隔离子入口与两类 profile 绑定一致，没有启动 worker。该路径的 owner／reader 准入回执是显式测试输入；另外通过严格 TLS 回环与 PGlite 执行实际 7 条 fresh-reader SQL，验证正常公开账号通过、混合成员拒绝、连接关闭。不能将准备路径通过写成真实来源同步或端到端生产验收。

模块图核对 1,897 个文件，无缺失引用；六处非字面导入为有限应用映射或固定刷新入口，真实安装仍须重新绑定刷新程序摘要。冻结依赖 15,974 个文件与 7 个链接、原来源候选 86 个文件及上轮组合候选 1,820 个文件均复核不变。最终日志、图、摘要清单及失败日志保存在私人候选中。

初次测试暴露历史回执／计划路径及两个准备夹具引用不完整，已修正测试输入，未放宽生产门禁。Python 旧测试改为独立虚构计划后，又纠正了把 Node 原文件摘要等同于 Python 排序规范化摘要的错误断言；最终明确验证二者不同、规范化摘要不受键顺序影响且会拒绝预算变化。

公共提交只含本记录，按文档范围验证格式、链接、隐私与差异；私人执行代码运行上述专项回归。应用字节未变，不重复整套应用检查和构建。本机结果不宣称平台通过。最新 develop 的缓存屏障执行核心为尚未安装的独立入口，本候选不引用它，也不据此改变既有缓存协议。
