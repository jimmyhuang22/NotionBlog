## 实现

- `media-query.ts` 仅接受原有两种有界封面选择，将正在等待的请求按最多32项合批。当前LOGIN／权限和reader／合集协议与RLS绑定读取在同一条参数化invoker SQL完成；使用按请求编号的定向LATERAL查询，缺失、重复、未知行或异常身份均拒绝。
- 单批执行、128项等待上限及独立8秒读取上下文，消除各图片多次重入pg队列。每个HTTP请求及其读后复查均重新参与SQL，不保存正资格或负结果；单访客取消不影响其他访客，整批取消后队列能继续工作。沿用现有池和M08只读事务控制，没有增加连接数、改凭据或放大期限。
- 版本化社交封面按原小图地址延迟重试一次，第二次失败使用既有失败占位，不再自动取大原图；未增加缓存破坏参数。旧地址的原图回退保持，替换图片与卸载清理旧重试，版式、样式和导航不变。

## 验证

定向检查包括并发图片与304、真实reader身份／RLS、文章及合集封面、撤回发生在两次读取之间、错误身份／协议、缺失／重复行、单人／整批取消、队列上限与继续排空；旧媒体缓存、版本匹配及撤回回归保持。

本机日常Chrome加载实际组件，使用仅localhost的503／404固定夹具：临时503请求小图两次后成功；持续503和404各两次后失败；社交原图请求为0；旧地址小图一次后原图一次成功；换图后旧重试没有继续请求，新图正常。夹具延迟脚本以覆盖首张图片在hydration前失败的路径；验证后清理临时页面、代理、服务和生成类型。开发控制台有Grammarly扩展增加body属性的hydration提示，未将其写成组件无错误或修改访客扩展。
