## 可复用的经验

1. **先定位数据停在哪一段。** 分别核对账户采集、Notion 平台记录与作品关联、网站内容批次、公开接口及浏览器显示。账户已更新而网页仍旧时，优先查内容发布与刷新，不重复采账户或下载封面。单个阶段成功只证明该阶段。
2. **分清人工体验、平台活动和栏目归年。** 当前游戏栏目仅按人工体验结束日（缺结束日取开始日）稳定归年；没有人工日期就保留无日期。平台首末日期独立显示，在玩活动和完成事件分别按当前时间线规则投影。旧“平台优先”或“取较晚日”的历史验收不能作为现行栏目规则；当前定义见[作品库年份接口](../LIBRARY_YEARS_API.md)和[稳定体验年份决定](../decisions/2026-10-20-game-stable-experience-dates.md)。
3. **在采集时按正确时区截为日期。** 完整和增量采集都显式传递站点时区；时刻先换时区再截日，已有纯日期保持原值。读端无法恢复先前被 UTC 截断的信息。定向验证覆盖跨日、跨年、夏令时、旧快照和未知首次日期，详见[采集时区修正](../decisions/2026-10-14-sync-collection-timezone.md)。Steam 没有提供的首次游玩日期保持 null。
4. **用实际解释器复现兼容错误。** 系统 Python 与开发解释器对合法 ISO 小数秒的接受范围可能不同。保留同一时刻，针对旧解析器补齐兼容格式，覆盖不同时区、合法小数位和非法输入；不顺手改任务期限、预算或资格判断。
5. **按发生时间区分历史证据与当前状态。** 原聊天最后一句可能早于后端的后续安装和运行。先查最新相关进度与本地状态，用代码版本、路径和实际效果说明结果；准备、安装、自然启动、发布及完整验收分别记录。历史年份数量、筛选子集和桌面浏览器结果也各有范围，不能写成当前全库或所有设备已通过。
6. **把上下文和验证成本控制在任务内。** 开始只读[项目入口](../START_HERE.md)和当前规则，按关键词查相关记录；不整批装入旧对话、决策与记忆。组内问题集中修，按影响验证；纯文档做格式、链接、隐私和差异检查。授权和临时错误按[现行工作规则](../decisions/2026-10-26-agent-working-rules.md)处理，批准覆盖同一任务，临时只读错误可以有界重试，不再追加签收或封存手续。
