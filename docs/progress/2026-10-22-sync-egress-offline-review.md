# 2026-10-22：维护回传的离线定位与独立适配器接续（Codex）

## 编辑登记与范围

用户要求继续离线诊断同步重复回传、核对历史维护候选并准备最小修复。由新 develop 的独立短期分支接续五个维护模块、两份测试和操作说明；不引入旧 Git 父链、来源配置或历史需求文件。没有修改依赖、DTO、fixtures、数据库协议／迁移、前端、网站默认读取入口或固定运行程序。

## 修改与结果

- 显式维护会话只使用调用方提供的原 reader／writer、精确 SQL 允许列表与共享持久响应预算。缓存损坏、额度耗尽、未知结果、丢失账本或未结清请求继续停止；登记语句不缓存、不重试。
- 仅对内容投影中按 Set 使用的 links／mediaIds 固定排序，保留所有成员与重复项，拒绝错误类型。正文与记录顺序、资格查询、撤回和版本检查保持。
- 小图登记状态独立随每次真实 SQL 返回；未变化来源描述可复用，null、变化后的登记内容、来源指纹和撤回仍使用本次证据。独立字段也计入回传上限。
- 新处理绑定独立 v2 命名空间和缓存键，首次需新填充，不与旧格式混用；不自动创建连接或启用业务调度。

接入与预算边界见[维护回传说明](../OPERATOR_SQL_EGRESS.md)。

## 验证

- 已用既有私人快照及原始缓存进行本机对照，完整 DTO 相同、当前集合移除及来源变化的行为分别验证。新适配器的 21 项专项检查通过，包含真实受限 reader／writer、过期、撤回、当前来源变更及独立字段超限。私人快照、路径和逐样本计量不进入公共文档。
- 一次完整离线 check 的类型及协议检查通过；测试共 2,497 项，2,479 通过、18 失败、无跳过或取消。失败集中在六个需要本机端口的文件，沙箱拒绝 listen；保留本次失败，不写成完整检查通过。随后在允许 loopback、仍阻断外部 Node 连接的环境，只补验六个受影响文件及最终适配器两文件，共 58 项全部通过。最后的缺字段拒绝保护也包含在该次补验中，未重复其余测试。
- 首次构建因跨目录依赖软链接被 Turbopack 拒绝，在编译前中止；换成同版本本机依赖副本后，最终 npm run build 及 48 份服务端追踪隐私检查通过。没有改构建配置或访问依赖 registry。
- 记录格式三项、源码隐私 1,606 文件、相关本地链接及差异检查通过。平台检查尚不能用上述本机结果代替，私人原生运行器已退役，不派发手动 CI。

## 限制与下一项

缺少历史原始 SQL 响应对，尚不能确定每次历史较大回传的全部原因或两项机制的实际占比；本机重排与登记状态回放不是线上账单节省证明。实际安装、新鲜有界观察与当前来源恢复分别处理，不复用旧窗口，不迁移账号、合并或部署。本候选先供代码审阅。
