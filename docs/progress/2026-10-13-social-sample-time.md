# 2026-10-13：社交卡片写明数字的采样时间（Claude）

编辑登记：Claude 本轮前端修改与验证完成。范围：`src/lib/home-feed.ts`、`src/components/social-card.tsx`、`src/components/collection-card.tsx`、`src/components/home-timeline.tsx`、`src/app/page.tsx`、`src/app/timeline.css`、一组测试和前端接手说明。没有新依赖；契约、fixtures、栏目开关、接口与媒体路由未改。

来由：后端的社交长期展示已经按周期采样（B 站每 6 小时、小红书每 24 小时），DTO 里每个平台、每个合集各有自己的 `observedAt`，`socialSampleStatus` 也已提供；卡片上还没有把这个时间写出来。后端交接指定由前端补上这一行。

## 改了什么

- 作品卡的每个平台行、合集卡的合计行，在数字下面加一行小字“数据截至 10 月 13 日 08:10”。时间是那一行自己的采样时间，按站点时区；与当年同年时省略年份，往年写出年份。
- 同一作品的不同平台各写各的时间，不取其中最新的一个代表全部；合集的时间是合集自己的，不是下面任何一行的。
- 超过采样周期还没更新的行，卡片与旧数字照旧，时间如实写旧的，后面加“，未按期更新”。这只是说明，不改变排序、折叠或是否显示。这句话的措辞是我定的，用户还没有看过。
- 没有数字的行（“数据未记录”）不写采样时间。时间不符合后端规则的，这一行小字不显示。
- “现在”由首页在读完第一页之后取服务器时间，作为 `now` 传给时间线和卡片。不读访客设备的时钟，服务器和浏览器第一次渲染的结果相同。翻页之后带来的、采样时间晚于这个时刻的行，算作没有超期。

## 接口与 provider

没有新的取数。用的是时间线 v2 已有的 `publications[].observedAt` 与 `collection.observedAt`，以及 `src/lib/content/social-sample-status.ts` 的 `socialSampleStatus`；前端在 `sampleTime` 里包一层，规则仍由后端那个函数决定。

## 怎么验证的

只用虚构数据验证；社交来源在正式站点和演示数据里都是关着的，没有用真实作品看过。

| 项目 | 结果 |
| --- | --- |
| 两个平台采样时间不同 | 各行显示各自的时间 |
| 一个平台超期、另一个没有 | 只有超期的那一行带“未按期更新”，数字都在 |
| 合集卡 | 合计行写合集的采样时间，下面关联平台的行写自己的 |
| 多 P 视频、去年采的数字 | 时间带年份，并标未按期更新 |
| 没有数字的行 | 仍是“数据未记录”，没有采样时间 |
| 七项数字、长标题 | 数字换行后采样时间仍在数字正下方、与数字左缘对齐 |
| 宽度 1280 与 390 | 没有横向滚动，采样时间都是一行 |
| 墨水深色、苹果、像素、千禧 | 用各主题的次要文字颜色，读得清 |
| 平常的首页（演示数据、社交关闭） | 照常渲染，加载下一页正常，控制台没有报错 |

方法：临时加一个不提交的预览页，用手写的虚构作品渲染首页时间线，本机开发服务与无界面 Chrome 查看后删除。规则另有单元测试（时区、年份、两个平台各自的周期、恰好到期、晚于页面时刻、不合规的时间）。自动检查结果见合并请求正文。

## 限制

- 真实的长期展示数据下没有看过；后端说明标签完成后由它统一做一次代表页面与发布配置的验收。
- 标签下的超期状态以页面生成的时刻为准；页面一直开着不刷新，状态不会自己变。
- “未按期更新”的措辞和是否需要这句话，等用户看过再定。

下一项：后端联合验收时按真实卡片复看一次；用户对措辞有意见再改。
