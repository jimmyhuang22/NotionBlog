# 2026-10-28：动态展开和收起改为高度过渡（Claude）

编辑登记：Claude 本轮修改 `src/components/status-body.tsx`、`src/app/motion.css`、`src/app/timeline.css`，新增 `src/lib/size-motion.ts` 与 `tests/size-motion.test.ts`，更新 `docs/FRONTEND_GUIDE.md`，新增决策 [2026-10-28-status-expand-motion](../decisions/2026-10-28-status-expand-motion.md) 并在第五批设计自检的决策第二行注明部分取代。契约、接口与媒体路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

## 原因

首页时间线和动态页用的是同一个动态卡片，原来的动效靠类名变化触发 CSS 动画：

- 首页前八条的入场规则 `.timeline--home [style*="--i"] .entry > *` 优先级更高，盖掉了展开和收起的动画，所以没有动效；收起时还要等 0.45 秒的兜底计时器才换回来。第九条以后又有动效，同一页前后不一致。
- 动态页上，有开头预览的长动态折叠时就带着展开的类名，进页面时每条都会自己拉一次帷幕；展开长动态时类名不变，反而没有动效；收起要连播三段。

## 改了什么

- 删掉类名触发的帷幕（`unfold`、`fold` 两段动画）和收起时的等待状态、计时器。
- 新增 `src/lib/size-motion.ts`：点按前量一次卡片，React 画完新内容后再量一次，用 `element.animate` 播放高度（短动态连同宽度）过渡，展开 260 毫秒、收起 220 毫秒。脚本动画不受上面那条 CSS 规则影响，首页前八条和其余各条一样。
- 卡片内容外面加了一层 `entry__card-body`，高度和裁切都在这一层做，卡片本身不裁，所以阴影、岛屿的气泡尖角和千禧的窗口边框在过渡中都完整。这一层自成一个排版块，原来按钮往卡片底边多拉 10 像素的写法移到这一层上，过渡结束时不会跳一下。
- 收起时滚回开头与收缩同时开始，目标按收起后的位置算，结束时开头在页头下方 16 像素。
- 顺带修了两处键盘焦点：展开前后“展开／收起”按钮在卡片里的位置不同，React 会换一个新按钮，焦点丢到页面开头；加载中按钮被设为不可用，焦点也会丢。现在展开前后是同一个按钮，加载中只标记为不可用（`aria-disabled`，点按无效）。
- `motion.css` 首页入场规则旁注明它的优先级会盖掉卡片子元素上的 CSS 动画。

## 怎么验证的

演示数据本机生产构建，无头 Chrome：

- 首页第 5 条（在前八条入场组里）和第 12 条长动态，以及动态页的长动态：展开、收起各只有一段 `entry__card-body` 上的高度过渡（260／220 毫秒），收起没有空等；进入首页和动态页时卡片上没有任何动画。
- 已读到底的长动态收起：卡片收缩与滚回同时进行，约 250 毫秒后开头停在页头下方 16 像素（首页和动态页一致）。
- 短动态：演示数据的短动态没有更多正文，展开后显示“没有更多内容”，没有过渡。另把它的正文请求临时换成一条长动态的正文，确认宽度从 388 过渡到 953、高度同时过渡，收起时反向。
- 过渡中再点按：上一段立即结束，只剩新的一段，最后停在折叠高度。
- 减少动态效果：不播放任何动画，直接切换。
- 1280 与 390 宽，墨水、苹果、岛屿、千禧的浅色与深色：在展开和收起的中途暂停截图，卡片底边阴影、岛屿气泡尖角与偏移阴影、千禧窗口阴影都完整；卡片本身的溢出保持可见。
- 展开、收起后焦点都还在按钮上。
- `npm run check`、`npm run privacy:check`、`npm run build` 结果见合并请求。

## 限制与下一项

- 只在演示数据下验证；有正文的短动态是临时替换正文请求测的。随下一次发布上线后在正式站点只读复查（只看、只点展开和收起）。
- 收起时的平滑滚动由浏览器决定时长，长距离时会比 220 毫秒的收缩稍长。Safari 与真机未测。
