# 2026-11-25：年轮滚动时的样式重算（Claude）

编辑登记：Claude 修改 `src/components/library-grid.tsx`（`useYearRings`）和 `src/app/library.css`（`.game-line__spine i`）。

## 问题

用户问游戏页的动效和加载还能怎么优化。正式站点实测（1440，滚动约 2 秒、128 帧）：帧率稳定 60，但样式重算共 581 毫秒，约每帧 4.5 毫秒；把年轮的写入全部拦掉后只剩 15 毫秒。原因是“读到哪了”的数值写在包住所有年份和盒子的 `.game-line` 上，每帧都让浏览器重算所有盒子的样式。

## 改法

- 竖线的进度改成直接写在线条自己身上（`transform: scaleY`，只需合成，不重排）。
- 年份的填实值写在年份数字上，值不变时不写。
- 看起来和原来一样。

## 怎么验证的

- 本机正式构建加未提交的预览页（线上数据），同一段滚动：样式重算 27 毫秒（拦掉全部写入时 25 毫秒），主线程总工作量 211 毫秒；滚到中间时竖线填到当前年份（2022），数字照常填实。
- Node 24 下 `npm run check` 与 `npm run build`，结果见合并请求。

## 同次测量的其他结论（没有改）

- 首屏 LCP 电脑 1.2 秒、手机 0.88 秒，CLS 约 0，没有长任务；大幕虚化和浮动坞磨砂对滚动开销没有影响。
- 封面图片每张回源等 300–470 毫秒（`cache-control: private`，Cloudflare 为 `DYNAMIC`），页面本身也不缓存：属于后端，要先定下架时怎么清 CDN。
- 手写字体首次访问约 1.2 MB（书架页 1.06 MB、首页 0.5 MB），是全站问题，不在游戏页单独处理。
