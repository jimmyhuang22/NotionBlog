## 正式接入建议

先准备完整 DNS 迁移清单和回退目标，保留既有管理后台、代理子域及测试子区。原权威中的代理标记和隧道记录不能视为能直接复制到其他权威后继续等效工作；要逐个准备独立海外边缘入口、证书和现有访问控制的延续。

国内网关需增加正式域名及受信证书，私有统计配置同步增加正式 HTTPS Origin，保留预览认证及现有可信地址覆盖。使用既有交付锁，从最新活动配置生成更改，避免覆盖正常内容交付所切换的端口，并验证下一轮自然交付仍保留配置。

在权威切换前验证新解析区默认线路仍到海外，正式主机名和证书已就绪。根域 CNAME 的 MX/TXT 行为、注册商 NS/DNSSEC 状态和所有现有代理子域须先验清；不能从测试子区成功推断根域迁移已通过。创建正式 SaaS 主机名本身可能改变现有 Cloudflare 主机名路由优先级，属于正式切换操作的一部分，不能当成无影响的预准备。

验收默认海外线路后，再启用国内线路至国内入口，同时检查 A 和 AAAA，防止 IPv6 绕回默认海外线路。复用现有集中统计和两个节点标签。两地验证正式域页面、资源、统计及自然内容交付；故障时先撤下国内线路恢复全部海外，传播遵循 DNS 缓存，不能称为即时故障切换。主权威迁移失败则按完整旧记录/NS 回退，旧网站已退役的主机不作为回退目标。
