# 2026-10-14：小红书 HTTP 有限试验（Codex）

编辑登记：用户批准测试前轮 GitHub 候选是否适合现有同步。本项只记录隔离原型与真实有限读取，不修改页面、原扩展、运行包、调度、凭据、来源协议或云端内容。依赖、真实链接、响应及证据留 SSD 忽略目录。

环境：隔离 Python 环境从官方 PyPI 安装 xhshow 0.2.0、curl-cffi 0.16.3 及其运行依赖，保存实际版本。参考 XHS-Downloader 的 HTML 读取方式与 MediaCrawler 的接口／状态结构，自写小适配器，不启动完整 WebUI／爬虫项目。源码审阅发现下载器 Cookie 分支关闭 TLS 校验，本试验不运行该分支，证书校验保持开启；无浏览器、代理轮换或登录 Cookie 导出。

范围与结果：只选择原固定清单中发布时间较早、中间和最新的三篇图文，使用已有含访问参数的分享链接；另读一次同作者主页。上限四次 HTTPS、单并发、每次两 MiB／十五秒、合计八 MiB／两分钟，无跳转或重试，首失败停止。实际四次均 HTTP 200，共 466,951 字节，包含三次一秒节流共约五秒；采样段 CPU 约 0.048 秒（不含依赖导入），Python 进程峰值 RSS 约 38.9 MiB。三篇 HTTP 请求合计约 1.30 秒／209 KiB，不含渲染或媒体下载；不能外推为整批覆盖、长期稳定性或精确节省比例。

字段核对：三篇 ID、作者、类型、原发布时间均与已保存的本地记录匹配，点赞、评论、收藏、分享字段存在，并通过原计数解析器；空分享数保持 null，不制造零。标题和封面字段也可读取。响应 Date 为本次请求时间，不能证明上游统计没有缓存。没有将原本地数据与当前数字相同作为必需条件。

目录边界：初始原型误把卡片外层当作 noteCard，停止为 DIRECTORY_IDENTITY_UNPROVEN。只对已下载 HTML 离线审阅：投稿 tab 是对象，卡片在 user.notes[0][i].noteCard；确认作者和笔记 tab，但三十张卡片的外层／内层笔记 ID 都是空字符串，HTML 也没有可用笔记链接，且 hasMore=true。因此匿名主页不能证明新作品发现或完整分页。原失败回执保留，后续 schema 诊断与修正没有追加平台请求。

接线限制：xhshow 仅用虚构 Cookie 做离线签名生成，约一毫秒、无网络，不是平台接受签名的证明；真实登录 Cookie＋签名 API 尚未测试。原固定采集器严格拒绝新的 HTTP 来源标签，已用原验证器核对，试验数据不能冒充 browser-note-state 或直接上传。HTTP 适配需要明确来源协议与现有持久展示的兼容处理，不能仅替换读取函数。

结论与下一项：已有笔记统计的轻量 HTTP 路线值得推进；先设计固定范围、请求预算、暂停原因／恢复、正确来源标签及旧运行兼容，不直接换包或重采全部笔记。新作品目录另做需要登录会话的有限测试，当前仍无账号自动发现证明。只读复核原全部小红书快照摘要及共享配置相同，无原 SQLite 修改、云读写、新权限或部署。仅记录格式、链接、差异和隐私检查，不重复应用全套／构建／CI。现有刷新方式与暂停状态仍按[周期说明](../SOCIAL_REFRESH_CYCLE.md)处理，原[浏览器目录安装记录](2026-10-14-bilibili-account-installation.md)不作为小红书自动发现证据。
