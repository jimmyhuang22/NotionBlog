## 改了什么

- `ContentImage`：图片的 `delivery.mode` 为 `display-only` 时，把 `delivery.maxWidth` 交给看大图，并且不再登记 1600 档（`src` 已经是最大展示版）。预览读不出来时照旧只退到 `src` 一次，`src` 也失败才显示“图片暂时无法显示”。
- 看大图（`Photo.maxWidth`）：判断“已经是完整图片”时用 `maxWidth`，没有它才用原件 `width`；顺序是页面预览 → `src`，之后放大不再请求任何更大的图。顶栏文案：加载中“正在加载清晰图…”，失败“清晰图没有加载出来，这是预览图”（没有预览时“图片没有加载出来”）。不带 `delivery` 的图片，逻辑与文案完全不变。
- 布局、样式、手势、键盘缩放、切图、关闭与焦点返回都没有改。

## 怎么验证的

演示数据、本机生产构建。在一条演示动态的正文里临时放了 6 张虚构图片（验证后已撤回，不提交），用无头 Chrome 拦截 `/media/v2/` 请求，按档位返回虚构 PNG 或错误码，并记录每张图的全部请求；1280 与 390 宽各跑一遍：

| 样本 | 页面请求 | 打开看大图 | 放大 4 次 | 顶栏 |
| --- | --- | --- | --- | --- |
| A 原件 2400，展示 1600 | 400 | `src` 一次（1600） | 无 | “正在加载清晰图…”，到达后清空 |
| B 原件 1000，展示 1000 | 400 | `src` 一次（1000） | 无 | 无 |
| C 80×80 | 400（实为 80） | 无 | 无 | 无 |
| D 展示文件损坏（503） | 400 | `src` 一次，503 | 无重试 | “清晰图没有加载出来，这是预览图” |
| E 已撤回（404） | 400、`src` 各一次后显示失败占位 | 不进入看大图 | — | — |
| F 不带 delivery（旧行为） | 400 | 1600 档 | 桌面放大超过 1600 后取原图；手机上 1600 已够用 | 旧文案 |

每张关闭后焦点回到原图片按钮；控制台无错误。`npm run check`、`npm run privacy:check`、`npm run build` 结果见合并请求。
