# 2026-10-17：课程页封面按屏幕挑 800／1600（Claude，开关关着）

编辑登记：Claude 本轮修改 `src/components/cover-image.tsx`、`src/app/study/[course]/page.tsx`。建在后端合并请求 387（课程封面 1600 档，Codex）之上；`image-preview.ts` 由 Codex 改，这里没有动。契约、接口与媒体路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

来由：课程页封面显示约 892 CSS 像素宽，800 档在高清屏上偏软。用户同意由后端给 13 张课程封面加 1600 档、前端按屏幕挑选（见后端的 `docs/decisions/2026-10-17-course-cover-1600.md`）。

## 改了什么

- `CoverImage` 新增可选的 `larger`（宽度与 `sizes`）：两档都是站内小图时给 `srcset`（800w、1600w）和 `sizes`，由浏览器挑；改取原图时 `srcset` 与 `sizes` 一并去掉，免得浏览器继续挑失败的那一档。
- 课程页封面用 `larger`，`sizes` 按正文栏宽：宽屏 `min(900px, 100vw − 388px)`，窄屏 `100vw − 32px`。
- **开关 `COVER_1600`（`src/app/study/[course]/page.tsx`）现在是 false**：正式站点在登记完成前收到 1600 会给原图（约 1.9 MB 的 PNG），比现在的 800 小图更重。后端回报新成功批次里 13 张已登记并回读后再打开。

## 怎么验证的

本机临时页面（已删除，未提交），一张开着 `larger`、一张不开；无界面 Chrome 拦下 `/media/v2/` 请求，用真实尺寸的测试图（800、1600、1672 宽）回应。

| 宽度与像素比 | 浏览器挑的 | 结果 |
| --- | --- | --- |
| 1280 ×1 | 1600 | 显示 |
| 1280 ×2 | 1600 | 显示 |
| 390 ×1 | 800 | 显示 |
| 390 ×3 | 1600 | 显示 |
| 1280 ×2，1600 回 503 | 1600 → 原图 | 显示，`srcset` 已去掉 |
| 390 ×1，小图都回 503 | 800 → 原图 | 显示 |

不开 `larger` 的那张始终只请求 800。正如后端提醒，桌面一倍屏也会挑 1600（800 不够 892 宽）。

一处测试陷阱：起初用 2×1 像素的测试图，带 `srcset` 时浏览器把它的宽度折算成 0，组件误以为图片坏了；换成真实尺寸后正常。真实小图不会这样。
