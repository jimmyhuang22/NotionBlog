## 显式安装器

新增 owner 会话工厂，生产入口内部创建一个真实 pg.Client，严格 CA／TLS 配置并拒绝连接串参数覆盖；回调只得到私有登记且当前事务有效的会话。裸 SqlExecutor、Pool、描述性假标记、过期会话和提前结束的事务均拒绝。查询／脚本限于本安装用途，实际 backend PID／事务 ID 逐次核对，已捕获失败仍阻止提交。

两个安装器在同一事务内完成前置校验、必要 DDL、模式摘要及末尾能力验证。固定行锁与语句期限有界；仅明确 COMMIT ACK 后工厂才返回。回调中的安装回执不能提前当作最终提交证明。异常明确区分未提交、提交未知、已提交但关闭失败；首错保留，回滚／关闭继续尝试，立即关闭失败也销毁并有界观察自有 socket。调用方处理固定 code／outcome，不把私有 cause 输出到公共日志，不自动重发未知提交。

[独立安装配方](../../database/incremental-owner-install-recipes.json)分别绑定历史原文 SHA、精确 BEGIN／COMMIT 边界与执行体 SHA；reader 仅取出精确 CREATE ROLE，由受控准入完成。两份旧 SQL 和 manifest 的四个原 SHA 均未变。schemaDigest 表示原模式身份，recipeDigest 表示新执行配方，不冒称逐字执行了旧原文。

既有集群组须满足原无登录／危险属性／父角色规则及当前库最小权限；额外私表／列／序列读取、函数 EXECUTE、对象所有权、未来默认授权等均拒绝，不重置属性、不 ALTER／DROP 角色或改变 LOGIN 成员。仅缺少本地隔离列且没有私有核心函数手工预授等部分安装迹象时走 fresh；空／错摘要、缺失能力、重新开放私有 API 和其他部分状态拒绝，不自动修复。两个扩展正反顺序及完整安装复验兼容。

本项只支持这两个受控安装器的兼容角色复用，不改变直接执行旧 SQL 的前提或其他基础迁移，不等于整个仓库任意同集群重装。相关[B03 安装说明](../BACKEND_READER_ISOLATION_PLAN.md)已同步新调用约定。内部学习发现只修正注释：槽位 fingerprint／revision 保障重放，不使用永久内部 event 去重账本。
