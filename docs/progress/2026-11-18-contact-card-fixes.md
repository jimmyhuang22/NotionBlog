# 2026-11-18：联系卡片两处修正（Claude）

编辑登记：Claude 修改 `src/components/contact-card.tsx`、`src/app/globals.css`。契约、接口与媒体路由、取数层、fixtures、栏目开关、依赖、站点配置与后端代码未改。

## 改了什么

用户在线上（#368 部署、邮箱已配置后）反馈：鼠标移到“写邮件”上字消失；点了也没跳转、没反应。

- 字消失：全站的 `a:hover { color: var(--accent) }` 比按钮自己的颜色规则优先，悬停时字变成与按钮底色相同的强调色。四个主题都有。改为 `.contact__action--main:hover` 也保持卡片色。
- 点击没反应：在线上用真实鼠标事件点“写邮件”，点击没有被页面拦截、链接是 `mailto:` 正确地址、按钮在最上层；所以是点击的那台电脑没有可处理邮件链接的邮件应用，浏览器静默忽略。新增退路：点“写邮件”约 1.5 秒后页面仍在前台（没有邮件应用接管），卡片下方提示“没有打开邮件应用？复制地址后用自己的邮箱发就好。”，读屏也会读到；关闭卡片时清除。

## 怎么验证的

- 线上只读：临时叠加新样式并真实悬停，四个主题（岛屿、墨水、苹果深色、千禧）悬停时字色均为卡片色，不再与底色相同；修正前四个主题字色都等于底色。
- 本机正式构建配占位地址（与 #367 相同的临时配置入口，验证后已还原）：岛屿 1280、墨水 390 悬停字可见；点“写邮件”后 1.8 秒出现提示，卡片保持打开。
- Node 24.21.0：`npm run check` 与 `npm run build`，结果见合并请求。

## 限制与下一项

- “页面仍有焦点”是推断：有邮件应用但浏览器先弹确认框的情况，提示也会出现（文案是问句，不算误导）。
- 真机与真实邮件应用的打开路径没有验证。
