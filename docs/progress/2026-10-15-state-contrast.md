# 2026-10-15：悬停、聚焦与渐变底上文字的对比度（Claude）

编辑登记：Claude 本轮前端修改与验证完成，范围为 `src/app/skins.css`、`src/lib/home-feed.ts`、`src/components/work-row.tsx`、`src/components/social-work-card.tsx`、`tests/home-feed-display.test.ts` 与说明文档。契约、接口路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

来由：第二轮全站排查（排查 10）写明“下一轮要补：悬停与聚焦状态；渐变背景上的文字”。用户同意由前端补做，并一起做两项小收尾。

## 怎么查的

**本机演示数据。** 写了一个无界面 Chrome 的检查，对每个页面做三件事：

- **静止**：逐个可见文字，按实际背景逐层叠算（含祖先的不透明度）；背景是渐变的，按渐变里每一个颜色分别算、取最差的；用渐变填字的（苹果首页的名字），按渐变的每个颜色对它下面的底色算。
- **悬停**：用开发者协议把每个链接和按钮依次强制成悬停状态，算它里面每段文字。
- **键盘聚焦**：真的按 Tab 走一遍，每到一处算文字对比度，以及焦点框颜色对它周围底色的对比度（标准 3:1）；没有焦点框的记下来人工看。

范围：墨水浅色、墨水深色、苹果浅色、苹果深色、像素深色、千禧浅色六种，每种看首页、动态、学习首页、一篇学习笔记、搜索结果、找不到页面，以及打开主题菜单的首页，1280 宽。共 42 次，每次 13 到 45 个可点元素、9 到 23 个焦点位置。

## 查到的

| 项 | 判断 | 处理 |
| --- | --- | --- |
| 像素、千禧：筛选条当前项获得焦点时焦点框看不见（像素 1.0、千禧 1.02） | 真问题。筛选条横向滚动时焦点框画在项目内侧，而这两套的当前项用强调色填满，和焦点框同色 | 这两套里当前项的焦点框改用它自己的文字色（像素是深色、千禧是白色） |
| 像素：搜索栏目标签悬停时文字 1.0 到 1.78 | 真问题。通用的悬停色把文字改成黄色，在像素里压在蓝色或黄色的标签上 | 像素里悬停改为底色变浅、文字保持深色，和像素的按钮一致 |
| 墨水：导航当前项“动态”“学习”报 1.0 | 误报。当前项下面那个墨点是用渐变画的，被算成了文字的底 | 不改 |
| 千禧：学习笔记里子页面链接的焦点框报 2.02 | 误报。卡片顶上的“三色灯”也是渐变，被算成了焦点框的底；截图上焦点框是蓝色画在白底上，很清楚 | 不改 |
| 搜索框没有焦点框 | 不是问题。焦点框画在外层的搜索条上（`:focus-within`） | 不改 |

改后复测像素和千禧的动态页、像素的搜索页，三处都过线。前后对比图存在本机忽略的目录里，已给用户看。

## 两项小收尾

- **像素主题时间行里的“昨天”“3 天前”**：像素的点阵字体没有中文，退回的中文字体在点阵字号下只有数字一半高。改为用像素主题自己的中文点阵字体，字号和它其他短中文标签一样。
- **“是否超期”的计算删掉了**：页面已经不显示“未按期更新”。`sampleTime` 只剩悬停提示要用的时间文字，不再调用后端的采样周期判断，参数里的平台也去掉了；测试随之改写（年份省略、跨时区、读不出时间的情况仍然覆盖）。后端自己的 `socialSampleStatus` 及其测试不动。

## 限制

- 只在演示数据下查；作品页、作品库、相册、关于页在演示数据下没有内容或栏目关闭，没有覆盖。
- 只查了 1280 宽；手机宽度下的悬停没有意义，聚焦没有单独查。
- 静止状态的检查只看前三屏。
- 误报是人工看截图排除的，检查本身没有改成能识别装饰性的渐变。
