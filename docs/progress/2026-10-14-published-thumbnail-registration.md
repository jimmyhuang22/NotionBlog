# 2026-10-14：同批次小图 SQL 登记入口（Codex）

编辑登记：从最新 develop 隔离新增登记 engine、CLI、测试与本项说明。只消费现有 accepted full／媒体计划／角色检查／小图 API 和原锁，不改共享契约、已有 helper、迁移、权限、来源、环境、调度、front 或其他会话的私有执行计划。图片连接修复的单独请求仍由原拥有方处理。

实现：计划只读私有元数据，绑定独立 reader 覆盖回执摘要；只选本次 full 中父指纹相符且已有覆盖证明的小图，历史、已变父图与未验证项分别计数。register 在原 canonical worker 锁下核验两个受限 LOGIN、状态、成员、父图和冲突，再调用已有不可覆盖的登记 RPC。逐项持久保存 inFlight／确认进度，最终独立 reader 核对；verify 无写入，未知提交不自动重试。

接口与 provider：[登记说明](../PUBLISHED_THUMBNAIL_REGISTRATION.md)。最多197候选／3,886,392B既有WebP覆盖；SQL保守18+3M、参数2MiB、rows4MiB、8分钟及显式绝对截止；HTTP全零。原图／Source／COS不读取，不生成或上传，不激活publication。覆盖输入是媒体拥有方的审阅证明，登记成功仍须后续独立对象字节验收。

验证：使用虚构完整 accepted full 与本地实际 PGlite 迁移／受限角色验证登记、幂等、独立读回、祖先撤回、父指纹变化、权限／输入预算失败与丢失回应；实际 CLI 使用模拟物理 Client 端口验证零HTTP、canonical锁、进度文件、防重复与凭据隔离。一次完整 `npm run check` 通过：1815 测试、类型、三项协议与846文件隐私，133.01秒；一次构建通过，42条server trace排除私有运行文件，4.21秒。最后补连接前目标比对与取消后迟到rows精确计数用例，再跑类型、13项受影响测试及隐私通过，未重复全套／构建。随后整合 develop 已合入的图片连接修复与补充记录，类型及69项受影响用例完成：68项首次通过，1项原生连接测试因沙箱禁止loopback监听触发Node断言；最小监听明确返回EPERM，允许该纯本机测试后单项通过。保留初次失败，不改他人的测试或图片代码，也不把这个环境限制写成应用故障。

局限与下一项：本轮没有真实云SQL／Source／对象调用，没有安装、切换网站或 main 部署。自然发布成功证据由原旧任务的现有回执取得，不是本轮重跑，也不是新预算入口实际运行证明。发布拥有方下一步从最新成功覆盖回执导出审阅输入，冻结同次accepted工件与实际计划摘要，再在明确的维护／writer交接条件下登记和做独立字节／访客验收。
