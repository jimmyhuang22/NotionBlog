# 2026-10-13：首次增量目录基线初始化（Codex）

编辑登记：本项仅修改 `queue.ts` 的首次目录种子事务、`discovery.ts` 的元数据指纹导出，新增 `discovery-baseline.ts`、本项测试与说明。不编辑完整内容回读、学习子目录轮巡、实际运行入口、数据库、图片或前端。

目标：复用同一轮完整来源采集的元数据，在完整发布经独立 reader 验证后初始化目录，避免首次增量扫描把已发布页面全部重新排队。初始化不设置水位，首次仍检查成员；真正的变化、缺失或未确认记录按既有机制生成提示。

实现：`captureDirectoryMetadata` 观察完整采集原有页元数据调用，`seal(records)` 生成绑定完整 records 的私有 companion；`initializeDirectoryBaseline` 要求同批独立完整 reader 证明及当前状态，才调用队列事务。原指纹算法导出复用，语义未变。缺失、冲突、不活动或时间不符的元数据不作种子。队列升级 schema 4，原子保存种子与回执；不设水位、不发任务、不清 pending／unknown，不覆盖已启动目录；相同回执重放不回滚后续扫描。接口见 [首次目录说明](../WEBSITE_DISCOVERY_BASELINE.md)。

验证：新增 14 项定点测试覆盖完整采集器、实际 SQLite 队列／重开、普通 data source、显式单页探针及原执行器；首次正文准备为零，新页和同时间戳属性修改仍入队，签名更新不误报，封面更换可发现。完整证明拒绝、模糊元数据回退正常发现、重放冲突及 schema 1／2／3 升级保持未知提交／关闭回执均验收。纳入最新 develop 的学习子目录 PR196、完整回读 PR197 与课程封面 PR198 后，Node 24 的 `npm run check` 通过：1,567 测试、类型、三协议及 663 文件隐私检查；`npm run build` 与 40 server trace 隐私检查通过。目录初始化代码未因整合改变，最新组合仍以对应提交的平台检查为合并依据。此处均为代码验收，日常数据同步不需要重复全套工程检查。

限制与下一项：数据全部虚构，仅本机端口验证；没有运行 Notion 采集、实际完整基线、云 SQL、图片 I/O、排程、站点开关或部署。主运行器在同一完整采集保存 companion，并在普通／学习基线初始化后消费接口；学习子目录、运行入口和图片各由原负责人接线，当前旧完整发布窗口保持原负责人独占。
