## 修改、接口与 provider

`ContentRepository.readLibraryPage` 返回 `{page, years, year}`；`readLibraryFirstPage` 是 SSR 独立实时入口。factory 验证参数、执行栏目权限包装；有能力时直接走新读取，失败向上传播；无能力的 provider/显式 legacy 配置使用原列表与年份编排和原缓存。原列表接口可继续消费共同读取生成的 w1 游标。

新 SQL 扩展以独立摘要登记，依赖既有 scoped/publication 资格能力。未登记或摘要不匹配拒绝读取；只有 nb_reader 可调用两项公开读取函数，私有状态启用 RLS，函数固定 search_path。默认 `DATABASE_LIBRARY_PAGE=legacy`；compact 要求 v2/scoped。未安装任何云端迁移，未修改实际运行环境。

封面准备复用已有本地 manifest/cloud mapping 适配器，仅传当前页已公开投影的元数据；允许返回媒体 ID 到受限尺寸的映射。随后重新检查完整候选集合并读取当前元数据，最终结果不使用准备阶段的旧 DTO。空结果、年份失败也执行最终检查。旧 producer 兼容性许可文件未修改；测试只更新当前源码的拒绝观测摘要，继续拒绝把新网站读取代码用于历史 capture 许可。

## 验证、收益与限制

独立 PG：702 页、26 项权限、32 项降级、22 项入口/投递、4 项最终语句并发、9 项缓存/cloud 适配器检查与 12,000 条数据的 10 组对照通过。`npm run check` 3,386 项通过、无失败或跳过；`npm run build` 和 50 项 server trace 隐私检查通过。

受限网络正常页原实现/精简/4 MiB：3/4/2 次 SQL，8.635/0.989/8.635 MiB，840.0/608.4/706.0 ms。原路径冷缓存 946.0 ms，热缓存 48.1 ms；新路径明显慢于热缓存，直连也未见稳定收益。24 个云端描述符新增一次批量映射 SQL、约 14.3 KiB；不做逐图查询。

结果在本项[评审报告](../reviews/2026-11-11-library-ssr-live-read.md)集中记录。独立 PostgreSQL 使用合成数据；云端映射通过正式适配器和合成 SQL 描述符夹具测试，不代表私有生产映射函数的计划与线上耗时。缓存使用正式 `readPublicProjection` 和真实本地 cache stamp SQL，存储端口是内存夹具，不代表托管 Next 缓存的读取时延。

新入口不会利用旧 DTO 热缓存，因此不能声称所有场景都提速。并发权限边界仍是最终 SQL 开始的快照，之后才提交的撤回由下一次请求观察到；媒体端点另有最终检查。当前仍为 O(N) 选择器读取、O(N log N) 排序，完整指纹会重复扫描，不是数据库 limit 下推。
