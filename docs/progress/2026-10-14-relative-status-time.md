# 2026-10-14：动态时间写成“今天、昨天、N 天前 · 日期”（Claude）

编辑登记：Claude 本轮前端修改与验证完成，范围为新增 `src/components/entry-moment.tsx`、`src/components/use-today.ts`，修改 `src/lib/format.ts`、`src/lib/timeline.ts`、`src/components/status-timeline.tsx`、`src/components/status-feed.tsx`、`src/components/home-timeline.tsx`、`src/app/status/page.tsx`、`src/app/timeline.css`、`tests/timeline.test.ts`。契约、接口路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

来由：反馈交接包 08。用户在反馈审查对话里看过四列对比原型，选定“七天内相对说法和日期都写”，把交接包的摘要贴到了这个对话。决定见 [决策记录](../decisions/2026-10-14-relative-status-time.md)。

## 改了什么

- **规则**（`src/lib/format.ts`）：`relativeDay` 比较两个日历日期，给出今天、昨天、前天、3 到 7 天前，其余没有；`momentLabel` 把它和日期拼成时间那一行。按日历日算，不按小时数算。
- **“今天”从哪来**（`use-today.ts`）：首次渲染用服务器生成页面的时刻，之后跟设备时钟，页面重新显示和每过一分钟各查一次，日期变了才重新渲染。
- **输出**（`entry-moment.tsx`）：动态页与首页时间线共用；相对说法和日期在同一个 `<time>` 里。
- **动态页**：`/status` 把生成页面的时刻传给列表。
- **首页**：每一条的时间都按新写法；一组连着的作品只覆盖一天时也加相对说法。
- **样式**：相对说法用墨色，日期保持原来的灰色、整体不换行。没有照原型把日期调淡，因为对比度不够（数字见决策记录）。

## 怎么验证的

**只在演示数据下验证过。**

- 单元测试 5 项新增（`tests/timeline.test.ts`）：当天、1、2、3、7、8 天；跨月与跨年；日期在今天之后；只记了日期；没有日期；UTC 落在前一天而站点时区已是第二天；临近零点前后二十分钟；夏令时开始那天（2026 年 10 月 4 日，23 小时）与结束那天（2026 年 4 月 5 日，25 小时）；一组作品在同一天与跨多天。
- 画面：本机开发服务器加一个不提交的临时页面，把演示动态的日期改到今天、昨天、前天、三天前（只记日期）、四天前、六天前、八天前、上个月、去年，三列并排（现状、改后、原型的调淡做法），浅色与深色各截一张；改后的样子另在 390 与 320 宽、苹果、像素、千禧主题下各看一次。320 宽下最长的一行仍是一行，没有横向溢出。
- 生产构建（`npm run build` 后 `next start`，演示数据）下的 `/status` 与 `/`，无界面 Chrome：
  - 正常时钟：第一条写“4 天前 · 10 月 10 日 19:00”，没有脚本错误和控制台报错。
  - 把浏览器时钟从一开始就拨快一天再打开：写“5 天前 · …”，没有水合报错。
  - 页面开着再拨快一天并触发“页面重新显示”：变成“6 天前 · …”；拨过七天：变回只写日期。
- 检查：`npm run typecheck`、三个 `*:protocol`、`npm run privacy:check`、`npm run build` 通过；`node --test`（除去本机跑不了的 `website-v2-runtime` 与 `qualified-shared-budget`）1893 项全过。

## 限制

- 没有在真实数据和正式站点上看过；“今天、昨天”这两种写法只在临时页面里出现过，真实路由上演示数据最近的一条是四天前。
- 像素主题里时间那一行的汉字本来就比数字小，相对说法因此偏小，这次没有调。
- 每分钟检查一次日期，过了零点最多晚一分钟才更新。
- 设备时钟不准的访客，首次渲染之后看到的“今天、昨天”跟着他的设备走。
- 交接包提到的“返回时恢复列表”和“复用刚看过的列表”都还没有做；做的时候恢复出来的条目会自动按当前日期重算，因为“今天”不存在列表数据里。
