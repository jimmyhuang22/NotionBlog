# 2026-11-03：静态资源缓存与图片回访修复（Codex）

## 编辑登记与范围

用户要求结合两份审查，先修静态资源和图片回访，正式发布前确认。本项从 develop `8ad29b1` 创建独立工作树，修改媒体 HTTP 包装、验收规则、回归测试及静态入口配置示例；不重做前端图片重试、304 提前返回或批量资格查询。

## 修改

- `tagged-v1` 仅对原接口已通过资格检查且获准缓存字节的版本 v2／s1／s3 图片设置 `private,max-age=300,must-revalidate`，同时覆盖 200、提前 304 和外层 304。实时来源排除标记、可变 s2、API、错误与模式关闭行为保持。
- visitor 验收只接受精确的五分钟例外；较长 TTL、public、immutable／stale 复用、可变路径及错误不能通过。保留 ETag、Cloudflare no-store、原有 Vercel 标签协议，不更改 DTO、SQL、provider、连接池或持续任务。
- Cloudflare 实读：0 条 Cache Rules／缓存响应规则、0 条 Page Rules、开发模式关闭，缓存级别“忽略查询字符串”，浏览器 TTL 四小时；规则模拟确认静态 JS 命中网站 8443 Origin Rule。此前样本一年 immutable JS 仍两次 DYNAMIC。官方文档将 8443 列为默认禁用缓存端口，因此候选增加仅服务静态资源的 8444 TLS 入口及两条狭窄规则，不碰现有 443／8443 服务。
- 已写 [静态启用及回退说明](../STATIC_ASSET_CACHE.md)；边缘 HIT 只能在获批启用后验收，目前没有更改云端配置。

## 验证

- 定向离线回归 32 项通过：版本图片 200／HEAD／304，真实 v2 路由 32 个验证请求合为两次资格查询且零对象读取，真实社交 SQL 资格与撤回，实时来源及可变地址排除，错误及其他 scope 的边界。
- 本机 Chrome 使用虚构图片、实际 thumbnail 与 public HTTP 包装：普通链接 A→B→A、后退／前进图片就绪；服务器仅收到首次图片 200、两次资格读取和一次对象读取。此项验证浏览器 HTTP 缓存，不冒充正式 Next Router 或真实数据库性能结果。
- 同一 Chrome 在首次响应 315 秒后再次普通链接回访：携带原 ETag 收到 304，累计资格读取 4 次、对象读取仍 1 次；过期前后策略与预期一致。
- 复用本机已有 Nginx 1.31.3 镜像，配置语法通过；9 个 TLS HTTP 场景通过（GET／HEAD 静态 200、POST 403、缺失静态 404、页面/API/媒体/两种路径穿越 404），未知 SNI 在 TLS 握手被拒绝。上游非静态路径故意设为 200，确认拒绝来自静态入口本身。未拉取镜像、未访问真实来源。
- 完整 check 首次因独立工作树遗漏第二锁文件的既有本机依赖而在 typecheck 中断；补齐同版本副本后继续，原失败日志保留。随后官方 Node 24.22.1 完整 check 通过 3292 项测试（零失败／零跳过），类型、lint、协议和隐私检查通过；本机生产 build 与 49 份 server trace 隐私检查通过。
- Linux amd64 自托管公开构建在已有隔离镜像中通过，49 份 server trace 隐私检查通过，不加载真实运行配置；Linux 产物只在本机准备，未上传或安装。
- 已构建 Next 应用实际 HTTP：JS、CSS、woff2 各 200，均为一年 immutable；缺失静态文件 404 且 no-store。临时浏览器页、HTTP 服务与 Nginx 容器均已关闭。
