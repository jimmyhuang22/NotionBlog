起因：动态页的 400 像素预览图在正式站点启用后，后端交回让前端做视觉与交互复验。复验结果和交给后端的事项写在下面；其中两处属于前端，已在这次改掉。

## 正式站点复验（2026-10-12 21:40 到 21:55 UTC，main 上的版本）

只读、点到为止：动态页访问两次（2025 年一次、2026 年一次），接口请求十来次，图片请求各一次；除看大图的那一张外，跳向原图的请求都在浏览器里拦下，没有下载原图。

| 项目 | 结果 |
| --- | --- |
| 动态列表的图片 | 首屏 12 条动态里加载了 16 张，全部是 400 像素的 WebP，合计约 430 KB、最大一张 67 KB；另有 1 张没有预览、仍走原图（与后端说的“4 张保留原图”相符）。1280 与 390 下三列与单张的排版正常，没有横向滚动，控制台没有报错 |
| 看大图 | 打开的是原图（地址不带预览参数，1800×1800），计数、Esc 关闭、焦点回到原来那张都正常；**但点开后约 3.2 秒屏幕是黑的**（站点 1.2 秒后才回跳转，再下载原图），其间上一张、下一张两个箭头挤在屏幕中间 |
| 等图时的格子 | 预览图每张要等 2.6 到 4 秒才到，这段时间格子是空白的 |
| 展开的动态正文 | 正文里的图片要的是原图，不带预览参数 |

交给后端或用户的（已写进后端的回执文件）：

- **预览图到得慢**：单张 8 到 30 KB，但站点要 2.6 到 4.1 秒才开始回（单独请求三张、同时请求六张都是这样），而且每次访问都重新等（`private, no-store`）。图片变小了，列表上的图仍然是过三四秒才出现。
- **其他页面的图片还是原图**：影视、书籍、游戏的封面（抽查到的影视封面最大 4.3 MB、游戏 2.4 MB），相册照片（3 MB 以上，其中一张 40 秒没有回），课程封面，都没有预览。作品库一页 24 张封面。
- **正文里的图片没有预览档位**：展开的动态、笔记和文章正文直接用原图。

## 改了什么

- **看大图先显示页面上的预览**：点开立刻看到列表里那张预览，按原图的最终位置和大小摆好，上一张、下一张在两侧；顶栏写“正在加载原图…”。原图在后台取，解码好了原地换上，位置大小不变。原图取不到时保留预览，顶栏写“原图没有加载出来，这是预览图”。翻到下一张时不再等上一张的原图。
- **不重复下载原图**：页面上的版本本身已经是原图（没有预览、预览地址跳到原图）时，看大图直接用它，不再取第二遍。相册照片和那几张没有预览的动态图片原来会下载两次。
- **等图的格子有占位**：图片还没到时，格子是一块浅色，不再是空白；到了照旧淡入。
- 没有单独预览的图片（正文里按原图显示的）行为不变：页面上已经有了，点开就是。

## 怎么验证的

演示数据下，本机无界面 Chrome。演示图片的预览和原图是同一个地址，为了走到“先预览后原图”这条路，验证时临时让每张演示图片有自己的地址和单独的预览地址，并在浏览器里把预览换成一张 400 像素的小图、把原图拖慢 3 秒；这些改动只在本机，量完已撤掉，没有提交。

| 项目 | 结果 |
| --- | --- |
| 打开 | 0.3 秒时已显示预览，照片框 1086×724、两个箭头在两侧、顶栏“正在加载原图…”；3.9 秒时换成原图，框的位置和大小完全相同，只请求了一次原图 |
| 连续翻页 | 每翻一张都先显示那一张的预览；翻走后不再等前一张 |
| 原图失败 | 预览保留，顶栏“原图没有加载出来，这是预览图” |
| 页面上已经是原图 | 直接显示，没有“正在加载”，没有再请求原图 |
| 正文里的图片 | 点开即显示，没有新请求 |
| 手机宽度（390） | 照片框 362×241，换原图前后一致 |
| 等图的格子 | 216×216 的格子在等图时有浅色底，图片到了底色撤掉 |
| 关闭 | Esc 关闭，焦点回到原来那张 |
| 第二个图片元素是否复用页面上的预览 | 在正式站点上实测：同一地址新建图片元素立即可用，没有产生新的图片请求（预览是 `no-store` 的，所以专门确认过） |
| 自动检查 | 见合并请求正文 |

## 限制

- 改动后的看大图没有在真实图片上看过，要等下一次发布；真实原图 4 到 7 MB，解码和换上的手感要在真机上看。
- 照片宽高未知时（真实数据里目前都有）看大图仍是原来的样子：预览按自己的大小显示，原图到了会变大。
- “先摆好最终位置”用了容器查询单位，较旧的浏览器不支持时退回到上一条的表现。
- 没有在 Safari、Firefox 和真机上看。
