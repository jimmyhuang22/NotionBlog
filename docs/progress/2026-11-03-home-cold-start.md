## 发现与实现

- 上次 AWS 空缓存发布后首页首批响应 261 毫秒、完整响应 3155 毫秒；列表预算内耗时 3010 毫秒，其中首页合成读取 2082 毫秒、社交快照 1622 毫秒、内容索引 1355 毫秒（并行），DTO 组装约 16 毫秒。主要成本在数据库冷读，不是页面布局。
- 自托管公开站点启用 tagged-v1 时，Next 准备好后、正式端口监听前，通过临时回环端口顺序读取内容版本和首页。先触发轻量读取初始化，再让首页在原有七秒预算中填充首屏缓存。
- 总预热等待十秒，累计响应正文 1 MiB；不请求图片、脚本、其他栏目或翻页。失败或超限后关闭临时监听器、记录脱敏结果并继续启动，不自动重试。普通开发、私有配置、Preview 和缓存关闭时不增加此读取。
- 首页成功取得首屏数据后才输出 inert template 标记；HTTP 200 的重试占位页不能被当作预热成功。首次访客依旧查询当前版本，版本变化、撤回、有效日窗口及原有数据库期限均保持。
- 这是将必要工作提前到启动阶段，不能表述为数据库冷查询本身提速；新版本对外就绪会晚一些，部署启动宽限须覆盖身份核验、Next 初始化和预热上限。

## 接口与 provider

- 复用 `/api/content/version` 与实际首页的现有服务、数据库只读身份及缓存入口，无新增 API、凭据或数据库安装。
- 原型先预热首屏 API，再访问首页时仍触发完整读取：同一内容版本生成了不同 Next 缓存项。因此最终直接预热首页，未修改框架缓存键或扩大缓存资格。

- 本机 Linux 隔离副本使用与生产相同的现有只读配置。旧版空缓存首页／首屏 API 因本机跨区域连接触及七秒上限，分别返回重试占位／503；保留失败，没有延长原请求预算。

- 本轮云端请求仅为现有公开内容的有限读取，无数据写入、图片下载、配置更改或生产重启；HTTP 正文低于 1 MB，数据库与连接开销估计数 MB 级，在每日小量只读范围内，未做独立计费计量。所有本项验证容器均已停止。
