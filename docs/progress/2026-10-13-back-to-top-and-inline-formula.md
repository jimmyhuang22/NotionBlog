## 改了什么

- **回到顶部按钮**。手机上悬浮的按钮固定在右下角，会压住卡片右端的内容（例如社交卡片行尾的“去看 ↗”），只有继续滚动才露出来。现在页面的内容栏伸到按钮底下时，按钮只在往回滚的时候出现，继续往下读就收起；内容栏碰不到按钮的宽屏上和原来一样，滚深了就一直显示。是否“伸到按钮底下”按内容栏右缘与按钮左缘的实际位置算，所以较窄的电脑窗口也适用。
- **列表里的行内公式**。动态条目未展开时那段文字里的行内公式原来显示成代码样式，展开后才排版。现在同样排版：先显示原文，随后用和展开后的正文相同的服务端渲染取回排好的标记，排版库不进浏览器。同一个公式只请求一次；没有公式的条目不发请求；排不出来的保留原文。

## 怎么验证的

只在演示数据下验证，本机开发服务与无界面 Chrome。演示动态的列表文字里没有行内公式，公式用一个不提交的临时页面、手写的虚构条目来看，看完已删除。

| 项目 | 结果 |
| --- | --- |
| 手机宽度（390），游戏列表与动态列表 | 往下滚按钮不出现；往回滚 50 像素出现；再往回 4 像素的抖动不影响；往下滚 60 像素收起；回到靠近顶部时收起 |
| 1024 宽的游戏列表、820 宽的动态列表（内容栏伸到按钮底下） | 同上 |
| 1280 宽的游戏列表与动态列表（内容栏碰不到按钮） | 滚深后一直显示，与原来相同 |
| 按下按钮 | 回到顶部 |
| 两个公式的条目、以公式开头并重复同一公式的条目 | 都排版成公式，段落仍是一行，390 宽没有横向滚动 |
| 没有公式、只有行内代码的条目 | 仍是行内代码 |
| 写错的公式 | 保留原文 |
