# 2026-10-20：开发、构建、Preview 与有限联调出站保护（Codex）

编辑登记：按用户四项确认，从当前 main 建独立分支。只修改开发／测试／构建入口、Next 配置与 instrumentation、CI 调用环境、隔离回归及本项说明。契约、页面／组件、SQL、角色、媒体对象、冻结业务运行包和调度不改，根检出其他会话的文档保留。没有生产连接、采集、云图下载、迁移或部署。

实现：测试／check／build／start 采用新鲜环境与 Node 预加载守卫，防止继承凭据或 production dotenv 恢复真实读取。普通开发继续 mock／本地素材，数据库回归沿用 PGlite。新代码 Preview／自定义部署在构建及新 Node 实例接收请求前隔离，CSP 约束浏览器图片与接口。明确的 Vercel Production 保留原 provider；本项不更改平台变量。旧部署不自动升级，其他托管平台正式入口需以后明确设计。

真实联调必须同时提供受限 reader、owner-only 计划、显式 opt-in 和有限期限。固定网关限制完整样本路径、方法与次数；远端目标通过本机中继共享连接／接收传输字节计数，包含 Node 工作进程，超限即停。时限先停止进程组，再强制终止拒绝退出的子进程。请求上限是网关样本请求，不声称统计所有 SQL 语句；字节统计包含 TLS／协议开销，触限的在途数据及其他客户端不能当作精确账单上限。旧 capture spec 保持，测试更新当前启动器摘要，继续证明新开发入口不得进入旧冻结业务运行包。

验证：Node 24 一次完整 check 通过 2,368 项测试、类型、三类协议和隐私检查。随后平台元数据处理与模块拆分的受影响回归 21 项通过，含历史 capture 拒绝规则的前一组 26 项通过；没有重复全套。最终隔离 Preview 构建通过，45 份 server traces 均排除私人运行文件。记录格式三项与最终 1,463 文件隐私检查通过。初次 sandbox loopback EPERM、构建的 ProcessEnv 类型错误及不必要的 dotenv-reader tracing 均保留，按原断言修正后补验通过。没有削弱冻结 capture spec、真实权限断言或隐私检查。

实际本机 HTTP：在故意提供虚构真实 provider／云端地址的 production dotenv 下，以 Preview 模式构建并启动；首页、内容列表、作品 v2 API 及一张本机封面返回 200，页面／API 含 CSP 与 noindex，返回内容不含虚构云身份／地址。旧社交 v1 在 mock 模式按既定规则返回 404；初始验收错误期待 200 的记录保留，源码核对后只补一次 v2 API 与一张本机图片，没有重读已通过页面。共五次 loopback GET，无生产请求或浏览器视觉验收；临时服务器验收后停止。正式平台部署／浏览器验收尚未执行。

边界与下一项：这些保护不是主机防火墙，不控制任意非 Node 工具或已存在的其他客户端；正常生产访客／采集用量仍需独立观察。待本机验收完成准备 PR，生产发布与既有历史 Preview 的处置另按授权执行；迁移继续暂缓。
