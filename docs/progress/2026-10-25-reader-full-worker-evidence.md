# 2026-10-25：隔离读取账号下的完整采集入口离线验收（Codex）

编辑登记：接续[协调器准入与准备链](2026-10-25-reader-selected-coordinator.md)，从最新 develop 建独立分支，只新增本记录。三份新增 JavaScript 仅作本机测试控制与传输路由，原统一候选及已封存的应用／协调器不改。

## 目的与修改

上一项的有效子入口只到准备或启动边界，本轮执行选定应用的实际隔离完整入口，验证独立公开读取账号可以完成新采集、发布与公开回读。原 native preload、连接池归属、共享预算、Auth helper、Notion SDK 和原业务流程均采用已封存字节；新夹具将 Notion／Auth 固定路由到严格 TLS 回环服务，并使用同一夹具许可中的父／子、owner 和缓存前置阶段。

数据库使用基础网站及缓存 DDL；公开 LOGIN 仅继承读取组，未直接授予所有 API。协议夹具将每个连接的用户切换为实际 SQL 角色，权限查询直接执行、不伪造角色结果；它不验证数据库密码，也未安装全部真实扩展，不能作为真实服务认证或完整数据库验收。虚构发布标识与清单只用于核对这 1,751 个应用输入，不代表新正式 release。

## 验证结果

最终五个独立场景全部通过，无跳过：

- 正例：完整采集并发布一条虚构影视记录，生成 capture／handoff，公开回读及独立快照核账一致；公开账号直接读私表仍被拒绝。执行七次虚构 Notion 请求和一组两次虚构 Auth 请求，零业务重试。
- 网站账号和证据账号：在 SQL／Auth／来源请求前拒绝，未分配数据库新运行。
- 混合组成员：一次原生权限查询后拒绝，Auth 和来源请求为零。
- 来源首次失败：仅一次来源请求，无重试；实际 fail_run 确认、运行状态为 failed，夹具 lease 清空且未发布。

正例来源子进程两条 PG TLS 连接、八次原生 SQL，关闭事件两个、pending 为零；独立 owner 和缓存前置各五次原生 SQL，均确认关闭，父进程自身 SQL 为零。来源共享逻辑计数十五，与原生八次是不同口径，不相加；来源失败场景的普通逻辑七次及清理两次也不等于其五次原生 SQL。Auth TLS 关闭及五个场景的自有进程、服务、数据库和目录清理均有回执。样本无图片，不代表媒体或业务容量测试。

首轮核账夹具未正确恢复管理角色，随后又因通用阶段上限不符原只读守卫而停止；改用既有显式角色恢复方式及选定目录原阶段上限。原始快照字段为 item.title，初始断言也已修正。失败日志保留，未改业务程序或放宽门禁；重复运行不累加。

三份新增 JavaScript 语法通过；原协调器完整清单及全部应用输入复核不变，因此不重复应用全套检查／构建，继承上轮记录的验证限制。另对最新图片登记父流程核对 22 处前像摘要及新增文件目标，补丁只读试应用通过，未实际应用或覆盖其工作。公共记录另做格式、链接、隐私与差异核验，本机结果不写成平台通过。
