# 2026-11-04：首页桌面首字节与回源连接（Codex）

## 编辑登记与范围

- 从 develop `a96f6e7` 建立 `codex/home-ttfb-20261104`。用户要求区分网络波动与源站延迟，验证能优化的改动，正式生效前确认。公网基线为 PR277（`9462d12`）。初次测量及候选验证期间未改线上配置。

## 测量与归因

- 对照[前后两次 Chrome 测量](2026-11-04-home-first-visit.md)，PR274 的三个桌面首字节约为 412、162、185 毫秒，PR277 约为 416、407、184 毫秒。两组慢样本的 Cloudflare 回源计时是 366–380 毫秒，其余为 129–135 毫秒。两组请求发出前耗时的中位数相差约 2 毫秒。旧版已有慢样本，前后各三次的中位数变化主要来自慢样本比例。
- 同一客户端网络，以独立进程串行请求 12 次公网首页，全部 200。首字节中位数 177 毫秒，范围 165–426 毫秒。随后将另 12 次公网测量与 AWS 入口端口收到的新 TCP 连接时间对齐，两次慢请求分别为 408、410 毫秒，等待期间均收到新连接。其余十次为 162–193 毫秒，各自等待期间未收到新连接。只保存 SYN 时间，不保存请求内容或来源地址。缺少逐条请求与 TCP 套接字的关联 ID，历史 Chrome 慢样本也无法逐条核对。
- AWS 本机串行做六组 Node 和 Nginx 回环对照，每组空闲约 12 秒后请求，再立即复测并从另一层入口请求。Node 空闲后与重复访问的首字节中位数为 16／13 毫秒，Nginx 为 20／19 毫秒。空闲后完整响应约 0.59 秒，重复访问约 0.16 秒。对应应用日志中的首页动态数据约 0.57–0.58 秒与 0.14–0.15 秒。流式首字节先于这部分数据，空闲后的正文延迟是单独的开销。
- 追加三次公网探针均为 166–177 毫秒，其中间隔 80 秒的一次约 167 毫秒。有限的连接关闭样本中，源站和对端均曾主动关闭。观测不足以将慢请求归咎于 Nginx 的默认空闲超时。
- 约 0.54 MB 公网 HTML，约 0.47 MB AWS 回环 HTML，另有小量日志和数据库读取。总量估计数 MB，未单独计量云端账单。

## 候选与验证

- 近期 500 条 Nginx 站点访问日志均为 HTTP/1.1。准备在两个共用 8443 的 TLS 监听声明上加 `http2`，让 Cloudflare 能通过 ALPN 协商 HTTP/2 并复用回源连接。使用现场 Nginx 1.24.0 对内存中候选做 `nginx -t` 并通过。再次读取现场配置与原件逐字节相同。
- 本机用 Nginx 1.24.0、测试证书和两个同端口监听声明对照。原写法协商到 HTTP/1.1，候选协商到 HTTP/2，两次请求使用同一连接。两组均接受显式 HTTP/1.1，并在 TLS 握手阶段拒绝未知域名。这个试验验证源站的协商与兼容性，不能估算 Cloudflare 连接复用率或公网改善幅度。
- 说明：[Cloudflare 回源计时](https://developers.cloudflare.com/speed/origin-analytics/)、[Cloudflare 回源 HTTP/2](https://developers.cloudflare.com/speed/optimization/protocol/http2-to-origin/)、[Nginx 连接空闲超时](https://nginx.org/en/docs/http/ngx_http_core_module.html#keepalive_timeout)。

## 授权上线与复测

- 用户明确授权先备份，再启用 8443 回源 HTTP/2，平滑重载并复测，出现异常则回滚。变更前核对原配置与受检基线一致，保留只允许管理员读取的备份。线上站点配置仅有两处监听声明改动，完整 `nginx -t` 通过，重载前后 Nginx 主进程 PID 一致。AWS 回环的 HTTP/2 与显式 HTTP/1.1 健康检查均返回 204，公网健康检查也返回 204。
- 从重载前记录的日志位置开始核对来源地址和协议。来自 Cloudflare [公布地址段](https://www.cloudflare.com/ips/) 的首页请求 36 次，全部为 HTTP/2 和 200，另有 1 次公网健康检查为 HTTP/2 和 204。测试窗口内 Nginx 错误日志无新增，保留配置和备份。
- 沿用同一客户端网络、Cloudflare 边缘节点及独立 curl 进程，使用相同压缩、请求头和串行间隔。上线前 36 次含原先两组和重载前补测一组，上线后分三组测 36 次，均返回 200。首字节中位数 174 → 170 毫秒，最大值 426 → 270 毫秒。以 350 毫秒为界，接近 400 毫秒的慢请求由 6/36 降至 0/36，严格达到 400 毫秒的由 5/36 降至 0/36。紧邻上线的两组各 12 次中，350 毫秒以上由 2 次降到 0 次。
- 上线后配对组采集约 46 秒，新建入站 TCP 连接为零，12 次首字节均为 165–187 毫秒。探针只输出连接时间。本次只覆盖单一网络和短窗口，结果描述慢请求频率的变化，不能保证未来没有慢样本。
- 本次追加公网测量 48 个首页响应，压缩正文约 0.92 MB，另有小量健康、日志及数据库读取。未单独计量云端账单。应用代码、接口及 provider 未变，记录随 develop 维护。
