## 问题与修复范围

旧代码在本机受信任转换器非零退出，以及下载正文为空／声明长度与实际长度不符时都返回 `IMAGE_REJECTED`。四个虚构输入经真实转换／下载入口和临时 SQLite 增量队列复现：每个在第一次失败就进入人工检查，未提交发布。这些结果只能证明失败，不能证明重试必然无效。

将上述情况改为既有 `IMAGE_UNAVAILABLE`。增量队列因此沿已有页面失败次数、指数退避和五次转人工规则处理，不增加即时重试或既有次数上限，不新增错误码。下载失败仍丢弃全部本次字节，不发布、不写缓存。受信任转换器的异常退出不据此判定图片永久不支持；持续失败仍会到达人工检查。

URL／完整 DNS／来源白名单、TLS、重定向、声明与实际大小上限、允许格式及实际签名、转换器身份／权限、转换输出检查均保留原拒绝。取消保持 `CANCELLED`，私有转换工作目录仍清理。没有 DTO、错误码集合、状态／迁移协议、公共 fixtures、依赖或 CLI 入口变化；v2 下载器的即时重试判据、队列策略和现有人工恢复入口不变。

共享下载器也用于直连 m1 图片代理；该层原本将这两个图片错误码都映射为 `CONTENT_UNAVAILABLE`，本项不改变其 HTTP 失败语义、单地址／关闭或资格复核规则。
