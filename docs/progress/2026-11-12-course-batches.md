# 2026-11-12：整门课程自动分批（Codex）

## 编辑登记与改动

本项涉及管理后端、增量 host/CLI、冻结弹窗与批处理测试。按成员页数和原图资产数分批，后端持久保存步骤并顺序执行；每批读取当前版本与冻结代数。host 对内部 refreshPageIds 验证格式及冻结组归属，准备时未轮到的组成员保持冻结，避免父级目录把其他批次带入当前增量，保留发布层硬限制、独立 reader 与队列恢复。CLI 显式传递选择，不允许普通恢复命令夹带刷新选择。

冻结按 50 个媒体描述符分批核验后统一提交。冻结按钮由操作类型决定，预览失败不再误显示“同步一次”；提示说明分批语义。东京专用 display 适配器与部署记录保留在私有运维目录，不含公共仓库中的来源身份或凭据。

最新 develop 的按压反馈 CSS 缺少一个媒体查询闭合括号，导致生产构建失败；本项仅补齐该括号，没有重新设计样式或部署正式站。

## 接口与 provider

仅内部 ManagementPorts.refresh.pageIds 和 host.refreshPageIds 可选输入；原浏览器 JSON DTO、SQL 协议、默认 provider 与定时任务配置不变。冻结的同步一次保留组保护，逐批原子发布；前批成功后后批失败不冒充整项成功，unknown 不重放。

## 验证

- 完整 `npm run check` 等价离线入口通过：3,403 项测试，0 失败、0 跳过。首次受限沙箱运行因本机端口权限失败并阻塞，停止后在允许本机监听的环境重跑；外网防护仍开启。
- 后续预算、CLI 和错误提示调整通过定向批处理／冻结 host／记录格式测试及 TypeScript 检查；覆盖批次覆盖完整性、第二批明确失败、结果不明、共享预算耗尽、重复执行拒绝、组外页面拒绝及真实 SQL 冻结刷新回执恢复。
- `build --webpack` 与构建隐私检查通过；补齐来自目标分支的 CSS 括号前构建失败，未把失败计为通过。本机控制台单独构建通过，东京 display 运行组合 9 项定向测试通过。
- 本项真实环境验收结果保存在忽略的私有运维记录；公共记录不包含课程身份、原始正文、来源 ID 或令牌。正式站、游戏采集及 DNS 没有部署改动。
- 首次真实刷新在准备阶段触发媒体上限，0 内容发布、无未确认写入；查明为父级目录联动读取跨批成员。补充读取隔离与回归测试后，20 项相关域／冻结 host／display 测试通过；失败记录保留，使用原队列 API 恢复准备项。

## 限制与下一项

预分批保留余量，但单页超过 100 个原图资产、重大父子关系变更导致准备结果超限时仍拒绝，不放宽数据库协议。总时长、字节与请求预算继续限制单项任务。正式站采用和域名切换不在本项范围。
