## 实现与接口

- 纯 routeCheck 复用原地址解析、栏目开关和 focus 规则，无数据列表、无效地址和关闭栏目不增加服务调用。
- 普通 Node `/api/internal/route-qualification` 执行原 metadata、课程／笔记所属关系、项目目录与撤回检查。仅该函数配置数据地区，middleware 不再导入 content runtime 或执行 SQL。DTO、provider、数据库与页面读取行为不变。
- 每请求不缓存的有界 POST，仅返回三种固定结果；五秒预算、无重试、禁止重定向、同域保护凭据、允许 origin、部署标识和严格响应校验。通信失败／超时／错误部署为 HTML 503，确认缺失为 HTML 404。页面层仍自行检查公开资格。
- 复用 CONTENT_READ_TIMING 开关输出固定字段的 client／handler 时间及实际地域，不输出地址、凭据、来源、正文或错误。两段时间互相包含，不应相加。

## 验证与局限

- Node 24 完整 `npm run check` 通过：类型、三协议、2,267／2,267 测试、零失败／跳过、隐私 1,327 文件；测试约 157 秒。`npm run build` 通过，45 项服务端 trace 均排除私有运行文件。
- 生产模式 loopback：25 个页面请求验证 HTML 200／404／503 与错误页 no-store，覆盖有效项目／课程／笔记、缺失、已有课程的错误归属、无效地址及固定错误页；另两个直接资格 POST 验证 fixed 结果。失败采用合法 database provider、显式空 reader URL，在任何真实数据库连接前失败；不以无效 provider 的布局错误充当服务不可用验收。初次脚本误用无效 provider 的失败记录保留在私有目录，修正脚本后通过。
- 隔离浏览器在 mock 下走项目首次、返回、回访和新文档切换，未捕获异常；媒体及外部请求在发送前拦截。本机首次项目 RSC 约 23ms，DOM 就绪约 449ms、绘制约 466ms；回访 DOM 约 9／30ms，但现有动画约 400／424ms。新文档暖服务器 DOM 约 28ms、动画约 419ms。这只说明本机 mock 的功能与交互等待，不与真实数据库或线上前后样本混比，不修改 Claude 动画。
- 本机 Vercel builder 22.0.1 消费已验证构建，不安装、不重建、不部署：普通资格函数及其平台生成入口均为 Node24／单一数据地区；middleware 保留九条 matcher、无地区覆盖、无 pg／Notion／content runtime 文件；其余 84 个函数未加地区覆盖。未使用已弃用的 preferredRegion。

当前只证明本机行为和打包，尚无新方案的线上前后耗时、真实平台配置接受或执行地域证据；受保护预览也仅验证了协议和同域凭据处理，不能冒充真实平台验收。

上一轮已发布方案的浏览器首次样本为 2637 → 2090ms、连续服务器的新文档为 1145 → 838ms；这不是本轮修复后数据，也不是 p95。上一轮真实资格目录仍在远端：总计约 1392ms，其中取得连接约 1027ms、两次往返约 342ms；同请求页面目录在数据地区约 11ms。本次针对这一已观察瓶颈移动 SQL，不声称数据库执行慢或已解决全部冷启动。
