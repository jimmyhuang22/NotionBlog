# 2026-10-13：内容读不到时详情页在正式环境里只剩一行平台报错（Claude）

编辑登记：Claude 本轮修改与验证完成。范围：`src/proxy.ts`（共享的请求入口，改前已得到用户同意）、`src/lib/route-verdict.ts`、`src/app/error.tsx`、新增 `src/app/content-unavailable/page.tsx` 与 `src/components/page-unavailable.tsx`、一项测试、前端接手说明。契约、fixtures、依赖、栏目开关、接口与媒体路由未改。

## 线上看到的情况

2026-10-13 05:10 UTC 起后端的内容批次到期，正式站点的内容整体读不到（原因与恢复见后端自己的记录）。趁这段时间把各类页面各开了一次，无界面 Chrome，1280 与 390 宽，另用 curl 对同一批地址各请求一次。

| 页面 | 表现 |
| --- | --- |
| 首页 | 个人介绍照常，时间线位置写“动态没有加载成功，请重试”并有重试按钮 |
| 动态、学习、影视、相册列表 | 200，完整页面，“页面暂时打不开”与重试 |
| 关于页 | 503，完整页面，同样的提示与重试 |
| 搜索 | “这次搜索没有成功，请稍后再试” |
| 作品页 | 正常（社交这一侧不受影响） |
| **课程、影视详情、书籍详情、相册、不存在的课程或影视** | **503，101 字节的纯文本，“The deployment is currently unavailable”，没有页头、没有提示、没有重试** |

最后一行就是问题。那 101 字节带着部署平台自己的错误标记，不是网站输出的。

## 原因

此前的修复（见 [内容读不到时详情页不再是空白的服务器错误](2026-10-13-unreadable-pages.md)）让请求入口在“查不到”时放行并把状态码设为 503，由页面自己显示提示。它在本机的生产构建上验证通过，当时注明没有在线上的真实停摆下验证。

这次在线上的读数是：没有参数的地址（关于页）按预期显示；带参数的地址（课程、作品详情、相册）全部被平台的报错页顶替。同一时间，“不存在”的地址走的是“改由固定地址应答并带 404”，对带参数的地址一样有效。由此推断：在部署平台上，放行时附带的状态码只对没有参数的地址有效。这是从读数推出来的，没有找到平台文档佐证。

## 改了什么

- “查不到”时不再放行，改成地址不变、由固定地址 `/content-unavailable` 应答，状态码 503，响应不缓存。做法与“不存在”时由 `/content-not-found` 应答完全一样。
- 新页面显示“页面暂时打不开”与重试，带页头和页脚，标记为不收录；重试是重新载入当前地址。提示的内容抽成 `page-unavailable.tsx`，错误边界与这一页共用。
- 规则写成两个可以单独测试的函数（`routeAnswer`、`standInStatus`），入口只负责照做。

代价：入口的查询偶尔失败而内容其实读得到时，访客先看到提示，重试即可；此前这种情况会直接看到内容。

## 怎么验证的

只在本机验证：生产构建，数据库模式且不给连接配置（内容读不到），以及演示数据。**没有在正式环境验证**，那需要一次发布和下一次内容读不到的时候。

| 项目 | 结果 |
| --- | --- |
| 内容读不到：关于页、课程、笔记、影视详情、相册、带定位的动态链接 | 都是 503、完整页面、有页头、“页面暂时打不开”与重试、不缓存、不收录 |
| 内容读不到：列表页、首页 | 仍是 200 与各自的提示；未知的作品库类型仍是 404 |
| 按重试 | 重新载入一次，仍读不到时再次显示提示，三秒内没有第二次载入 |
| 从站内跳转过去（路由跳转到影视详情、关于页、笔记） | 一次整页载入后显示同一提示，没有循环 |
| 两个固定地址直接访问 | `/content-unavailable` 503，`/content-not-found` 404 |
| 演示数据 | 存在的游戏、课程与关于页 200；不存在的游戏与课程 404 |
| 390 宽 | 提示页没有横向滚动 |
