# 2026-10-13：社交读取连接生命周期修复（Codex）

编辑登记：本项独立分支从 develop 建立，只修改网站社交 reader 的 Pool 生命周期、脱敏诊断、固定依赖和对应测试／说明；不接管普通内容恢复、缩略图登记、B站／小红书采集和 Claude 页面。用户在看到具体方案后明确要求继续，新增依赖及角色上限调整已获得授权。

限定故障时段的数据库日志已确认社交 reader 的 FATAL／SQLSTATE 53300，错误为该角色连接数超过上限；与已记录的并发 HTTP 503 时间吻合。角色连接上限为四，源码模块全局 Pool 的每进程上限为二。实际托管环境启用了 Fluid，既有配置使用 session pooler。现有顺序读取成功并不能证明并发读取已恢复。

已接固定 `@vercel/functions@3.9.11` 的官方连接池辅助库，让平台等待 pg 空闲连接释放，再暂停实例；仅社交空闲超时调整为五秒，保留活动连接和既有身份／协议检查。既有锁文件依赖版本均保持，新增库的正常传递依赖锁定。服务器诊断只允许固定事件、阶段和脱敏错误码，继续保持原有公共 503，无模拟回退、权限放宽或首页降级。

实际云操作：即时确认角色原限额四、整库容量满足方案门槛，事务内只将此角色的 CONNECTION LIMIT 调到十六；提交后另读回确认。登录状态、默认事务只读、高权、继承和角色成员前后相同，凭据和公开资格未改。六个顺序生产社交 GET 均 200／private no-store／noindex；其中 v2 每次仍为原有 243 卡片，v1 按其旧资格规则为空。这仅证明调整后的顺序读取，不冒充并发验收；不重复原并发压测。操作及完整读回只留私有回执，没有新迁移或自动应用程序。

针对性验证：使用真实 pg Pool 和官方辅助库，只有网络 Client 被明确模拟；验证两个活动连接、第三个排队请求的复用、空闲连接清理前的平台等待和活动连接保留。另验证查询只尝试一次、原错误内部保留／HTTP 脱敏 503、空闲错误脱敏及成功查询无日志。三项通过，模拟时钟避免真实等待五秒；这不是云端实例暂停或真实并发流量证明。完整 check／build 在本项集中运行，结果下方补记。
