并发时连接池等待队列峰值均为 29。每张图片先确认当前公开资格、匹配来源与缩略图描述，再读取私盘上的预生成 WebP，返回前重新确认资格和发布版本。这两轮查询争用同一个两连接池。单独执行数据库能力校验并计入事务控制，中位数为新加坡 4.3 毫秒、上海 6.1 毫秒。资格 RPC 还包含发布状态、资格与缩略图描述查找，内层查询未逐一计时。取得描述后，本机选择 400 像素规格的计算不到 0.01 毫秒。

两站在独立只读探针用现有批量接口对同一组 30 张图做资格确认、磁盘读取与再次确认。三轮全批约为新加坡 34–38 毫秒、上海 45–71 毫秒。批量结果、发布版本和描述均与逐张读取相符。它衡量单批的服务端工作，浏览器首字节还会计入批次等待、HTTP 和网络，实际收益需在隔离应用和两站复验。

两站回环均返回 `private, max-age=86400, must-revalidate` 和 `CDN-Cache-Control: no-store`。`Vary` 中的 RSC 路由头由 Next 输出。两站抽样封面在附带不完整的 RSC 请求头时，框架返回加 `_rsc` 的 307，普通图片请求直接返回 200 WebP 并完成资格与磁盘读取。本次保留这些头和现有缓存策略。[图片回访缓存决定](../decisions/2026-11-03-static-media-revisit-cache.md) · [Cloudflare 缓存头规则](https://developers.cloudflare.com/cache/concepts/cache-control/)

## 待决定的封面优化

1. 保留现有 Cloudflare 策略，在应用中合并同一小窗口内的资格查询。首次核验和读盘后的重查各用独立批次，均校验当下版本与撤回状态。缺项沿用逐图检查，保留未就绪与无资格的差别。控制批次大小和等待时间，同一连接池给目录查询留容量。验收目标为 30 张并发时源站首字节 P95 约 100 毫秒，另验撤回、切版和页面并发。公网耗时仍包含网络。
2. 仅让获准公开的版本化 WebP 进入 Cloudflare 共享缓存。键包含主机、公开授权绑定和规范化尺寸。撤回先在源站生效，持久登记并清除该页面对应的所有 URL（含主机和尺寸），再做多入口复查；其他页面独立绑定同一物理图片时仍可访问。Purge 失败需重试、告警并可迅速禁用该路由的边缘命中；关闭过期后继续供图，先验证约一分钟的撤回目标和失效兜底，再考虑放量。Cloudflare 的按 URL 清除可用于免费计划，实际成本和预算取决于命中率、路由及失效运维。[清除能力与额度](https://developers.cloudflare.com/cache/how-to/purge-cache/) · [按 URL 清除](https://developers.cloudflare.com/cache/how-to/purge-cache/purge-by-single-file/)
3. 单独评估公开页面缓存。它可以减少游戏列表 HTML 的首字节时间；现役自托管配置的 `PUBLIC_CONTENT_CACHE` 处于关闭，启用前须验收现役 profile 兼容、发布刷新及撤回。图片首次请求仍独立处理。[公开缓存决定](../decisions/2026-10-21-public-content-cache.md)
