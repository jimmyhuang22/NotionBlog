## 修改与验证

- 首页首条动态若有封面，给第一张封面设置 eager 和高请求优先级。同组其他封面及后续行保持懒加载。取消「全部动态」的自动预取，链接仍正常导航。
- 拦截两组各两次公开首页 HTML 响应并在测试浏览器内重放，两组都等完整 HTML 到达后才解析。只替换首张封面的加载属性时，从节点出现到封面可见由 1.54–1.68 秒降至 1.06 秒。请求从等 0.42–0.56 秒变为解析时立即发出。两组图像下载均约 1.1 秒。截图抽样确认封面真实显示，不能用这组缓冲 HTML 对照代替正式上线的流式响应。前期 DOM 注入未改变网络优先级，舍弃该实验。
- Node 24.22.1 完整 `npm run check` 通过 3304 项，零失败和跳过。本机离线生产构建及断网 Linux AMD64 公开自托管构建通过，各检查 49 个 server traces。通过回环地址在本机运行 Linux 候选，使用既有只读身份和真实公开首页数据。Chrome 核对仅首张封面为高优先级，正常只发一次 800 档图片请求，其他媒体保持懒加载。「全部动态」首访零预取，点击后正常进入动态页。
- 浏览器拦截首个缩略图请求并模拟一次 503，候选只重试同一个地址一次，随后 200 显示，零原图回退。验证为本机受控故障，不是公网故障。
- 公网测量及实验访问的浏览器传输正文约 19 MB。本机只读候选的数据库、对象和连接开销估计数 MB，合计低于每日小量读取额度，未独立计量云端账单。真实运行生成的缓存不进入发布包。
