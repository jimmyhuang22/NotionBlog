## 修改

- 新增 `scripts/self-hosted/preflight.ts`：核对根与游戏源码两个 package/lockfile 的依赖声明、适用平台非 optional 包及已存在 optional 包的版本、关键构建入口和声明文件。只读包元数据，不执行私人代码或安装依赖。
- 构建前由实际构建用户检查目录穿越与写入权限，创建后删除临时目录探针；拒绝悬空或指向 release 外的输出链接，允许 Next 指向当前 release 依赖的链接。构建后可用 runtime 阶段，在真实运行 UID 与最终挂载下核对产物和专用入口可读；runtime 检查不写文件。
- Linux 构建同时检查宿主可用内存、进程可用内存和 cgroup 容量约束。起始门槛为容量 1280 MiB、进程可用 1024 MiB、宿主可用 1280 MiB；swap 单列且不代替 RAM。不自动扩容或调配置。这是停止低资源构建的经验门槛，不保证任何负载下的峰值。
- 专用构建入口在启动 Next 前自动执行 build 预检。显式命令额外要求预期 UID／架构；失败退出且不修复、不重试。macOS 本机运行明确报告 Linux 内存未验证，显式 build 预检返回非零，避免误作生产验收。

## 本机验证与限制

定向回归覆盖缺少第二份安装、锁定版本与声明漂移、缺少传递依赖／类型／ESM 入口、只读目录、不可穿越祖先、合法／越界／悬空链接、运行读取权限，以及宿主总内存大但容器限制小／可用内存不足／仅 swap 充足等情况。实际构建入口的失败路径验证发生在 Next 启动前。Node 24 本机定向 13 项、完整 `npm run check` 3434 项均通过；`npm run build`、51 个服务端 trace 隐私扫描与 HTTPS 内部 rewrite 集成回归通过。首次完整验证因沙箱禁止回环监听（`listen EPERM`）中止；允许本机端口后仍沿用外连阻断重跑通过，未放宽项目网络隔离。

预检不等于完整安装包校验，也不代替构建、启动标记、服务健康和实际页面验收。本次没有 Linux 目标机执行结果；两站须在下一次获准部署时，在各自真实用户、挂载及限制内执行。实现与验证阶段的云端连接、公网 HTTP、真实 SQL、云端出口流量、线上写入和部署均为 0；本机合成数据库与回环 HTTP 仅用于离线测试。后续获准提交仅访问 GitHub，不访问生产服务。
