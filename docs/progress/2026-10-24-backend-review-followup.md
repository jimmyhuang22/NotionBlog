## 修改

- B03：经用户单独确认，新增 NOLOGIN 同步读取组的显式迁移与安装函数。网站组不再拥有私有同步证据／验收函数；同步连接严格要求 `nb_delta_reader`，沿用整个角色图、LOGIN、TLS 与函数权限核验。网站在本 runtime 首次查询前检查可达角色及私有同步函数权限，失败时不发出内容查询，且不缓存失败。详细允许列表和安装顺序见[角色隔离方案](../BACKEND_READER_ISOLATION_PLAN.md)。
- B09：新增显式撤回恢复迁移，保留同一已接受政策下被中央 deny 隐藏的行及其媒体；公开内容、子树与媒体读取仍使用原资格过滤。增量专用发布校验保留祖先完整性、根链存在、许可名单、墓碑、正文及媒体完整性；原完整基线发布函数不放宽。明确来源删除／归档／移出范围仍删除子树，解除中央 deny 不使这些数据复活。增量仅推进持久发布指针，不延长或替换完整资格。
- B12：单次图片 Retry-After 超过 120 秒立即报 RATE_LIMITED，不缩短等待后提前重试。Notion 调度器支持 HTTP 日期，保存完整冷却截止；超过 120 秒的排队或新请求快速返回冷却错误，后续短头值不缩短已有暂停，超大数字不溢出为立即请求。
- B15：队列本地 schema 升至 5，新增历史索引；每轮最多回收 200 条已有后续完成世代且收尾已确认的旧尝试。保留未确认提交、当前世代失败计数、未确认收尾和每页最后一次真实提交证明。目录扫描与学习子页面发现依靠现有原子游标／版本校验，不再为内部事件永久增加去重行。通用外部事件入口仍保存去重记录。

## 接口与 provider

公共 DTO、依赖、fixtures、栏目和来源配置保持原样。新增 SQL 均由已有本机 Supabase CLI 生成文件名，并用 PGlite 离线验证；没有下载新工具。新迁移有独立摘要，不改历史迁移、原协议摘要或旧运行包兼容许可。私有备份只接受已知的可选扩展摘要；恢复目标必须具备相同扩展，仍不激活发布或恢复凭据。

`installIncrementalWithdrawalRecovery(db)` 与 `installIncrementalReaderIsolation(db)` 仅接受显式 owner executor；启动、构建与普通同步均不调用。新组不自动授予任何 LOGIN，也不生成凭据。源码合入不等于真实账号隔离或运行包安装。

增量 CLI 新增本机 `compact-history`，使用现有配置、私有运行目录与同一发布锁；每次最多清理 200 条。运行只返回删除数量，不查询来源、数据库或媒体，不恢复任务。新队列 schema 不能交回旧运行包直接打开。

## 局限与上线前提

本项没有访问项目数据库、Storage、业务网站或媒体，没有真实角色／LOGIN／凭据变更、安装、同步、恢复任务或部署。

网站防护会拒绝尚未隔离的旧账号：正式发布前须在另行有效授权下完成真实权限审计、迁移、LOGIN 分离与公开读取验收。两个扩展支持任意安装次序，但从旧版本已经丢失的撤回行无法凭空找回，须另行获批执行完整基线恢复；新迁移防止后续再次丢失，不声称修复了已有生产数据。

历史 events 无来源分类和安全重放水位，不能可靠批量删除；它们继续保留。新的内置发现路径不再增加该账本，外部接入若持续送入事件，仍需定义持久去重／归档水位后才能清理。SQLite 回收的是可复用页，不自动 VACUUM 或缩小真实文件。旧运行目录尚未升级或清理。
