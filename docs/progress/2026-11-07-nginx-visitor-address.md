# 2026-11-07：AWS 网站可信访客地址（Codex）

## 范围与接口

- 用户批准核对现役配置、备份、语法检查、平滑重载、健康和伪造头验收，以及异常回滚。现役配置与此前离线验收的基线逐字节一致。
- 网站的 8443 监听仅接受 Cloudflare 当前网段传入的 `CF-Connecting-IP`，再用解析后的地址覆盖 `X-Real-IP` 与 `X-Forwarded-For`。访问日志继续记录原 TCP 对端，公网为边缘节点。示例与自托管说明同步更新。
- 核对过的 8444 入口只允许读取静态资源，其他路径返回 404。此变更不安装网站程序或业务运行包。

## 验证

- Cloudflare 官方清单与候选的 15 个 IPv4 和 7 个 IPv6 网段一致。本机 Nginx 1.24 断网测试覆盖可信 IPv4／IPv6、缺失或无效地址、不可信来源和原对端访问日志。
- 线上备份后完整 `nginx -t` 通过，再平滑重载。通过带随机标记的健康请求，在主机内比对实际转给 Node 的头；原始请求和访客地址不写入回执。
- 公网正常请求与伪造 `X-Real-IP`／`X-Forwarded-For` 的请求均为 204，Node 的两个地址头均与可信地址一致。不可信回环请求伪造三种地址头时，Node 的两个标准头仍为回环地址。
- 主域名、www、源站 HTTP/2 和 HTTP/1.1 健康均为 204。Nginx 与网站主进程 PID 一致，两服务 active，自动重启计数为零；复核窗口内 Nginx 的 systemd 错误日志数为零，探针进程均已退出。
- 第一轮验收曾在伪造 `CF-Connecting-IP` 时收到 403；探针清理阻塞后主动结束该探针，原配置及健康已核验恢复。独立小量请求确认该专用头触发拒绝，普通及伪造标准转发头的请求返回 204。修正探针清理后，第二轮按上述公网／回环分工验收通过。保留首轮失败及回滚记录。
- 读取配置、日志摘要和健康探针的云端响应预计低于 0.1 MB，未单独计量账单。原始证据、配置备份位置和校验值保留在私有任务目录。
