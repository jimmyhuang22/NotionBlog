# 2026-10-22：搜索游标在读库前校验格式

编辑登记：Codex。从最新 develop `42e20ea` 建立独立分支，只修改共享搜索参数校验、分页解析复用及定向回归。较前轮新增的公开缓存业务锁改动不涉及搜索函数，已保留。原连接池对照继续使用其唯一已授权任务等待，本项不新建真实窗口。

## 问题与修复

搜索参数原校验只限制游标的类型、长度和空白字符，完整的 `w1` 格式及整数偏移直到取得搜索结果、扫描文本并准备分页时才验证。格式错误的游标因此也会先执行能力及内容 SQL；数据服务不可用时，还可能先得到服务不可用错误。

把原分页格式解析提取为同一个内部函数，搜索请求在进入 provider 前调用。错误前缀、错误摘要长度／字符、负数、非规范前导零、小数／指数偏移、超出安全整数范围和多余后缀均提前返回既有 `INVALID_QUERY`。泛用分页继续用相同解析器，再检查当前结果摘要和偏移范围；接口与游标格式保持。

格式正确的游标仍需读取当前资格和数据，摘要已失效或偏移超过当前结果长度的情形仍在取得当前结果后校验。本项只减少能够仅凭参数确认无效的请求，不把所有旧游标或所有无效请求都描述为零查询。

## 离线对照

用仓库真实迁移、PGlite 受限 reader 与一百条虚构记录复现，覆盖 qualified／published 与 on-demand／filtered／precomputed 六种组合。每种组合分别创建 reader 后查询一个格式错误的游标：

| 版本 | SQL 调用（含能力检查） | 内容读取 | SQL 结果行序列化字节 |
| --- | ---: | ---: | ---: |
| 原版 | 2 | 1 | 83,911 |
| 提前校验 | 0 | 0 | 0 |

以上字节为虚构本机 SQL 结果 JSON，不能当作 TCP、计费流量或真实站点节省。此次没有新增线上读库、网页、来源或图片请求。

新增四项定向回归与此前十五项分页／撤回测试合计十九项通过。覆盖 legacy 和三条 scoped 路径在能力检查前拒绝错误游标、非数据库 fallback 在快照读取前拒绝、生成游标继续分页，以及合法格式仍读取 provider 并保留服务失败语义。

另对排序替代方案做了本机微测试：复用 Collator 在两万条 Unicode 样本约快 14.5%，英文样本却慢约 151%；各组排序相同，收益不稳定，因此保留现有排序，不把此原型加入应用。样本为虚构 CPU 对照，非 SQL／HTTP 延迟。
