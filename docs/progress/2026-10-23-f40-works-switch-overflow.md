# 2026-10-23：作品页手机宽切换平台时页面瞬间变宽 6px（F40 补充）

负责 UI/UX 的 Claude。反馈审查在正式站 390 宽从 B 站切到小红书时，测到切换中途文档宽 396、视口 390，结束后恢复。

## 原因

切换期间 `.works__stage.is-moving` 用 `overflow: clip` 裁掉滑出、滑入的卡片，并用 `overflow-clip-margin: 24px` 留出阴影。外扩的这 24px 也算进页面的可滚动宽度；手机上页面左右留白（`.wrap`）只有 18px，于是列表右缘 372 + 24 = 396。去小红书时是从右侧滑入的新卡片撑出，回 B 站时是向右滑走的旧列表撑出，两个方向都有。521px 起留白是 28px，大于 24px，不受影响。

## 改了什么

- `src/app/timeline.css`：520px 及以下把切换时的外扩改为 18px，与页面留白相同。手机上超出这 18px 的部分本来就在屏幕外，看起来没有变化；动效节奏、卡片依次进场、封面渐显和不再预取另一平台都不变。没有改组件、接口或共享范围。

## 验证

演示数据，`next dev`，无头 Chrome，每次 B 站→小红书→B 站→小红书→B 站四次切换，每帧记录文档宽度与超出视口的元素：

- 修改前 390 深色：四次切换都到 396（去小红书在约 140 毫秒，撑出的是滑入的卡片；回 B 站在约 190 毫秒，撑出的是离场的旧列表）。
- 修改后 320、390、520、521、768、1280（深色）：每帧都等于视口宽度，结束后没有残留的离场层。
- 390 浅色下的苹果、千禧、岛屿主题，以及减少动态效果：同样每帧不超出。
- 390 切换中途截图：旧列表向左滑出、新卡片从右侧进来，与修改前一致，没有横向滚动条。
- `npm run check` 与 `npm run build` 见合并请求。
