# 2026-11-13：修复自托管 HTTPS 反代下的内部 rewrite（Codex）

编辑登记：本项只改自托管 Next 初始化、离线构建后的回归检查及本记录，不编辑前端组件或其他工作线。

## 问题与修改

关闭栏目本应通过中间件返回完整404页。自托管HTTP监听地址是回环IP，NextURL把它规范化为localhost，而路由层仍保留原IP，导致绝对rewrite被误判为外部代理；外层HTTPS信息随之让Next向纯HTTP端口发起TLS请求，返回500和EPROTO。

专用入口通过共用初始化函数让Next内部主机名统一为localhost，使rewrite留在站内处理。HTTP服务实际监听地址仍由原启动参数决定，外部HTTPS头不改，也不把目标拼接到访客提供的Host。中间件404/503判定、公开范围及provider不变。

## 验证

构建后用真实Next应用、中间件和错误页启动回环HTTP服务，模拟HTTPS反代的Host与转发协议头；关闭的博客、项目栏目分别验证GET/HEAD的404、no-store、原frame保护、站内rewrite、页面导航和无代理错误，并对照HTTP请求及开启栏目200。检查接入普通离线build，真实生产构建不启动读者验收进程。

Node24.21.0：完整 `npm run check` 3401通过、0失败、0跳过；`npm run build` 通过，50条构建隐私追踪及构建后真实HTTP回归通过。测试替身整理后，6项环境隔离测试单独复验通过。旧逻辑负对照只在离线进程中将内部主机名恢复为127.0.0.1，新测试立即捕获HTTPS HEAD /blog的500与EPROTO；不改实际服务或被测源码。首次check受沙箱回环监听限制中断，授权本机监听后完整重跑通过；首次构建后测试误以为页面含数字404，改为现有中文错误页断言后完整build通过，历史本机日志保留。
