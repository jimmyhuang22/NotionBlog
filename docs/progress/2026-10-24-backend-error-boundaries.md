# 2026-10-24：后端启动、回滚与缓存错误边界（Codex）

编辑登记：从最新 develop `bc6248179abadcab211be4cb531be986f241dd5c` 建立独立工作树。本项处理交接包 B13、B16、B22，范围为同步启动回执、列明事务／连接／社交上传清理路径及缓存 HTTP 错误映射；不修改其他会话的共享根目录改动。

## 修改

- B13：网站同步子进程先验证参数与私有输出目录，再把双锁身份、来源摘要、恢复准入和 Notion 读取器初始化纳入统一回执生命周期及原有截止时间。锁争用保留 BUSY，恢复准入保留有限允许列表中的 RELEASE_INVALID 等错误码；未知外部错误仍映射为固定代码。回执写入失败也不会把原始失败改写成 MISCONFIGURED，控制台另报 receiptWriteFailed。子进程不释放父进程持有的锁。
- B16：三个 SQLite 事务及三种数据库恢复器在回滚失败时保留原始受控错误。owner CLI 对失败操作使用 release(true) 销毁连接，连接建立失败也会关闭池；释放异常不阻止池关闭。社交执行器尝试全部云连接、数据库和锁的清理，已有失败优先保留；只有清理自身失败时仍返回明确失败。小红书上传使用已经验证的 scope 摘要写暂停，不在异常或 finally 中重读可能已消失／损坏的配置，关闭失败不覆盖原始暂停原因。
- B22：缓存响应装饰器和两个真实内部路由覆盖同步配置异常与异步拒绝，返回统一 JSON 503 与 no-store。复用原内容错误映射并保留原导出位置，避免循环导入；未知 provider 异常不暴露原始详情。正常缓存、条件请求、签名鉴权和清除事件语义保持。

## 接口与 provider

公共 DTO、依赖、fixtures、栏目、SQL schema、迁移及云端配置不变。仅增加内部清理工具及无循环依赖的 HTTP 错误模块。有效私有目录尚未确认前不尝试落盘回执，避免使用无效输出路径；底层文件系统无法写入时仍不能保证产生回执。冻结运行包与兼容目录不更新，源码合入不自动安装业务运行程序。
