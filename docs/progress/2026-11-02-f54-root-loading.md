# 2026-11-02：F54 刷新闪墨水与作品页露出首页加载画面（Claude）

编辑登记：Claude 修改 `src/app/loading.tsx`，新增 `src/components/root-loading.tsx`。契约、接口与媒体路由、fixtures、依赖、栏目开关、全局入口（`layout.tsx`）与后端代码未改。

## 来由

F54：用户选岛屿后刷新，先闪墨水再回岛屿；在作品页刷新，先出现首页的自我介绍和“最近”占位，地址仍是 `/works`。反馈核查已在线上复现两项。

## 原因

- **主因是 Cloudflare 的 Rocket Loader。** 站点改由 Cloudflare 代理后，线上 HTML 注入了 `rocket-loader.min.js`，页面所有脚本的类型都被改写，等它加载完才执行。这些脚本包括 head 里首绘前设主题的脚本，也包括 Next 流式输出时把加载画面换成正文的替换脚本。主题因此晚执行，先露出墨水；替换也晚执行，页面停在加载画面上。以前的 Vercel 不经过这一层，所以这是切换以后才出现的。
- **根级加载画面是首页的样子。** 线上首次打开任何地址时，服务器最先发出的是根级加载画面，栏目自己的占位排在后面。根级加载画面原本照着首页画，注释也以为“只会在首页出现”，所以只要替换稍晚，别的栏目就会露出首页。
- 证据（无头 Chrome，岛屿深色，`/works` 各刷新 3 次，逐帧记录主题与标题）：
  - 原样线上页面：每次都先显示约 0.9 秒的墨水加首页加载画面；
  - 同一份线上 HTML 去掉 Rocket Loader 后：第一帧就是岛屿，首页占位只在一次采样里出现约 6 毫秒。

## 改了什么

- 根级加载画面按地址区分：首页照旧画自我介绍和时间线占位，内容到达时不动；其他地址改用通用占位（`PageLoading`）。栏目自己的占位不变。
- Rocket Loader 属于 Cloudflare 配置，按分工交给 Codex 关闭，交接说明在本机私有目录。前端没有改 `layout.tsx` 里的主题脚本。

## 怎么验证的

- Node 24.21.0，以最低优先级运行：`npm run check` 通过，3268 个测试全部通过，0 失败、0 跳过；`npm run build` 通过，49 份服务端追踪隐私检查通过。
- 本机正式构建（演示数据），前面加一个代理，把服务器输出卡在正文段之前 1.5 秒，放大加载窗口。无头 Chrome 1280 宽，逐帧记录：
  - 首页：加载期间一直是自我介绍，内容到达不跳；
  - `/works`：只出现“作品”标题和作品占位，岛屿与墨水各测过。
- 本机的 `/works` 不会先发根级加载画面（线上的自托管公开模式会），所以另加了一个临时路由，在布局里等 1.5 秒，迫使根级加载画面出现。改前这个路由显示首页的站名和“正在加载动态”，改后显示通用占位。临时路由验证后已删除。

## 限制与下一项

- 主题闪烁要等 Codex 关闭 Rocket Loader 才会消失，本改动只解决“露出首页”这一半。
- 以上只用演示数据在本机验证过。线上效果要等本改动发布、Rocket Loader 关闭后，按 F54 验收标准复验：首页与 `/works` 各刷新 3 次，岛屿深浅色、苹果、千禧，手机 390 与桌面，学习、影视等相邻路由。
- 没有测 Safari 和真机。F54 的关闭由反馈对话复验后决定。
