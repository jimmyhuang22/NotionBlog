# 2026-10-22：私人仓库同名切换（Codex）

## 修改与结果

用户明确批准整轮私人同名切换后，先将旧仓库改为独立的私人归档名称，再将旧检出的共享远端指向归档，最后让干净仓库取得 NotionBlog 名称并更新独立检出远端。两边仓库 ID、可见性和 main／develop 引用逐项回读；旧 Git 历史、工作检出及私人运行根完整保留。

README 快速开始使用最终仓库地址和目录名；迁移说明、需求和公开准备报告同步当前执行状态，不把仓库改名写成已经公开、部署重绑或全部聊天接续成功。应用、DTO、provider、依赖、fixtures、SQL、运行输入和工作流不改。

## 验证与边界

- 切换前验证新旧 Git 备份及独立对象库，保存两边配置和本机修改。切换后 main／develop 引用保持受检值；两个 Git 配置除各自 origin URL 外逐字节一致，旧工作检出关联保留。
- 专用 CI 仍注册在同一个干净仓库 ID 下，运行器在线空闲，旧归档无运行器。专用账户、服务、磁盘和任务前守卫原字节不变，仅维护计划的仓库名称随改名更新。此为注册与服务核对，没有将改名冒充第二次完整 Actions 验收。
- 应用与工作流保持此前完整通过的版本：2,476 项测试、零失败／跳过、生产构建和 48 份服务端追踪隐私检查；本轮纯文档另核对记录格式、链接、隐私和差异，不重复整套应用检查。
- 当前可见应用项目和聊天仍记录旧目录；私有交接中保存新的独立目录、远端、仓库身份和逐项回读要求。没有批量移动聊天、替换旧 .git 或把旧分支推入干净历史，也没有声称其他聊天已收到通知。

文档复核通过：记录格式 3 项；源码隐私覆盖 1,596 个候选文件；692 份 Markdown 的 857 个本地链接无缺失；差异与暂存隐私另行核对。
