# 2026-10-14：作品页有封面后按行等高排开（Claude）

编辑登记：Claude 本轮前端修改与验证完成，范围为 `src/components/works-list.tsx`、`src/components/social-work-card.tsx`、`src/app/timeline.css`，以及说明文档。契约、接口路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

来由：首页作品卡片（合并请求 311）给用户看过后，用户说立即合入，并要求作品页也改、先看原型，同时问真实封面怎么实现。311 已合入 develop。作品页给了三个样子的对比图（电脑 1280 与手机 390），用户选了“等高排列”。决定见 [决策记录](../decisions/2026-10-14-works-page-covers.md)。

## 改了什么

- **作品页**：已加载的作品里只要有一件带封面，各年份下就不再是清单，而是首页那一排用的同一种小号卡片，换行排开。B 站横封面一行三张，小红书竖封面取等高的宽度；手机上两列，横封面占整行。没有封面的作品用占位补齐。全都没有封面时仍是原来的清单。
- **小号卡片的数字都压在封面底部**（首页那一排和作品页共用）。上一轮小红书的小卡片把点赞放在日期下面，窄卡片里会折成两行；现在有真实封面时放到封面上，没有封面时仍在标题下面。
- 小号卡片的样式从“在一排里”改为跟着卡片自己的类名，所以一排和作品页是同一套。
- 后端交接包第十二节补了前端查到的现状（读取入口把封面固定为空、B 站同步已记录封面引用、站内已有存储与小图的路）和“封面可以分批到位”。

## 怎么验证的

本机开发服务器加一个不提交的临时页面，用 2026-10-13 从正式站点读下来的作品（真实标题、数字和地址）渲染作品页的列表组件，另加三个虚构情形：合集同时发在小红书、数字超期、没有地址。**封面是本机画的示意图**（五种比例），不是真实封面。临时页面与截图都没有提交。

| 看了什么 | 结果 |
| --- | --- |
| 全有封面，1280、700、390 宽 | 没有横向溢出；1280 一行三张横封面或横竖混排，同行等高；700 一行两张横封面；390 两列，横封面占整行 |
| 只有 B 站有封面，1280 宽 | 小红书的卡片是带平台标志的占位，行仍然齐平，点赞在标题下面 |
| 全无封面，1280 宽 | 和改动前一样的清单 |
| 读屏拿到的链接名称（Chrome 辅助功能树） | 标题、日期、类型与集数、“播放 … 点赞 …”、去向；没有封面的多一句“封面未记录”；同一作品的另一个平台是单独一个链接 |
| 超期的数字 | 卡片里写出“数据截至 …，未按期更新” |

检查见合并请求说明。

## 限制

- **没有在真实封面下看过**，数据里封面仍然全是空的，所以线上的作品页现在还是清单。封面到位后要在正式站点复验：裁切、两档小图、浅色封面上白字是否清楚、一页 20 件加载更早时的衔接。
- 只在无界面浏览器里看过，没有在真机上看；其余皮肤和深色模式这一轮没有单独截图（卡片本身上一轮在四套皮肤下看过）。
- 手机上为了不留空位，相邻两件的先后可能和时间差一位。
- 首页那一排在这次改动后没有重新截图；它和作品页用的是同一个组件、同一套样式。
