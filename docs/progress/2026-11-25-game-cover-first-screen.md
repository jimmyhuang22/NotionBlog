# 2026-11-25：游戏列表首屏封面冷缓存对照（Codex）

对照 #542（`4fb16e7`）与 #548（`0efeef5`）。本次不改应用代码、数据库、内容和缓存配置。两站的旧构建仅在各自回环端口短时运行，读取与现役应用相同的已发布内容。正式入口继续使用 #548。用户批准本次额外流量最多 24 MB。[#542 上线记录](2026-11-25-release-542-dual-site.md) · [#548 上线记录](2026-11-25-release-548-dual-site.md)

## 浏览器取样

同一台 Mac 的 Chromium 打开实际游戏列表 `/library/games`。每次新建浏览器配置，在 1440 × 900、DPR 1、默认动效下从页面顶部开始。同站的两版走同一条私有回环转发，浏览器使用 HTTP/2。以导航为计时起点，使用 Element Timing 和视口交集确认图像已画出，结合淡入状态记录首张与最后一张可见封面出现的时间。重复封面合并计数，视口外预取保留。有效对照须核对实际构建与视口内封面集合。

从墨尔本经私有链路测得的时间包括本机浏览器与传输，访客的分流、运营商链路和地区可以影响实际耗时。新加坡完成的结果为单组对照。源站图片首字节 P95 见原部署记录。

## 取样结果

| 站点与轮次 | 首屏封面数 | 首张 #542 → #548 | 首屏全部 #542 → #548 |
| --- | ---: | ---: | ---: |
| 新加坡 | 9 | 1,560.5 → 1,390.8 ms（快 169.7 ms） | 1,660.5 → 1,424.2 ms（快 236.3 ms） |

上海的回环对照在目录 HTML 或首屏资源下载阶段超时。通过单条 SSH 连接转发的 HTTP/2 对照确认 #542 返回 200 并读完游戏列表 HTML，取样到期时仍未取得整组封面绘制时间。两轮配对未完成。

从同一台 Mac 向上海正式 HTTPS 入口定向直连，对 #548 另做两次相同视口的冷缓存访问。首轮收到 200 后 HTML 下载未在取样窗口内完成。第二轮成功核对上海现役构建及同一组 9 张封面，HTML 首字节为 3.49 秒，首张封面在 **26.79 秒**出现，首屏全部封面在 **27.06 秒**出现。这是该次墨尔本至上海链路的浏览器实测。上海 #542 的有效浏览器基线仍待取得，现有 #548 公网测量用于记录当前体验。此前上海 30 张封面的源站首字节 P95 从 372.7 降到 157.8 毫秒。[源站并发数据](2026-11-25-release-548-dual-site.md#正式切换与验收)
