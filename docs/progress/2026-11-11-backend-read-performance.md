## 修改与接口

### 社交共享缓存

- 基础行改用独立进程缓存端口，外层页面仍保留 Next 缓存，解决嵌套 unstable_cache 绕过内层读取。保持 namespace、发布版本、固定日窗口及加载前后的 read_stamp 检查。
- 缓存最多 4 项、8 MiB 编码数据、2 个实际在途加载，每次加载最多 64 位等待者；这里的字节上限不是整个 Node 进程内存上限。
- 加载拥有独立读取预算与 7 秒硬期限；每位等待者保留自己的截止时间和取消。最后一位退出时中止加载，实际加载排空后才释放容量。失败不缓存，迟到结果不覆盖新项。
- 全进程共享数据状态，各模块保留自身预算函数；跨路由清理共享状态，清理失败也不会留下已匹配的旧行。私有错误品牌保留跨模块的版本重试和超大/不存储结果行为。

### 作品 SQL

- 保留原 MATERIALIZED 的 RLS 过滤集合，按 work_id 用窗口排名分组一次，再连接候选作品；维持原排序、空合集、20/500 上限及 21/501 超限哨兵。
- trial、retained、playback 与每日新增继续走原视图、角色和权限。未调整数据库迁移、索引或账号。

### 媒体取消

- 内部 ObjectStorage.read 新增可选 AbortSignal，Supabase/COS 组合调用方取消与自身 20 秒上限；writer 调用不传信号时保留原语义。
- 网站原图、混合媒体、display、published thumbnail 与社交原图接入同一预算 helper。共享缩略图使用独立下载控制器和逐等待者取消，全部退出才取消下载；迟到失败不能删新条目，未结束的传输继续占用缓存预留量。
- social transport 去掉隐式绑定首个访客信号；Auth 保持独立 10 秒会话预算。下载前后资格、祖先撤回、304、内容摘要验证和错误不回退规则保持。
- 没有实施报告第四至第六项：分页/树优化与 Supabase storage 生命周期另行处理。缓存满额仍沿用已有 bypass，不宣称新增了全局媒体下载并发上限。
