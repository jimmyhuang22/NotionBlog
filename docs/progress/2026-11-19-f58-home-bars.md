# 2026-11-19：首页第 8 行的加载灰条不再留下（F58，Claude）

编辑登记：Claude 修改 `src/app/motion.css`。契约、接口与媒体路由、取数层、fixtures、栏目开关、依赖、站点配置与后端代码未改。

## 问题

反馈 F58（审查员交接包 `2026-11-19-feedback-F58.md`）：首页第一次打开时，首屏第 8 行（`--i:7`）的日期后和卡片上方留着加载占位的灰条，一直不消失。原因：清灰条的 `bars-out` 是 1 毫秒、`step-end`、`forwards` 的动画，延迟 `calc(var(--i) * 150ms + 90ms)` 在第 7 行算成 1.1400000000000001 秒，浏览器在最后一步之前就判定动画结束，`step-end` 停在了起始值。

## 改了什么

- `bars-out` 改为 `step-start`：动画一开始就取终值 `none`，`forwards` 保持；延迟期间没有向前填充，灰条照旧显示到这一行出现。其余首屏动画（墨线、圆点、各行出现）不变。

## 怎么验证的

- 无头 Chrome 新建资料目录，每次都是第一次打开首页，4.5 秒后读首屏 8 行 `.entry` 的计算样式 `background-image`：
  - 本机正式构建（演示数据）岛屿 1440、墨水 390、千禧 1280：8 行全部为 `none`；
  - 线上（修复前）同样三组：第 8 行仍是 `linear-gradient`，复现 F58。
- 打开后 0.25 秒读取：第 1 行已清，第 2 到 8 行仍带灰条，说明每行的灰条仍等到自己出现时才撤。
- Node 24.21.0：`npm run check` 与 `npm run build`，结果见合并请求。

## 限制与下一项

- 第 8 行是月份标题或作品的情况只在演示数据里出现过的排列下看过；上线后由审查员在线上复验并关闭 F58。
- 同一写法的缓动动画（墨线 `ink-run` / `ink-settle`、圆点 `ring-in`、`arrive`）不受影响：它们差一点结束也看不出来，`ink-settle` 停在接近 0 的透明度。
