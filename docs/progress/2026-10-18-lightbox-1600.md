# 2026-10-18：看大图先换 1600，放大才取原图（Claude，F32）

编辑登记：Claude 本轮修改 `src/components/lightbox.tsx`、`src/components/content-image.tsx`。契约、接口与媒体路由、`imagePreviewSrc`、fixtures、依赖、栏目开关、全局入口与后端代码未改。

按[决策记录](../decisions/2026-10-18-lightbox-1600-previews.md)接前端：页面上的图片有小图预览、且地址是新版媒体路径时，看大图先显示小图，再取 `imagePreviewSrc(image, 1600)` 换上（顶栏写“正在加载清晰图…”）；不再自动取原图。放大（加号键、双击、双指或触控板捏合）到 1600 的像素不够时（屏幕上需要的像素超过 1600 的 1.1 倍）才取原图，顶栏写“正在加载原图…”，到了解码后换上，缩放位置不变。

- 没有 1600 档时媒体路由在同一地址给原图：取回的宽度不小于原图宽度就当作已是原图，不再请求。
- 1600 取不到：照旧取原图。原图取不到但 1600 已在：留在 1600，顶栏说明。
- 演示数据与旧路径的图没有 1600 地址，行为与之前相同（小图后直接取原图）。
- 适用于所有用 `ContentImage` 的地方：相册、学习笔记、游戏／影视／书籍详情正文、展开的动态。

## 怎么验证的

本机开发服务器的临时页面（已删除，未提交），用 3200 宽“原图”、1600、400 三张测试图并给服务端加延时，无头 Chrome 1280 宽：

| 情况 | 打开后 | 请求 |
| --- | --- | --- |
| 有 1600 | 0.3 秒小图、“正在加载清晰图…”；1.3 秒换成 1600 | 只有 1600 |
| 有 1600，加号放大两次（1×） | 立刻“正在加载原图…”，约 1.6 秒后换原图 | 放大后才请求原图 |
| 有 1600，加号一次（1×） | 需要 1758 像素，未超过阈值，不取原图 | 只有 1600 |
| 有 1600，2× 屏放大 | 取原图 | 放大后才请求原图 |
| 1600 地址给的是 1200 宽原图 | 换上后不再请求，放大也不请求 | 一次 |
| 1600 地址 404 | 小图后取原图 | 1600、原图 |
| 没有 1600 地址 | 与之前相同 | 原图 |

控制台无错误。外观没有改：顶栏、加载圈与照片占位都是原样，没有重截主题与手机宽度。
