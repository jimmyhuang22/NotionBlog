## 发现与修改

- 普通封面与栏目读取共用连接池。小图各自读取两次资格，每次经只读事务和截止时间设置；304 判断原先在整个图片响应生成之后，连条件请求也先读取对象。图片并发会产生连接排队，影响尚未缓存的栏目导航。上轮只验证社交作品图片，未覆盖该路径。
- thumbnail SQL 适配器将同时到达的请求分组，每组最多 32 项，队列最多 128 项，只执行一个媒体批次；继续以原调用身份执行原资格函数。每次响应的复查仍发起新的 SQL，不保存公开资格。单个调用取消不影响其他访问者；全部取消时停止批次。
- 已启用公开 HTTP 缓存的 v2 请求，可用已验证的缩略图摘要比较浏览器 ETag；匹配时经过当前资格和变化复查返回 304，不读取 Storage。未匹配仍验证对象字节，缺失缩略图仍经服务端的合格原图路径处理。
- 普通 v2 小图的 HTTP 错误只在原地址等待 600ms 后重试一次，再失败显示既有占位。服务端已负责缺失版本的原图处理，客户端不再因临时错误追加原图请求；旧版兼容地址保留原有处理。图片替换会清理重试状态和定时器。
- 历史 capture 兼容性测试只更新当前网站读取文件的精确哈希观察值，继续断言新代码不能消费旧冻结快照；未改冻结协议、允许集合或同步程序。
