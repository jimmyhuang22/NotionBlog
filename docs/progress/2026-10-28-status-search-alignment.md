# 2026-10-28：动态页照影视排版、搜索页对齐其他栏目（F48，Claude）

编辑登记：Claude 本轮修改 `src/app/status/page.tsx`、`src/app/search/page.tsx`、`src/app/timeline.css`、`src/app/library.css`、`src/app/globals.css`、`docs/FRONTEND_GUIDE.md`。契约、接口与媒体路由、fixtures、依赖、栏目开关、全局入口与后端代码未改。

## 用户的选择

反馈 F48：“动态页面排版和所有其他的排版都不一样”。第一版对比（卡片定宽）用户觉得难看，说明本意是：学习、作品、影视、书籍、游戏、相册的标题位置都一样，只有动态不一样，动态的年份条也和影视、书籍、游戏不一样。第二版按影视、游戏的结构排，用户选“丙（卡片撑满）”，并同意搜索页一起对齐。

## 改了什么

- 动态页：原来页头和时间线各自是 760 宽的窄版居中，年份条挤在标题右边。现在和影视页一样，一个普通 `wrap` 里依次是只有标题的页头、标题下方靠左的年份条（复用 `library__filters`，间距与影视、游戏相同），以及时间线。时间线竖线去掉原来的 8 像素缩进，对准标题和年份条的左边；“已定位到这条动态”与“加载更多”跟着左移。卡片仍贴合内容，最宽撑到内容区右边。首页时间线不变。
- 年份筛选时时间线变淡的规则原来依赖“年份条在页头里”，改为 `.status-page:has(.status-filters .link-pending[data-pending]) .timeline`。
- 搜索页：从窄版改为普通 `wrap`，标题与其他栏目对齐；搜索框、栏目与结果保持原来的 704 宽，靠左。

## 怎么验证的

演示数据本机生产构建，无头 Chrome：

- 320、390、768、1024、1180、1280、1440、1920 宽：动态页标题、年份条、竖线、月份标题，搜索页标题、搜索框、结果的左边，都与作品页标题左边相同（差值 0）；1280 宽为 148，1440 宽为 228。
- 墨水、苹果、岛屿的浅色与深色及千禧，在 1280 与 390 宽：对齐不变，无横向溢出。
- 年份条临时加到 20 多个年份时，320 宽下年份条在 18–302 内横向滚动，不撑出页面横向滚动，在标题下方不遮挡标题。
- “已定位到这条动态”提示（临时插入页面测量位置）与卡片内容左边对齐；图片动态的图片在卡片内正常；首页时间线竖线仍在内容左边往右 8 像素。
- `npm run check`、`npm run privacy:check`、`npm run build` 结果见合并请求。

## 限制与下一项

- 只在演示数据下验证；演示的动态都很短，卡片贴合内容。长动态撑满的样子见第二版对比图（正式站点注入）。随下一次发布上线后在正式站点复查。
- 定位功能不接受演示数据的编号，“已定位到这条动态”是在页面里插入同样的元素量的位置。真机与读屏未测。
