| 审查点 | 当前行为 | 源码结论 |
| --- | --- | --- |
| v1／v2 旧入口混用 | 数据库 v1 入口只接受版本 1（含既有未配置默认值）；v2 入口只接受显式版本 2。不匹配先返回 no-store 404，不取得 SQL 连接或读对象 | 版本隔离已完成；保留合法 v1 部署，不能据未知生产状态删除路由 |
| 取消与期限 | 两条数据库媒体入口沿已有 8 秒读取预算传递请求取消；活动 SQL 取消后销毁客户端，迟到对象不能发起下一次资格 SQL | 已有实际路由离线验收；不等同于所有旧底层 HTTP 即时停止或已回收流量 |
| live-notion 原图／小图 | 混合原图字节和默认／显式 live-notion 小图带服务器 Response 对象的 WeakSet 标记；公共 HTTP 包装将其 Vercel CDN 头固定为 no-store，并移除共享标签 | 实时源资格不会被响应升级为共享 CDN 缓存绕过；访客请求头不能伪造标记 |
| 数据库资格小图与回退 | database 小图允许沿既定共享缓存规则交付；缺图或分类为暂时性传输失败时，返回实时原图对象并保留其排除标记 | 不需要全局禁止“公共缓存开启＋默认 live-notion 配置”；按实际响应资格区分，避免误关合法数据库图片缓存 |
| 条件请求与撤回 | 新缓存模式仍是浏览器 private, no-cache, must-revalidate；当前资格通过后才可 304。404／503／跳转不升级缓存；实时字节的 200／304 均禁用共享 CDN | 不把旧 ETag 当成继续授权；缓存关闭时的旧一天私有浏览器规则保持 |
| 直连 m1 | B20 独立使用中央拒绝检查、有界图片代理和 no-store，不经过数据库 v2 公共缓存包装 | 没有引入另一条共享缓存路径 |

Vercel 的专用 CDN 头与浏览器 Cache-Control 分别控制不同缓存层，不能只看到浏览器 private 就认定共享层关闭。平台说明见[缓存头优先级](https://vercel.com/docs/caching/cache-control-headers)；真正需要下架的已缓存内容仍沿既定强制删除流程，[软失效与强制删除不同](https://vercel.com/docs/caching/cdn-cache/purge)。本轮只查公开平台文档，没有检查项目配置或发站点请求。
