# 2026-11-25：游戏页筛选切换的动效和平台一排的间距（Claude）

编辑登记：Claude 新增 `src/components/game-wall-motion.ts`，修改 `src/components/game-tools.tsx`（按下时记下盒子位置；名字和款数合成一行文字）、`src/components/library-grid.tsx`（新列表落地时播放变化）、`src/app/library.css`，更新 `docs/FRONTEND_GUIDE.md`。

## 做了什么

- 用户觉得筛选切换“生硬”：按下后旧列表不动，新列表来了一下子换上。看过本机原型（现状、甲 淡入、乙 滑到新位置）后选**乙**：
  - 按下状态或平台的同时，年份和盒子淡到 45%，表示在读（书架页早有这一步，游戏页换成年轮后丢了）；
  - 新列表来了，屏幕上两边都有的盒子从原来的位置滑到新位置，新出现的盒子一只接一只浮现，年份从淡变实；
  - 只动屏幕上的部分；系统开了“减少动态效果”时只淡下去，不做动画。按下时的位置按页面坐标记，所以浮动坞切换时的滚动不影响滑动。
- 平台一排：名字和款数间隔与图标一样（7px），款数小一号又按中线对齐，看着发飘。改成名字和款数是一行文字，款数在名字的基线上、离名字 4px，图标仍居中。

## 怎么验证的

- 本机正式构建加未提交的预览页（线上数据，加了 0.7 秒延迟模拟正式站点的等待）：按下后 20 毫秒采样，透明度从 100 降到 45，新列表到达后回到 100；乙有滑动、浮现和年份淡入的动画，甲只有浮现；滚动位置保持 420。
- 平台一排：Switch 的名字和款数文字底边都在 624.3px，款数离名字 4px，项与项之间 32px 不变。
- Node 24 下 `npm run check` 与 `npm run build`，结果见合并请求。

## 限制与下一项

- 动效只在本机预览看过，没有录屏逐帧看；随下次发布在正式站点复看。
