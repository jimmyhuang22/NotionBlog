## 线上停摆的原因与发布 #155 的复查

## 这次修的问题

停摆期间，首页、列表页和搜索都有明确的提示，但关于页返回的是 21 个字节的“Internal Server Error”，没有页头，也没有重试。本机复现后发现不只是关于页：影视／书籍／游戏详情、课程、笔记、相册和带定位的动态链接都一样。

原因在请求入口：它在页面输出之前先查一次“这一页在不在”，用来给不存在的页面返回 404。查询本身失败时错误直接抛了出去，整个请求就成了空白的服务器错误。判断函数的做法没有错（失败不能当成“不在”），缺的是入口对失败的处理。

现在分成三种结论：在，放行；不在，返回 404（原样）；**不知道**（查询失败），放行并把状态码设为 503，页面自己再读一次，读不到时显示已有的“页面暂时打不开”和重试按钮。

| 验证（本机生产构建） | 结果 |
| --- | --- |
| 内容读不到（数据库模式、不给连接配置） | 关于页、影视详情、课程、笔记、相册、带定位的动态链接：修改前 500、21 字节；修改后 503，完整页面，显示“页面暂时打不开”与重试，响应不缓存。列表页仍是 200 加同一提示；未知的作品库类型仍是 404 |
| 按一次重试 | 重新请求一次，仍读不到时整页重新载入一次并再次显示提示，没有循环载入 |
| 演示数据 | 关于页与存在的游戏详情 200；不存在的游戏、相册、课程与动态定位 404 |
| `npm run typecheck`、三项协议检查、隐私检查、`npm run build` | 通过 |
| 测试 | 除 `tests/website-v2-runtime.test.ts` 外全部通过；该文件只能在 Node 24 上跑，由 GitHub 检查覆盖 |

限制：

- 修复只在本机用“数据库没有配置”的失败方式验证过，没有在线上的真实停摆下验证；线上停摆时的错误（资格到期）与它走的是同一条失败路径，但没有实测。
- 入口的查询偶尔失败而页面自己读成功时，访客看到的是正常页面，状态码却是 503。没有收录的页面受影响很小，记在这里备查。
- 状态码是 503 时，站内跳转会退回整页载入（框架对非成功响应的处理），所以重试是一次整页载入而不是局部刷新。
- 线上复查用的是本机无界面 Chrome：桌面宽度看了首页与影视列表，手机宽度看了首页与游戏列表，各一次；书籍列表没有看，也没有在真机、Safari 与 Firefox 上看。
