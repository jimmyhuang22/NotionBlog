原捕获只有课程，或此前只完成了课程时，排除旧 course DTO 后可复用集合会变空。原规划器将空数组一律当作无效捕获，导致合法的课程重采在主机预检及预算规划时误报 CHECKPOINT_FAILED。新增两种恢复模式的真实冻结目录回归均复现失败。

规划器现在把零可复用页视为全部当前成员尚待采集，保留未知新工作成本和原预算限制；原捕获本身须非空、具有一致历史 lease，主机明确先检查，worker 继续核验新服务器资格。没有新增配置覆盖或跳过资格的布尔开关。课程独立配置也通过实际 PGlite 发布、规划回调与旧捕获／批次不变核对。

新增主机回归复制公开源码及本地依赖引用，在临时冻结项目中追加虚构的已审目录项，执行实际主机 `--check` 路径；真实目录保持空。混合／仅课程与两种恢复模式均通过，错误两份清单摘要、旧配置摘要、捕获索引、资格和未知条目均拒绝，锁／session／子进程／SQL 不启动。测试不读取旧 Git 对象或私人运行包。
