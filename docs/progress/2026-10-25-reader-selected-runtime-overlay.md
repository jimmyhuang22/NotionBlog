# 2026-10-25：读取隔离入口移植到统一恢复方案选定应用（Codex）

编辑登记：接续[双读取准备链](2026-10-25-reader-chain-integration.md)及[前提证据](2026-10-25-reader-prerequisite-evidence.md)，从最新 develop 建独立分支，只新增本记录。实现和证据留在忽略目录，不修改统一负责人候选、旧封存包或实际运行配置。

## 修改与目的

核对发现原隔离候选基于较早的应用，而统一恢复方案选定应用已增加 writer 会话有界续期。两者共有文件中有八处字节差异，且各有独有文件；直接替换隔离应用或完整 child 会覆盖新续期逻辑。

新建独立移植候选，逐项核验并保留统一应用全部 1,743 个原文件，新增八个隔离 helper，共 1,751 个应用文件。七个 helper 沿用既有隔离候选原字节；完整采集隔离子入口则从统一方案选定的 run.ts 重新派生，只移入读取身份检查。保留其三次有界续期实现、零业务重试和原收尾；原入口仍存在，候选未被安装或接入统一协调器。

另形成带摘要的逐模块采用清单。统一方案已有额外缓存阶段、父控修复／停止／writer 准入，以及新访客 run/version/source 与响应契约检查，不能被旧隔离协调器覆盖。后续必须在选定协调器上移入双 profile、fresh-reader、host、准备绑定及四个后置读取检查。旧隔离预算不能替代当前整图预算，增量检查仍需按实际槽及字节上限重编，不产生许可。

公共接口、provider、依赖版本与锁文件、数据库迁移均不改变。新候选只用于应用兼容和采用交接，统一负责人原候选及隔离旧包保持不变。

## 验证

读取边界专项七项全部通过，无跳过：实际完整采集子入口经严格回环 TLS/PGlite，独立公开账号通过，网站账号、证据账号和混合权限拒绝；后置 SQL 适配器每次重查身份；证据 host 正确初始化且拒绝混用网站读取组。有效子入口只到虚构刷新钩子，未进行完整来源采集。

运行完整 `npm run check`：类型、冻结协议与媒体核验通过；全量测试 2,708 项中 2,699 通过、9 项失败、零跳过。失败均位于依赖 `git ls-files` 组装临时 release 的既有测试：独立副本没有自己的 Git 索引，临时包漏装模块。为该副本建立只含 1,751 个已审输入的本机索引后，受影响文件 19 项全部通过，覆盖这 9 项失败；未重复整套命令，不把历史失败命令改称全套通过，重复用例不累加。

更早首轮类型检查因副本遗漏游戏依赖链接停止，已连接同一份已有冻结依赖。依赖链接被隐私工具当普通文件读取时出现目录错误，仅在该私人验证仓库的本机 exclude 中登记两个 node_modules 链接；全部 1,751 个应用输入仍在索引与隐私扫描中，最终通过。源码 gitignore、守卫和协议未放宽，依赖未安装或下载，失败证据保留。

随后一次离线 webpack 构建退出 0，48 份服务端追踪隐私核验通过；使用已有五份本机字体缓存及原离线网络守卫。构建后重新核对原 1,743 文件字节不变。两份原候选完整清单另行核验保持。公共记录按文档范围检查格式、链接、隐私和实际差异，不将本机结果写成平台通过。
