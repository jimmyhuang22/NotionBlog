## 建议执行顺序

### 1. 有界只读准入

先获得完整执行包所对应的新授权。进入窗口后，核验文件前像、目标、TLS、实际登录 owner、原缓存能力、完整目录及新扩展不存在或精确已安装的状态。将观测的安全字段先保存，再判断是否符合条件；失败时保留具体子条件，避免只留下一个聚合错误。查询只返回目录、计数／布尔、摘要和私有操作引用，不读正文、媒体定位或凭据值。

`classifyCommitCatalog` 的 legacy／installed 分类是必要条件，不能单独证明整个项目兼容：它没有检查全部原投影表的触发器清单、任意额外对象、所有 LOGIN 成员关系、真实运行包或在途会话。需补独立清单和身份核对；现场返回与固定期望不符时停止，不用现场结果自动学习、删掉多余权限或扩大期望。已安装态只进入核账，不重跑 CREATE TABLE／CREATE FUNCTION。

### 2. 受控排空

按已审运行图阻止本项相关的新唤醒，等待既有操作自行完成；保持来源暂停及维护 STOPPED，不发取消信号、不偷锁或重置计数。临时 hold 和控制文件变化也必须包含在将来授权及前后像内。排空超时、外来文件／锁变化、未知提交或无法归属的活动立即停止；不杀云端会话或盲目清理。

真实入口需要“拥有方关闭证据＋本机原锁＋数据库短事务锁”共同证明。最终事务锁定 `nb_v2.state`、实际存在且已列出的全部缓存投影表、缓存状态／事件，以及安装后可用的 B10 配置／意图表，顺序固定，使用与写入冲突的表锁和有界等待；不阻止普通只读访问。具体锁模式与顺序须在隔离多会话中验证，不能将预先做的一次活动查询当作之后不会再有写入的保证。[PostgreSQL 的锁说明](https://www.postgresql.org/docs/17/sql-lock.html)要求锁在同一事务持有至结束；只查询已提交空意图也看不到另一个未提交事务的意图。

### 3. 原子安装，先保持关闭

安装事务在上述锁内重新核对原函数／owner／权限及本项不存在的前像，再执行固定的独立 B10 正文，确认单例配置为 version 1／false、意图为空、14 函数及完整 ACL／约束／延迟触发器吻合，提交后再用新会话核对。

canonical SQL 自带最外层 `BEGIN`／`COMMIT`，不能直接嵌套到安装器的事务中，否则内部 COMMIT 会释放外层排空锁。安装器需严格识别并只剥离这唯一一对外层控制语句，固定原文件及提取正文两个摘要，在自己的事务边界执行；原文件不改写。此处理及部分失败／COMMIT 丢失必须先验收。安装语句沿用 2 秒 lock／15 秒 statement 上限，外层还有总期限；不是整轮操作 15 秒结束的承诺。

明确的提交前失败执行 ROLLBACK；已经发出 COMMIT 但响应不明时记录 UNKNOWN，停止后续启用。不能靠随后 ROLLBACK 的 ACK 宣称原提交未发生；仅在同一许可预留的核账连接中读取精确后像，不重放迁移或未知写入。

维护暂时保持 STOPPED、guard 不变，记录安装后的目录与预期拒绝。若未来恢复维护，应另以完整原始前像和只允许这一处定义替换的审阅器核对，再批准 CAS 更新 guard；不能调用旧“增加观察器”审阅器，也不能将 `catalog_sha()` 当前值直接回填为批准。B10 启用不以恢复维护为验收条件。

### 4. 在排空窗口显式启用

仅在安装提交和独立核账明确、真实生产者包确认以 COMMIT 成功作为成功边界、运行图仍持有且有完整回退能力时进入。核对原包没有强制 `SET CONSTRAINTS ... IMMEDIATE`；它会提前执行延迟触发器并重新提前占锁，见 [PostgreSQL 约束时机说明](https://www.postgresql.org/docs/17/sql-set-constraints.html)。

用新的短事务重取同一组排空锁，完整检查当前目录、缓存原模式、单例配置 false 和空意图，然后按精确前值 CAS 将唯一配置改为 true，要求更新行数为 1。提交后只读核账；响应不明不重试 UPDATE。恢复临时消费者 hold 只恢复本轮进入前已启用的原任务，不解除来源／社交／媒体或维护原有暂停，不因开关已开就启动一次业务。

### 5. 分别记录结构与业务结论

结构验收包括安装目录、权限、开关、空意图和明确提交。只有存在另行批准的实际业务操作，才验证其提交、原事件／generation、原消费者 purge／精确 ACK 以及有界网站版本／页面回读。B10 窗口本身不制造内容发布、下架样本、来源采集、媒体上传或清缓存事件；不能拿无写入期间 generation 不变来证明生产并发或刷新成功。

若只批准结构安装，就以“已安装／启用，业务效果待自然或另获批准的运行验收”结束；性能结论继续限于已完成的原生隔离证据。业务任务若本来暂停，仍保持暂停。

## 回退与故障结果

| 情况 | 处理与可报告结果 |
| --- | --- |
| 安装前像不符／锁繁忙／已有同名部分对象 | 不写入；停止并保存差异，不覆盖或重装旧库 |
| 安装明确回滚 | 报告未安装；保持原暂停及 guard，不删除历史事件 |
| 安装／开关 COMMIT 不明 | 报告 UNKNOWN；保留意图与拥有权证据，最多使用预留只读核账，不重放未知写 |
| 启用后需要恢复旧自动路径 | 再阻止新唤醒并排空，在同组数据库锁内确认无在途写入、空意图和 true 前值，CAS 改 false，提交后核账；待办事件继续由原消费者处理 |
| 意图非空或目录／权限漂移 | 停止；不删意图、不手动补事件、推进 generation 或清队列 |
| 已恢复 false | 只报告运行模式回退；新对象及新函数仍在，维护 guard 仍按安装后目录处理 |

日常回退保留 B10 对象和新函数定义，不执行 DROP、全量迁移回滚或恢复旧函数正文；后两项属于另一个 DDL 变更。现有 deny、失败／未知回执、待办、COS 文件与业务历史完整保留。本轮释放锁／还原临时文件时逐项核对 inode 和前后像；外来替换留在原处，不能为了写“清理完成”覆盖他人的状态。
