# 内容数据库备份与隔离恢复

本流程验收内容库的可恢复性。它与网站发布、定时同步及图片优化分别推进；恢复历史快照不会启用网站内容。

## 备份范围

混合图片模式的普通图片留在 Notion，新增普通图没有 Storage 对象。既有 `export --media` 可能因此明确失败，不能作为混合模式完整图片备份；核心 JSON 归档仍可恢复 v1 政策与内容，媒体定位须恢复后重新同步。v2 使用独立内容／媒体命名空间，不在本 v1 归档范围内，见 [混合媒体说明](HYBRID_MEDIA.md)。

内容归档包含 `state`、`sources`、`permits`、`denied`、`runs`、`records`、`media`、`tombstones` 八张应用表。导出使用单条 SQL，全部表来自同一 MVCC 快照，包含已发布、暂存及历史批次。`media` 保存对象描述和引用，不包含图片字节。

归档不包含数据库登录密码、Auth 账户／会话、云端项目设置、Storage 策略或迁移历史。目标库从匹配的源码安装核心与 reader 迁移；读取／写入身份另行配置。数据库备份与图片对象备份必须分别核对。[Supabase 备份说明](https://supabase.com/docs/guides/platform/backups)同样明确数据库备份不包含 Storage 对象字节。

真实归档包含私有正文、来源和公开策略。存入受保护且不跟踪的本机目录，目录权限 700、文件 600，不能放入 Git、构建产物或公开回执。记录归档大小和 SHA-256，复制或传输后重新核对。保留一份原始备份用于恢复比对。

## 执行顺序

1. 登记本轮操作者及目标，确认没有另一任务修改同一运行根。导出来源使用操作员权限；网站 reader／worker writer 不提权、不借用彼此会话。
2. 导出内容库。在项目目录内，现有 CLI 只接受忽略的 `.local/` 路径，输出文件已存在时拒绝覆盖：

   ```sh
   node --env-file=.local/source-operator.env scripts/database.ts export .local/backup-new
   ```

3. 创建独立的空 PostgreSQL 数据库，核对目标连接。保持源码、冻结协议及迁移摘要一致。使用仅包含目标连接的私有环境文件安装迁移，再恢复：

   ```sh
   node --env-file=.local/restore-target.env scripts/database.ts migrate
   node --env-file=.local/restore-target.env scripts/database.ts restore .local/backup-new
   ```

4. 将恢复后的各表与备份逐项比对，按主键排序后比较全部内容和策略字段，不能只比较行数。单独核对完整批次的内容类型、课程祖先与允许名单、正文及媒体描述；历史样本不能算作完整批次。
5. 核验恢复后的安全状态：`current_run`、`lease_run`、`lease_until` 为空；revision、epoch、fence 各递增一次；历史批次资格过期，原 staging 批次变为 failed。reader 的内容、年份和课程树请求应明确失败，不能返回 mock 或自动恢复历史发布。
6. 验证非空目标拒绝，包括只含中央撤回记录的目标；验证归档内部及目标库的版本不匹配拒绝，恢复中途发生约束错误时全部事务回滚。失败后比对目标，确认没有部分写入。

恢复会检查归档外层协议、内部唯一 state 行及目标库的协议／schema 摘要，并在事务内锁定应用表，避免空库检查后被其他操作插入数据。七张数据／策略表任意一张非空均拒绝。迁移登记表和初始 state 行属于空迁移库的基础结构。

## 图片与发布边界

以上命令仅恢复内容及媒体清单。需要图片字节备份时，先与图片任务协调，再使用现有 `export ... --media`；文件需完整回读并核对格式、大小和 SHA。`restore ... --media` 还涉及目标对象上传，须使用独立目标存储及对应身份，不能默认上传回当前桶。本轮内容恢复验收不证明图片备份、Storage／Auth 恢复或托管云库恢复已经完成。

恢复成功后，仍需核对当前来源、公开策略和撤回记录，用新鲜完整同步批次验收后再执行获准的发布。旧资格和旧成功 checkpoint 不能作为恢复后发布的依据。操作者保留匿名验收回执；结束时停止临时数据库，记录私人归档的实际保存位置。
