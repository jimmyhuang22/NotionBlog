# B18：缺失课程编号保持空值的实施方案

状态：用户于 2026-10-25 明确批准本方案的源码与离线验证；实现已完成，验证结果见[进度记录](progress/2026-10-25-content-unknown-values.md)。基线为已合入 B10 主机适配的 develop。本方案只涉及课程编号，游戏拥有方式在同项 B18 修复中处理。

## 问题与目标

两套 Notion repository 都把缺失编号依次替换成标题中匹配的编号和页面 ID。`Course.code` 仍要求字符串，两个数据库 payload 校验器也拒绝 null；`courseName` 与学习项目归类直接调用字符串方法。因此不能只删除两行 fallback，否则会使同步或页面读取失败。

拟定行为：只取已配置编号属性的实际非空值。编号缺失或为空时，公开 DTO 中 `code` 明确为 null；保留完整课程标题，不从标题推断编号。`id`、URL、物理父链与公开资格保持原规则。

例如：来源标题为 `ABC123 Example course`、编号属性为空时，返回 `code: null` 和原始完整标题。实际编号属性为 `ABC123` 时，返回该编号，继续沿用已确认的“编号出现一次”显示规则。

## 拟修改范围

| 范围 | 具体变更 |
| --- | --- |
| 共享 DTO | `contracts/content.ts` 的 `Course.code` 从 `string` 改为 `string \| null`，字段仍必需；不改其他领域中具有明确枚举含义的 `unknown` 状态 |
| Notion provider | `src/server/notion/repository.ts` 与 `website-repository.ts` 停止标题正则与页面 ID 兜底；空属性统一为 null |
| 数据库读写校验 | `src/server/database/validation.ts` 与 `website-validation.ts` 同时允许 null 和原有合法字符串；仍拒绝缺失字段、数字、对象等错误值。同步与增量路径复用这些校验器 |
| 格式化与项目归类 | `courseName` 对 null 返回完整标题；`studyProjects` 不对 null 调用字符串方法。无编号课程不匹配显式 `courseCodes` 名单，只进入已有的 `courseCodes: null` 归类；未配置收纳分组时不新建分组或改配置 |
| 最小组件兼容 | 课程卡片的辅助技术名称只组合实际编号和标题，避免读出字面 `null`；检查面包屑、侧栏和课程标题的既有缺省行为。保持组件结构、样式和布局，不增加新的视觉方案 |
| 虚构测试样本 | 增加无编号课程的局部测试数据，覆盖两种 Notion provider、数据库往返、项目归类与页面渲染；不改真实来源配置或私人安装包 |

搜索上下文已具备编号缺失时使用课程名的规则，需验证新 DTO 沿用该行为；不改搜索匹配、排序、协议能力或 SQL。

## 兼容与接续

现有合法字符串快照继续可读。没有来源证据时，不批量猜测或清洗历史编号，不改存量数据库、Notion 属性或缓存。既有页面 ID／标题推断值可能暂留在旧快照里，不能把源码修复写成历史数据已修复。

新 payload 中的 null 会被旧版读取校验器拒绝。未来真实安装和发布必须先让所有相关读取／验收程序支持 nullable DTO，再启用产生新 payload 的同步程序；网站 Git 发布不会自动更新独立业务运行根。已冻结的旧私人候选不能只替换其中某个文件后使用，须由其拥有方重新固定依赖和安装图。本次确认不授权上述真实更新。

当前源码核对未找到要求课程编号非空的 SQL 字段约束；数据库存储的是 item JSON。本次预计无需新迁移或修改冻结 SQL 协议；实施时仍用隔离数据库核验，发现额外共享协议影响则先补充方案。

## 验证与验收

1. 两套 Notion provider：编号属性缺失、空值、标题恰好含编号及实际编号各有覆盖；只有实际属性可生成编号。
2. 两套数据库校验器与隔离往返：新 null 和旧字符串成功，缺失字段或错误类型明确失败；同步及增量准备不因 null 中断。
3. 格式化、默认与显式项目归类：不推断编号、不错误匹配名单、不丢弃默认收纳的课程，保留既有课程与笔记导航目标。
4. 用局部虚构样本验证卡片、课程页、笔记面包屑及搜索来源行：无字面 `null`、无虚构页面 ID 编号、有编号时显示仍只出现一次。
5. 在独立分支集中运行 `npm run check`、离线 `npm run build`、隐私和实际差异核验，通过后按日常规则向 develop 开 PR 并普通合并。平台跳过不记为通过。
