## 本轮修正

owner预算的预写入可能在IPC截止后才完成。原来预写入与终态共用文件，迟到写入会把最终失败记录替换成旧的未开始状态。现在每次预写入使用独立attempt文件，终态使用单独文件；关闭未完成请求时同步标明失败与未知结果。没有退款、重试或延长10秒期限。

私人控制器副本的body准入现在核对真实pipeline、规范run／operation、独立binding中的来源／release／期限、有效的绝对截止和足够剩余时间。最终join不得自行制造PASS pipeline；连接关闭和锁释放必须为布尔true，plan摘要必须有效。失败body使用补充回执时，原始字节摘要、catalog摘要、候选数量及零写入须完整匹配，原失败保留。候选仍只返回完成提案，不写实际控制器状态。

## owner与只读证明

实际端口不能只凭连接字符串、客户端超时或启动参数声称角色、只读会话和服务器超时已验证。必须记录当次服务器实际效果以及验证成本；若既定一次SELECT范围无法覆盖额外证明，先固定新的具体方案和范围，不能自动加SQL、BEGIN、SET或重连。当前固定元数据SELECT保持不变，不新增迁移、角色、GRANT或通用SQL通道。

私人适配候选只接受父进程显式传入的连接资料，在独占连接中拟采用BEGIN READ ONLY、SET LOCAL八秒限制、身份／只读／实际限时SELECT、原固定元数据SELECT及ROLLBACK，正常路径共五次SQL提交、一次连接；最多8KiB逻辑请求与6KiB逻辑响应，旧broker的一次元数据／10秒／4KiB上限保持。临时设置依据[PostgreSQL SET LOCAL](https://www.postgresql.org/docs/17/sql-set.html)，独占client依据[node-postgres事务说明](https://node-postgres.com/features/transactions)。这些是源码候选的成本，未授予实际额度；逻辑字节不当TCP流量，查询未知保守扣账且不重试。

host在内部生成新run，适配器在首个固定请求绑定该run；原broker仍校验run及nonce。回滚、关闭或终态保存未证实时不交付元数据，迟到attempt不会覆盖终态。该只读端口只服务资格元数据，不能用于policy写事务；后者仍需独立owner事务及当次窗口。实际配置／服务器与pooler效果未由本机TLS／PGlite／协议夹具证明。

## 持锁结算顺序

未来owner接入应先取得原控制器锁，再重新读取同一operation的实际pipeline、worker和全部后置证据，校验新run／配置／release／服务器期限与无未决写入。读取的完整控制器前像必须与候选期望字节一致，不能只比较runId。通过后才原子保存一次完成提案，读回确切结果再释放自己的锁。

写前发现变化应停止，保留原状态；写入或回执结果未知时保留未知账本，核对实际文件，不自动再次写入、重新promote、补采或恢复排程。此处是接入顺序，不是已经完成实际写回或持有锁的证明。

私人文件适配候选已在虚构目录验证该顺序：独占同名锁、重读冻结摘要的各项证据、比较完整状态字节与文件身份，持久记录唯一尝试后才执行一次同目录rename。待写临时文件也在rename前复核原字节与身份；最终回执按确切字节读回。写入应答丢失只观察前像／后像／其他状态，不重放写入；进程退出留下的锁不自动接管。跨进程排他依赖所有参与者遵守同一锁协议，不能声称文件rename提供不合作写入者之间的数据库式CAS。来源、实际文件映射与完整release仍属于上表的未完成项。

## 软件与政策回退分开验收

1. 未安装前不需要“回退运行”；保留原运行根、清单和失败账本。本轮不移动它们，也不把源码入口迁出当运行移交。
2. 未来替换文件前，在当次空闲窗口保存每个目标的原字节、权限、路径及摘要，固定恢复目标；禁止整目录替换或覆盖另一个负责人更新。
3. 软件恢复只恢复当次确实替换且仍匹配安装后像的文件。旧prepare不能自动选新latest／新capture；旧软件读取新捕获的资格须单独证明。
4. policy逆向仍由原独占事务校验状态与指针。旧成功的有效期不会因软件或映射回退自动延长；promote结果未知时不能直接恢复旧指针或把旧资格改成新资格。

本说明没有创建可执行的真实配置、选择实际owner凭据、读取来源／数据库或授权安装、恢复任务、同步、共享分支合并与部署。
