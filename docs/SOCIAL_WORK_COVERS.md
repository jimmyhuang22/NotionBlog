# 社交作品封面

独立工程扩展，默认 `SOCIAL_MEDIA_ENABLED=false`。`true` 时，首页与作品 API 在既有分页版本确定后补 `cover`，补图不会使旧游标失效。普通作品取第一条 publication 所属平台，合集自己的封面优先；无合集封面时，season 选当前合格且日期明确的最新成员，multi-part 取对应视频。同日期按稳定 publication key 排序；该成员缺封面仍为 null，不跨平台借图。

## 安装与权限

独立迁移 `supabase/migrations/20261014014825_social_work_covers.sql` 依赖已有 reader／collection／retained 扩展。开发合并不自动安装迁移，也不设置 LOGIN 或密码。新增 `nb_social_media_worker` 默认 NOLOGIN、无提权能力，仅继承当前社交 reader 的受限可见范围，并可写媒体旁记录和绑定，不能修改作品批准、统计、来源绑定或 Notion 内容。原统计 worker 只通过受保护的 trigger 同步封面 URL 摘要；无新直接表写入权限。

未安装下方衔接扩展时，网站 `/media/social/s1.…` 使用当前公开资格与当前封面摘要检查，私有对象回读后再检查一次；中央撤回、关闭绑定、来源封面变化、未审核笔记类型变化和合集版本变化阻断旧路径。旁记录按 trial／retained 模式隔离，一种模式的更新不会覆盖另一种的合集图片来源。存储错误明确失败，未知图片 404，不输出平台 URL 或对象凭据。当前图片响应为 `private, max-age=86400, must-revalidate`；后续服务端读取资格撤回不等同已缓存图片立刻消失。

服务端使用 `SOCIAL_MEDIA_` 前缀的独立存储配置：例如 `SOCIAL_MEDIA_STORAGE_PROVIDER`、`SOCIAL_MEDIA_STORAGE_URL`、`SOCIAL_MEDIA_STORAGE_BUCKET`、`SOCIAL_MEDIA_STORAGE_API_KEY` 及专用 reader 登录／令牌；COS 使用 `SOCIAL_MEDIA_COS_*`。Supabase 专用账号只设置服务端 `app_metadata.notionblog_social_storage_role=reader|writer`，不设置旧 `notionblog_storage_role`；两类工厂拒绝混合身份，不从旧身份回退。专用 reader 登录同时核对 JWT 与 Auth 当前用户，注入的取消／传输控制也覆盖登录请求。

可选安装模板为 `database/social-storage-policies.sql`：独立私有桶 `notionblog-social-media`、摘要键、受限 SELECT／INSERT，没有 UPDATE／DELETE；旧 Notion 桶及策略不修改。安装前审核所有既存全局 Storage 策略；模板合并不等于已经安装或创建专用 Auth 账号。不得将宽权限密钥放入客户端。COS IAM 同样必须另核对独立身份与对象范围，不能假设旧 Notion 媒体资格涵盖社交对象。受限 writer 的数据库配置为 `SOCIAL_MEDIA_DATABASE_URL`／`TLS`／`CA_CERT`（完整键名均带 `SOCIAL_MEDIA_DATABASE_`）；URL 用户必须为新专用 worker，远程 TLS 验证不关闭。

## 同步输入与复用

`publicationCoverSource` 直接从已经校验的 B 站／小红书私有观察生成媒体输入；`collectionCoverSource` 接收同一次采样已取得的 SSR、目标和真实采样时间，不额外抓网页、不改统计协议。它核对完整成员／账号身份后提取合集 `ugc_season.cover` 或多 P 的 `videoData.pic`。队列运行器在精确统计云回执和本地 ACK 之后提供旁记录，再进入独立媒体任务；具体安装状态见私有运行回执，不把统计自然刷新本身当作封面刷新证明。

私有目录 `sources.json` 形状为 `{version:1,mode:"retained"|"trial",sources:[{kind,key,platform,url,observedAt}]}`，来源值只在忽略目录。每批最多 20 个来源、单张最多 20 MiB、总原图读取最多 80 MiB，单并发、总 180 秒、最多 120 个对象操作；失败立即停止余项派发，回执列出失败与尚未处理数。对象操作不是底层 HTTP 请求配额，实际运行另按存储适配器、原授权与传输条件确定预算。

```sh
node scripts/social-media/cli.ts plan /absolute/private/directory
# 只有获得具体执行授权、迁移／身份／存储已验收时：
node scripts/social-media/cli.ts sync /absolute/private/directory --execute
```

plan 仅读取私有输入、校验并写本机计划，不读取凭据或联网。sync 从同目录 `media.env` 读取独立配置，有锁、单连接及私有回执。来源尚不可公开或已改变时，在下载前阻断；上传原件和变体并逐件独立回读通过后才登记，登记时再由 SQL 检查资格和当前摘要。访客不下载平台图片或运行编码。

以来源 URL 摘要而非 observedAt／整份统计响应 SHA 识别封面变化；签名参数变化目前保守视为引用变化，不擅自剥参数。未知原地换图不声称能靠 URL 检出。已登记且摘要相同直接跳过；登记失败可复用私有缓存，不重下、不重压。相同字节摘要共享不可覆盖对象；小图不放大、保持比例，并且严格小于原图才上传。原图本身宽度已不超过请求档位时可原件复用，不伪称重新编码；大图无法得到合格预览时保留 null 并记录失败。

完整引用变化时，只把同一 kind／key 的旧私有缓存作为候选：缓存必须通过身份、元数据、文件字节摘要和当前编码配方检查。先校验新引用的当前公开资格，再对该新地址读取一次；只有原件字节摘要完全相同才复用已有原件与 400／800，不重新编码。图片实际变化或编码配方不匹配时仍走正常生成流程；坏缓存明确失败，不在源请求失败后把旧图当成新地址的采集成功。已有已验证绑定的连续展示另见下节。完整 URL 摘要仍更新，未剥除或猜测签名、日期和路径。

若同一 owner 的既有数据库绑定已经登记完全相同的三档文件元数据，独立 reader 逐个回读、验证摘要后可省去全部 PUT，再登记新引用。共享摘要只读一次；文件缺失、权限拒绝或字节不符立即停止，不自动补传。没有既有登记证明时仍执行不可覆盖上传与回读。源或资格在读取中变化时，登记前的复核及 SQL 资格检查阻止旧候选公开。登记响应丢失后，下一次先读实际绑定，已完成登记直接 unchanged；不自动整批重跑。

回执增加 `sourceRequests`、`encoded`、`reusedEncodings`、`uploads` 和 `objectReads`，分别记录源调用、编码调用、同字节编码复用、存储 put 调用和独立 read 调用。它们是本层调用／尝试数，取消或失败也保留已派发计数；Auth、冲突处理和适配器内的物理 HTTP 另行计量。引用和既有登记均未变时，这五项为零。此工程不自动安装周期任务；仍由原采样运行器在成功更新后提供当前私有来源，媒体的实际执行窗口、额度和失败待办单独安排。

## 发布验收

先完成迁移／真实 LOGIN 和 TLS／最小权限／对象读写证明，再按已批准作品盘点做一次有界封面同步。验证首页与作品 API、400／800、撤回、封面更换与已有游标；最后 Claude 复验真实图片画面。无需完整 Notion 内容重采，不能借用另一会话的对象额度、窗口或授权。

## 已验证封面的换签衔接

页面读取的后续修复使用 `/media/social/s2.<kind>.<key>` 稳定 owner 引用，避免新代登记后打开页面的延迟图片仍请求失效的 `s1` 资产地址。它只解析当前模式下仍可读取的绑定，不保存历史访问资格；两次资格检查和字节校验保留。原不可变 `s1` 路径及其浏览器缓存例外保持兼容。无需新增数据库对象或更改媒体任务；上线前的旧页面需首次获取新版页面，代码准备不代表正式部署。

稳定地址的浏览器复用使用 `private, no-cache, must-revalidate` 与 ETag，替代其最初的 no-store 策略；CDN 与 Vercel-CDN 专用头仍明确 no-store。ETag 包含当前 owner 地址、显示模式、请求档位及已验证图片的字节摘要、类型和大小，不包含临时 URL、统计时间或登记代号。浏览器每次复用时仍需回源校验：匹配的 If-None-Match 在两次当前 RLS 绑定校验后返回空体 304，不打开对象存储；不匹配时读取并验证图片字节，再复核当前绑定并返回 200。原图、400、800 及 trial／retained 不混用验证标记，真实换图、撤回、缺图与读中变化的阻断继续生效。弱验证标记、标记列表及单独的通配符按 GET 条件请求处理；非法或超大条件头回到正常完整读取，不授予额外访问。

这会减少已有图片的对象读取与重复传输，但每次校验仍有数据库资格检查与网络往返；不保证刷新完全无加载时间，也不改变已缓存旧 `s1` 图片的一天例外。错误响应保持 no-store，校验失败不退回浏览器旧图成功；浏览器已取得的图片无法远程抹除。条件缓存代码合并不代表线上已启用，正式发布验收另记。

`20261018134559_social_cover_rotation.sql` 是独立可选扩展，取代本说明原先“来源地址一变即撤下旧图”的 publication 读取行为。它不改变合集来源时间／成员资格，不改变 DTO、分页、媒体路径、采集频率、对象或运行包。当前实例已按具体授权安装；开发合并不会为其他环境自动安装，云端执行仍须按具体方案批准。

同一已授权 publication 的来源地址非空且类型不变时，继续读取该模式唯一的已验证绑定。新地址仍使用完整 URL 摘要，仍必须成功下载、校验、独立回读、按当前精确摘要登记，才原子替换绑定；既不剥除签名，也不从旧图推断新图字节相同。真正改图时同样在新图准备好前展示旧图，失败会保留旧图及失败待办，不能称为新图已经同步。每个 owner／mode 只有一个绑定，成功替换后旧路径不再获得后续服务端读取资格。

来源封面明确为空、笔记类型改变或源记录删除时，清除旧绑定；恢复同一地址／类型也需重新登记，不能复活旧绑定。作品撤回、账号绑定禁用和成员撤回继续由当前公开资格限制，媒体对象读完后的第二次资格检查保留。先前已隐藏的 publication 绑定不加入连续展示：内部 `continuity_ready` 只为当前合格绑定初始化，随后只有严格登记触发器可以设为真。隐藏绑定保留，供独立媒体 worker 复用对象元数据，直到自然排程按新地址重新验证成功。

原 `cover_source_matches` 继续作为写入的严格校验，新 reader 判定单独命名。新的仅供触发器调用的登记保护先锁定当前来源行再检查精确摘要，拒绝较早通过采集检查、但登记时已过期的候选。增加一个内部布尔列，没有新表、角色或表写入权限；worker 不能直接修改此列。新增 reader 函数只给现有受限社交 reader，两个内部触发函数不向 worker、reader 或客户端开放执行。

回退使用 `database/social-cover-rotation-rollback.sql`，恢复原精确摘要读取规则并移除本项内部列、函数与触发器，保留当前绑定和对象，不恢复真实移除或类型改变已清除的绑定。具体安装前像、锁等待上限、事务内回滚样本和自身消费者暂停／恢复方案保存在私有安装包；不触发网站部署。

## COS 迁移与统一缓存

网站 reader 与周期媒体 worker 必须指向相同的已核验存储目标；只改网页环境变量不能迁移对象，也不能接续后续上传。worker 在 provider 为 COS 时不再构造 Supabase Auth／Storage 会话：使用显式 `SOCIAL_MEDIA_COS_WRITER_*` 上传，再使用不同的 `SOCIAL_MEDIA_COS_READER_*` 独立回读。网站仅配置 reader；不得部署 writer 到网站。worker 可显式配置 `SOCIAL_MEDIA_COS_WRITE_ENDPOINT=accelerate` 与 reader 的 `SOCIAL_MEDIA_COS_READ_ENDPOINT=accelerate`；默认仍为 regional，版本化控制请求始终走地域地址。设置只选择已有桶的地址，不自动开启加速；安装方先核实桶状态和本次成本，签名使用实际请求的 host。原有 Supabase 路径继续兼容，未知 provider 明确失败。

迁移入口 `scripts/social-media/migrate.ts` 只复制本机已通过大小、类型及 SHA 校验的文件；按内容摘要去重，固定输入与上限，逐件不可覆盖 PUT／独立 GET 核验并保存进度。中断的 PUT 先读核对，不盲目重传；不能取得存在／缺失证明时保留未知状态。它不抓来源、不编码、不改绑定、不删旧对象。安装方在自己的私有协调入口累计实际请求／字节／时间，迁移完成后再核对当前绑定的新增差异。

切换顺序：准备新冻结运行包和旧环境／入口回退；完整证明当前绑定的原件、400、800 均已到目标；在媒体消费者自身锁空闲时保留并切换 provider／运行包；最后切网站 reader 并发布适配代码。统计采集和 Notion 同步不由此重启或暂停。回退恢复旧 reader 和旧媒体入口，旧对象与绑定保留。不得在两端仍会写不同存储时宣布迁移收尾。

新页面返回 `/media/social/s3.<kind>.<owner>.<file-version>`。版本由原件和两档文件元数据计算，不含平台临时 URL、统计时间或登记代号。字节不变的换签保持地址；实际换图改地址。浏览器对该不可变版本使用 `private, max-age=86400, must-revalidate` 和 ETag，已有 `s2` 可变路径继续每次条件核验，`s1` 兼容保持。每个到站请求仍核对当前 RLS、当前文件版本和读后的绑定，304 也不能绕过资格。一天内的浏览器已下载副本存在既有撤回窗口；不承诺远程立即抹除。

服务器只短暂缓存已校验的不可变小图字节，不缓存公开资格；缓存命中前后仍做当前绑定检查。媒体请求共享有界取消，配置原生 HTTPS 时取消包装保留该运输方式。作品页取消另一平台的隐藏列表及十张图片预取，首页和作品仅在新首屏／游标／统计完全一致时恢复当前会话已加载分页；其他列表维持历史返回恢复。错误响应继续 no-store，不将旧图成功当作新的来源同步成功。

正式验收限实际所需样本：B 站 800、小红书 400、首页与平台来回切换，分别记录首访、浏览器缓存命中及条件 304；仅检查响应缓存头不等于证明实际浏览器复用。源失败、迁移、网站发布和后续自动上传各自交回状态，不用一次全内容重采代替媒体验收。

## 合集采样时间快速接续

统计更新合集采样时间后，媒体仍需按精确 ACK 接续来源。周期消费者先对最多五百个已 ACK、已有相同摘要绑定的待办执行一条元数据 UPDATE，再处理原最多二十张的图片批次。当前资格、采样时间、来源与绑定摘要逐项一致才恢复读取，只更新采样时间，不下载／编码／上传，不扩大公开资格；换图、空来源、缺绑定及失效 ACK 留待原流程。队列完成仍核对原 generation，丢失响应不伪造成功。

`queue-cli.ts refresh-collections <social-runtime> <media-directory> --execute` 提供同一独立元数据入口，可由安装方放在精确统计 ACK 后执行以减少等待；它不消费剩余图片工作。常态仅安装周期时，仍有统计完成至下一 tick 的窗口；不可将它描述为原子提交或零空窗。入口复用现有消费者／媒体锁与受限身份，不给统计 worker 媒体写权限，不自动安装任务。
