# 从这里开始

最后核对：2026-11-13。本文件直接改写、不往后追加，保持在 10 KB 以内；事实变了就改这里。与其他文档说法不一致时，以本文件和 [AGENTS.md](../AGENTS.md) 为准，并顺手修正另一处。

## 怎么读

决策、进度与存档加起来有数 MB，没有人能在一次对话里读完，硬读只会挤掉做事的上下文。按下面的顺序读，够用就停：

1. 本文件，以及 [AGENTS.md](../AGENTS.md)（全部常设规则）。Claude 另读 [CLAUDE.md](../CLAUDE.md)。
2. 本机有 `.local/PROJECT_MEMORY.md` 时，读它开头的当前要求与个人配置；归档部分按需检索。
3. 按手头任务读相关专题文档，目录见 [文档导航](README.md)。
4. 用文件名和关键词找最近的、与本任务相关的十几条记录，例如 `ls docs/decisions | tail -20`、`rg 关键词 docs/decisions docs/progress`。决策第二行写着“状态：”的，按状态处理。
5. 存档 [DECISIONS.md](DECISIONS.md) 与 [PROGRESS.md](PROGRESS.md) 只在需要 2026-10-12 以前的背景时检索。

[项目需求](REQUIREMENTS.md)按日期记录了需求的来龙去脉，查某个功能的边界时检索相关章节即可。

## 当前事实

- **仓库**：干净的新仓库 2026-10-23 按用户授权公开；旧归档仓库保持私人。原创源码使用 MIT 许可证，个人内容与配置不随源码提交。
- **分支**：`develop` 日常集成，`main` 线上。每项工作从最新的 develop 开短期分支或工作树，不在落后的检出上直接改共享规则或记录。
- **检查**：合并请求在 GitHub 托管 Ubuntu 上运行 check／build 与隐私历史检查。合并到 develop 按影响完成本机验证即可，不等平台检查；发布到 main 要求完整检查通过。私人阶段用过的 Mac mini 运行器已于 2026-10-22 退役。
- **部署**：默认生产目标已改为新加坡 Oracle；正式域名已切到新加坡。main 仍是发布源码，手工安装对应 Linux ARM64 产物，合并 main 不会自动更新主机。AWS 保留但不再更新、不删除；旧 Vercel 投递不是主站上线证据。入口统一为[生产部署与交接](PRODUCTION_DEPLOYMENT.md)，底层机制见[自托管说明](SELF_HOSTED.md)。新加坡现役数据库页面模式为 legacy，媒体为 display-only/private-disk，published 读取依赖一处现役 profile 适配；不能直接套用旧 AWS 双 legacy 配置或 amd64 产物。
- **栏目**：由运行配置 `CONTENT_FEATURES_JSON` 开启，代码默认只开动态与学习。据前端记录，正式站点还开启了作品、影视、书籍、游戏和相册；博客与“项目”关闭，正式 HTTPS 下 GET/HEAD 返回 404 已有验收记录。
- **后台任务**：网站内容采集、发布与游戏任务已迁到新加坡独立私人运行根；其他私人任务按各自最新交接维护。网站发布不安装、覆盖或启动这些程序，不恢复旧 Mac／东京排程。身份、路径及调度细节只在私人交接中核对。

## 常设规则在哪里

全部写在 [AGENTS.md](../AGENTS.md)，这里只列要点：

- **合并与发布**：develop 本机验证后自行合并；main 只由用户合并；发布请求打开期间暂缓向 develop 合并。
- **云端流量**：小量只读直接做，每天合计 50 MB 以内；写入、安装、恢复定时任务、发布、批量下载和超出额度的读取先问用户，一两句话说清即可。一次批准覆盖整个任务，“继续”就是继续同一个任务。
- **出错**：没写入、没发布的临时错误自行修正或重试，最多 3 次；写入结果不明或数据对不上时立即停下再问。
- **不做的事**：不把封存包、清单、签收作为开工前提；不要求拿不到的证明；同一件事不开多条执行线。
- **记录**：每项工作一个进度文件；决策只记长期有效的选择，一次性的批准写进进度记录。

这些规则的来由见 [2026-10-26 的决定](decisions/2026-10-26-agent-working-rules.md)。
