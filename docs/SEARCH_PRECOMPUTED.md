# 搜索文字派生片段

本扩展仅优化反复提取已存正文的成本，不改变搜索 DTO、匹配顺序、公开范围或采集流程。默认关闭的代码已交付；2026-10-20 经单独授权完成一次真实库安装、单批次填充与部分只读对照，**性能验收未通过，网站继续使用原路径**。本次没有启用配置或部署，详见[验证记录](progress/2026-10-20-search-precomputed-validation.md)。

## 当前验证结果

同步按用户要求暂停后，用户明确允许采用现有已发布批次，替代原“同步全部后置完成”的执行前提；原后置未完成的事实保留。固定原子安装在同一事务内登记已审核的清理结构摘要，保留原清理保护和政策；生成仅针对一个新鲜核对的当前批次。2,245 条记录、90 批、正文及片段合计 29,107,851 字节，全部生成并通过摘要核验，随后关闭生成入口。没有常态生成或新的采集任务。

只读对照使用真实受限 reader，只返回规范化摘要、条数和时长。首对准备样本旧／新为 3,186.828／1,347.504ms，条数、投影字节和摘要一致；准备样本不计入暖配对中位数。原窗口截止后，用户另给最多 60 秒、仅补原剩余读取的窗口。第 4 次搜索（新路径的第 2 次读取）返回 PostgreSQL `57014`，事务回滚，验证器停止且未重试；当时服务端 statement timeout 配置为 5 秒，保存的错误不含精确取消原因，尚不能定位到具体算子或 I/O。

最终搜索尝试 4／8（成功 3、已知错误 1）、版本读取 1／2；其余未执行，两个计时窗口均已结束。缺少完整暖配对样本和末尾版本复核，不能据首对宣称生产提速、全部真实权限撤回通过或建议启用。新增祖先撤回检查仅在本机虚构数据上通过。六把本次持有的共享锁已正常释放，同步暂停保留。原账本、失败用量、生成禁用证据和固定批次绑定均保存在忽略目录；不得重置用量、自动延长窗口或重放失败读取。

后续独立只读诊断已从同一取消事件的日志确认 **statement timeout**；日志未提供内部执行阶段，因此仍未定位具体算子或 I/O。派生表已有自动统计，当前游标的非执行计划使用既有索引并排序。两种本机改写均不采用：批量关联仅改善约 1.7%，先排序 ID 的方案仅约 0.2%；均为各自虚构数据组内的三轮暖中位对照，不是线上收益。本轮没有重跑托管搜索、安装或填充，详见[诊断记录](progress/2026-10-20-search-precomputed-diagnosis.md)。

后续证据已区分测量包装与业务函数：减少验收 SQL 的大 JSON 物化后，一次新的独立托管诊断中新／旧路径仍为 3,397.726／2,391.121ms，不能作为稳定提速。该诊断未重开原验收，详见同一[诊断记录](progress/2026-10-20-search-precomputed-diagnosis.md)。上述暂停为各次执行时的历史状态；用户随后明确恢复了原同步调度，见[暂停及恢复决定](decisions/2026-10-20-development-sync-pause.md)。原样本绑定和关闭的预算不随恢复变成新批次的验证证明，网站预计算继续关闭。

## 读取与兼容

服务端 `DATABASE_SEARCH_PROJECTION` 缺省或为 `on-demand` 时继续原 API，不要求安装本扩展。显式 `precomputed` 要求 v2 与 `DATABASE_READ_PROJECTION=scoped`，并在原能力检查的同一次 SQL 中核对独立迁移摘要与算法版本；缺失或不匹配拒绝服务，不静默换 provider。旧迁移、冻结 producer、schema digest 和公共接口保持原样。现有真实预览启动器不会转发这个新选项，本项不修改另一负责人正在准备的开发隔离发布；未来云预览须先整合其最终启动器并验证参数传递。

`nb_read_api.read_search_precomputed(mode,kinds)` 每次取得当前快照，逐条执行原 `record_eligible`，再读取私有 `nb_search.parts`。主键为 run／记录，命中还要求算法版本、正文 SHA-256 和片段 SHA-256 一致；不满足则在同一 SQL 内执行冻结的原遍历语义。该副本固定 32 层及单数组两万项边界，避免以后替换旧函数时错误解释旧片段。正文过大而未生成仍可走原读取路径，继续受原整体输出限制约束。

片段保留内部链接与图片守卫，不存储已通过资格的结论。链接、媒体与父级撤回每次通过原 `search_scope` 现查，应用继续净化文字并在匹配后复核 revision。片段没有浏览器、CDN 或跨请求权限缓存。搜索仍扫描所选合格记录，不是新的全文索引；仍有两万条、32 MiB 传输与应用 16 MiB 紧凑正文上限。暖调用仍为读取加版本复核两次 SQL，首次能力检查仍为一次 SQL。

## 生成与清理

本项采用独立管理员批次入口，**没有触发器、采集程序接线或调度**。迁移仅建空表，生成期限和目标均为空；摘要也须所有者核对文件后单独登记。网站 reader、同步 writer、Supabase API 角色均没有私有 schema、表或生成函数权限。RLS 是额外防线；只读 API 使用固定 `search_path`，只授予既有 reader 组。

- `nb_search.configure_generation(mode,run,fence,revision,seconds)`：所有者为一个确切批次设定最长 900 秒窗口，支持当前 `qualified`／`published` 或持有效租约的 `staging`。锁定原权威状态，核对 run、fence 和 revision；不续租、不改指针、不授予公开。
- `nb_search.generate_batch(run,fence,revision,afterId,limit,maxBytes,millis)`：以 ID 顺序从已存正文生成；最多 25 条，单正文及单派生片段各 1 MiB、单片段数组两万项，输入与派生文字合计最多 4 MiB，计算检查期限最多 1,000ms。返回 count／lastId／bytes；下一批显式传回 lastId。记录数、字节和期限都必须由调用者逐批记账，不能自动循环至无限完成。
- 开始和结束均核对原批次，staging 复用原 `assert_lease`，旧 run／fence、revision 改变、过期窗口或失效租约均拒绝。参数非法、超限、深度错误或派生内容无效会回滚整个调用；没有吞错写入。计时为批内检查，不能中断已开始的单个遍历；未来执行必须另设有限 `lock_timeout`、`statement_timeout` 和客户端截止时间，不能称为硬 CPU 限额。
- `nb_search.disable_generation()` 清除生成目标和期限，保留可重建的片段。原记录删除通过复合外键级联删除对应片段；原 run 删除清空生成目标。没有额外保留原正文、改变历史存档范围或接管原清理调度。

这一选择避免改变正在运行的冻结 producer。新发布／增量 run 没有自动生成时，读取安全回原提取，性能收益随覆盖率变化。未来若要接入自然同步，必须由原同步负责人审核身份、租约、写入预算与失败收尾；不能把当前所有者函数授予网站或直接替换运行包。

## 后续安装、验收与回退

本节保留一般执行要求，首次真实执行状态以上述记录为准，不再代表尚未安装。后续固定计划仍须核对最终提交及 `database/search-precomputed-protocol.json` 的文件摘要，实际迁移所有者和 reader 身份、既有端点、当前 run／revision／fence，以及同步和维护窗口。仅按批准的总批次、SQL／字节／时限预算处理一个确切当前 run；已安装／填充部分不得盲重放。不得复制真实正文进公开 fixtures、重采 Notion 或请求图片。安装空扩展／部署默认关闭的代码本身不会提速。

安装还需原历史清理负责人复核：`nb_search.parts` 入向原记录的外键会改变现有清理程序的结构摘要。以已安装清理 SQL 的原始保护函数在 PGlite 复现，未重新审核的摘要会明确拒绝维护；不能盲装后等下一次清理失败，也不能删除该保护。仅在原负责人确认无在途任务、复核确切外键差异和归档／恢复影响后，由其按既有流程登记新摘要，再释放原共用锁；本项不自动改清理配置、调度或冻结运行包。

进一步使用原冻结维护执行器、归档与恢复校验器和确切 SQL，在本机完成两个历史批次的归档、原模式恢复校验及删除；派生项级联清理，受保护原记录、当前公开搜索和 run 摘要保持。原六表恢复无需携带可重建的片段。原删除行数指标只统计原负载，级联片段行需另计，不能把原指标当作全部物理工作量；维护负责人仍须审核真实拓扑、WAL／时间成本及窗口。本机模型不替代云端锁竞争或完整恢复验收。

通常填充目标须来自原负责人已完成全部后置的成功回执和执行前的新鲜元数据；本次用户明确批准的暂停批次例外见[范围决策](decisions/2026-10-20-search-precomputed-validation-scope.md)，不推广为以后默认规则。不能采用仍持有效租约的恢复批次，也不为了优化直接填充旧回退批次。新 run 不继承片段，常态生成未接入前，发布换批会恢复原提取成本；一次填充只能验证该批，不能称为持续生效。读取沿用网站实际选择的模式及原 `retain_last_success` 政策；时间戳过期不能单独证明不可读，更不能为提速擅自切换到 persistent 模式或更新原有效期。

正式验收复用 F21 的同一组 14 页定义、既有基线和分段计时，由发布负责人分配一次请求预算；不为本候选重新扫站。需记录新部署身份、实际函数地域、HTML／首字节／可见内容、search-read／text／match／version、派生覆盖率、错误和暖访问回退。首访小样本不能写成冷启动 p95。建议搜索 read 的配对中位至少改善 30%、暖 HTML 中位回退不超过原 100ms 容差，公开 DTO 与撤回检查全部通过；这些是后续验收建议，生产绝对耗时须实测，不套用本机比例。详情、首页、作品页分别验收，不因搜索改善放行旧地域候选。

评估优先同一稳定批次内交替比较旧／新数据库 API，只返回规范化结果摘要、条数和时长，限制完整搜索执行次数，不把正文导出本机。HTML 暖回退应有同批、同客户端的受控前后样本；旧 14 页基线只作参考，来源／内容／代码变化时不能伪装成严格配对。本次批准的云预算和窗口已经使用并关闭；后续执行须给新的具体范围，不自动沿用剩余次数。准备和本机预演不冒充正式取样结果。

回退优先选择已核实的旧读取部署／`on-demand` 配置对应的新部署，同时停用生成，保留原数据和可重建表。修改或删除平台环境变量本身不改变已经运行的不可变部署。生成失败只重查状态和结果，不盲重放。清理扩展另安排窗口，不在回退时自动 DROP／删除原记录。
