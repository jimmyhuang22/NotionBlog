# 固定 v2 同步入口

最新阶段：用户选择每两小时自动运行，沿用每轮 90 分钟及去重媒体 2 GiB 上限。此前仅安装候选的限制由本次持续运行授权取代；首次完整正文及图片缓存建立仍可能较慢，具体运行状态见 [进度](progress/2026-10-12-website-periodic-sync.md)。

`scripts/website-sync/run-private.mjs` 是 v2 网站同步的独立主机入口，配合原件复用。旧 `scripts/notion-sync/run-private.mjs`、v1 状态和调度不改变；不能把旧 v1 入口或旧单次批准当成 v2 持续运行授权。

## 固定源码与私有配置

从已提交版本导出独立 release，按相同锁文件准备依赖，不从开发工作树或 `current` 符号链接直接启动。私有 manifest 使用 `format=website-v2-release-1`，记录 commit、规范 Node 绝对路径／版本／SHA，以及所有导出源码的相对路径／SHA。入口核对文件与 Node 身份、拒绝 `.git` 开发检出和被改动源码；manifest 保存在源码之外、600 私有文件。依赖按锁文件安装或复用同锁文件已验证的本机依赖；源码摘要不代表逐个核对整个依赖目录。

另以 600 私有 JSON 保存 `format=website-v2-runtime-1`：

| 字段 | 用途 |
| --- | --- |
| `project`、`manifest` | 规范绝对路径的独立 release 与对应 manifest |
| `privateRoot`、`stateDir` | 现有 700 输入根与其 `state/`；业务锁不能换成第二个状态目录 |
| `sourcesFile`、`sourceSha256` | 独立 v2 来源文件及已确认输入字节摘要，不覆盖 v1 来源 |
| `cacheDirectory`、`originalsDirectory` | 私有原件验证缓存与可选只读镜像，目录不能重叠 |
| `readerEnv`、`readerUrlFile` | 独立受限 reader 配置及可选既有连接地址文件，不提权 writer |
| `refreshSha256`、`converterSha256` | 现有权威续期模块及 HEIC 转换器摘要 |
| `timeoutSeconds`、`maxMediaBytes` | 显式协作预算，最多 5,400 秒；去重媒体最多 2 GiB，不能当作总网络预算 |
| `collectionConcurrency` | 可选逐页正文／媒体并发，整数 1–4；缺省 1。只接受绑定 runtime 的显式值，不改变总请求节流或额度 |
| `notionIntervalMs` | 可选 Notion 请求起始间隔，整数 350–5,000 毫秒；缺省仍为 700。绑定 runtime 摘要并显式传给子进程，不从 shell 继承 |

路径不含凭据，私有输入仍来自 `notion-readonly.env`、`supabase-worker.env`、原续期模块和转换器。v2 来源必须明确配置，入口不读取 shell 或网站的 provider／来源开关。

## 检查与实际运行

```sh
"$TASK_NODE" "$TASK_RELEASE/scripts/website-sync/run-private.mjs" \
  --config "$TASK_RUNTIME_CONFIG" --mode publish --check
```

`--check` 只核对本机 release、私有文件、输入语法／摘要、目录隔离和预算；不联网、不续期、不取锁、不创建缓存、不启动 worker。它不能证明当前 Notion 权限、服务器政策、凭据时效或真实同步成功。

省略模式默认 `dry-run`。实际 `dry-run` 会完整读取 Notion 与图片、建立缓存记录，不能把它当成便宜的检查；`stage` 会写受限暂存与转换图，`publish` 会更新完整批次，均须在对应授权范围执行。最初候选阶段只安装和离线检查；现已按用户后续授权进入下述持续运行阶段。

## 锁、会话和预算

实际运行取得同一个输入根 `manual-run.lock` 和同一个 `state/worker.lock`，已有续期锁也拒绝启动，不偷锁。子进程只接收白名单私有配置和固定 PATH，不继承 shell 秘密／Node options；临时配置为 600，结束后清理自己的文件和锁。v2 输出在 `state/website-v2/`，不覆盖 v1 checkpoint。

受限 writer 与独立 reader 均验证数据库角色和 TLS。Storage 会话在需要时通过原助手续期，要求服务器确认且静态连接／桶／API 配置不变；不新增身份或权限。来源仍按原公开规则完整枚举，图片通过[强验证器与原件复用](WEBSITE_IMAGE_REUSE.md)减少重复正文下载；HEIC 保留完整转换流程。

子进程用协作预算与取消信号约束 Notion、图片和发布阶段，Notion 请求体最多 2 MiB，观察到的网络／网关错误才有限重试，取消后不追加重试。父入口在预算加 30 秒后要求终止，最多再等 60 秒；强杀或断电后须核对残留状态和云端 lease，不从非零退出码推断没有 promote。

## 结果与后续

每次独立 run 目录保存进度和私有回执；发布后用受限 reader 核对当前 run 与冻结 schema，由服务器执行资格检查。只有发布与读取确认均通过才更新 v2 `last-success-private.json`；其他运行仅更新 `latest-run-private.json`。缺失／截断回执和提交后丢响应保留“可能已发布”，不自动再次完整运行。

自动学习发现期间，`progress-private.json` 与最终回执记录当前课程序号、活动课程总数、已完成课程数、已发现学习页数和已扫描 block 数。课程开始／完成事件另写入 600 的 `discovery-progress-private.jsonl`；失败保留最后的部分进度，不能标成完整目录。事件不包含课程 ID、标题或正文，记录失败只标记 `discoveryProgressWriteFailed`，不把诊断文件变成新的发布条件。

Notion 统计中的 `attemptsByMethod` 区分页面、block、schema 与数据源查询；它与 SDK 尝试数一致，可能包含被共享账本拦截的尝试，实际准入请求以共享账本为准。上述记录只供计算规模和定位阶段，不是断点续跑输入，也不能替代公开资格或快照。

调整间隔并不增加请求／字节／时间额度。部署前根据实际规模分别安排目录发现、正文、媒体及发布后登记；不得仅凭工程测试通过认定预算足够。所有间隔继续共用队列、429／529 退避和取消信号。Notion 还有连接与工作区两级限流，须服从实际 `Retry-After`，见[官方限制说明](https://developers.notion.com/reference/request-limits)。

不根据本机结束时间计算或延长服务器资格，不把本机成功时间当作当前在线保证。首次实际更新仍需为尚无验证记录的图片完整 GET，之后才能测量全库复用量与耗时；完整正文枚举、失败恢复余量及独立托管恢复继续分阶段验收。主机入口本身不安装定时器、执行迁移、改政策或部署网站。

## 每两小时运行

`scheduled.mjs --config <私有配置>` 调用同一固定 publish 入口。用户随后选择统一接入现有 Dagu：网站每两小时 :10、游戏每天 09:00，均按 Australia/Melbourne；Dashboard 只读展示 Dagu 的结果和历史。Dagu 自身继续由 launchd 保活，两个业务任务原有 LaunchAgent 已卸载并私有归档，不同时启用两套排程。

参考 [Dagu 网站模板](../scripts/website-sync/templates/scheduled-dagu.yaml) 与 [游戏模板](../scripts/game-sync/templates/daily-dagu.yaml)。不设置自动重试或漏跑补执行；保留原业务锁和未知发布结果保护。网站自身上限仍为 5,400 秒，Dagu 外层多留 120 秒给退出和回执收尾，不增加采集预算。网站固定运行副本与独立 Node 放在内盘；Node 不能长期依赖临时 npm 缓存路径。实际配置、来源、凭据、回执及旧 launchd 文件只留私有交接；[launchd 模板](../scripts/website-sync/templates/scheduled-launchd.plist) 仅供其他安装方式参考，当前未启用。

`scheduled-status-private.json` 记录编排状态，原 `latest-run-private.json`、`last-success-private.json` 和逐次回执继续由既有主机程序维护。只有发布及 reader 核对都通过才计成功；第一次成功及变化后的失败尝试本机静态通知，普通成功与重复同一失败安静。若上次可能已 promote 但未验证，后续暂停；先核对服务器 current／lease 和完整回执，归档待核回执后再恢复，不自动删锁或重试未知提交。

后台 Notion 限流等待由整轮 AbortSignal／90 分钟上限控制，不能沿用交互读取的 9 秒排队、10 秒 SDK 上限；单次 HTTP 仍为 8 秒、响应仍最多 2 MiB。429／529 的 SDK 有界重试按完整 `Retry-After` 等待，不增加外层限流重试循环。私有进度记录限流响应次数和最后等待秒数，不记录上游正文或身份；网页读取默认预算保持原值。

设备睡眠、未登录、网络或会话失效会影响运行。每两小时是触发频率，四小时仍是服务器资格上限；失败不会延长旧资格。正常同步不运行工程测试、构建或网站部署。


## 有界正文采集与恢复边界

显式 `collectionConcurrency=4` 允许同一来源最多四页同时处理，来源之间及首次自动课程目录发现仍顺序执行。每页正文内部仍保持既有顺序；输出按原来源序号和学习目录序号归位，父节点先于后代。Notion 请求继续使用同一个节流队列与总账，不能把四路误认为允许四倍请求速率。媒体读取／尺寸识别可重叠，去重字节计账及 Storage 提交串行；相同原件不会因同时完成而重复 PUT，首个提交错误阻断后续提交，已开始的页面会排空后才退出。取消信号同时传给 worker 和运输层。

`progress-private.json` 和最终回执新增 `collection`：当前来源序号、来源总数、当前来源候选页数、当前来源已完成正文数、累计完成正文数和阶段。已被 deny 排除的页不计入完成数。课程目录发现成功不代表正文全部完成；`collection.phase=complete` 也只是收集完成，发布状态仍由 `published` 和独立 reader 决定。进度与回执采用 600 临时文件、fsync、原子替换，观察者不再读到截断 JSON；图片诊断保留首个终止错误，后续在途页不会清掉它。

这些进度文件仍是诊断，不包含可恢复的完整正文。失败后可复用原件强验证缓存与已独立证明的小图；不得跳过新的来源资格检查，也不能跳过先前只在内存中完成的目录发现。当前混合媒体运行器不支持跨进程正文断点续跑。

后续恢复设计分三种情况：

1. **已成功发布，只缺回执／小图／快照**：先用独立 reader 确认实际批次，复用该批次继续后置，不再运行全文采集。公开资格已失效或批次变化时停止，不能手改有效期。
2. **完整采集成功，尚未确认发布**：若要恢复，必须先保存绑定源码、来源摘要、policy epoch、lease、deny、目录顺序、正文和媒体描述的完整私有工件，并实现实际云状态核对及幂等提交规则。当前混合模式尚未接入此工件和恢复入口；仅写一份 JSON 不构成可恢复性。
3. **采集中断**：跨运行复用逐页内容需要重新确认成员、物理父链、撤回和每个后代的变化，不能只看课程或父页更新时间。先明确验证协议再实现持久缓存；不以部分计数、过期 signed URL 或失败批次作为公开输入。

已有 `published/storage` 增量主机需要同次完整接受基线，不能直接用于本机混合媒体链路。详情见 [增量主机](INCREMENTAL_HOST.md) 和 [完整基线工件](FULL_BASELINE_ARTIFACT.md)。本次并行修正不启用增量、不更换 provider、不调整实际时间／请求预算或恢复调度；真实速度和下一轮是否足够仍待获准执行验证。


## 单页媒体刷新与逐页保存

仅完整采集 worker 使用单页异步上下文：过期图片第一次刷新时重新读取该页及完整祖先／schema资格；同页最多30秒复用，计时从请求开始而非完成开始。块图片按已知直接父节点取得完整最新兄弟列表，相同父节点内复用最多30秒，每张图片仍比较原来源指纹、存在性、类型、归档状态与物理归属；嵌套祖先继续实时读取。超过30秒才返回的读取直接拒绝。结束该页前再次独立核验 owner、祖先、配置与编辑版本，变化即失败，不暂存部分批次。所有上下文在成功／失败后释放；不同并发页和访客媒体接口不共享。此优化不降低统一节流、预算或撤回守卫。

固定主机入口可显式设置 `captureCollection: true`，缺省 false；与其他运行输入一起固定在 manifest／预算绑定中。成功完成当前页采集后，将正文记录、媒体描述／定位指纹、原 lease 保存至该 run 的 `collection-private/page-<id>.json`。目录700、文件600、每页和索引原子落盘；失败保存已有完成页，不伪造未完成页。记录数最多20000，正文与来源证明、媒体描述累计最多128MiB；图片字节继续保存在既有原件缓存。全收集完成且独立最终资格复核通过后才写入完整标记及父子发布顺序。保存失败阻止发布。

索引绑定 run、解析后的配置摘要、来源文件SHA与运行源码提交，每页有摘要。`inspectCollectionCapture` 是离线检查函数，逐项检查文件权限、硬链接、内容摘要和媒体引用，只输出计数；始终返回 `publicationEvidence=false`、`resumable=false`。它没有发布／续租／回放入口。前一轮未启用保存的正文无法事后恢复。

这里先解决中断后丢失已完成正文的问题，尚不宣称跨进程续发：旧批次已fail，不能借新begin把旧快照的资格重新计时；公开配置、成员集合、所有后代变化、物理父链与中央deny仍需重新证明。仅检查父页last_edited_time或内容文件SHA不足以批准回放。恢复协议与当前混合媒体模式的适配完成前，不能自动加载这些页跳过真实来源扫描。新字段未装入实际主机配置，当前维护和调度状态不变。

### 保存内容的重新验证与截止时间

`runRevalidatedWebsiteSync` 是独立的服务端工程入口，输入包括受保护采集目录、原运行身份、受限 writer 连接和显式 qualified 模式；它保留为严格完整重读验证入口；固定主机的完成页复用入口见下一节。它先验证全部文件哈希及原租约，再取得新租约并调用 `nb_revalidation_api.bind_run`，之后才进行 Notion 读取。缺少扩展、原批次过期或政策已变时停止并清理新租约，不自动变成普通全量运行。

扩展 SQL 由 `database/qualified-revalidation-protocol.json` 固定摘要，独立安装于冻结 v2 之后。`nb_writer` 仅可执行绑定函数，不能直接更改 runs 或绑定表；reader 与 PUBLIC 无访问权。服务端强制 `new.valid_until = min(new.valid_until, old.valid_until)`，本机仅用服务器回执和单调时钟提前停止浪费的读取。原批次日期不改；续租、再次恢复、重新运行均不能为被恢复内容延长有效期。SQL 暂存、发布和 qualified 读取沿用既有到期拒绝。

当前实现重读完整成员／正文，验证当前媒体字节与绑定，所有保存页都必须存在且一致；目录 ordinal 采用新发现的顺序。新增成员正常采集，源内容变化则整轮停止。旧 DTO 从不写库，原件缓存继续使用现有强验证器。这个严格验证入口不跳过正文映射；下述主机复用入口可跳过已验证的正文映射，但仍需要当前目录／依赖读取，不保证全库 Notion 请求降幅，也没有自动定时恢复。源端读取不是事务，不能保证所有页面在同一瞬间的状态。

安装前需确认扩展摘要、角色权限和实际剩余时间；若剩余时间不足以完成重新验证和后置验收，应放弃恢复，不修改旧日期。完整新采集属于另一个有独立预算和窗口的运行。详见[实现交接](progress/2026-10-16-collection-revalidation-expiry.md)。


### 固定主机的完成页恢复

首次采集显式设置 `captureCollection: true`。完成页包含 `sourceReads`，仅存来源读取方法、ID、哈希及分页请求估计，不存源响应或签名地址。需要恢复时，默认用同一源码与来源配置，生成新的 runtime 文件并设置以下字段，再把该文件摘要绑定到新的共享预算输入：

- `resumeRunId`：原失败批次 UUID，工件固定来自 `state/website-v2/<run>/collection-private`。
- `resumeIndexSha256`：原目录 `index-private.json` 的实际 SHA256。
- `captureCollection: true`：恢复本身继续保存新的完成页，后续中断不丢掉本轮进度。
- `resumeRequestReserve`：本轮媒体处理前要求的最小剩余 Notion 请求数，正整数、最多 50000；不是追加授权。
- `resumePostSeconds`：小图登记与网站验收所需剩余资格预留，0–7200 秒。恢复绑定后，服务器剩余资格必须覆盖 `timeoutSeconds + resumePostSeconds`。

仅接受 qualified／Notion 混合媒体、stage 或 publish。必须通过既有 `qualified-budget-cli.ts`，直接调用不带共享预算的主机入口会拒绝恢复。默认仍只检查：

```sh
node scripts/website-sync/qualified-budget-cli.ts --config PRIVATE_RUNTIME --budget PRIVATE_BUDGET --ledger FRESH_PRIVATE_LEDGER --mode publish --check
```

另行获准的执行使用同样输入，把 `--check` 改为 `--execute`。每次只执行一个批次，不自动重试；默认只有同版本、同来源／配置、同政策且尚未过期的原批次能绑定；下述窄范围源码兼容入口是唯一例外。离线 check 不证明数据库仍有效，实际 bind 才核实。缺少旧依赖摘要的文件不能用于这个入口。

恢复扫描当前成员，复用本轮已获取的完整列表，逐页比较全部来源依赖。未变页复用已映射正文；变化页重新采集，新的 ordinal 采用当前目录，已缺失成员不发布。复用页仍验证当前图像字节与定位指纹，Storage 转换图只读回已有对象；失败即停止，不偷偷上传替代物。正文采集默认仍为 16MiB；后台可显式配置 `maxCollectionBytes`，上限 64MiB，媒体仍最多 2GiB。单条内容、逐批 SQL 与媒体上限不变。

当前响应缓存只在本次采集内存在，最多 30000 项读取与实体条目／256MiB 原始响应，旧进程响应不加载。发布前的全部 owner／祖先复核使用另一个新建读取会话，不接受采集会话的响应；共享祖先在最终复核会话中只读一次。原目录扫描后已读过的内容无需在本次构建正文时再请求；重启仍必须重查当前目录和依赖，因此不是零读取的断点续传。

`resume-plan-private.json` 记录保存页、当前页、新增／未完成页、缺失页、已知验证请求、最大已保存页成本、剩余额度、请求预留和估计的重试情形。未知页可能比已保存页更大，`guaranteedCompletion` 始终 false。目录发现本身不在剩余估计里；已在共享账本扣费。`progress-private.json` 和最终回执记录实际复用、重采、新页数与当前读取缓存命中，不将它们计作发布成功。

固定主机与共享预算解析器可接受显式至 7200 秒的采集上限；旧 runtime 的 5400 秒不变，延长必须写入新批准的预算和窗口。小图与验收仍是独立后置阶段，不能用恢复重置原资格。


### 过期图片修复后的源码兼容接续

原过期图片缓存缺陷的生产版本可通过显式 `resumeProducer: { project, manifest, manifestSha256 }` 指向只读旧冻结包，使用已审查的修复版本接续。主机和实际子进程均验证两份完整 manifest、Node 身份及每个文件摘要；兼容检查只允许固定旧提交与固定新旧 worker 摘要之间的变化，外加恢复入口／计划、类型声明和文档／测试。正文映射、依赖证明、捕获格式、媒体字节验证、SQL、DTO 或依赖发生其他变化，一律拒绝。不存在通用的“忽略版本”开关。

旧 capture 的版本、run、索引和内容文件均不改。新回执记录原生产版本和当前运行版本，新保存页属于新运行；来源摘要、当前成员、全部依赖、媒体字节与最终独立资格复核仍执行。数据库绑定仍把新有效期压到旧有效期以内，不能用修复后的代码延长旧资格。离线兼容通过不代表剩余时间足够；必须保留完整采集上限加后置窗口，否则放弃接续。

请求准入使用 `max(resumeRequestReserve, knownWorkEstimate)`。其中已知工作估计为保存页依赖读取量加当前页数的 owner 复核；复杂祖先、图片刷新、新增／变化页及重试可能增加请求，显式预留应覆盖这些开销。把最复杂保存页成本乘到全部当前页的结果仍记录为情景估计，但不再作为强制准入条件。所有实际请求仍受共享账本硬上限限制；任何估计都不是完成保证。


### 重新验证后建立新批次资格

用户明确要求：旧批次过期不代表内容变化，已保存的正文不能因此一律作废。新增 `resumeQualification: "fresh"`，与原 `"original"` 模式分开；缺省仍为 original。两者都必须提供上述恢复工件、来源摘要、共享预算、请求预留、后置时间与继续保存选项。只有 fresh 允许使用已过期失败批次的缓存；它不是沿用旧公开证明。

fresh 使用普通 `begin_run` 建立新租约和服务端原政策规定的截止时间，然后通过独立 `nb_revalidation_api.inspect_fresh_run` 检查旧批次身份及新租约。函数只检查，不修改任何批次日期，不替换冻结函数。旧批次必须失败、来源配置相同、原 fence/revision 匹配；其过去的 epoch/revision 不授予当前资格。新批次必须当前有效、尚未暂存，也未绑入旧截止恢复。reader／PUBLIC 不可执行，writer 无直接改表权限。扩展与摘要见 `database/fresh-qualification-protocol.json`。

读取当前全部成员，比较保存页的完整来源依赖哈希，独立复核当前 owner／祖先和中央 deny。匹配页复用映射正文，变化页补采，新成员正常采集；撤回页不发布，读取不确定时停止。所有复用页保存到新批次自己的工件；原失败文件与账本不变。图片仍使用现有缓存验证，转换图回读已有对象。不能只用父页编辑时间证明深层正文没变，当前依赖比较仍会读取嵌套块列表，因此这是正文映射和媒体工作的复用，不是零 Notion 请求、也不承诺目录扫描消失。源端仍不是事务快照。

服务器新资格需覆盖 `timeoutSeconds + resumePostSeconds`，实际 Notion／SQL／字节额度、绝对停止线继续由共享账本控制。fresh 不触发自动重试，不意味着安装或真实执行已经获准，也不切换持久发布模式。

最新容量修复的跨版本接续由 `database/capture-requalification-compatibility.json` 固定审查过的前后文件字节摘要。原映射／依赖证据／DTO／依赖锁中未列出的变化继续拒绝；没有运行者可指定的通用忽略开关。旧工件用原 releaseCommit 检查，不能伪装成新版本。

### 大规模采集到验收的容量边界

| 环节 | 边界与处理 |
| --- | --- |
| 正文采集 | 默认16MiB；后台显式 `maxCollectionBytes` 最多64MiB，最多20000条 |
| 耐久保存 | 累计128MiB，包含正文、来源证明和媒体描述；不包含图片字节 |
| 当前来源读取会话 | 最多30000个缓存项、256MiB，只有本轮真实响应可以进入 |
| SQL暂存 | 仍逐条正文、分批媒体；每次请求原16MiB限制不变 |
| 默认网站快照 | 冻结 SQL 聚合16MiB限制不变 |
| 运维完整快照 | 显式 `snapshotPageSize: 1..100`、`maxSnapshotBytes: 1..64MiB`；逐页绑定同一run/revision，首尾核对，逐页执行当前下架／过期检查 |
| 图片与媒体 | 原2GiB总量和单图边界不变；不能从正文容量推断媒体一定足够 |

大快照验收必须使用新的分页选项，并按页数与响应总量重新绑定独立 SQL 预算。不能只扩大采集容量，再沿用旧的单次全正文快照或旧八次 SQL 输入。既有已批准输入原样保留，新输入另行生成。
