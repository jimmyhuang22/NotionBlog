## 每次执行前后的最小核对

1. 消费同一最终方案、输入摘要与累计账本。固定小图历史执行合计218次请求、上传1,774,454B／响应1,772,384B；后续执行须累加其实际增量。成功对象按摘要取并集，不能把重叠回执的数量相加。共享锁只保证串行，不能代替累计预算。
2. 原两轮转存窗口已结束。存储拥有方已另获20分钟续办授权，先核验两个unknown，再继续其余固定候选；全部轮次仍共享600次请求和15MiB文件体。本次核对时首次续办停在两个地址的TLS预检超时，新增HTTP／文件体均为零；拥有方沿同一截止时刻接续连接检查。该授权不包含 Source完整采集、政策／SQL写入、原件迁移或网站模式切换。新的获准截止时刻以一次性启动回执为准。
3. 旧 publisher 及其小图步骤退出后，按具体维护方案交接同一锁；不删除租约或并行启动两套 writer。政策变化会使旧 qualified 发布失效，恢复旧环境文件不能保证内容恢复，需要实际可重新发布的旧范围与恢复预算。
4. full 已有准备工件或接受状态不确定时先按原操作身份 lookup／seal，不能重新采集或盲重发 promote；增量unknown先 recover，独立确认、两个缓存完成后才 ack。
5. 对缺对象、字节不符、权限漂移、范围／政策不一致或未确认提交，记录具体缺项并停止进入切换阶段。已有同版验收直接复用，补齐尚缺或受影响部分，不重跑已成功的全量来源和全图传输。

## 切换放行与分工

媒体交付、同次接受工件、运行初始化、代表增量／恢复和访客独立访问的真实证据齐备后，再由运行与发布拥有方提交具体维护方案及网站发布变更。日常 develop 合并按影响验证；有 develop → main 发布请求开着时保留工作分支，等发布合并后继续。main 发布仍按最终集成版本验收及当次用户授权执行，见 [发布期间的合并约定](decisions/2026-10-13-develop-hold-during-release.md)。

本页由“查看重构进度”整理既有证据，不占用存储或主运行器的执行窗口。存储续办由“查找预览图功能进度”统一执行；首次工件、学习、现有发布与前端验收沿 [既有分工](REFACTOR_ROLLOUT.md#回滚与分工)交回。对象数量和执行结果更新时，以绑定最终回执的 [小图转存记录](THUMBNAIL_STORAGE_TRANSFER.md)及对应执行者记录为准。
